# 模块功能方案（按现状与分期实施）

> 本文档不再把“研究蓝图中的理想模块”直接写成当前能力，
> 而是将每个模块统一拆成：**当前能力 / 短期增量 / 中期演进 / 远期研究**。

## 1. 使用说明

- **当前能力**：仓库中已经存在、可在代码中找到实现路径
- **短期增量**：基于现有模块即可补齐，改动面较小
- **中期演进**：已有基础设施，但需要跨模块接线或新增持久化结构
- **远期研究**：研究报告中成立，但当前仓库不应承诺为现成能力

## 3. 各模块落地说明

### 3.1 数据采集与快照

- **当前能力**：围绕日级市场快照组织工厂输入，已可支撑每日调度
- **短期重点**：补“本次采集是否完整、缺了什么、是否降级”的结构化说明
- **中期重点**：把快照对象定义成稳定契约，便于后续看板和调度复用
- **远期方向**：若要进入更高频工厂，才需要实时数据质量与流式处理

### 3.2 候选生成与初筛

- **当前能力**：候选生成以启发式规则为主，已接入轻量 AI 候选增强；初筛仍以轻量回测为主
- **核心设计（数据信号→策略参数映射）**：候选生成的核心是“每个数据信号定义一个参数偏好区间，多信号叠加取交集后采样”（详见《策略工厂方案》`docs/plans/策略工厂方案.md` 第 3.2 节），主要驱动源包括：
  - 恐贪指数驱动：恐惧→RSI 抄底/价值精选；贪婪→短周期动量/敏感逃顶
  - 波动率分量驱动：高波动→长周期过滤；低波动→短周期捕捉微弱趋势
  - 因子 IC 驱动：IC>0.03 且上升→生成对应策略变体；IC 下降→避免或反向；多因子权重随 IC 动态分配
  - 资金流驱动：北向净流入→成长/质量；净流出→防御型价值；融资变化→动量或避险
  - 分类配额补位：低于最低配额时自动补位
- **短期重点**：把“为什么生成 / 为什么被筛掉”写成机器可读字段
- **中期重点**：按策略类型拆分阈值，减少单一规则误伤
- **远期方向**：完整工业级 RL / LLM 自治工厂只保留为研究方向，不写成当前路线承诺

### 3.3 去重与相似性识别

- **当前能力**：参数相似度去重已经可用，且已补重复原因、命中对象与阈值说明
- **短期重点**：继续观察行为向量复筛阈值与缓存命中效果
- **中期重点**：先复用 `vector_search.py` 的进程内索引，不急于直接上数据库向量索引
- **远期方向**：`pgvector/HNSW` 只有在去重规模、持久化和查询性能成为瓶颈时才值得落地

### 3.4 质量门禁与报告

- **当前能力**：四步质检已经存在，且结果已结构化落库到质量报告
- **短期重点**：继续补齐更多摘要字段与对外展示口径
- **中期重点**：增加复检入口，并把失败原因进一步标准化
- **远期方向**：复杂解释文本、综合评级和自动复检暂不建议前置

### 3.5 生命周期、孵化与淘汰

- **当前能力**：状态机、生命周期扫描、淘汰检查都已存在，且已引入最小观察窗口与 1/5/10/20D 前向收益总览
- **短期重点**：调优晋级/淘汰阈值，减少误伤
- **中期重点**：继续提升多周期 `signal_forward_returns`、净值序列与环境标签在孵化判断中的权重
- **远期方向**：真正把 `paper_trading.py` 绑定为孵化账户，并用 NAV 驱动状态转换

### 3.6 审计与状态追踪

- **当前能力**：已有淘汰日志、血缘记录与 append-only 状态审计日志
- **短期重点**：补更多事件 metadata 与筛选口径
- **中期重点**：为策略详情页继续扩展事件时间线查询能力
- **远期方向**：完整 Event Sourcing / CQRS 不应进入近期排期

### 3.7 接口层与展示层

- **当前能力**：策略超市端点已覆盖列表、详情、创建、发布、订阅、评论、信号与前向收益，并补了工厂运行态、质量报告、手动触发、事件流、孵化概览、运行历史详情、最近运行对比、轻量趋势视图、状态/指标筛选、失败原因聚合、错误指纹标准化以及规则命中统计
- **短期重点**：补更多聚合看板与筛选能力，继续扩展基于运行历史的趋势展示、失败聚合分析与规则覆盖观察
- **中期重点**：继续扩展工厂概览，减少纯文档口径管理
- **远期方向**：运营控制台、批量干预、完整告警面板属于更高阶段建设

## 4. 推荐排期顺序

### 4.1 一期：最小可落地补齐

1. 工厂摘要统一统计口径
2. 质量报告摘要与失败原因标准化
3. 孵化阈值参数化
4. 运行失败聚合与错误指纹增强

### 4.2 二期：把现有基础设施真正接起来

1. 提升 `signal_forward_returns` 与净值序列在晋级口径中的权重
2. 扩展向量画像与跨批次候选复用
3. 增强状态事件 metadata 与时间线查询
4. 扩展工厂运行趋势与运营视图

### 4.3 三期：研究能力再评估

1. `paper_trading.py` 与孵化链路真正绑定
2. `pgvector/HNSW` 持久化向量检索
3. 完整 Event Sourcing / CQRS
4. 工业级 RL / LLM 自治工厂

## 5. 当前不应写成“已实现”的事项

- `pgvector/HNSW` 去重
- 完整 Event Sourcing / CQRS
- 模拟盘 NAV 驱动晋级
- 工业级 RL / LLM 自治工厂
- 工厂级熔断器、运营总控台、完整审计回放系统

## 6. 最终口径

`03` 的用途应是“给排期和实施评审使用”，而不是继续扩写研究蓝图。

因此后续凡是新增模块描述，都应先回答两件事：

1. 它是否已经在当前仓库中有明确实现证据？
2. 如果没有，它属于短期补齐、中期演进，还是远期研究？

只有这样，模块方案才不会再次混淆“当前事实”和“未来方向”。
