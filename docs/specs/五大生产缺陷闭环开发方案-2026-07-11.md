## 一、方案结论（一句话 + 终态）

### 1.1 一句话

项目不是“没做晋级门禁”，而是 **门禁已立、证据链与退出闭环未稳；就绪定义停在基础设施层；重实现仍锁在 akshare 宿主；运维能力停在脚本**。  
因此开发主线必须是：

> **先修证据生成与退出连续性 → 再把生产探针产品化 → 再渐进瘦 MCP 与运维 Intent 化。**

### 1.2 终态定义

| 维度 | 终态 |
| --- | --- |
| 晋级闭环 | formal / promotion_ready 只由真实证据 + hard gate 达成，可在产品内解释 blockers |
| 证据链 | signal → order → fill → position → close → audit 血缘完整；缺 `signal_id` fail-closed |
| 退出连续 | open 持仓有日更 exit 评估；exit signal/policy → exit order 转化达标；round-trip 可审计 |
| Live 就绪 | `production_ready` 必须过工厂生产探针，Mock e2e 通过不能单独点亮 |
| 宿主边界 | 编排/契约/门禁语义归 strategy-factory（及 quant-core primitives）；akshare-mcp 为 host/provider/data |
| 运维 | 高频 diagnose 与产品 API 同源；Desktop 可看 blockers、证据覆盖、dry-run 动作 |

### 1.3 非目标（明确禁止）

1. **不降低** hard gate 阈值（`production_trade_floor=20`、expectancy>0、pnl_conversion>0、execution_conversion≥0.20）。
2. **不**用 quality/dry-run 会话制造 formal / 伪晋升。
3. **不**默认打开实盘交易；写动作必须 Intent + control token。
4. **不**让 Desktop 直连 MCP / manager / 本地 Python。
5. **不**一次性大搬家 akshare 工厂代码。
6. **不**把 Graphify 2026-05 基线当当前真相（仅参考 blast radius）。
7. **不**把“Agent 进程活着 / factory_status 可达”等同于生产就绪。

## 二、当前事实基线（代码证据）

### 2.1 运行主链

```text
Desktop UI
  → Agent HTTP / agent_* tools only
    → strategy-factory（cycle_pipeline + runtime shells）
      → default_bootstrap 动态加载
        → akshare_mcp.adapters.strategy_factory_runtime.configure_strategy_factory_runtime_services
          → host runtime providers（canonical bootstrap 必需 19 个；host 注册面更宽）
            → incubation_factory.runner phases
            → matching_engine / promotion_pipeline / lifecycle_shared
```

说明：`DEFAULT_REQUIRED_RUNTIME_PROVIDERS` 明确列出 19 个必需项；`configure_strategy_factory_runtime_services()` 还可注册更多 host-only providers。文档禁止再写“必需 20+”。

### 2.4 Hard gate 与 promotion_ready（不可放宽）

**Hard gate 通过条件（已实现）：**

- `realized_trade_count >= production_trade_floor`（默认 20，**最低门槛**）
- `trade_expectancy > 0`
- `pnl_conversion_efficiency > 0`
- `execution_conversion_efficiency >= 0.20`

**状态梯：**  
`missing` → `bootstrap_pending` → `insufficient_samples` → `failed_metrics` / `bootstrap_ready` / `passed`

**promotion_ready（摘要）：**

- primary/secondary skill LCB 与 effective_n、coverage、stability
- **`execution_hard_gate_passed`**
- `risk_hard_gate_status == "passed"`
- `not blockers`
- 可选 cross-regime / DSR（默认 OFF）

### 2.5 本机工作区数据现状（2026-07-11 抽样）

默认库 `data/db/akshare_mcp.sqlite3` 当前为空工厂样本：

- `strategies = 0`
- `paper_orders / paper_trades / strategy_signals = 0`
- `strategies` 表仅有旧 `status` 列口径（无 `incubating` 列于该空库）

**含义：** 空库不能否定历史 formal=0 诊断，但说明 **任何 Live 就绪定义若只看进程可达，会在证据全 0 时误判**。  
历史有样本环境下的退出断链证据见 `scripts/factories/EXIT_PATHWAY_DIAGNOSIS_REPORT.md`（open 高、closed 极低、exit order 转化极低）。

## 三、五大缺陷：根因链与目标修复面

### 缺陷 1：生产晋级闭环未稳（formal / hard gate / 证据链）

**症状**

- formal 难产出或不可解释
- hard gate 长期 missing / bootstrap_pending / insufficient_samples
- Phase 3e/3f 回填依赖不完整血缘

**根因链**

```text
候选入孵
  → 信号生成
    → 订单创建（可能缺 signal_id / position 血缘）
      → 撮合成交
        → 退出不足 → 无足够 realized round-trip
          → audit 证据缺口
            → hard_gate 不通过
              → promotion_ready = false
                → formal 不晋级（正确行为被错误上游饿死）
```

**修复面**

1. 血缘 fail-closed  
2. 退出闭环抬升 realized 样本  
3. 证据 gap 可观测（API + 产品）  
4. 不降门槛

### 缺陷 2：akshare 宿主过重，独立化未完成

**症状**

- strategy-factory 无静态 import，但仍依赖 AKShare 动态注册才能跑
- 工厂业务改动爆炸半径在 MCP 包

**根因链**

```text
边界设计（动态 bootstrap）
  + 重实现未迁出
  + 契约/门禁实现仍在 lifecycle_shared（akshare）
  = 独立化进度有限（工程判断；证据：SF 仅 runtime shell，runner/I/O 仍在 AK，见 §2.3 规模表）
```

**修复面**

- 冻结 AK 新工厂功能  
- 契约与门禁纯函数上移  
- matching/promotion/incubation phase 编排渐进迁移  
- 与 `docs/specs/四工厂独立化与MCP瘦身拆分开发方案` 对齐，但 **P0 不阻塞于大迁移**

### 缺陷 3：Mock 产品完成 ≠ Live 生产就绪

**症状**

- Desktop Mock e2e / 页面可用  
- readiness 可能 partial/ready  
- 工厂证据仍空或断链

**根因链**

```text
financial_readiness 只探：
  AI / control / DB 可写 / MCP / factory_status 可达
不探：
  formal 分布 / signal_id 覆盖 / exit 转化 / hard_gate 直方图 / evidence gaps
```

**修复面**

- 扩展 production probes  
- Desktop 展示工厂就绪指标  
- `production_ready` 与 mock 解耦

### 缺陷 4：退出与信号连续性历史薄弱

**症状（历史样本）**

- open 堆积、closed 极低  
- exit signal 存在但 exit order 转化极低  
- stale close 默认 OFF 等策略缺口

**根因链**

```text
entry 成交
  + 缺日更 exit 评估 / exit_policy 不全
  + backlog 选择未覆盖“有仓需平”
  + signal_id 断链
  = 无 round-trip → hard gate 永久饿死
```

**修复面**

- Phase 3c2 候选逻辑  
- exit_policy 入池校验  
- stale close 策略化（非静默永远关）  
- 覆盖率与漏斗指标产品化

### 缺陷 5：运维能力在脚本，不在产品

**症状**

- `diagnose_*` / `live_readiness_smoke` 能力完整  
- Desktop 只能看 status/JSON  
- 值班依赖本地脚本与专家知识

**根因链**

```text
脚本直连 SQLite / Agent
  产品只做只读 status
  无同源 service 层
  = 双实现风险 + 不可操作
```

**修复面**

- diagnose 上收 service  
- Agent 只读工具 + Intent 写动作  
- Desktop Ops / Factory 面板

## 四、目标架构与数据流

### 4.1 目标职责划分

| 包 | 拥有 | 不拥有 |
| --- | --- | --- |
| `strategy-factory` | 周期编排、状态机、runtime contract、晋级语义编排、诊断聚合 API 契约 | 外部行情源、FastMCP host |
| `aiask-quant-core` | signal/order/position/audit 存储 primitive、共享回测/风险 primitive | 工厂业务 phase |
| `akshare-mcp` | MCP host、数据接入、SQLite provider、具体 data adapter | 长期拥有工厂业务真相 |
| `agent` | Desktop 唯一 HTTP 面、readiness、agent_* 工具门面 | 直写工厂 DB 旁路 |
| `desktop` | 只读面板 + Intent 触发 | 导入 Python/MCP |

### 4.2 目标证据链

```text
SignalGenerator / SignalTracker
  → strategy_signals（稳定 signal_id）
    → paper_orders（强制 signal_id + position_id + strategy_id）
      → matching_engine fills（继承血缘）
        → paper_trades / strategy_trade_positions
          → exit_signal 或 exit_policy → exit_orders → close
            → execution audit snapshot
              → evaluate_execution_audit_gate
                → overview.promotion_ready
                  → formal / graduation
```

任一环节失败必须产生 **稳定 gap code**，可被 diagnostics API 聚合。

### 4.3 目标 readiness 分层

| 层 | 含义 | 决定 |
| --- | --- | --- |
| L0 Infra | Agent/DB/MCP 可达 | 能否登录运维 |
| L1 Factory Runtime | factory_status/runs 正常 | 能否调度 |
| L2 Evidence | 信号/订单/成交/血缘覆盖 | 能否形成审计 |
| L3 Continuity | exit/round-trip/hard_gate 分布 | 能否晋级 |
| L4 Production Ready | L0–L3 全过 + 无 critical blockers | 可宣称生产就绪 |

**Mock 只覆盖 L0–L1 UI 契约；不得点亮 L4。**

## 五、分期开发计划

### Phase P0-A：证据链 fail-closed（Week 1，前半）

**目标**：新建路径上不允许 silent 断链。

#### 任务清单

| ID | 任务 | 主要文件 | 说明 |
| --- | --- | --- | --- |
| P0-A1 | 订单创建强制 `signal_id` | `akshare_mcp/services/incubation.py`、incubation_parts `specs` | 缺失则抛/记 `missing_signal_id`，不落单 |
| P0-A2 | 强制 `position_id` / `strategy_id` 一致性 | 同上 | 与 `_build_signal_id` / `_build_position_id` 对齐 |
| P0-A3 | 撮合继承血缘 | `matching_engine.py` | fill/trade 写入 signal/position；缺则 `missing_signal_lineage` |
| P0-A4 | 回填只补可证血缘 | runner Phase 3e/3f | 禁止伪造 signal_id |
| P0-A5 | 契约测试 | `packages/akshare-mcp/tests/`、`scripts/factories/test_evidence_chain_completeness.py` | signal→order→trade→close |

#### 验收

```sql
-- 新建样本后：missing signal_id 应为 0
SELECT
  COUNT(1) AS orders,
  SUM(CASE WHEN signal_id IS NULL OR TRIM(CAST(signal_id AS TEXT)) = '' THEN 1 ELSE 0 END) AS missing_sid
FROM paper_orders
WHERE strategy_id IS NOT NULL;
```

- 单测覆盖“缺 signal_id 拒单”
- CI：`test_evidence_chain_completeness` 绿

#### 回滚

- 功能开关：`INCUBATION_FAIL_CLOSED_SIGNAL_ID=1`（默认 ON 于新路径；紧急可 OFF，但必须告警）
