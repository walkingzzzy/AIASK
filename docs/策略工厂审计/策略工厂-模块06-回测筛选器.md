- 过时/夸大描述：旧版“完全没有组合回测复用”的说法需要改为“候选级 shared result 已复用，但 portfolio engine 调用本身缺独立 timeout/内层缓存”；文档不得暗示完全没有缓存。
- 仍然成立的问题：单候选 evaluated codes 全部 gather，缺早期终止；`engine.run_backtest` 和 portfolio engine `to_thread` 缺 timeout；portfolio engine 没有独立结果缓存；异常股票可能长期占用并发槽。
- 建议优先级：P0 修正缓存表述；P1 回测/组合引擎 timeout；P2 早停与异常样本隔离；P3 portfolio 内层 cache。下方优化建议中的代码块为概念示例。

## 职责

回测筛选器对候选策略执行实际回测，验证其在历史数据上的表现是否达标。支持分层验证（目标层 + 代表层 + 组合层）。

## 核心方法 `async filter(candidates, db) -> List[dict]`

```python
async def filter(self, candidates, db):
    # 1. 预加载 K 线到缓存
    await self.preload_klines(db)

    # 2. 并发回测每个候选
    concurrency = BACKTEST_CONCURRENCY  # 默认 4
    sem = asyncio.Semaphore(concurrency)

    async def _test_guarded(candidate):
        async with sem:
            return await self._test_one(candidate, db, engine)

    results = await asyncio.gather(*[_test_guarded(c) for c in candidates])

    # 3. 按阈值筛选
    passed = [r for r in results if r["passed"]]
    return passed
```

async def _test_one(self, candidate, db, engine):
    # 1. 解析回测计划
    evaluated_codes, target_codes, representative_codes, code_source, validation_focus = \
        self._resolve_backtest_plan(candidate)

    assumptions = self._build_backtest_assumptions(candidate)
    # → commission_rate, slippage_bps, tradability_filter, initial_capital, ...

    # 3. 并发回测每只股票
    code_sem = asyncio.Semaphore(BACKTEST_CODE_CONCURRENCY)  # 默认 4

    async def _run_one_code(code):
        klines = self._kline_cache.get(code) or await db.get_klines(code, limit=500)
        if len(klines) < 100:
            return {"status": "skipped", "reason": "insufficient_klines"}
        result = await factory_pkg.asyncio.to_thread(
            engine.run_backtest, code, klines, strategy_type, {**params, **assumptions_kwargs}
        )
        return result

    code_results = await asyncio.gather(*[_run_guarded(code) for code in evaluated_codes])

    # 6. 事件窗口指标
    event_window_metrics = self._build_event_window_metrics(...)

## 分层验证架构

```
候选策略
    │
    ├── 目标层（Target Layer）
    │     └── 候选指定的 target_symbols（如 ["600519", "000858"]）
    │
    ├── 代表层（Representative Layer）
    │     └── REPRESENTATIVE_STOCKS（10 只大中小盘代表性股票）
    │
    └── 组合层（Combined）
          └── 目标层 + 代表层的加权汇总
```

验证焦点模式：
| 模式 | 主层 | 说明 |
|---|---|---|
| `candidate_target_only` | target | 仅验证目标股票 |
| `event_target_only` | target | 事件驱动仅验证目标 |
| `target_plus_representative` | target + representative | 两层都验证 |
| `broad_generalization` | combined | 广泛泛化验证 |

## 已识别的优化方向

---

### 优化 1：单候选回测缺少早期终止（🔴 高优先级）

**现状问题**：`_test_one` 对所有 evaluated_codes 完成回测后才判断是否通过。如果前 2 只股票的 Sharpe 已经远低于阈值，继续回测剩余 8 只是浪费。

**建议方案**：引入早期终止逻辑——当已完成样本的平均 Sharpe 低于阈值的 50% 时提前终止。

**影响**：典型场景下减少 30-40% 的回测计算量。

---

### 优化 2：Portfolio 引擎缺内层 timeout 与专用复用（🟡 中优先级）

**现状问题**：`BacktestFilter.filter()` 已通过 `shared_result_key` 对相同候选做结果复用；但 `_run_portfolio_engine_summary` 内部调用 portfolio runner 时仍没有独立 timeout，也没有面向组合层 `(strategy_type, params, codes)` 的专用缓存。若同一轮出现等价组合层输入，仍可能重复执行组合回测。

**建议方案**：在候选级 shared result 之外，增加 portfolio 层 cache key，并用 `asyncio.wait_for()` 包裹 portfolio runner。

**影响**：避免重复的组合回测计算，并防止组合引擎异常长期占用并发槽。

---

### 优化 3：回测引擎调用缺少超时保护（🟡 中优先级）

**现状问题**：`asyncio.to_thread(engine.run_backtest, ...)` 没有超时限制。如果回测引擎因某只股票的数据异常而挂起，会阻塞整个并发槽位。

**建议方案**：为每次回测调用添加 30s 超时。

**影响**：防止单只股票的异常数据阻塞整个回测流水线。

---

### 优化总结

| # | 改进项 | 影响 | 实现难度 | 优先级 |
|---|---|---|---|---|
| 1 | 回测早期终止 | 减少 30-40% 计算量 | 中 | 🔴 高 |
| 2 | Portfolio 结果缓存 | 避免重复组合回测 | 低 | 🟡 中 |
| 3 | 回测引擎超时保护 | 防止单股挂起阻塞 | 低 | 🟡 中 |
