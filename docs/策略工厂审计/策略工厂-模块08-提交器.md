## 代码审计结论

- 准确性状态：基本准确。
- 代码证据：`submitter.py` 组装主类；`_submitter_actions/runner.py` 与 `runner_parts/submission_flow.py` 执行候选提交；`runner_parts/gate_payloads.py` 生成 Gate A/B/C payload；`services/submission_coordinator.py` 与 `services/lifecycle_coordinator.py` 处理提交和生命周期。
- 已实现能力：策略政策检查、提交质量门、semantic contract、read_only、formal/observe/deferred/lane 分流、IncubationBudgeter plan、生命周期协调、质量报告/metrics 持久化、submission replay。
- 过时/夸大描述：文档需要更明确区分 Submitter 自身、SubmissionCoordinator 和 LifecycleCoordinator；提交路径不是单一保存动作，而是门禁、预算、lane、持久化、孵化/向量联动。
- 仍然成立的问题：validation report 与 risk report 当前串行；提交持久化失败主要记录 warning，缺面向候选的 retry/DLQ；refresh_existing 场景的语义合约复用仍可优化。
- 建议优先级：P0 补 coordinator/lane/read_only/incubation budget 输出；P1 验证/风险并发与持久化 retry/DLQ；P3 语义合约缓存。下方优化建议中的代码块为概念示例。

## 职责

提交器是策略工厂的最后一站，负责：
1. 执行策略政策检查
2. 运行提交质量门（Gate-3）
3. 确定提交 Lane（formal/observe/live_ready/refresh）
4. 持久化策略记录
5. 触发生命周期转换（创建孵化账户、向量索引等）

## 核心方法 `async submit(candidates, snapshot, db) -> dict`

```python
async def submit(self, candidates, snapshot, db, *, read_only=False):
    # 并发提交（SUBMIT_CONCURRENCY = 3）
    sem = asyncio.Semaphore(SUBMIT_CONCURRENCY)

    async def _submit_one(candidate):
        async with sem:
            return await self._submit_candidate(candidate, snapshot, db, read_only=read_only)

    results = await asyncio.gather(*[_submit_one(c) for c in candidates])
    return self._build_submit_result(results)
```

## 单候选提交流程（`_submit_candidate`）

```python
async def _submit_candidate(self, candidate, snapshot, db, *, read_only):
    # 1. 生成策略 ID 和名称
    strategy_id = uuid4().hex
    name = _auto_name(strategy_type, params)

    # 2. 运行验证报告
    validation_report = await self._validation_gateway.run_validation_report(strategy_type, params, db)

    # 3. 运行风险报告
    risk_report = await self._risk_gateway.run_risk_report(strategy_type, params, db)

    # 4. 运行提交质量门（Gate-3）
    gate = await run_submission_quality_gate(db, strategy, validation_report, risk_report, backtest_metrics)

    # 5. 应用策略政策
    gate = self._apply_factory_submission_policy(candidate, name, gate, backtest_metrics)

    # 6. 语义合约审计（如启用）
    if _semantic_contract_feature_enabled():
        candidate["confidence_contract"] = synthesize_confidence_contract(candidate)
        semantic_audit = audit_candidate_semantic_contract(candidate)
        gate = _apply_semantic_contract_gate(gate, semantic_audit)

    # 7. 确定提交 Lane
    submission_action = self._resolve_submission_action_plan(gate, candidate, ...)
    submission_lane = submission_action["submission_lane"]

    # 8. 构建质量报告
    quality_report = self._build_quality_report(...)

    # 9. 持久化策略记录
    await self._submission_coordinator.persist_candidate(...)

    # 10. 执行生命周期转换
    post_gate = await self._submission_coordinator.handle_new_candidate(...)
```

## 策略政策检查（`_factory_policy_outcome`）

```python
def _factory_policy_outcome(cls, candidate, *, name, gate, backtest_metrics, refresh_existing):
    reasons = []

    # 1. 最少回测交易数
    if trade_count < FACTORY_SUBMISSION_MIN_BACKTEST_TRADES:  # 默认 4
        reasons.append(f"backtest trade_count {trade_count} < {min_trades}")

    # 2. 拒绝通用 AI 名称
    if FACTORY_SUBMISSION_REJECT_GENERIC_AI_NAMES and cls._is_generic_ai_name(name):
        reasons.append("candidate name is too generic")

    # 3. 任务偏好匹配
    if strategy_type not in allowed_strategy_types:
        reasons.append(f"strategy_type not in allowed_strategy_types")

    # 4. 策略偏好匹配（soft/medium/hard）
    if not set(strategy_preferences).intersection(style_tokens):
        if preference_strength == "hard":
            reasons.append("style does not align with preferences")
        elif evidence_override:  # 强证据覆盖
            warnings.append("overridden by stronger target evidence")

    # 5. 目标覆盖率（事件驱动策略）
    if event_driven and target_coverage < FACTORY_SUBMISSION_MIN_EVENT_TARGET_COVERAGE:  # 0.8
        reasons.append("target coverage below threshold")
```

## 提交 Lane 分流

| Lane | 条件 | 最终状态 | 后续动作 |
|---|---|---|---|
| `formal_incubation` | Gate-3 通过 + 正式槽位 | incubating | 创建 paper_account + 孵化流水线 |
| `observe_incubation` | Gate-3 通过 + 观察槽位 | submitted | 排队观察 |
| `live_ready_review` | 满足 Live 层阈值 | submitted → listed | 晋升审查 |
| `refresh_existing` | 去重判定为刷新 | 保持原状态 | 更新指标 |
| `deferred_budget_queue` | 超出孵化预算 | submitted | 排队等待 |

## StrategyLifecycleCoordinator

```python
async def execute(self, db, request: LifecycleTransitionRequest):
    # 1. 创建 task_run 记录
    task_run = await self._start_task_run(db, request, trace_context)

    # 2. 持久化 execution_audit_snapshot
    execution_snapshot = await self._persist_execution_snapshot(db, request, trace_context)

    # 3. 状态转换
    if gate_passed:
        if lane == "formal_incubation":
            await _update_strategy_status(db, sid, "incubating", ...)
            # 4. 确保孵化账户
            await incubation_gateway.ensure_account(db, strategy, ...)
            # 5. 运行孵化流水线
            await incubation_gateway.run_pipeline(db, strategy, ...)
            # 6. 构建向量索引
            await build_strategy_vector_profile(db, strategy)
        elif lane == "live_ready_review":
            await self._enqueue_live_ready_review(db, strategy, ...)
        elif lane == "observe_incubation":
            await self._enqueue_paper_observation(db, strategy, ...)
    else:
        await _update_strategy_status(db, sid, "rejected", ...)

    # 7. 记录领域事件
    await self._record_domain_event(db, ...)

    # 8. 刷新 closure_review
    await self._refresh_closure_review(db, ...)
```

## 已识别的优化方向

---

### 优化 1：验证报告和风险报告串行执行（🔴 高优先级）

**现状问题**：`_submit_candidate` 中 `run_validation_report` 和 `run_risk_report` 串行调用，但两者无数据依赖。

**建议方案**：并发执行验证和风险报告：

```python
validation_report, risk_report = await asyncio.gather(
    self._validation_gateway.run_validation_report(strategy_type, params, db),
    self._risk_gateway.run_risk_report(strategy_type, params, db),
)
```

**影响**：单候选提交耗时减少 30-50%。

---

### 优化 2：提交失败无重试机制（🟡 中优先级）

**现状问题**：如果 `_submit_candidate` 中的持久化操作失败（如数据库瞬时不可用），候选直接丢失，不会重试。

**建议方案**：添加单次重试 + 死信队列。

**影响**：避免因瞬时故障丢失已通过所有 Gate 的高质量候选。

---

### 优化 3：语义合约审计每次重新计算（🟢 低优先级）

**现状问题**：`synthesize_confidence_contract` + `audit_candidate_semantic_contract` 对每个候选都完整执行，即使候选的核心参数未变化（如 refresh_existing 场景）。

**建议方案**：对 refresh_existing 候选复用已有策略的语义合约审计结果。

**影响**：refresh 场景下减少不必要的计算。

---

### 优化总结

| # | 改进项 | 影响 | 实现难度 | 优先级 |
|---|---|---|---|---|
| 1 | 验证/风险报告并发 | 提交耗时减少 30-50% | 低 | 🔴 高 |
| 2 | 提交失败重试 | 避免丢失高质量候选 | 中 | 🟡 中 |
| 3 | 语义合约缓存 | 减少 refresh 场景计算 | 低 | 🟢 低 |
