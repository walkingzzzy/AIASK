## 代码审计结论

- 准确性状态：部分过时。
- 代码证据：`spawner.py` 通过 fragment loader 组装；`spawner_parts/factories.py` 实现 `spawn()`、source batch 合并、动态填充、`_expand_signal_variants()` 上限；`spawner_parts/part_5.py` 接入 `ParameterDistributionRegistry`；`spawner_parts/selection.py` 生成 spawn report。
- 已实现能力：5 类信号来源、event-ready source 权重/预算、fear-greed/资金流/事件/因子偏好的动态填充、`SPAWNER_FILL_BUDGET_MAX` 扩展上限、历史参数分布采样、目标股票对齐与基础 tradability 参数注入。
- 过时/夸大描述：旧版对填充市场适配、信号扩展预算和参数采样方式的绝对化表述均不再准确；应改为“已有基础控制，但负反馈、质量预估、流动性实筛和采样策略仍可增强”。
- 仍然成立的问题：缺历史失败候选的负反馈闭环；目标股票对齐没有实时流动性/停牌/ST 实筛；spawn report 质量预估不足；历史分布不足时仍回退到 legacy jitter。
- 建议优先级：P0 修正过时表述；P1 失败负反馈和流动性过滤；P2 Thompson/UCB 类采样与来源贡献学习；P3 质量预估和敏感性预筛。下方优化建议中的代码块为概念示例。

## 职责

Spawner 根据市场快照和因子研究结果，通过信号触发和配额填充两种机制生成策略候选。

## 核心方法 `spawn(snapshot) -> List[dict]`

```python
def spawn(self, snapshot: dict) -> List[dict]:
    # 1. 判断事件引擎是否就绪
    event_ready = self._event_research_ready(snapshot)
    event_ready_supplemental = self._event_ready_supports_local_fill(snapshot)

    # 2. 构建信号批次（5 个来源）
    source_batches = self._build_signal_batches(snapshot)

    # 3. 合并信号批次（带事件预算上限）
    signal_candidates, source_raw_counts, source_budget_caps, source_budget_weights = \
        self._merge_signal_batches(source_batches, event_ready, event_ready_supplemental)

    # 4. 扩展信号变体
    signal_candidates += self._expand_signal_variants(snapshot, signal_candidates)

    # 5. 配额填充（补齐不足的类型）
    quota_candidates = self._fill_gaps(snapshot, signal_candidates)

    # 6. 应用目标股票对齐（从 stock_family_allocation 分配目标）
    candidates = [
        self._apply_snapshot_target_alignment(candidate, snapshot)
        for candidate in [*signal_candidates, *quota_candidates]
    ]

    # 7. 构建生成报告
    self.last_report = self._build_spawn_report(candidates, ...)
    return candidates
```

### 优化 1：缺少历史失败策略的负反馈（🔴 高优先级）

**现状问题**：Spawner 不感知之前生成的候选在 Gate/Backtest/Dedup 阶段的失败历史。每轮都可能重新生成与之前被拒绝的策略高度相似的候选，浪费 Gate 和 Backtest 的计算资源。

**具体表现**：
- 同一 `(strategy_type, params_hash)` 组合可能连续多轮被生成 → 被 Gate-1 拒绝 → 再次生成
- Deduplicator 虽然检测与已有策略的重复，但不检测与"已被拒绝"策略的重复

**建议方案**：

```python
class StrategySpawner:
    # 维护最近 N 轮被拒绝的策略签名
    _rejection_memory: set[str] = set()
    _REJECTION_MEMORY_SIZE = 200

    @classmethod
    def record_rejections(cls, rejected_candidates: list[dict]):
        """由 CandidatePipeline 在 Gate 失败后调用。"""
        for candidate in rejected_candidates:
            sig = cls._candidate_signature(candidate)
            cls._rejection_memory.add(sig)
        # 保持内存有界
        if len(cls._rejection_memory) > cls._REJECTION_MEMORY_SIZE:
            cls._rejection_memory = set(list(cls._rejection_memory)[-cls._REJECTION_MEMORY_SIZE:])

    def spawn(self, snapshot: dict) -> List[dict]:
        # ... 现有生成逻辑 ...
        # 最后过滤掉与已拒绝策略相似的候选
        candidates = [c for c in candidates if self._candidate_signature(c) not in self._rejection_memory]
        return candidates

    @staticmethod
    def _candidate_signature(candidate: dict) -> str:
        """生成候选的轻量级签名用于快速比对。"""
        strategy_type = candidate.get("strategy_type", "")
        params = candidate.get("params", {})
        # 对关键参数取整/分桶，避免 jitter 导致的误判
        key_params = {k: round(v, 1) if isinstance(v, float) else v
                      for k, v in sorted(params.items())[:5]}
        return f"{strategy_type}:{hash(frozenset(key_params.items()))}"
```

**影响**：减少 30-50% 的无效候选进入 Gate/Backtest 流水线，节省回测计算资源。

### 优化 2：历史分布不足时仍会回退到 Jitter 随机化（🔴 高优先级）

**现状问题**：当前代码已经通过 `ParameterDistributionRegistry.from_snapshot(snapshot)` 尝试使用历史参数分布；只有当 registry 样本不足或缺失时，才会回退到 `_legacy_varied_defaults()` 里的 `_jitter()` / `_jitter_f()`。因此问题不是单一路径采样，而是冷启动或低样本阶段仍可能出现：
- 探索空间集中在基准值附近
- 历史反馈不足时无法指导参数选择
- 候选之间只在小范围扰动上不同

研究表明，贝叶斯优化在策略参数搜索中显著优于随机搜索（参考 [Bayesian Optimization in Trading](https://www.daytrading.com/bayesian-optimization)）。

**建议方案**：

```python
# 方案 A：基于历史表现的自适应参数采样（已部分实现为 ParameterDistributionRegistry）
# 建议增强：当 registry 有足够样本时，使用 Thompson Sampling 而非均匀采样

def _resolved_varied_defaults(self, strategy_type, idx, *, snapshot=None, registry=None):
    parameter_registry = registry or ParameterDistributionRegistry.from_snapshot(snapshot)

    # 如果有足够历史样本（≥10），使用 Thompson Sampling
    if parameter_registry.sample_count(strategy_type) >= 10:
        sampled = parameter_registry.thompson_sample(strategy_type)
        if sampled:
            return dict(sampled["params"]), "thompson_sampling", sampled["sample_count"]

    # 否则使用现有逻辑
    sampled = parameter_registry.sample(strategy_type, idx)
    if sampled:
        return dict(sampled["params"]), "historical_distribution", sampled["sample_count"]

    return self._legacy_varied_defaults(strategy_type, idx, snapshot=snapshot), "fixed_defaults", 0

# 方案 B：参数扰动幅度随轮次递减（模拟退火）
def _jitter_with_annealing(self, base, lo, hi, *, cycle_count=0):
    """随着轮次增加，逐步缩小扰动范围（探索→利用）。"""
    anneal_factor = max(0.3, 1.0 - cycle_count * 0.02)  # 50 轮后稳定在 30%
    delta = max(1, int(base * 0.2 * anneal_factor))
    return max(lo, min(hi, base + random.randint(-delta, delta)))
```

**影响**：参数搜索更高效，减少"有效试验次数"（effective number of tested strategies），降低过拟合风险。

### 优化 3：配额填充已有市场偏好，但最低配额仍可动态化（🟡 中优先级）

**现状问题**：`_fill_gaps()` 已经通过 `_preferred_fill_types(snapshot, current_counts)` 读取 fear-greed、北向资金、融资变化、事件 ready 和因子偏好来调整填充顺序；但底层 `CATEGORY_MINIMUMS` 仍是静态下限。下一步问题是“静态最低配额与市场适配度之间缺少动态折扣”，例如：
- 极度贪婪环境下，防御/均值回归类最低配额可以降低而不是完全按静态下限补齐
- 极度恐惧环境下，趋势/成长类最低配额可以降低，并提高防御类探索比例

**建议方案**：

```python
def _fill_gaps(self, snapshot, signal_candidates):
    fg = snapshot.get("fear_greed_index", 50)

    # 动态调整配额：根据市场环境缩减不适配类型的最低配额
    adjusted_minimums = dict(CATEGORY_MINIMUMS)

    if fg >= 70:  # 极度贪婪
        # 缩减防御类配额
        adjusted_minimums["value_factor"] = 1
        adjusted_minimums["rsi"] = 1
        adjusted_minimums["mean_reversion_short"] = 0
    elif fg <= 30:  # 极度恐惧
        # 缩减趋势类配额
        adjusted_minimums["momentum"] = 1
        adjusted_minimums["ma_cross"] = 1
        adjusted_minimums["growth_factor"] = 1
        # 增加防御类配额
        adjusted_minimums["value_factor"] = 4
        adjusted_minimums["macro_timing"] = 4

    # 使用调整后的配额进行填充
    ...
```

**影响**：减少与当前环境不匹配的候选生成，提高 Gate 通过率。

### 优化 4：趋势集群限制过于粗糙（🟡 中优先级）

**现状问题**：`_TREND_CLUSTER_TYPES` 硬编码为 5 种类型，趋势类不超过总量的 60%。但：
- 60% 的阈值是固定的，不随市场环境调整
- 在强趋势市场中（FG>70），60% 可能过于保守
- 在震荡市场中（FG 40-60），60% 可能过于激进

**建议方案**：

```python
def _dynamic_trend_cluster_cap(self, snapshot) -> float:

    fg = snapshot.get("fear_greed_index", 50)
```

### 优化 5：信号批次权重固定不可调（🟡 中优先级）

**现状问题**：5 个信号来源（event_driven、fear_greed、factor_ic、volatility、fund_flow）的预算上限和权重是固定的，不根据各来源的历史贡献度动态调整。

**建议方案**：

```python
def _dynamic_source_weights(self, snapshot) -> dict[str, float]:
    """基于历史 Gate 通过率动态调整信号来源权重。"""
    # 从 snapshot 中读取上一轮各来源的 Gate 通过率
    source_pass_rates = snapshot.get("_source_pass_rates", {})

    base_weights = {
        "event_driven": 0.25,
        "fear_greed": 0.20,
        "factor_ic": 0.25,
        "volatility": 0.15,
        "fund_flow": 0.15,
    }

    # 按历史通过率调整权重（通过率高的来源获得更多预算）
    for source, base_weight in base_weights.items():
        pass_rate = source_pass_rates.get(source, 0.5)
        # 通过率 > 50% → 权重上调；< 50% → 权重下调
        adjustment = (pass_rate - 0.5) * 0.4  # ±20% 调整幅度
        base_weights[source] = max(0.05, min(0.40, base_weight + adjustment))

    # 归一化
    total = sum(base_weights.values())
    return {k: v / total for k, v in base_weights.items()}
```

**影响**：高质量信号来源获得更多预算，低质量来源被自动抑制。

### 优化 6：目标股票对齐缺少流动性过滤（🟡 中优先级）

**现状问题**：`_apply_snapshot_target_alignment` 从 `stock_family_allocation` 分配目标股票时，不检查股票的实时流动性。可能分配到停牌、ST、或日均成交额极低的股票。

**建议方案**：

```python
@classmethod
def _apply_snapshot_target_alignment(cls, candidate, snapshot):
    # ... 现有分配逻辑 ...

    # 新增：流动性过滤
    if target_symbols:
        liquidity_data = snapshot.get("_stock_liquidity", {})
        filtered = []
        for code in target_symbols:
            stock_liq = liquidity_data.get(code, {})
            # 排除：停牌、ST、日均成交额 < 500 万
            if stock_liq.get("suspended"):
                continue
            if stock_liq.get("is_st"):
                continue
            if stock_liq.get("avg_turnover_20d", float('inf')) < 5_000_000:
                continue
            filtered.append(code)

        if filtered:
            candidate["target_symbols"] = filtered[:budget]
        else:
            # 所有目标都不满足流动性要求 → 回退到 broad_generalization
            candidate["research_task"]["validation_focus"] = "broad_generalization"
            candidate.pop("target_symbols", None)
```

**影响**：避免回测时因流动性不足导致的虚假信号；减少 Gate 阶段因目标股票不可交易而被拒绝的候选。

### 优化 7：`_expand_signal_variants` 已有总量上限，但缺质量/多样性裁剪（🟢 低优先级）

**现状问题**：当前 `_signal_expansion_budget()` 已用 `remaining`、`SPAWNER_FILL_BUDGET_MAX` 和信号强度限制扩展预算；剩余问题是上限主要控制数量，没有按预估质量、参数距离或来源多样性选择最值得保留的变体。

**建议方案**：

```python
def _expand_signal_variants(self, snapshot, signal_candidates):
    variants = []
    # ... 现有变体生成逻辑 ...

    # 限制变体总数不超过信号候选的 50%
    max_variants = max(2, len(signal_candidates) // 2)
    if len(variants) > max_variants:
        # 按多样性排序，保留最不同的变体
        variants = self._select_most_diverse(variants, limit=max_variants)

    return variants
```

**影响**：控制候选总量在合理范围内，避免 Backtest 阶段过载。

### 优化 8：缺少参数敏感性预筛（🟢 低优先级）

**现状问题**：Spawner 生成的参数组合不经过任何敏感性检查就进入 Gate 流水线。某些参数组合天然不稳定（如 `short_period=14, long_period=15` 的 MA 交叉），在 Gate-2 的参数扰动测试中必然失败。

研究表明，参数敏感性是过拟合的关键指标（参考 [AlgoXpert IS-WFA-OOS Protocol](https://arxiv.org/abs/2603.09219)）。

**建议方案**：

```python
@staticmethod
def _is_parameter_sensitive(strategy_type: str, params: dict) -> bool:
    """快速预判参数组合是否天然不稳定。"""
    if strategy_type == "ma_cross":
        short = params.get("short_period", 5)
        long = params.get("long_period", 20)
        # 短长期均线过于接近 → 高敏感性
        if long - short < 8:
            return True
        # 比值过小 → 信号过于频繁
        if long / max(short, 1) < 1.5:
            return True

    if strategy_type == "momentum":
        lookback = params.get("lookback", 20)
        threshold = params.get("threshold", 0.02)
        # 极短 lookback + 极低阈值 → 噪声交易
        if lookback <= 3 and threshold < 0.01:
            return True

    if strategy_type == "rsi":
        oversold = params.get("oversold", 30)
        overbought = params.get("overbought", 70)
        # 超买超卖区间过窄 → 信号过于频繁
        if overbought - oversold < 30:
            return True

    return False

def spawn(self, snapshot):
    # ... 生成候选 ...
    # 预筛：移除天然不稳定的参数组合
    candidates = [c for c in candidates if not self._is_parameter_sensitive(c["strategy_type"], c["params"])]
    return candidates
```

**影响**：减少 10-20% 的无效候选进入回测，节省计算资源；提高 Gate-2 通过率。

---

### 优化 9：生成报告缺少质量预估（🟢 低优先级）

**现状问题**：`spawn_report` 只记录数量统计（候选数、来源分布、类型分布），不提供质量预估。调度器无法根据生成质量决定是否值得继续执行后续的 Gate/Backtest 流水线。

**建议方案**：

```python
def _build_spawn_report(self, candidates, ...):
    report = {
        "summary": {
            # ... 现有统计 ...
            # 新增：质量预估
            "estimated_gate_pass_rate": self._estimate_pass_rate(candidates),
            "parameter_diversity_score": self._parameter_diversity(candidates),
            "signal_strength_avg": self._avg_signal_strength(candidates),
            "recommendation": self._spawn_quality_recommendation(candidates),
        }
    }
    return report

def _spawn_quality_recommendation(self, candidates) -> str:
    """基于候选质量给出建议。"""
    if len(candidates) < 5:
        return "low_volume_warning"
    if self._parameter_diversity(candidates) < 0.3:
        return "low_diversity_warning"
    if self._estimate_pass_rate(candidates) < 0.2:
        return "low_quality_warning"
    return "proceed"
```

**影响**：为周期运行器提供早期终止信号；当生成质量极低时可跳过后续流水线。
