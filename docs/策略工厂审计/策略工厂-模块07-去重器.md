## 代码审计结论

- 准确性状态：描述偏简。
- 代码证据：`deduplicator.py` 组装主类；`deduplicator_parts/evaluation.py` 处理参数相似、语义/身份、向量行为和 refresh/revision 决策；`deduplicator_parts/reporting.py` 输出去重报告；`deduplicator_parts/policy.py` 维护阈值与策略。
- 已实现能力：参数相似度、向量行为检查、tested object/hash/identity signature、刷新已有策略、从已有策略派生 revision、血统深度限制、质量压力、refresh 冲突折叠、并发分析。
- 过时/夸大描述：不能只描述为“参数+向量去重器”；当前实现已经包含语义身份、血统治理和 refresh/revision 生命周期语义。
- 仍然成立的问题：已有策略扫描按 `listed`/`incubating` 各 limit=500；候选主要按 strategy type bucket 比较，跨类型语义重复可能漏检；行为向量构建涉及 CPU/面板构建，进程池与缓存仍可评估。
- 建议优先级：P0 补丰富去重语义；P1 现有策略增量/分页扫描；P2 跨 family/跨类型语义索引；P3 CPU 密集行为向量进程池。下方优化建议中的代码块为概念示例。

## 职责

去重器检测候选策略是否与已有策略过于相似，支持三种决策：保留、去重、刷新已有策略。包含血统追踪和质量压力机制。

## 核心方法 `async deduplicate(candidates, db) -> List[dict]`

```python
async def deduplicate(self, candidates, db):
    # 1. 加载已有策略（按 strategy_type 分桶）
    existing = await db.list_strategies("incubating", limit=500)
    existing += await db.list_strategies("listed", limit=500)
    existing_by_type = self._bucket_existing_by_type(existing)

    # 2. 对每个候选分析是否与已有策略重复
    analyzed = await self._analyze_against_existing(candidates, existing_by_type, db)

    # 3. 候选间互相去重
    intra_deduped = self._intra_deduplicate(analyzed)

    # 4. 折叠刷新冲突（多个候选刷新同一策略时保留最优）
    collapsed, dropped = self._collapse_refresh_existing_candidates(intra_deduped)

    # 5. 返回保留的候选
    return [item for item in collapsed if not item.get("dedup_result", {}).get("duplicate")]
```

## 已识别的优化方向

---

### 优化 1：行为向量构建串行化（🔴 高优先级）

**现状问题**：`_prewarm_candidate_behaviors` 虽然使用了 `asyncio.gather`，但 `_build_behavior_klines` 内部调用 `build_strategy_panels` 是 CPU 密集型操作，受 GIL 限制。

**建议方案**：使用 `ProcessPoolExecutor` 替代 `to_thread` 进行 CPU 密集型的策略面板构建。

**影响**：多核环境下行为向量构建速度提升 2-4x。

---

### 优化 2：已有策略加载无增量更新（🟡 中优先级）

**现状问题**：每次 `deduplicate()` 都重新加载全部 incubating + listed 策略（最多 1000 条）。连续多轮运行时，大部分策略不会变化。

**建议方案**：引入增量加载——仅加载上次去重后新增/变更的策略。

**影响**：减少 50-80% 的数据库查询量。

---

### 优化 3：向量相似度阈值不区分策略类型（🟢 低优先级）

**现状问题**：`VECTOR_THRESHOLD=0.93` 对所有策略类型统一适用。但不同类型的策略行为差异天然不同——趋势策略之间的行为相似度通常高于均值回归策略。

**建议方案**：按策略类型设置差异化向量阈值。

**影响**：减少趋势策略的误判重复，增加均值回归策略的去重精度。

---

### 优化总结

| # | 改进项 | 影响 | 实现难度 | 优先级 |
|---|---|---|---|---|
| 1 | 行为向量多进程构建 | 构建速度提升 2-4x | 中 | 🔴 高 |
| 2 | 已有策略增量加载 | 减少 50-80% DB 查询 | 中 | 🟡 中 |
| 3 | 差异化向量阈值 | 提高去重精度 | 低 | 🟢 低 |
