## 代码审计结论

- 准确性状态：基本准确。
- 代码证据：`event_engine.py` 定义 `LocalEventDrivenResearchEngine`；`refresh()` 调用 `_ensure_theme_definitions()`、`_load_universe_state()`、`_deactivate_stale_local_events()`；`_DEFAULT_THEME_LIBRARY` 为默认主题库。
- 已实现能力：默认主题定义落库、股票池与 K 线摘要、主题 alias 命中、方向判定、市场内部指标、事件/信号/暴露持久化、stale local events 失活。
- 过时/夸大描述：“主题库硬编码不可扩展”应修正为“默认主题库会落库，但 refresh 当前仍遍历 `_DEFAULT_THEME_LIBRARY`，尚未把 DB 主题作为主输入源”。
- 仍然成立的问题：`_load_universe_state()` 对股票 K 线逐只串行加载；事件信号缺 TTL/置信度自然衰减；主题扩展仍需配置/DB 主导；事件阈值与权重缺历史校准。
- 建议优先级：P0 修正主题库表述；P1 K 线并发加载；P2 DB/配置主题源与信号衰减；P3 阈值学习。下方优化建议中的代码块为概念示例。

## 职责

事件引擎从本地数据库的行情和股票池中识别市场主题轮动，生成事件驱动的策略候选信号。

## 核心方法 `async refresh(db, snapshot) -> dict`

```python
async def refresh(self, db, snapshot):
    # 1. 加载全市场股票池 + 最近 K 线
    stocks = await db.list_stocks(limit=6000)
    for stock in stocks:
        klines = await db.get_klines(stock["code"], limit=30)
        stock.update(self._summarize_klines(klines))

    # 2. 按行业/板块聚合
    sector_scores = self._aggregate_groups(stocks, "sector")

    # 3. 推导行业轮动（热门/冷门板块）
    rotation = self._derive_sector_rotation(snapshot, sector_scores)

    # 4. 构建市场内部指标
    market_internals = self._build_market_internals(stocks, rotation)

    # 5. 对每个主题评分
    events = []
    for theme in _DEFAULT_THEME_LIBRARY:
        event = await self._evaluate_theme(stocks, theme, rotation, sector_scores, snapshot)
        if event and event["confidence"] >= threshold:
            events.append(event)

    # 6. 返回事件信号
    return {"events": events, "market_internals": market_internals, "rotation": rotation}
```

## 方向判定

```python
@classmethod
def _determine_direction(cls, rows, rotation):
    avg_return = mean([row["return_20d"] for row in rows])
    sectors = {row["sector"] for row in rows}

    if sectors & hot_sectors and avg_return >= -0.01:
        return "positive"
    if sectors & cold_sectors and avg_return <= 0.01:
        return "negative"
    if avg_return >= 0.03:
        return "positive"
    if avg_return <= -0.03:
        return "negative"
    return "neutral"
```

## 已识别的优化方向

---

### 优化 1：股票行情串行加载（🔴 高优先级）

**现状问题**：`_load_universe_state` 对每只股票逐一串行调用 `await db.get_klines(code, limit=30)`。120 只股票 × 每次 ~50ms = ~6s 纯 IO 等待。

**建议方案**：并发加载所有股票的 K 线：

```python
async def _load_universe_state(self, db, limit=120):
    rows = await _call_optional_async(db, "list_stock_universe", limit=limit, default=[])
    sem = asyncio.Semaphore(20)
    async def _fetch_one(row):
        async with sem:
            klines = await _call_optional_async(db, "get_klines", row["code"], limit=30, default=[])
            return {**row, **self._summarize_klines(klines)}
    return await asyncio.gather(*[_fetch_one(row) for row in rows if row.get("code")])
```

**影响**：行情加载从 ~6s 降为 ~0.5s（20 并发）。

---

### 优化 2：主题库硬编码不可扩展（🟡 中优先级）

**现状问题**：`_DEFAULT_THEME_LIBRARY` 硬编码 7 个主题，新增主题需要修改代码。

**建议方案**：支持从数据库或配置文件加载主题定义，硬编码作为 fallback。

**影响**：运营团队可动态添加/调整主题，无需代码发布。

---

### 优化 3：缺少事件信号衰减机制（🟡 中优先级）

**现状问题**：事件信号一旦产生就保持 active 状态，直到下一次 refresh 时被 `_deactivate_stale_local_events` 清理。没有基于时间的自然衰减。

**建议方案**：为事件信号添加 TTL 和置信度衰减。

**影响**：避免过期事件信号持续影响 Spawner 的候选生成。

---

### 优化总结
