## 职责

淘汰检查器定期审查已上架（listed）策略，当策略表现恶化或不适合当前市场环境时，自动将其淘汰（deprecated）。

## 核心方法 `async check(db, current_fg_level) -> List[dict]`

```python
async def check(self, db, current_fg_level="neutral"):
    listed = await db.list_strategies("listed", limit=500)

    # 并发检查（ELIMINATION_CONCURRENCY = 8）
    sem = asyncio.Semaphore(ELIMINATION_CONCURRENCY)

    async def _check_one(strategy):
        async with sem:
            return await self._check_strategy(db, strategy, current_fg_level)

    results = await asyncio.gather(*[_check_one(s) for s in listed], return_exceptions=True)
    return [item for item in results if item and not isinstance(item, BaseException)]
```

## 单策略检查流程（`_check_strategy`）

```python
async def _check_strategy(self, db, strategy, current_fg_level):
    red_flags = []

    # 1. 加载回测指标
    metrics_list = await db.get_strategy_metrics(strategy["id"])
    backtest_metrics = metrics_list[0]  # period="all" 或 "backtest"

    # 2. 加载验证和风险指标
    quality_report = await db.get_strategy_quality_report(strategy["id"])
    validation_metrics = quality_report.get("validation_report") or ...
    risk_metrics = quality_report.get("risk_report") or ...

    # 3. 检查红旗
    max_drawdown = abs(float(backtest_metrics.get("max_drawdown") or 0))
    sharpe_ratio = float(backtest_metrics.get("sharpe_ratio") or 0)
    win_rate = float(backtest_metrics.get("win_rate") or 0)
    validation_grade = validation_metrics.get("grade")
    var_percent = float(risk_metrics.get("var_percent") or 0)
    cvar_percent = float(risk_metrics.get("cvar_percent") or 0)
    stress_loss_percent = float(risk_metrics.get("stress_loss_percent") or 0)

    if max_drawdown > 0.30:
        red_flags.append(f"回撤{max_drawdown:.1%}>30%")
    if sharpe_ratio < 0:
        red_flags.append(f"Sharpe {sharpe_ratio:.2f}<0")
    if 0 < win_rate < 0.30:
        red_flags.append(f"胜率{win_rate:.1%}<30%")
    if validation_grade == "D":
        red_flags.append("验证评级为D")
    if var_percent > 4.0:
        red_flags.append(f"VaR {var_percent:.2f}%>4%")
    if cvar_percent > 6.0:
        red_flags.append(f"CVaR {cvar_percent:.2f}%>6%")
    if stress_loss_percent <= -25.0:
        red_flags.append(f"压力测试损失{stress_loss_percent:.1f}%")

    # 4. 信号命中率检查
    signal_stats = await db.get_signal_stats(strategy["id"])
    if signal_stats["total_signals"] >= 10:
        hit_rate_5d = signal_stats["hit_rate"].get(5)
        if hit_rate_5d is not None and float(hit_rate_5d) < 0.30:
            red_flags.append(f"5日信号命中率{float(hit_rate_5d):.1%}<30%")

    # 5. 市场环境匹配
    suitable_regimes = self._REGIME_MAP.get(strategy_type)
    if suitable_regimes and current_fg_level not in suitable_regimes:
        red_flags.append(f"{strategy_type}策略不适合当前{current_fg_level}环境")

    # 6. 淘汰决策
    fatal = max_drawdown > 0.30
    should_eliminate = fatal or (len(red_flags) >= 2)

    if should_eliminate:
        await _update_strategy_status(db, strategy["id"], "deprecated",
            actor_id="elimination_checker",
            reason="elimination_checker_triggered",
            metadata={"red_flags": red_flags, "fg_level": current_fg_level})
        await db.save_elimination_log(strategy["id"], date.today(), red_flags, reason)
        return {"id": strategy["id"], "red_flags": red_flags, "reason": reason}

    return None
```

## 红旗体系

| 红旗 | 条件 | 严重程度 |
|---|---|---|
| 回撤过大 | max_drawdown > 30% | **致命**（立即淘汰） |
| Sharpe 为负 | sharpe_ratio < 0 | 严重 |
| 胜率过低 | win_rate < 30%（且 > 0） | 严重 |
| 验证评级 D | validation_grade == "D" | 严重 |
| VaR 过高 | var_percent > 4% | 中等 |
| CVaR 过高 | cvar_percent > 6% | 中等 |
| 压力测试损失 | stress_loss_percent ≤ -25% | 中等 |
| 信号命中率低 | 5 日命中率 < 30%（≥10 信号） | 中等 |
| 环境不匹配 | 策略类型不适合当前 FG 环境 | 轻微 |

## 已识别的优化方向

---

### 优化 1：淘汰决策缺少渐进降级（🔴 高优先级）

**现状问题**：策略要么保持 listed，要么直接 deprecated。没有中间状态（如"观察期"或"降权"）。一次性淘汰可能过于激进——策略可能只是暂时表现不佳。

**建议方案**：引入 `warning` → `probation` → `deprecated` 三级降级：

```python
if len(red_flags) == 1 and not fatal:
    # 单个非致命红旗 → 进入观察期
    await _update_strategy_status(db, strategy["id"], "probation", ...)
elif should_eliminate:
    await _update_strategy_status(db, strategy["id"], "deprecated", ...)
```

**影响**：避免因短期波动误淘汰长期有效的策略。

---

### 优化 2：不考虑策略运行时长（🟡 中优先级）

**现状问题**：新上架的策略（如运行不到 1 周）和运行 3 个月的策略使用相同的淘汰阈值。新策略的指标可能因样本不足而波动较大。

**建议方案**：对运行时长不足的策略使用宽松阈值或豁免检查。

**影响**：避免新策略因早期样本不足被过早淘汰。

---

### 优化 3：环境不匹配不应作为淘汰依据（🟢 低优先级）

**现状问题**：`_REGIME_MAP` 中的环境不匹配被计为红旗。但市场环境是周期性的——当前不匹配不代表策略本身有问题。

**建议方案**：环境不匹配仅作为 warning，不计入淘汰红旗。

**影响**：避免因市场环境轮动导致的误淘汰。

---

### 优化总结

| # | 改进项 | 影响 | 实现难度 | 优先级 |
|---|---|---|---|---|
| 1 | 渐进降级机制 | 避免误淘汰 | 中 | 🔴 高 |
| 2 | 运行时长豁免 | 保护新策略 | 低 | 🟡 中 |
| 3 | 环境不匹配降级为 warning | 避免周期性误淘汰 | 低 | 🟢 低 |
