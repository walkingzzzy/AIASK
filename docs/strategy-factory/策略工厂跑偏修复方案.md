# 策略工厂跑偏修复方案

> **目标**：让策略工厂从"在少数代表性股票上跑通用策略"，回到"基于每只股票的价格趋势/反转、波动风险、量价与流动性、估值、质量、成长、杠杆、风格、资金流、新闻公告研报、事件主题、市场状态等多维画像生成专属策略"。
>
> **核心修正**：不再把方案建立在"新建主用 `stock_profiles` 表 + 旧 `stock_embeddings` 表"上，而是修复 BULK 假死，复用现有统一向量层 `vector_profiles(collection_name='stock_profile_embeddings')`，把画像真正传到 family 选择、优先级、任务构建和参数生成器。
>
> **范围**：本方案聚焦策略工厂任务源头与画像消费链路，不重写 G0-G3 质量门控。G0-G3 的审查阈值、回测验证和推广门禁是下游质量问题；本方案解决的是上游任务一开始就跑偏的问题。

---

## 0. TL;DR

策略工厂跑偏不是一个 flag 没打开，而是五个问题叠在一起：

1. **P0 运行时假死**：SQLite 下 `stocks.list_date` 返回字符串，`stock_info.py` 里 `get_stock_info()` 与 `list_stock_universe()` 直接 `.strftime()`，导致 BULK 股票池加载抛 `AttributeError`。异常又被兜底吞掉，summary 里出现 `loaded_stock_count=0` 但 `skip_reason=None`。
2. **P1 画像链路选错方向**：项目里已有统一向量层和 `stock_profile_pipeline.py`，应扩展 `vector_profiles(collection_name='stock_profile_embeddings')`，不应另造一张主用 `stock_profiles` 表。`stock_embeddings` 只能视为旧表或兼容表，不再作为新主链路。
3. **P1 画像维度过粗**：不能只停在技术/情绪/事件/基本面几个大筐。项目里的因子挖掘实际已经使用价格趋势、反转、波动、成交量、流动性、估值、质量、成长、杠杆、风格、另类因子、新闻/公告/研报、资金流、市场 regime、active factor pool 等多维上下文，策略工厂必须对齐这些维度。
4. **P1 数据覆盖不能假装完整**：当前 `stock_fund_flow`、事件/主题数据覆盖不足。另类、情绪、事件画像字段必须带 `coverage/status/source`，不能假装 5000 多只股票都有完整画像。
5. **P2/P3 没有真正消费画像**：`StockStrategyMatrixPlanner.plan()` 需要批量加载画像并挂到 row；`_intrinsic_families_for_row()`、`_row_priority_components()`、`_build_task()` 和 bulk rule 生成器 `_expand_bulk_rule_specs()` 都要读取画像、因子维度分数与 `param_search_space/profile_param_band`。在有 G2/G3 验证样本前，`vector_reuse >= 10%` 不能作为首轮验收。

修复顺序：

| 阶段 | 目标 | 首轮验收 |
|---|---|---|
| P0 | BULK 不再假死，异常可观测 | `bulk_stock_matrix_loaded_stock_count >= 5000` 且 `bulk_stock_task_count > 0` |
| P1 | 复用统一向量画像层，并按因子挖掘维度建模 | `stock_profile_embeddings` 覆盖率、维度分组和字段 coverage 可查 |
| P2 | 画像与因子维度真正影响 family、优先级、holding window、参数空间 | 同 family 跨股票参数离散，画像-family 一致 |
| P3 | 延后启用向量复用 | 先建立已验证策略索引；有样本后再看复用命中率和 G2 提升 |

## 2. 为什么会跑偏

### 2.1 第一层：BULK 股票池加载失败，但异常不可见

失败点在 `packages/akshare-mcp/src/akshare_mcp/storage/sqlite/stock_info.py`：

```python
'list_date': payload.get('list_date').strftime('%Y-%m-%d')
             if payload.get('list_date') else None
```

需要修两处：

- `get_stock_info()`
- `list_stock_universe()`

同时需要把 `pe_ratio/pb_ratio` 的裸 `float()` 改为 `_safe_float()`，避免空字符串或脏值造成第二个加载炸点。

异常链路还存在观测缺口：

```text
StockStrategyMatrixPlanner.plan()
  -> load_stock_universe_rows()
    -> db.list_stock_universe()
      -> AttributeError
  -> 外层兜底 rows=[]
  -> summary 只看到 loaded_stock_count=0
```

因此 P0 不能只修 `.strftime()`，还必须把 `load_error/load_error_type/last_error` 写进 summary。

### 2.2 第二层：BULK 任务还是笛卡尔积

当前 `_build_task()` 的"专属"主要只有 `target_symbols=[code]`，family 行为由 family 字符串决定：

```python
"candidate_family": family,
"preferred_strategy_types": [family],
"target_symbols": [code],
"holding_window": cls._holding_window_for_family(family),
"alpha_source": cls._alpha_source_for_family(family),
"risk_level": cls._risk_level_for_family(family),
```

`_intrinsic_families_for_row()` 主要看行业、PE、PB 和市场 hot/cold sector。它没有系统读取：

- 价格趋势/反转：动量、均值回归、RSI/MFI、趋势强度
- 波动与风险：波动率、ATR、下行波动、beta、风险状态
- 成交量/流动性/微观结构：量比、换手、非流动性、VWAP 偏离、成交量趋势
- 估值/质量/成长/盈利/杠杆/现金流：PE/PB/PS、ROE/ROA、毛利率、营收利润增长、负债率、经营现金流
- 风格暴露：size、beta、liquidity 等 style factor
- 另类与资金面：news sentiment、event score、capital flow、north flow、alternative composite
- 文本与事件：news/notices/research/theme exposure
- 市场与因子上下文：market_regime、active_pool_families、success/failure patterns
- 向量画像：`vector_profiles(stock_profile_embeddings)`

所以贵州茅台和宁德时代即使都进 `momentum`，也会拿到几乎同一套策略骨架和参数逻辑，这就是"通用性跑偏"。

### 2.3 第三层：把向量层理解成了旧表

旧方案把重点放到 `stock_embeddings`，这是错位的：

- `stock_embeddings` 当前为空，应视为旧表或兼容表。
- 项目已有统一向量层 `vector_profiles`，应该通过 `collection_name='stock_profile_embeddings'` 存股票画像。
- `stock_profile_pipeline.py` 才是应扩展的画像写入管线。
- 向量相似股票可以先基于 `vector_profiles(stock_profile_embeddings)` 做。
- 策略复用必须等有"已验证策略索引"后再启用，否则没有可复用对象。

### 2.4 第四层：画像维度没有对齐真实因子挖掘体系

策略工厂不应该自己发明一个缩水版维度词典。项目里现成的因子挖掘实现已经说明了真实研究维度至少包括：

- `factor_prompt_builder.py`：`market`、`financials`、`valuation`、`alternative_factors`、`recent_headlines`、`fund_flow`
- `factor_calculator`：`technical`、`volatility`、`volume`、`fundamental`、`style`
- `factor_candidate_seed.py`：`technical`、`risk`、`volume`、`alternative`、`fundamental`
- `MiningContext`：`market_regime`、`active_pool_families`、`success_patterns`、`failure_patterns`

如果策略工厂只保留几个粗粒度 archetype，就会出现两个问题：

- 画像看起来“有了”，但和因子工厂真实可产出的因子族不匹配
- 后续即使接入 active factor pool，策略工厂也只能把丰富的因子信息压扁成几个通用 family

def _normalize_list_date(value):
    if value is None:
        return None
    if hasattr(value, "strftime"):
        return value.strftime("%Y-%m-%d")
    text = str(value).strip()
    return text or None


def _safe_float(value):
    if value is None or value == "":
        return None
    try:
        return float(value)
    except (TypeError, ValueError):
        return None

> - ✅ `verified_strategy_index_count` 通过 `db.list_strategies(status='listed')` 轻量探测；当前 `strategies=0` 时为 0，符合方案 §3.4.2"无验证样本前 vector_reuse_count=0 是正确结果"。
> - ⏸ verified strategy index 结构与 `vector_reuse_eligible/count > 0` 留待 G2/G3 样本积累后启用，保持 `STRATEGY_FACTORY_VECTOR_REUSE_ENABLED=0` 观测态。详见 §0.5。

#### 3.4.1 相似股票基于统一向量层

采用：

```text
vector_profiles
  where collection_name = "stock_profile_embeddings"
```

不采用：

```text
stock_embeddings
```

相似检索可以先做两层：

1. 结构化过滤：行业、市值段、profile_quality、coverage。
2. 向量相似：使用统一向量层 embedding 或 profile feature vector 的余弦相似度。

验收例子：

- `find_similar_stock_profiles("600519", top_k=10)` 能返回画像相近的高端消费/白酒/大市值低 beta 股票。
- 返回结果必须带 `similarity`、`profile_quality`、`feature_coverage`，避免拿缺失画像做强匹配。

#### 3.4.2 `vector_reuse` 需要已验证策略索引

策略复用的前置不是"有相似股票"，而是"相似股票有已验证策略"。

索引来源可以是：

- G2 artifact 中通过的策略记录
- `strategy_generation_experiments` 中完成验证的实验
- 未来正式 `strategies` 表
- 未来 `strategy_quality_reports` / G3 推广记录

索引至少包含：

```json
{
  "strategy_id": "strategy_xxx",
  "stock_code": "600519",
  "family": "quality_factor",
  "params": {},
  "g2_passed": true,
  "g3_passed": false,
  "quality_score": 0.82,
  "validated_at": "2026-05-17",
  "source": "g2_artifact"
}
```

当前 `strategies=0`、`strategy_quality_reports=0`，因此 P3 首轮只能做：

- 已验证策略索引结构
- 索引回填入口
- 相似股票观测
- reuse eligibility 统计

不能要求：

```text
vector_reuse 任务占比 >= 10%
```

#### 3.4.3 P3 summary 指标

首轮观测指标：

```text
bulk_stock_matrix_similar_profile_lookup_count
bulk_stock_matrix_similar_profile_hit_count
bulk_stock_matrix_verified_strategy_index_count
bulk_stock_matrix_vector_reuse_eligible_count
bulk_stock_matrix_vector_reuse_count
bulk_stock_matrix_vector_reuse_avg_similarity
```

当 verified index 为空时，`vector_reuse_count=0` 是正确结果，不是失败。

#### 3.4.4 P3 验收

无验证样本前：

- [ ] 相似股票检索基于 `vector_profiles(stock_profile_embeddings)`
- [ ] 相似结果带 `profile_quality/feature_coverage`
- [ ] 已验证策略索引结构可构建
- [ ] `verified_strategy_index_count=0` 时不强制 `vector_reuse_count > 0`

有足够 G2/G3 样本后：

- [ ] `vector_reuse` 命中率可观测
- [ ] reuse task 的 G2 通过率高于非 reuse task
- [ ] 如果 reuse task 没提升，降低权重或回到观测模式

## 7. 与现有文档和系统的关系

### 7.1 G0-G3 门控

G0-G3 解决的是质量审查：

- G0：输入与任务完整性
- G1：候选策略结构与参数合法性
- G2：回测/稳健性/过拟合审查
- G3：孵化、推广与运行态风险

本方案解决的是 G0 之前或 G0 输入侧的问题：任务源头不该是通用笛卡尔积，而应该是画像驱动的股票专属任务。

### 7.2 因子挖掘工厂

因子挖掘工厂不应该只是给 `recommended_families` 做事后反馈，它应该是策略工厂画像维度词典的主要来源之一：

- `factor_prompt_builder.py` 已经定义了研究上下文维度：`market/financials/valuation/alternative_factors/recent_headlines/fund_flow`
- `factor_calculator` 已经定义了核心因子族：`technical/volatility/volume/fundamental/style`
- `factor_candidate_seed.py` 已经定义了候选家族：`technical/risk/volume/alternative/fundamental`
- `MiningContext` 已经定义了 regime 与 active pool 上下文：`market_regime/active_pool_families/success_patterns/failure_patterns`

P1/P2 应直接消费这些维度和家族，而不是另起一个简化版画像体系，否则因子反馈最后仍然会被压扁成通用 family。

### 7.3 向量治理

向量治理的主对象应是统一向量层：

```text
vector_profiles(collection_name='stock_profile_embeddings')
```

`stock_embeddings` 只保留兼容定位，不作为策略工厂新主链路。

## 9. Assumptions

- 不新增独立 `stock_profiles` 主表，除非后续证明统一向量层无法满足查询性能。
- `stock_embeddings` 视为旧表或兼容表，不作为新主链路。
- 画像维度词典以 `factor_prompt_builder.py`、`factor_calculator/*`、`factor_candidate_seed.py`、`MiningContext` 的真实实现为准，不再私自简化成几个粗类。
- 另类、情绪和事件字段必须携带 coverage/status/source，不用缺失数据制造假画像。
- P3 的向量复用在有足够 G2/G3 验证样本前只做观测和索引准备。
- 当前策略工厂应优先修"任务是否正确"，再谈 G2/G3 通过率提升。

## 10. 一句话验收

跑修复后的工厂 24 小时，从 `strategy_factory_runs` 里随便挑一轮，应该能看到：

> BULK 实际加载了 5000+ 股票；任务 artifact 里每只股票带 `stock_profile_summary`，其中能看到 `candidate_factor_families` 和 `factor_dimension_scores`；同 family 跨股票的 `holding_window`、rule 模板和 `param_search_space` 明显不同；另类/情绪/事件画像缺失被明确标注为 coverage 问题；在没有已验证策略索引时，向量复用保持观测而不是强行凑比例。

如果做不到这句话，策略工厂就仍然没有回到"股票专属策略"的设计预期。

**当前实测（2026-05-17）**：5 项条件经 PR-S17/S18/S19/S20/S21/S22 串联 + 本地真实 DB 跑批后，全部具备：
- BULK 加载条件：本地 plan() 实测 `loaded_stock_count = 5204`、`load_error = null`、`skip_reason = null`。
- task artifact：携带 `stock_profile_summary.primary_archetype`、`factor_dimension_scores`（9 维全有）、`recommended_families`、`profile_quality / feature_coverage`。
- 同 family 跨股票差异：实测样本里 `growth_oriented` / `mean_reversion` / `high_volatility_trader` 三只股票在同 family 路径下分别拿到不同的 `holding_window / risk_level / param_search_space`（包含 `lookback_days / fast_window / rsi_overbought` 等 family 特异参数）。
- 缺失字段透明：`metadata.raw_features_grouped` 统一标 `coverage="missing" / status="not_available|insufficient_coverage|insufficient_kline"`，5204 只里有 9 只 low_confidence + 1 只 failed 即为真实数据稀缺，不被掩盖。
- vector_reuse 真复用通路验证：4 条 listed 策略 + 5204 画像下，命中 24 task / `avg_similarity = 0.977`。env 默认 `STRATEGY_FACTORY_VECTOR_REUSE_ENABLED=0`，启用后端到端通过。

**仍需做的**：
- 生产 24h 复跑（沙盒环境无法长跑，需要在生产调度器上跑）。
- 把 backfill 接入定时任务做增量更新。
- G2/G3 验证样本积累到 ≥ 10 后开启 `STRATEGY_FACTORY_VECTOR_REUSE_ENABLED=1`。
