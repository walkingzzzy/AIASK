> 基于：代码审查 + 数据库实测 + 行业标准联网调研
> 核心发现：**因子计算引擎代码已完整存在，问题仅在于配置参数和运行时状态**

## 0. 当前因子系统为什么没有产出真实因子

### 0.1 数据库实测结果（2026-05-14）

| 因子类型 | 行数 | 股票数 | 日期数 | 问题 |
|---|---|---|---|---|
| 经典 6 因子（momentum/value/quality/growth/volatility/reversal） | 600 | **100** | **1 天** | 只有 100 只股票的当日快照 |
| factor_candidate（50 个种子因子） | 897,550 | **300** | 60 天 | z-score 标准化值，非原始因子值 |

### 0.2 根本原因（代码审查后修正）

经过深度代码审查发现，**因子计算引擎已经完整存在**，问题不是"没有代码"，而是：

| # | 真正的问题 | 代码位置 | 后果 |
|---|---|---|---|
| 1 | **`DEFAULT_UNIVERSE` 只有 160 只硬编码股票** | `factor_scheduler.py` 第 50-160 行 | 因子只覆盖 ~100 只（部分失败），全 A 股 5,515 只的 1.8% |
| 2 | **调度器可能未被启动** | `get_factor_scheduler().start()` 需要在服务启动时调用 | MCP 服务未持续运行时因子不会被计算 |
| 3 | **IC 计算需要 ≥ 10 只股票成功** | `quant_mgr_classic.py` 第 540 行 | kline 加载失败太多时 IC 不被计算 |
| 4 | **每次只处理 200 只上限** | `quant_mgr_classic.py` 第 480 行 `codes[:200]` | 即使传入更多股票也被截断 |
| 5 | **kline 加载依赖网络 fallback** | `_load_klines_with_fallback` | 网络超时时大量股票计算失败 |

## 2. 修复方案（基于已有代码，最小改动）

> **核心认知**：不需要重写因子计算引擎（已完整存在），只需要：
> 1. 扩大股票宇宙（160 → 全 A 股）
> 2. 确保调度器被启动
> 3. 解除 200 只上限
> 4. 确保 kline 数据本地优先

### 2.1 PR-F1：扩大因子计算宇宙（P0，1 小时）

**位置**：`packages/akshare-mcp/src/akshare_mcp/services/factor_scheduler.py`

**问题**：`DEFAULT_UNIVERSE` 硬编码 160 只股票。

**改动**：在 `FactorScheduler.run_once()` 中动态加载宇宙：

```python
async def _load_dynamic_universe(self, db) -> list[str]:
    """从 stocks + kline_1d 动态加载有足够数据的全 A 股代码。"""
    try:
        rows = await db.fetch(
            "SELECT s.code FROM stocks s "
            "WHERE s.list_status = 'L' "
            "AND EXISTS (SELECT 1 FROM kline_1d k WHERE k.code = s.code LIMIT 1) "
            "ORDER BY s.code"
        )
        codes = [str(r["code"]).strip() for r in (rows or []) if r.get("code")]
        if len(codes) >= 500:
            return codes
    except Exception as exc:
        logger.warning("_load_dynamic_universe failed: %s, using DEFAULT_UNIVERSE", exc)
    return list(DEFAULT_UNIVERSE)  # Fallback
```

在 `run_once()` 开头替换 `self.universe`：

```python
async def run_once(self):
    db = get_db()
    # PR-F1: 动态加载全 A 股宇宙
    dynamic_universe = await self._load_dynamic_universe(db)
    if dynamic_universe:
        self.universe = dynamic_universe
        logger.info("FactorScheduler: dynamic universe loaded, %d stocks", len(self.universe))
    # ... 原有逻辑 ...
```

**效果**：宇宙从 160 只 → ~5,000 只。

### 2.2 PR-F2：解除 200 只批处理上限（P0，30 分钟）

**位置**：`packages/akshare-mcp/src/akshare_mcp/tools/managers/quant_mgr_classic.py`

**改动**：

```python
# 原来：
for stock_code in codes[:200]:

# 改为：
max_codes = min(int(kw.get("max_codes", 1000) or 1000), 2000)
for stock_code in codes[:max_codes]:
```

`FactorScheduler` 的 `batch_size` 已经控制每批大小（默认 50），所以实际每次调用不会超过 50 只。解除 200 上限只是移除不必要的硬限制。

### 2.3 PR-F3：确保调度器启动（P0，30 分钟）

**位置**：MCP 服务启动入口

**问题**：`FactorScheduler` 需要 `scheduler.start()` 被调用。

**改动**：在 `.env` 中添加控制变量，在服务启动时检查并启动：


### 2.4 PR-F4：kline 加载本地优先（P0，30 分钟）

**位置**：`quant_mgr_classic.py` 中 `_load_klines_with_fallback`

**改动**：因子计算场景下，本地 `kline_1d` 表已有 6,098,227 行（5 年历史），不需要网络 fallback：

```python
async def _load_klines_with_fallback(db, code, limit=252):
    # 因子计算只需要历史数据，本地 DB 足够
    klines = await db.get_klines(code, limit=limit)
    if klines and len(klines) >= 30:
        return list(klines), ["db.get_klines"]
    # 本地数据不足时不调网络（因子计算不需要实时数据）
    return list(klines or []), ["db.get_klines(insufficient)"]
```

### 2.6 PR-F6：因子有效性自动筛选（P1，2 小时）

**位置**：新建 `packages/strategy-factory/src/strategy_factory/application/research/factor_effectiveness.py`

**改动**：从 `factor_ic_history` 自动筛选有效因子，替代 `FACTORY_RESEARCH_FACTORS` 硬编码：

```python
async def select_effective_factors(db, *, min_ic=0.03, min_icir=0.5):
    """自动筛选有效因子。"""
    rows = await db.fetch(
        "SELECT factor_name, "
        "AVG(ic_value) as avg_ic, "
        "COUNT(*) as ic_days, "
        "SUM(CASE WHEN ic_value > 0 THEN 1 ELSE 0 END) * 1.0 / COUNT(*) as win_rate "
        "FROM factor_ic_history "
        "WHERE ic_date >= date('now', '-60 days') "
        "GROUP BY factor_name HAVING COUNT(*) >= 20"
    )
    effective = [
        r["factor_name"] for r in (rows or [])
        if abs(float(r.get("avg_ic") or 0)) > min_ic
        and float(r.get("win_rate") or 0) > 0.55
    ]
    # Fallback
    return effective or ["momentum", "value", "quality", "growth", "volatility", "reversal"]
```
