## 2. 策略工厂当前如何使用这些数据

### 2.1 因子库使用链路

```
FactorScheduler.run_once()
    → 计算 6 因子 × 160 只股票的因子值
    → 写入 factor_values 表
    → 计算 IC 值写入 factor_ic_history 表
        │
        ▼
FactorResearchBuilder.build(db, snapshot)
    → db.get_factor_ic_history(factor_name, "20", 20)  [读本地 ✅]
    → 构建 factor_research artifact（ranked_factors, preferred_strategy_types）
        │
        ▼
StrategySpawner._factor_maps(snapshot)
    → 从 snapshot["factor_research"] 提取 IC 值和趋势
    → IC > 0.03 且 trend="rising" 的因子 → 对应策略类型优先生成
    → 例：momentum IC=0.05 rising → 优先生成 momentum/ma_cross 策略
```

**问题**：`factor_ic_history` 只有 5 行，`FactorResearchBuilder` 读到的数据几乎为空，导致 `preferred_strategy_types` 回退到默认值，因子驱动形同虚设。

### 2.2 向量数据使用链路

```
Deduplicator.deduplicate(candidates, db)
    → 对每个候选，找已有策略中参数相似的
    → _vector_check(candidate, suspicious_list, db)
        → _build_behavior_klines(strategy_type, params, db)
            → _build_strategy_panels(strategy_type, params, db, sample_size=4)
            → 得到策略收益率序列作为"伪 K 线"
        → gateway.find_similar_patterns(
            query_klines=behavior_klines,
            candidate_klines_dict=existing_behavior_klines,
            method="returns",
            metric="cosine",
            backend="index",
          )
        → cosine_similarity > 阈值 → 判定为重复
```

**问题**：
- `_build_behavior_klines` 需要先跑一次回测生成收益率序列，计算成本高
- 如果 `strategy_behavior_embeddings` 集合中已有策略的向量指纹，可以直接查询而不需要重新回测
- 当前 `strategy_vector_profiles` 表为空，说明提交时的向量指纹没有被持久化到正确位置

### 2.3 回测引擎数据获取

```
BacktestFilter._test_one(candidate, code, db)
    → klines = self._kline_cache.get(code) or await db.get_klines(code, limit=500)
    → engine.run_backtest(code, klines, strategy_type, params)
```

**合规**：回测引擎只读本地 `klines` 表，不调外部 API。✅

## 3. 核心问题诊断

### 问题 A：策略工厂被 readiness hard_gate 阻塞（根本问题）

**证据**：`strategy_factory_runs` 唯一一条记录状态为 `skipped`，原因：
- `runtime_disabled`（`.env` 中未设置 `STRATEGY_FACTORY_RUNTIME_ENABLED=1`）
- `readiness_score: 0.0`
- `governed_pool_blocked`（governed candidate pool 不可用）

**这意味着**：策略工厂从未真正执行过完整流水线。所有下游问题（strategies=0, backtest_results=0）都是这个根因的结果。

**阻塞链路**：
```
STRATEGY_FACTORY_RUNTIME_ENABLED=0 (未设置)
    → readiness 阶段直接返回 "runtime_disabled"
    → 整个 cycle 被 skip
    → 不执行 collect / factor_research / spawn / gate / dedup / submit
```

### 问题 B：经典因子 IC 历史深度不足（中等）

**数据现状**：
- 50 个 `factor_candidate:factor_memory_seed_*` 因子：每个 60 天 IC 历史 ✅
- 6 个经典因子（momentum/value/quality/growth/reversal/volatility）：**每个仅 1 条记录**（2026-05-14）

**影响**：策略工厂 `collect_parts/evaluation.py` 中的趋势计算需要至少 10 条 IC 记录才能判断 rising/falling：
```python
if len(ics) >= 10:
    avg5 = np.mean(ics[:5])
    avg10 = np.mean(ics[5:10])
    delta = avg5 - avg10
    factor_ic_trend[fname] = "rising" if delta > 0.005 else ...
else:
    factor_ic_trend[fname] = "flat"  # ← 经典因子全部回退到 flat
```

经典因子只有 1 条记录 → 趋势全部为 `flat` → `_strong_rising_factor_names` 返回空 → Spawner 无法做因子驱动的方向选择。

**但 50 个 seed 因子有 60 天历史**，如果策略工厂能识别并利用这些因子（如 `factor_memory_seed_vol_10d` IC=0.04），就能做出有意义的方向选择。

### 问题 C：因子命名不匹配（中等）

**策略工厂查询**：`db.get_factor_ic_history("momentum", "20", 20)`
**数据库中的名称**：
- 经典因子：`momentum`（匹配，但只有 1 条）
- Seed 因子：`factor_candidate:factor_memory_seed_momentum`（不匹配）

**FactorResearchBuilder 的 fallback 链路**：
1. 先从 `snapshot["factor_research"]["ranked_factors"]` 读（需要 FactorResearchBuilder 成功构建）
2. 再从 `active_candidate_pool["top_candidates"]` 读（需要 governed pool 可用）
3. 最后 fallback 到 `snapshot["factor_ic"]`（collect 阶段写入的经典因子 IC）

如果 FactorResearchBuilder 能正确读取 seed 因子的 IC 历史并构建 `ranked_factors`，命名问题就不是障碍。但当前因为 runtime_disabled，整个链路从未被触发。

### 问题 D：向量系统完备但策略行为向量为空（低，因果关系）

**数据现状**：
- 向量基础设施完善：13 个集合、38,964 个 profiles、50,005 个图节点
- K 线模式向量覆盖全市场（5,500 只股票 × 4 种模式）
- 因子候选向量已有 50 条
- 策略文本向量已有 219 条（`strategy_artifact_text_embeddings`）
- 新闻/公告/研报向量已有 187 条
- **但 `strategy_behavior_embeddings` = 0**

**原因**：没有策略产出（strategies=0），所以没有策略行为向量。这是问题 A 的下游结果。

### 问题 E：直接调用外部 API（低，仅 1 处）

`futures_calendar_research_parts/part_5.py:87` 直接 `import akshare`。影响面小。

## 4. 修复方案

### 4.1 PR-DQ1：打通因子库到策略工厂的数据链路（最高优先级）

**目标**：让策略工厂能正确读取已有的 897K 因子值和 3005 条 IC 历史。

**问题定位**：策略工厂查询 `db.get_factor_ic_history("momentum", "20", 20)`，但数据库中的因子名是 `factor_candidate:factor_memory_seed_momentum`（带前缀）。经典 6 因子（momentum/value/...）只有 1 天数据。

**步骤**：

1. **确认命名映射**：检查 `FactorResearchBuilder._load_factor_history_meta` 是否做了名称转换
2. **开启因子自动刷新**：
```bash
# .env 修改
STRATEGY_FACTORY_FACTOR_AUTO_REFRESH=1
```
3. **确保 FactorScheduler 定期运行**：让经典 6 因子的 IC 历史从 1 天积累到 60+ 天
4. **利用已有的 50 个 factor_memory_seed 因子**：这些因子已有 60 天 IC 历史，策略工厂应该能读取并利用它们的 IC 信号来指导候选生成

**验证**：
```sql
-- 策略工厂应该能读到这些数据
SELECT factor_name, COUNT(*), AVG(ic_value) 
FROM factor_ic_history 
WHERE ic_value > 0.03 
GROUP BY factor_name 
ORDER BY AVG(ic_value) DESC;
```

**预期效果**：
- `FactorResearchBuilder.build()` 返回有意义的 `ranked_factors`（当前 IC 最强的因子排在前面）
- `StrategySpawner` 优先生成 growth/volatility 相关策略（因为这些因子 IC 最高）

### 4.3 PR-DQ3：让策略工厂首次成功产出策略（最高优先级）

**目标**：解决策略工厂从未成功产出策略的根本问题。

**排查步骤**：

1. **检查 K 线字段名兼容性**：`kline_1d` 表用 `time` 字段，但 `BacktestEngine` 可能期望 `date` 字段
2. **检查 `db.get_klines()` 的实际实现**：确认它读的是 `kline_1d` 表且字段映射正确
3. **开启 runtime**：
```bash
STRATEGY_FACTORY_RUNTIME_ENABLED=1
STRATEGY_FACTORY_FACTOR_AUTO_REFRESH=1
```
4. **降低 readiness 门槛**（临时）：让策略工厂能跑通一次完整流水线
5. **手动触发一次 `run_once`** 并观察每个阶段的输出

**验证**：
```sql
SELECT COUNT(*) FROM strategies;  -- 应 > 0
SELECT COUNT(*) FROM backtest_results;  -- 应 > 0
SELECT COUNT(*) FROM strategy_factory_runs WHERE status = 'success';  -- 应 >= 1
```

### 4.4 PR-DQ4：Gate-1 因子预筛（中优先级）

**目标**：利用因子 IC 数据在 Gate-1 阶段直接拒绝"依赖无效因子"的候选。

**当前可用信号**（基于实际数据）：
- `growth` IC=0.31 → growth_factor 策略应该优先
- `momentum` IC=-0.04 → momentum 策略当前应该降权
- `quality` IC=-0.06 → quality_factor 策略当前应该降权
- `reversal` IC=-0.60 → mean_reversion_short 策略当前应该**拒绝**
- `volatility` IC=-0.25 → volatility_breakout 策略当前应该降权

**逻辑**：
```python
STRATEGY_FACTOR_DEPENDENCY = {
    "momentum": "momentum",
    "ma_cross": "momentum",
    "value_factor": "value",
    "quality_factor": "quality",
    "growth_factor": "growth",
    "rsi": "momentum",
    "mean_reversion_short": "reversal",
    "volatility_breakout": "volatility",
}

def _factor_ic_prescreen(candidate, factor_ic_map):
    dependent = STRATEGY_FACTOR_DEPENDENCY.get(candidate["strategy_type"])
    if dependent and dependent in factor_ic_map:
        ic = factor_ic_map[dependent]
        if ic < -0.05:  # 因子严重失效
            return False
    return True
```
