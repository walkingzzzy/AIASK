## 1. 核心架构原则

### 1.1 数据流向（单向依赖）

```
外部数据源                    本地数据库                    策略工厂
(Tushare Pro / AKShare)  →   (SQLite)              →    (只读消费)
                              │                          │
                              │  kline_1d (610万条)       │  候选生成
                              │  stocks (5515只)          │  回测验证
                              │  financials (11.2万条)    │  质量门禁
                              │  factor_values (89.7万条) │  因子驱动
                              │  factor_ic_history (3365) │  趋势判断
                              │  vector_profiles (3.9万)  │  去重筛选
                              │  主题图 (15节点+10边)     │  事件驱动
                              │                          │
                              ←─────────────────────────←┘
                              数据缺失时触发同步（不直接调外部）
```

### 1.2 三条铁律

| # | 原则 | 验证状态 |

| 1 | **策略工厂永远只读本地数据库** | ✅ 已验证：`grep "import akshare" strategy-factory/src/` = 0 结果 |

- ❌ 在策略工厂代码中 `import akshare as ak` 并调用数据接口 → **已清除（0 处）**

| 主题图节点数 | ≥ 10 | ✅ 15 | 警告 |

### 3.2 运行时检测（每轮 cycle）

| 阶段 | 检测 | 当前表现 |
|---|---|---|
| collect | `completion_ratio < 0.7` | partial（部分数据源降级） |
| factor_research | `stale = true` | ✅ completed（auto_refresh 已开启） |

| dedup | 向量引擎不可用 | ✅ 正常（index 后端 + fallback） |
| submit | 验证报告失败 | 有 NameError 在 supplemental gate（非阻塞） |

### 3.3 数据缺失的处理流程

```
策略工厂发现数据缺失
        │
        ▼
记录缺失详情到 persistence_failures / warnings
        │
        ▼
判断严重程度
        │
        ├── 轻微（单只股票 K 线不足）→ 跳过该股票，继续运行 ✅ 已实现
        │
        ├── 中等（因子数据过期）→ 触发 factor_scheduler.refresh() ✅ 已实现
        │                         本轮使用旧数据继续
        │
        └── 严重（K 线表为空 / 股票表为空）→ 本轮标记为 SKIPPED ✅ 已实现
                                              断路器计数 +1
                                              等待下一轮重试
```

## 8. 与 sync_daily 的协作契约

### 8.1 sync_daily 的职责

- 定时（每日盘后）从 Tushare Pro 拉取数据写入本地 SQLite
- 支持增量同步（`sync_daily/engine.py`）和全量同步（`sync_complete.py`）
- 覆盖：stocks / klines / financials / valuations / dragon_tiger / north_fund / blocks / macro
- 数据源优先级：Tushare Pro → AKShare/东财（兜底）

### 8.2 策略工厂的职责

- ✅ 只读本地数据库（已验证：0 处外部 API 调用）
- ✅ 检测数据质量问题并记录（readiness_score / warnings / degraded 标记）
- ✅ 在数据不足时优雅降级（跳过/降级/重试），不崩溃
- ✅ 因子自动刷新已开启（`STRATEGY_FACTORY_FACTOR_AUTO_REFRESH=1`）

### 8.3 边界约定

- 策略工厂**不拥有**任何数据同步逻辑 ✅
- 策略工厂**不知道** Tushare Pro 的 API 签名或频率限制 ✅
- 策略工厂**只知道**本地表结构和 DAO 接口 ✅
- 数据源切换（Tushare → 其他）对策略工厂**完全透明** ✅
