## 0. 前置铁律

1. **先 P0-1 再开 toggle**：regime/IC 基于过期数据 = 错误路由/错误中性化。数据不新鲜时严禁开 toggle 跑真实 cycle。
2. **一次只开一个 toggle**：单变量灰度，便于归因。
3. **命令输出写临时文件再读**（PowerShell scrollback 会被污染 / PSReadLine 崩溃）。
4. **高风险操作前备份 DB**（`data/db/akshare_mcp.sqlite3`，仓库已有 `*.backup-*` 先例）。
5. **autoshelf 默认不开**：质检流水线先只打标签，人工确认后再开 `STRATEGY_FACTORY_FACTOR_QC_AUTOSHELF_ENABLED`。

## 1. 本批次新增 Toggle 一览（全部默认 OFF）

| toggle | 阶段 | 作用 | 影响面 |
|---|---|---|---|
| `STRATEGY_FACTORY_BATCH_IC_NEUTRALIZE_ENABLED` | P0-2 | 每日 batch IC 走行业/市值/beta 中性化 dual-IC | 改变入库 IC 数值分布 |
| `STRATEGY_FACTORY_PER_SYMBOL_REGIME_ENABLED` | P0-3 | 信号 evidence 逐标的推断 trend/vol regime | 填充 regime 切片（命中率矩阵前提） |
| `STRATEGY_FACTORY_STOCK_FIRST_ROUTER_ENABLED` | P1-2 | 逐股矩阵由路由器（regime+周期+排除项）选族 | 改变 bulk 矩阵 family 选择 |
| `STRATEGY_FACTORY_FORWARD_DAYS` | P2-2 | 前向收益采集窗口（如 `1,5,10,20,40`） | 多采 40 日窗口（长线命中率前提） |
| `STRATEGY_FACTORY_FORWARD_HORIZONS` | P2-2 | 命中率聚合窗口（如 `5,10,20,40`） | 命中率按 bucket 切片纳入长线 |
| `STRATEGY_FACTORY_FACTOR_QC_PIPELINE_ENABLED` | P2-1 | 每日质检流水线打标签 | 写 `validation_summary.qc_*` |
| `STRATEGY_FACTORY_FACTOR_QC_AUTOSHELF_ENABLED` | P2-1 | 据标签自动改写 quality_status/status | 自动上架/下架（**最后才开**） |

> 启用方式：写入 `.env` 或进程环境变量；修改后需**重启 MCP / 工厂进程**才生效。

## 2. 操作顺序（强依赖链）

### 步骤 A · P0-1 数据新鲜度（运维，必须最先做）

1. 备份 DB（破坏性前置）：复制 `data/db/akshare_mcp.sqlite3` 为 `*.backup-rollout-<日期>`。
2. 摸底：`check_db_freshness(max_stale_days=5)`（核心宇宙优先；全市场扫描返回大，慎用）。
3. 同步过期 K 线：`sync_stale_klines(codes=[...])` → 复查 staleness 归零。
4. 回填因子 IC：跑 `FactorScheduler.run_once`（依赖 K 线已新鲜）→ 查 `factor_ic_history.maxdate` 接近最近交易日。
5. 验收：`get_sync_status` 无堆积；`get_dead_letters` 无新增。

> 详见 `docs/data/数据维护手册-2026-06-03.md` §2/§3。

### 步骤 B · 先开"采集类"toggle（低风险，先把数据攒起来）

- 开 `STRATEGY_FACTORY_FORWARD_DAYS=1,5,10,20,40` + `STRATEGY_FACTORY_FORWARD_HORIZONS=5,10,20,40`。
- 开 `STRATEGY_FACTORY_PER_SYMBOL_REGIME_ENABLED=1`（让新信号带 trend/vol regime）。
- **观察**：跑 SignalTracker backfill，确认 40D 窗口被识别（`per_window` 出现 `40D` 键，computed 随 T+N 增长）；
  新信号 evidence 的 `payload.regime` 出现非 unknown 的 trend/vol。
- 这两类只增数据、不改生成决策，可较早开。

### 步骤 C · 再开"中性化"toggle（改 IC 分布，需阈值复检）

- 开 `STRATEGY_FACTORY_BATCH_IC_NEUTRALIZE_ENABLED=1`。
- 跑一次 `batch_compute_factors`（或等 FactorScheduler 18:00 自动跑），对比开关前后同因子 IC：
  - 期望：行业/市值偏见被剥离，IC 量级可能下降（正常）。
- **阈值复检**：检查 `_from_factor_ic` lane 与 `evaluate_validation_evidence` 的 `min_rank_ic_ir` 在新口径下是否仍合理；
  必要时经 env 收紧/放宽（`STRATEGY_FACTORY_FACTOR_*` 阈值）。

### 步骤 D · 开"路由器"toggle（改生成，影响面最大）

- 前提：步骤 B 的 regime 已在跑（路由器依赖 profile.regime + dimension scores）。
- 开 `STRATEGY_FACTORY_STOCK_FIRST_ROUTER_ENABLED=1`，同时 bulk 矩阵入口需开
  `STRATEGY_FACTORY_BULK_ENABLED=1`（否则逐股矩阵不生成）。
- **观察一轮 `--once` cycle**：
  - 趋势股任务族应为趋势族、超卖股为均值回归、低估值为价值族；震荡股**不含**趋势族（排除项生效）。
  - 抽查 task 的 `candidate_family` / `holding_period_bucket` 是否与个股状态匹配。
- 异常时立即关 toggle 回退（OFF 即恢复 recommended_families + sector 偏置，零变化）。

### 步骤 E · 最后开"质检流水线"（先标签后自动上下架）

1. 先只开 `STRATEGY_FACTORY_FACTOR_QC_PIPELINE_ENABLED=1`（autoshelf 仍 OFF）：
   - 跑 `FactorMiningFactory.run_maintenance()`，看 `qc_pipeline_report.decisions` 分布（promote/quarantine/retire 计数）。
   - 人工抽查若干因子的 `validation_summary.qc_labels` + `qc_shelf_decision` 是否合理。
2. 确认无误后再开 `STRATEGY_FACTORY_FACTOR_QC_AUTOSHELF_ENABLED=1`：
   - 此时 promote→active、retire→retired、quarantine→quarantine 自动写回。
   - **高影响**：会真实改变因子池可用集合，务必先备份 + 小范围观察。

### 6.3 灰度发现并修复：中性化小样本自由度守卫

- **现象**：n=10 截面 + 8 个行业哑变量列 → 自由度仅 2，OLS 过拟合行业均值，残差化把 rank_IC 翻号。
- **根因**：`_neutralize_factor_values` 原只有 `valid_mask.sum()<3` 守卫，无自由度守卫。
- **修复**：`factor_analysis.py` 加自由度守卫——`(有效样本数 - 设计矩阵列数) < FACTOR_NEUTRALIZE_MIN_DOF(默认5)`
  时跳过中性化、返回原始值，并记 `reason=insufficient_degrees_of_freedom`。
- **复跑验证**：同一 n=10 截面 → neutralized_rank_ic 现等于 plain（0.329=0.329，不再翻号），dof=2/design_cols=8 透明标注。
- **生产影响**：`batch_compute_factors` 真实截面通常数百只，dof 充足，守卫为 no-op；仅保护稀疏截面（某日某行业样本太少）。
- **测试**：`test_batch_ic_neutralize_p0_2.py` 加 2 个守卫单测；全 akshare-mcp 套件 **56 passed** 无回归。

### 6.4 灰度结论

- Phase 0-3 五条新路径在真实数据上行为正确；P0-2 经灰度加固后安全。
- P0-1 数据过期是真实存在的（代表股 50% 过期 14 天），按 §2 步骤 A 同步可解。
- 正式灰度（开 toggle 跑真实 cycle）仍需**重启 MCP/工厂进程加载新代码** + 先做全市场 P0-1。
- 命中率矩阵要出数，需先有策略流入 + 前向数据 T+N 累积（当前库 0 策略）。
