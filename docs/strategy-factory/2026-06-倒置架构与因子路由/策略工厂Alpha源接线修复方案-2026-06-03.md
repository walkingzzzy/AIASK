## 0. TL;DR（给拍板的人）

- 设计文档 §6 的前提"alpha 源是随机抖动的通用 TA"——**已过时一半**。
- 生产 DB 实测：`factor_ic_history` 已有 **1757 行 / 34 个因子**，其中遗传规划(`gp_*`)与强化学习(`rl_*`)挖掘出的因子 IC 高达 **0.108 / 0.105**（日频 A 股有真实预测力）。
- **真正的缺陷是"接线断 + 数据过期"，不是"没有 alpha 引擎"**：已挖出的强因子被算出来、存进库、排好序，然后被 spawner 直接忽略，永远不会变成策略候选。
- **根因修复杠杆极高且便宜**：把 IC 验证过的 `gp_*`/`rl_*` 因子接回 `_from_factor_ic` 生成链，每个候选合成 `prediction_contract`。这**一次同时修好两层**——真实先验 edge（IC 筛过）+ 真实语义契约（因子表达式 + 验证过的 IC 就是可证伪的断言），并在源头饿死 `fixed_defaults` 填充物。
- 这比 §6.4 的悲观结论**更乐观**：不需要"换 alpha 源"，现有源就有料，只是没接上。

## 1. 重新定位：前提只对了一半（实证）

### 1.1 生产 DB 实测证据

查询库：`data/db/akshare_mcp.sqlite3`，表 `factor_ic_history`。

| 指标 | 实测值 |
|---|---|
| 总行数 | 1757 |
| 不同因子数 | 34 |
| 日期范围 | 2026-01-26 ~ **2026-05-21**（过期 13 天） |

近 90 天 IC 排名（节选，按样本量排序）：

| factor_name | 样本数 | 平均 IC |
|---|---|---|
| `rl_factor_1` | 42 | **+0.1047** |
| `gp_factor_6` | 41 | **+0.1080** |
| `gp_classic_risk_adjusted_rank_momentum_7` | 41 | +0.0425 |
| `gp_factor_3` | 41 | +0.0449 |
| `rl_factor_4` | 42 | +0.0361 |
| `gp_factor_2` | 42 | +0.0065 |
| `rl_factor_2` | 42 | −0.0565 |

> `gp_` = 遗传规划挖掘；`rl_` = 强化学习挖掘。
> 日频 A 股截面 IC 到 0.10+ 是**有真实预测力**的量级，远高于随机抖动通用 TA 的 ≈0。

**结论**：系统早就有一个能产出真实非零 IC 因子的 alpha 挖掘引擎，
只是策略工厂的生成链没有消费它。

### 1.2 三处缺陷的代码/数据定位

| 缺陷 | 位置 | 证据 |
|---|---|---|
| **接线断**：`_from_factor_ic` 硬编码只认 5 个经典因子名 | `domain/spawner_parts/serialization.py:111-180` | `if factor_name == "momentum"/"value"/"quality"/"reversal"/"growth"` 分支结构；`gp_factor_6`/`rl_factor_1` 不在其中 → 被忽略 |
| **factor_pool 饿死**：高质量 lane 不出货 | `domain/spawner_parts/serialization.py:2-110`（`_from_factor_pool`） | 需要 `factory_pool_payload.factors[].expression_dsl`，snapshot 中为空 → 该 lane 返回 `[]` |
| **数据过期**：IC 与门难通过 | `factor_ic_history.maxdate = 2026-05-21` | 即使经典因子，过期 IC + `ic_value>0.03 AND trend=="rising"` 与门 → 不 spawn → 落 `fixed_defaults` |

**因果链**：
```
factor_ic_history 有强因子(gp_/rl_)
        │  但 _from_factor_ic 只认经典5因子
        ▼
强因子被丢弃 ──┐
factor_pool 空 ─┼─> 高质量 lane 全部不出货
IC 过期 ───────┘
        ▼
spawn 落到 quota_fill / fixed_defaults 兜底
        ▼
填充物候选无 evidence_chain / 无 prediction_contract
        ▼
进 paper 也产不出真实语义 evidence（只能靠 P1 proxy 补丁）
```

**所以 `fixed_defaults` 填充物不是"无 alpha 可用"，而是"已挖出的 alpha 被丢在表里没接进生成链"。**

## 2. 联网检索：2024-2026 学界共识（印证倒置架构方向）

> 检索自 arXiv（2024-2026，约 15 篇）。以下内容已改写以符合版权许可，原文请见链接。
> 合规说明：本节内容为转述/概括，非逐字引用。

### 2.1 范式：搜假设，不搜参数

现代系统化 alpha 发现已从"在固定 TA 族上调参"转向"生成公式化 alpha **表达式**"，三条主流引擎：遗传规划(GP)、强化学习(RL)、LLM 驱动生成。

- [Alpha-GPT：人机交互 alpha 挖掘](https://arxiv.org/abs/2308.00016)（EMNLP 2025 Demo）
- [LLM 驱动 alpha 挖掘 + 正则化探索对抗 alpha 衰减](https://arxiv.org/abs/2502.16789)
- [LLM-Powered MCTS 公式化因子挖掘](https://arxiv.org/abs/2505.11122)

**本 repo 已经在做这件事**（`gp_*`/`rl_*` 因子已落库）。

### 2.2 学界点名的失败模式，正好命中本 repo

| 失败模式 | 来源 | 本 repo 对应 |
|---|---|---|
| GP 易产"复杂、不可解释、过拟合"公式 | [arXiv 2604.09601](https://arxiv.org/html/2604.09601v1)、[2412.00896](https://arxiv.org/html/2412.00896v1) | 需要"财务逻辑/可解释性"门（= 缺失的语义契约） |
| 同质因子加剧拥挤、加速 alpha 衰减 | [arXiv 2502.16789](https://arxiv.org/abs/2502.16789) | Deduplicator 正是这个直觉（按相关性去相关） |

### 2.3 免回测、多维评价（对倒置架构的强背书）

[AlphaEval（arXiv 2508.13174）](https://arxiv.org/abs/2508.13174)提出沿 **5 个维度**评价 alpha——
预测力(IC)、稳定性、抗扰动鲁棒性、财务逻辑、多样性——**不依赖昂贵回测**。

这几乎逐条对应本项目设计文档的"观察农场 + 向前测量 + 多维画像"：

| AlphaEval 维度 | 倒置架构对应 |
|---|---|
| 预测力(IC) | ForwardVerifier 前向命中率 / forward_ic |
| 稳定性 | 跨 regime 标签的稳定性（P1 改动D） |
| 鲁棒性 | `factor_robustness_check` MCP 工具 |
| 财务逻辑 | **prediction_contract / evidence_chain（本方案要补的）** |
| 多样性 | Deduplicator（P0 已 env 可配） |

### 2.4 推论

"财务逻辑/可解释性"维度 = 缺失的那条**语义契约**。
现代框架要求每个 alpha 携带可解释 rationale——正是 `fixed_defaults` 填充物没有的东西。
本方案的"合成 prediction_contract"正是补齐这个维度。

## 3. 修复方案（分级 · 映射文件 · 验收标准）

### P-A（根因修复 · 最高杠杆 · 纯软件 · 单文件可单测）

**把已挖出的 alpha 接回生成链**——改造 `_from_factor_ic`。

- 文件：`packages/strategy-factory/src/strategy_factory/domain/spawner_parts/serialization.py`
- 改动：去掉"只认经典 5 因子"的硬编码分支，改为：
  1. 遍历 `factor_ic_history` 中所有 IC 通过阈值的因子（含 `gp_*`/`rl_*`）。
  2. 为每个因子生成候选，并合成 `prediction_contract`：
     - `direction` ← IC 符号（IC>0 → up，IC<0 → down/反转族）
     - `horizon_days` ← 因子持有期（`expected_holding_period`，缺省 20）
     - `claim` ← "因子 X 的近 90 天 OOS IC=Y、趋势 Z"
     - `evidence_chain` ← 该因子的 IC 历史片段（source_type=`factor_ic_validated`）
  3. 因子 → 策略族映射：复用已有 `preferred_strategy_types_for_factor`（factor_pool lane 已用）。
- **设计原则**：用 env toggle 包裹（如 `STRATEGY_FACTORY_FACTOR_IC_GENERIC_INTAKE_ENABLED`，默认 OFF），
  默认零行为变化；ON 时启用泛因子接入。遵循 P0/P1 既有的"默认 OFF、可单测、回归零变化"模式。
- **一次修好两层**：真实先验 edge（IC 筛过）+ 真实语义契约（因子表达式 + 验证过的 IC = 可证伪断言）。
  → `fixed_defaults` 在源头被饿死，不再依赖 P1 proxy evidence 补丁。

**验收**：单测——给定含 `gp_factor_6`(IC=0.108) 的 snapshot，
`_from_factor_ic` 产出带 `prediction_contract` 且 `evidence_chain` 非空的候选；
toggle OFF 时回归原 5 因子行为，零变化。

### P-B（喂活 factor_pool lane）

**把 gp_/rl_ 因子的表达式注入 snapshot。**

- 文件：`packages/strategy-factory/src/strategy_factory/application/research/factor_research_builder.py`
  （及 `_opportunity_snapshot.py` 的 `factory_pool_payload` 组装处）
- 改动：从 `factor_candidate_registry` / `factor_ic_history` 拉取通过门槛因子的
  `expression_dsl`，填入 `snapshot["factory_pool_payload"]["factors"]`，
  使 `_from_factor_pool`（serialization.py:2）能出货。
- **验收**：snapshot 的 `factory_pool_payload.factors` 非空时，
  `_from_factor_pool` 产出带 `factor_dsl` 的候选。

### P-C（同步 factor_ic_history 新鲜度）

**和 K 线同样的过期问题，刷新到当日。**

- 现状：`factor_ic_history.maxdate = 2026-05-21`（过期 13 天）。
- 手段：复用因子 IC 计算调度（`calculate_factor_ic` / `validate_factor_oos` MCP 工具或既有调度器），
  把 IC 历史回填到当前交易日，使 trend 判断准确。
- **验收**：`factor_ic_history.maxdate` 推进到最近交易日；trend 标签基于新鲜数据。
- **注意**：这是运维/数据任务，非纯代码改动；与 K 线同步是同类 T+N 数据问题。

### P-D（配套 · 对齐学界 · 防过拟合/拥挤）

- **OOS + 鲁棒性门**：用已有 `validate_factor_oos` / `factor_robustness_check` MCP 工具，
  只让通过 OOS + 鲁棒性的因子进 observe（AlphaEval 的预测力+稳定+鲁棒三维）。
- **去相关**：用 Deduplicator 按"因子值相关性"去相关（对抗拥挤，§2.2）。
- **衰减裁判**：观察农场天然就是 alpha 衰减的廉价向前裁判（无需额外建设）。
- **阈值可配**：把 `_from_factor_ic` 里 `ic_value>0.03 AND rising` 的裸与门改成
  env 可配 + 用 `skill_lcb`/分位，而非裸阈值。

## 5. 诚实边界（必须明确）

### 已验证（代码/数据实证）
- 接线 gap 真实存在：`_from_factor_ic` 硬编码只认经典 5 因子（serialization.py:111-180，已读）。
- 强因子已在库且 IC 非零：`factor_ic_history` 1757 行、`gp_factor_6` IC=0.108、`rl_factor_1` IC=0.105（DB 实测）。
- factor_ic_history 过期 13 天（maxdate=2026-05-21，DB 实测）。

### 不能承诺（诚实撤回过度乐观）
- 即使 IC=0.10 的因子也可能**拥挤/衰减**，接进去**不等于赚钱**（§2.2 学界明确警告）。
- 本方案**不制造 edge**，只**停止丢弃已挖出的 edge**。
- 接入后这些 `gp_*`/`rl_*` 因子向前到底行不行，**由倒置观察农场用最低成本给出诚实判决**——
  这正是 §2.3 学界免回测多维评价在做的事。

### 相对 §6.4 的修正
- 设计文档 §6.4 结论"重构不会凭空造 edge、若候选仍是随机抖动通用 TA 则前向命中率≈50%"——
  **前半句仍成立**（重构不造 edge），**后半句的前提被证伪**：候选**不必**是随机抖动通用 TA，
  现有 GP/RL 因子池就有真实 IC，只是没接上。
- 因此 alpha 源层的判决应从"不可靠"上调为"**有料但未接线**"。

**意义**：toggle ON 后，已挖出的 GP/RL 因子不再被丢弃，每个候选都是带语义契约的

### P-B · 已实施并验证（2026-06-03）

**诊断修正（实测推翻原假设）**：原方案 §3 P-B 假设“snapshot 不携带 DSL”。

**改动文件（1 个源文件 + 1 个测试）**：
- `akshare-mcp/.../factor_mining_factory/pool/active_pool.py`：`get_active_factors`

- `akshare-mcp/tests/test_factory_deep_repair.py`：新增 2 个测试。

### P-C（factor_ic_history 全量新鲜度同步）· 仍为运维任务（未做）

**性质判定（已实证）**：这不是代码缺陷，是数据/运维任务——全市场（5000+ 股）
