## 0. 一句话结论

两份文档**都不是空想**：引用的函数名、文件结构、阈值数值绝大多数能在代码里对上，
属于有据可查的高质量诊断，且都诚实区分了"事实 vs 判断"、都声明"不承诺赚钱"。
**核心诊断都成立**，但各有少数关键事实错误，会改变优先级排序：

- **文档A** 诊断准确度 ≈ 90%。最重要的纠正：**P1-b「行业+市值中性化未实现」是错的**——
  它已实现且默认开启；真实任务缩小为"把已有中性化器接进每日 batch IC 路径"。
- **文档B** 核心诊断（spawn 是 market-first、缺"诊断→类型路由"桥）**属实**。
  路由器（SR-0/SR-1）现在就能建；但真正想要的"命中率矩阵（SR-3）"被**前向数据恒 0**
  与 **trend/vol regime 休眠**双重卡住——文档部分坦白了前者、低估了后者。

**两份方案都可行**，但它们各自想要的"验证答案"共享三个先决条件（见 §4）。

### 1.2 关键纠正：中性化已实现（文档A 唯一实质性事实错误）

文档A 把"行业+市值中性化"列为 P1-b 待建缺口（🟡 未见明确实现）。**这是错的**：

`packages/akshare-mcp/src/akshare_mcp/services/factor_analysis.py` 的 `_neutralize_factor_values`
正是文档说"缺"的那套截面回归取残差法：

- `pd.get_dummies(industry, drop_first=True)` 构造行业哑变量（避免完全共线）；
- `log(market_cap)` 加入市值风格；
- 加入 beta 风格列；
- `np.column_stack([ones, X])` 加截距 → `np.linalg.lstsq` OLS → **取残差**作为中性化因子；
- 在 `calculate_ic_dual` 里 `enable_neutralization=True` **默认开启**。

**但有一个更精确的真相（这才是真正的小缺口）**：
中性化只在 akshare-mcp 的 dual-IC 路径生效；而**每日调度器**走的
`handle_batch_compute_factors`（`tools/managers/quant_mgr_classic.py`）计算 IC 时用的是
简化版 `AnalysisFactorsMixin.calculate_factor_ic`（只返回 `{ic, rank_ic}`，**不做中性化**）。

> **结论**：P1-b 不应是"建中性化"（已有），而应改为"**把已有的中性化器接进每日 batch IC 路径**"——
> 一个小得多、精确得多的接线任务。

### 2.2 纠正：regime 三维里两维是休眠的

文档B 称"regime 标签 P1-D 已加（trend/vol/sentiment）"，略有夸大：
- 维度定义确实存在（`REGIME_DIMENSIONS=("trend_regime","vol_regime","sentiment_regime")`）；
- 但生产者 `incubation.py` 里**只有 `sentiment_regime` 真算**（由 fear_greed：<30 fear / >70 greed / else neutral）；
- `trend_regime` 与 `vol_regime` **硬编码为 "unknown"**，注释写明"需逐标的行情(后续接入)"。

> 影响：SR-3 想"按 regime 切命中率"，但三维里两维是空表——这个二阶依赖文档B 没充分标注。

### 2.3 纠正：前向数据不是"仅 3D"，而是"采 1/5/10/20，但中长 horizon 实测算出 0"

- 代码采集窗口是 `FORWARD_DAYS=[1,5,10,20]`，**不是"仅 3D"**，且 **40 天根本没采集**
  （40 只作为 low_frequency profile 的 secondary_horizon 出现，SignalTracker 不收）。
- 但《策略工厂修复进度总览》§6① 实测：`signal_forward_returns` 仅 3D 有数据（113 行），
  5D/10D/20D **computed=0**（K 线不够新鲜 + 需 T+N 累积）。
- **所以文档B 的实质判断对**：中长线命中率**现在确实算不出来**；只是"3D"这个数字与采集窗口表述不准。

## 3. 两方案共享的三个先决条件（地基）

两份方案各自想要的"验证答案"都依赖以下三项，否则建完也看不到结果：

| # | 先决条件 | 为何是前提 | 落点 / 依据 |
|---|---|---|---|
| 1 | **修 K 线数据新鲜度** | 前向收益恒 0 → 命中率矩阵全空、因子 trend 失真 | `数据维护手册-2026-06-03.md` §2/§3；`sync_stale_klines` / FactorScheduler 重算 |
| 2 | **把已有中性化器接进每日 batch IC 路径** | 日频入库 IC 当前未去除行业/市值偏见（文档A P1-b 的精确形态） | `quant_mgr_classic.py:handle_batch_compute_factors` 改调中性化 dual-IC 路径 |
| 3 | **激活 trend/vol regime 的逐标的接线** | 否则 SR-3 regime 切片是空表，跨 regime 晋升门也缺输入 | `akshare-mcp/services/incubation.py:500-528`（当前硬编码 unknown） |

> 三项都属"小而关键的接线/运维"，不是大重构。做完才能让两份方案的验证目标"可被测量"。

## 4. 落地排序建议（按杠杆）

```
先修地基（可并行，1-2 天量级）
 ├─ [P0-1] K线新鲜度同步（运维，数据维护手册 §2/§3）
 ├─ [P0-2] 中性化接进每日 batch IC（文档A P1-b 精确版，小接线）
 └─ [P0-3] trend/vol regime 逐标的接线（解锁 regime 切片）

再建桥与货架（地基就绪后）
 ├─ [P1] SR-0 诊断契约 + SR-1 路由器（文档B，默认 OFF，可单测）← 最高杠杆
 ├─ [P1] 因子字典显式化（文档A P1-a）
 └─ [P2] 每日因子质检流水线编排（文档A P2，编排已有零件）

观察与判决（需 T+N 时间累积，非代码能即时给）
 ├─ [P3] SR-2 多周期前向采集补 40 horizon + bucket 切片
 ├─ [P3] SR-3 命中率矩阵（type×regime×bucket）← 真正的目标，受数据时间约束
 └─ [P4] SR-4 组合层 / 存储触发式演进（DuckDB+Parquet）
```

不做（已被现有路线取代）：vectorbt 裸代码 + 沙箱（DSL 路线更优更安全，文档A 已论证）。
