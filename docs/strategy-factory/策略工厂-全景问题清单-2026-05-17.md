# 策略工厂 · 全景问题清单（2026-05-17 审查）

> 本文档汇总策略工厂当前实际存在的全部问题，覆盖从任务源头到提交闭环、从业务逻辑到工程稳定性、再到文档治理的 29 项。
>
> 输入：代码审查 + 已有审计文档（`docs/策略工厂审计/`、`docs/strategy-factory/`）+ 修复方案对账（`策略工厂跑偏修复方案.md`）。
>
> 与现有方案的关系：本清单只列出问题，不重复给出代码补丁。具体改动落在各专项方案里（跑偏修复 / 选股逻辑 / 因子挖掘 / 实盘就绪 / 数据质量 / 性能优化）。本清单作为索引和优先级抓手。

---

## 30 秒 TL;DR

当前 `strategies = 0 / strategy_metrics = 0 / backtest_results = 0 / strategy_factory_runs = 1`，工厂本质上没有真正落库任何策略。原因是 4 类问题叠加：

1. **硬伤**：BULK 假死、Spawner 选新股 / 北交所、因子宇宙太小、事件链路断开。任何一条都足以让工厂跑空。
2. **业务逻辑缺陷**：即使跑通，Gate-3 没命中率门禁、没有样本外验证、伪因子、画像未消费 —— 产出的策略不会赚钱。
3. **工程稳定性**：回测无 timeout、提交无 DLQ、串行 IO 拖慢、调度窗口固定。
4. **文档 vs 代码不一致**：审计文档对部分模块的描述已过时。

## 一、硬伤：当前工厂几乎产不出策略

### #1 BULK 股票池静默假死（P0）

- **位置**：`packages/akshare-mcp/src/akshare_mcp/storage/sqlite/stock_info.py:220` 与 `:122`
- **现象**：`payload.get('list_date').strftime(...)` 假设是 `date` 对象，但 SQLite 返回字符串 → `AttributeError`。异常被 `StockStrategyMatrixPlanner.plan()` 外层兜底吞掉，summary 里只看到 `bulk_stock_matrix_loaded_stock_count=0` 但 `skip_reason=None`。
- **附带**：`pe_ratio / pb_ratio` 用裸 `float()` 存在同样的脏值隐患。
- **专项方案**：`策略工厂跑偏修复方案.md` §3.1（**未实施**）。

### #2 Spawner 选股不过滤北交所 / 新股 / 流动性差的股票

- **位置**：`packages/strategy-factory/src/strategy_factory/domain/spawner_parts/selection.py` 的 `_snapshot_target_symbols()`
- **现象**：直接从 `stock_family_allocation` 按 priority 取前 N，实测拿到 `920185 / 920045 / 688981` 这种 84 根 K 线的新股，Gate-1 `insufficient_klines` 一刀全砍。
- **附带矛盾**：矩阵路径 `_MIN_HISTORY_BARS=100` 偏低，与 `_GATE_1_MIN_KLINES=250` 自相矛盾。
- **专项方案**：`docs/strategy-factory/策略工厂-选股逻辑修复方案.md`（PR-U1/U5，部分实施：DB 层加了北交所过滤，但 Spawner 选股层未加）。

### #3 因子库股票宇宙只有 160 只（占全 A 股 1.8%）

- **位置**：`quant_mgr_classic.py` 的 `DEFAULT_UNIVERSE` 硬编码 + `codes[:200]` 上限
- **现象**：`factor_ic_history` 仅 3,005 行，6 个经典因子 1 天快照。`FactorResearchBuilder` 拿到的 IC 几乎为空 → `preferred_strategy_types` 回退到默认 → **因子驱动形同虚设**。
- **专项方案**：`docs/strategy-factory/策略工厂-因子挖掘修复方案.md`（PR-F1）。

### #4 事件驱动任务未接入主流程

- **位置**：`packages/strategy-factory/src/strategy_factory/infrastructure/mcp_adapters.py` 的 `MCPStrategyFactoryRepositoryAdapter`
- **现象**：未代理 `list_event_injections / list_theme_edges / get_theme_node / list_theme_exposure`。事件已入库、主题图已建，但 `opportunity.py` 调用时拿不到 → `manual_event_task_count=0`，整个事件驱动链路在主 run 里空跑。
- **专项方案**：`docs/strategy-factory/策略工厂-性能优化方案.md` §方案 A。

## 二、业务逻辑缺陷：跑通了也不会赚钱

### #5 Gate-3 没有命中率 / 盈亏比门禁

- **位置**：`_evaluate_trade_profile`、`backtest_filter_parts/`
- **现象**：只看 Sharpe / 回撤 / 交易数，不检查 `win_rate / profit_factor / payoff_ratio / expectancy`。命中率指标已落库，但门禁没读，profit_factor 整套计算不存在。
- **专项方案**：`docs/strategy-factory/策略工厂-实盘就绪改造方案.md` §2.3。

### #6 回测无样本外 / Walk-Forward 验证

- **位置**：`backtest_filter_parts/reporting.py:30+`
- **现象**：出现 `target_layer_oos_return` 字段，但只是"target 层"的命名，没有真正训练/测试切分、没有 walk-forward。Sharpe / 回撤全部是样本内统计。
- **行业基准**：Walk-Forward Efficiency ≥ 50% 是可交易策略的基本门槛。
- **专项方案**：`docs/strategy-factory/策略工厂-实盘就绪改造方案.md` §1.2。

### #7 "伪因子" — value/quality/growth 实际上都是价格动量变体

- **位置**：`multi_factor_strategy.py / single_factor_strategy.py`
- **现象**：
  - `ValueFactorStrategy` 用 60 日收益率 + 均值偏离 → 这是 reversal
  - `QualityFactor` 用收益率标准差的负值 → 这是 low-volatility
  - `GrowthFactor` = 短期收益率 - 长期收益率 → 这是动量加速度
- **数据可用性**：`financials` 有 11.2 万条但没接进来。
- **专项方案**：`docs/strategy-factory/策略工厂-实盘就绪改造方案.md` §0、`策略工厂-因子挖掘修复方案.md`。

### #8 股票画像维度没有真正消费

- **位置**：`StockStrategyMatrixPlanner._intrinsic_families_for_row()`（`stock_strategy_matrix_parts/normalizers.py:644-682`）
- **现象**：只看行业、PE、PB、市场冷热板块。已有的 `vector_profiles(stock_profile_embeddings)` 16,545 条记录、`factor_calculator` 的 technical/volatility/volume/fundamental/style 分类、`MiningContext` 的 market_regime / active_pool_families / success_patterns 全没读。茅台和宁德都拿一套 momentum 骨架。
- **专项方案**：`策略工厂跑偏修复方案.md` §3.3 P2（**未实施**）。

### #9 FACTOR_STRATEGY_MAPPING 静态硬编码

- **位置**：`factor_research_builder.py` 的 20 行 dict
- **现象**：没有反向学习闭环 —— 哪个因子→哪个 family 真正提升过 Gate 通过率从来没回写过。
- **专项方案**：暂无（建议纳入因子挖掘修复方案的下一版）。

### #10 Spawner 没有历史失败负反馈

- **位置**：`_family_gate_feedback`、`spawner_parts/factories.py` 的 `_expand_signal_variants`
- **现象**：只跟踪 EMA 提交数，对"被 Gate-2 反复淘汰的策略类型/参数空间"没有负反馈。`_expand_signal_variants` 仍按固定预算扩展。
- **专项方案**：暂无。

### #11 EMA 反馈正反馈死循环

- **位置**：`factory_scheduler.py` 的 `_family_gate_feedback` 衰减逻辑
- **现象**：没出现过的 family 每轮 ×0.7 衰减，触发 `IncubationBudgeter` 的 `ema_submit < 0.3 → score -= 2.0`，越冷越选不到。没有 EMA 下限或周期性探索重置。EMA 也只在内存，进程重启丢光。
- **专项方案**：`docs/策略工厂审计/策略工厂-模块01-调度器.md` §优化 3、4（**未实施**）。

### #12 Deduplicator 扫描范围只看最近 500 条

- **位置**：`deduplicator_parts/policy.py:110` `list_strategies(status, limit=500)`
- **现象**：listed + incubating 各 500 条无分页。一旦库存超过 500 条，去重语义会漏。同时按 strategy_type 分桶比较，跨类型语义相似（例：`mean_reversion_short` vs `rsi`）会漏检。
- **专项方案**：`docs/策略工厂审计/策略工厂-模块07-去重器.md` §优先级 P1（**未实施**）。

### #13 Elimination 缺年龄/样本量门槛 + 把 regime 错配当红旗

- **位置**：`elimination.py`
- **现状**：probation 降级已实现（`:118-150`，审计文档说"无 probation"已过时）。但仍存在：
  - 没看 strategy 上架年龄/累计交易数
  - `current_fg_level not in suitable_regimes` 直接计为红旗 → 周期性环境切换会清洗掉本来正确的策略
  - `limit=500` 同样有分页问题
- **专项方案**：`docs/策略工厂审计/策略工厂-模块10-淘汰检查器.md`（**部分实施**）。

### #14 IncubationBudgeter 探索性替换不按质量损失最小化

- **位置**：`incubation_budgeter_parts/evaluation.py`
- **现象**：从 observe 尾部反向找非探索候选直接换，权重 `_BASE_PRIORITY_SHARPE_WEIGHT=10.0` 等硬编码，没有 profile 化。
- **专项方案**：`docs/策略工厂审计/策略工厂-模块11-孵化预算分配器.md` §优先级 P2（**未实施**）。

## 三、工程稳定性

### #15 回测引擎调用无 timeout

- **位置**：`backtest_filter_parts/models.py:54` `factory_pkg.asyncio.to_thread(engine.run_backtest, ...)`
- **现象**：外层无 `asyncio.wait_for`。某只异常股票可能长时间占用并发槽。portfolio engine 同样问题。
- **专项方案**：`docs/策略工厂审计/策略工厂-模块06-回测筛选器.md` §优先级 P1（**未实施**）。

### #16 K 线预加载失败无 retry

- **位置**：`backtest_filter_parts/normalizers.py:36`
- **现象**：`await db.get_klines(code, limit=500)` 单次失败就空 list，无重试、无降级到上次缓存。
- **专项方案**：`docs/策略工厂审计/策略工厂-模块05-质量门禁.md` §优先级 P1（**未实施**）。

### #17 提交持久化失败无 retry / 无 DLQ

- **位置**：`_submitter_actions/runner_parts/persistence.py`
- **现象**：失败只 `logger.warning`，candidate 实际就丢了，下一轮也不会重试。
- **专项方案**：`docs/策略工厂审计/策略工厂-模块08-提交器.md` §优先级 P1（**未实施**）。

### #18 验证报告 / 风险报告串行

- **位置**：`_submitter_actions/runner_parts/submission_flow.py`
- **现象**：`await validation_gateway.run_validation_report(...)` 完才 `await risk_gateway.run_risk_report(...)`，可 `asyncio.gather`。
- **专项方案**：`docs/策略工厂审计/策略工厂-模块08-提交器.md` §优先级 P1。

### #19 `_load_universe_state()` 逐只串行加载 K 线

- **位置**：`event_engine.py`
- **现象**：`for stock in stocks: klines = await db.get_klines(...)` ~5500 只全串行。事件引擎慢主要在这里。
- **专项方案**：`docs/策略工厂审计/策略工厂-模块09-事件引擎.md` §优先级 P1。

### #20 `_load_budget_feedback / _load_stock_family_allocation` 串行 IO

- **位置**：`factor_research_builder.py` 的 `_feedback_routes.py` / `_research_context_sources.py`
- **现象**：实测 factor_research 5-13s，budget feedback 3.3s + stock_family_allocation 2.0s 占大头。
- **专项方案**：`docs/strategy-factory/策略工厂-性能优化方案.md`。

### #21 白名单缓存只在 ResearchPlaneRunner 类变量上

- **位置**：`research/runner.py:417-456` `_whitelist_cache`
- **现象**：1 小时 TTL，但每个进程实例独立，并发 / 多进程下重复加载。
- **专项方案**：暂无（建议纳入性能优化方案下一版）。

### #22 调度器固定窗口

- **位置**：`factory_scheduler.py` 的 `_compute_next_wait`
- **现象**：盘中 720s、盘后 3600s 写死，daily 模式只有 19:00 一个时间点（`FACTORY_DAILY_RUN_TIME`）。不按 last-cycle 产出率自适应。
- **专项方案**：`docs/策略工厂审计/策略工厂-模块01-调度器.md` §优化 8（**未实施**）。

### #23 Spawner 目标股票对齐没有实时停牌 / ST 实筛

- **位置**：`research/runner.py` 的 `_sanitize_local_spawn_targets`
- **现象**：只在写入候选时检查 K 线长度，没问停牌、ST、涨跌停占比、退市风险。
- **专项方案**：`docs/strategy-factory/策略工厂-选股逻辑修复方案.md` §扩展。

### #24 断路器恢复后无自适应退避

- **位置**：`factory_scheduler.py:195` `_circuit_state` 已初始化，但 `_factory_scheduler_loop_parts/policy.py` 的 `_loop` 只有 `closed/open` 两态判断
- **现象**：half-open 探测路径未串起来。指数退避 `_compute_error_backoff` 已实现，但和探测路径未联动。
- **专项方案**：`docs/策略工厂审计/策略工厂-模块01-调度器.md` §优化 2（**部分实施**）。
