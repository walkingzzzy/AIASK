# 策略工厂逐轮监控使用说明

## 功能说明

自动监控策略工厂四工厂的每一轮执行，并实时记录到Markdown文档中，便于追踪问题和分析趋势。

## 启动方式

### 方法1：使用启动脚本（推荐）
```bash
cd C:/Users/walking/Desktop/aiask
bash scripts/monitoring/start_monitor.sh
```

### 方法2：手动启动
```bash
cd C:/Users/walking/Desktop/aiask
export PYTHONIOENCODING=utf-8
nohup F:/Python311/python.exe -u scripts/monitoring/monitor_strategy_factory_rounds.py >> logs/monitor_v10.log 2>&1 &
```

## 查看实时记录

```bash
# 查看实时运行记录（自动更新）
cat 策略工厂实时运行记录-v10-20260613.md

# 查看监控日志
tail -f logs/monitor_v10.log
```

## 输出文件

- **策略工厂实时运行记录-v10-20260613.md** - 主报告文件，每轮自动更新
- **logs/monitor_v10.log** - 监控脚本运行日志

## 记录内容

每一轮完成后自动记录：

1. **基本信息**
   - 运行ID
   - 开始/结束时间
   - 耗时

2. **工厂漏斗**
   - spawned（生成数量）
   - submitted（提交数量）
   - gate_3_passed（G3通过数量）

3. **质量指标**
   - 交易预测命中率
   - 平均预测评分
   - 孵化中策略数

4. **策略分布**
   - submitted状态数量
   - incubating状态数量
   - rejected状态数量

5. **问题标记**
   - ⚠️ 命中率偏低（<35%）
   - ⚠️ G3全部未通过
   - ⚠️ 无孵化策略

## 停止监控

```bash
pkill -f "monitor_strategy_factory_rounds"
```

## 配置参数

编辑 `scripts/monitoring/monitor_strategy_factory_rounds.py`：

- `CHECK_INTERVAL = 60` - 检查间隔（秒）
- `DB_PATH` - 数据库路径
- `REPORT_PATH` - 报告输出路径

## 故障排查

### 监控未启动
检查进程：
```bash
ps aux | grep monitor_strategy_factory
```

### 报告未更新
检查监控日志：
```bash
tail -100 logs/monitor_v10.log
```

### 编码错误
确保设置了环境变量：
```bash
export PYTHONIOENCODING=utf-8
```

## 与策略工厂服务的关系

- **策略工厂服务**：实际执行策略生成、回测、提交
  - 进程：`run_strategy_factory_quality_session.py`
  - 日志：`logs/strategy_factory_v10_startup.log`

- **监控脚本**：监控工厂服务并记录每轮结果
  - 进程：`monitor_strategy_factory_rounds.py`
  - 日志：`logs/monitor_v10.log`

两者独立运行，监控脚本不会影响工厂服务。

## 最佳实践

1. **先启动策略工厂服务，再启动监控**
2. **定期检查报告文件，识别问题趋势**
3. **每24小时查看累计统计，评估整体表现**
4. **发现异常时，结合日志文件深入分析**
