# 策略工厂规模化调整方案

> 文档日期：2026-04-03（在 2026-04-02 规模化版本基础上，补入基于当前代码的“生产可用性补线”）  
> 背景：当前策略工厂已经具备“全市场研究候选生成 + Gate 审查 + 提交/孵化”的基本框架，但“规模化产能”和“可直接用于实盘交易”仍是两条尚未完全重合的建设主线。  
> 本文档基于实际代码链路（非理想化架构图），同时覆盖：现状诊断、规模化方案（P0/P1/P2）、生产可用性修正方案、配置变更清单与实施路线图。

## 一、现状诊断（基于代码核实）

### 1.1 系统本质定位

当前实现**不是**简单选股器，而是"**任务驱动的候选工厂**"，但它离"5000+ 股票 × 多策略家族 × 持续生成"目标还差一层关键抽象。

```
当前主链路：机会扫描任务 → 每个任务生成少量候选 → Gate 压缩
目标主链路：全市场逐股策略规划 → 每只股票 × 多策略家族展开 → Pre-Gate 廉价过滤 → Gate 精选
```

已完成的代码侧调整（当前状态）：
- ✅ 机会扫描宇宙默认值已扩至接近全量（`OPPORTUNITY_UNIVERSE_LIMIT=6000`）
- ✅ Bulk Matrix 宇宙在开启时可扩至接近全量（`STOCK_STRATEGY_MATRIX_UNIVERSE_LIMIT=6000 if enabled else 500`）
- ✅ 选股逻辑已从纯市值排序改为因子 + 行业分散打分（`_factor_scored_top_codes`）
- ✅ 行业数据已补全（5,470 只股票有申万行业分类）
- ✅ 每任务目标股票已扩至 8 只
- ✅ Gate-0 白名单已从早期 9 类扩至 15 类（含扩展规则家族）

### 1.3 核心瓶颈清单（已代码核实）

| # | 瓶颈 | 代码位置 | 当前值 | 影响 |
|---|------|---------|-------|------|
| **B1** | 每任务候选数硬上限 | `_factory_scheduler_loop.py:308` | `min(..., 10)` 硬编码 | 任何配置都无法突破，杠杆效应最大 |

| **B4** | Bulk Matrix 已有入口但仍未形成实盘级组合闭环 | `stock_strategy_matrix.py` + `cycle_runner.py` | 已有 per-stock/task 化入口，但仍主要输出“研究候选” | 能覆盖更多股票，但还不能证明“组合级可交易” |

| **B7** | Spawner 日常市场被部分抑制 | `spawner.py:173-178` | event_ready 抑制 fear_greed/volatility/fund_flow 三路 | `_from_factor_ic` 不受影响，但其余三路在事件就绪时被压缩 |
| **B8** | Gate 是线性漏斗 | `quality_gates.py:235-415` | Gate-1 代表股 Top-K 压缩 | 规模扩大 10 倍后将成为严重瓶颈 |
| **B9** | 因子研究是偏置层非分配器 | `factor_research.py:433-445` | 输出全局 `preferred_strategy_types` | 没有输出"每只股票适合哪些 family"的 per-stock 分配 |

### 1.4 抑制机制精确描述

**Spawner 分支逻辑（`spawner.py:168-183`）：**

```python
def spawn(self, snapshot):
    if not event_ready or fear_greed < 30 or fear_greed > 70:
        signal_candidates += self._from_fear_greed(snapshot)   # 受抑制
    signal_candidates += self._from_factor_ic(snapshot)         # 无条件运行 ✓
    if not event_ready or event_ready_supplemental:
        signal_candidates += self._from_volatility(snapshot)   # 受抑制
        signal_candidates += self._from_fund_flow(snapshot)    # 受抑制
```

修正点：`_from_factor_ic` **不受** `event_ready` 管控，始终执行。受抑制的是 fear_greed、volatility、fund_flow 三条路。"补位"触发条件（`spawner.py:191-199`）要求北向 ≥50 亿、融资 ±2%、恐贪偏离 ≥18 之一，日常震荡市场几乎不满足，补位上限被锁定在 `SPAWNER_EVENT_FILL_BUDGET_MAX=3`。

**Gate-0 类型白名单（当前代码）：**

```python
_VALID_STRATEGY_TYPES = frozenset({
    "momentum", "ma_cross", "rsi",
    "value_factor", "quality_factor", "growth_factor",
    "multi_factor", "macro_timing", "dsl_rule",
    "volatility_breakout", "gap_fill", "mean_reversion_short",
    "sector_rotation", "north_capital_track", "margin_divergence",
})
```

注意：`dsl_rule` 仍是 LLM 自治生成的核心入口类型，Gate-0 不会拦截它，但通过后仍需通过 DSL 编译器校验。扩展规则家族虽然已进入白名单，但当前“可直接实盘”的关键短板已转移到组合回测、执行现实性、验证协议和目标池一致性上，而不是类型数量本身。

**AI 约束链（`_strategy_llm_provider_prompt.py:105-185`）：**

```
DSL 字段白名单（open/high/low/close/volume）
+ 指标白名单（sma/ema/roc/rsi/volume_ratio 等）
+ 操作符白名单（gt/gte/lt/lte/cross_above/cross_below）
+ target_symbols 与 research_task 对齐要求
+ output_contract 结构约束
→ AI 是"受控 DSL 生成器"，而非开放式 alpha 发现器
→ 这保证了策略可回测性，但限制了 alpha 来源
```

**当前完全缺失的能力：**

- ❌ 无全市场逐一扫描（`_opportunity_utils.py` 的 `_factor_scored_top_codes` 只从宇宙里动态选 8 只/任务，不是遍历）
- ❌ 无"同一只股票 × 多种策略家族"的系统性展开
- ❌ 无持有期标签（短/中/长线）、风险等级标签写入生成 → Gate → 孵化全流程
- ❌ 因子研究只产出全局偏好，不产出 per-stock 的 family 分配计划

### 1.5 生产可用性阻塞项（2026-04-03 新增）

> 2026-04-02 版本已经把“规模化”主线理顺；本次补充明确当前代码与“可直接用于实盘交易”的关键差距。  
> 结论：当前工厂更准确的定位是“研究候选/孵化候选工厂”，还不是“可直接实盘的组合策略工厂”。

| # | 阻塞项 | 当前代码事实 | 关键位置 | 对实盘的直接影响 |
|---|--------|--------------|----------|------------------|
| **G1** | 多股票策略未做组合级回测 | `BacktestFilter` 对每个股票单独调用回测，再对结果取 `median` 聚合；`BacktestEngine` 每次只跑一个 `code` | `application/backtest_filter.py` + `services/backtest/engine.py` | 不能验证真实组合 NAV、组合换手、相关性、容量和资金分配 |
| **G2** | Gate-3 验证协议错配 | 交易策略会先无条件进入 `_run_statistical_gate()`，使用 IC/IR 逻辑，再附加交易型 gate | `application/submission_gate.py` | event/DSL/macro 交易规则可能被因子式验证误杀 |
| **G3** | 策略完整性不是硬门槛 | Gate-0 只校验 `strategy_type` / `params` / DSL 编译，不强制 `trade_plan`、`risk_rules`、`portfolio_spec`、`execution_assumptions` 等 | `application/quality_gates.py` | 会放行“可研究但不可直接交易”的候选 |
| **G4** | 成本/容量/冲击多为审计字段 | `market_impact_bps`、`arrival_price_policy`、`implementation_shortfall_proxy`、`max_position_pct` 主要写入 audit，不真实进入成交仿真 | `services/backtest/_engine_support.py` | 回测收益和实盘收益偏差会系统性偏乐观 |
| **G5** | 事件窗验证仍是 proxy | `event_window_metrics` 直接复用 `target_metrics or combined_metrics` | `application/backtest_filter.py` | event 命中率、事件衰减、异常收益并未被真实验证 |
| **G6** | 目标池约束三层语义不一致 | 任务契约是 `strict_intersection + allow_same_theme_only`，但 prompt 允许无交集回退，执行层又没有真正实现 same-theme 扩池 | `domain/targets.py` + `_strategy_llm_provider_prompt.py` | event 任务可能在“目标池生成”和“扩池 fallback”之间出现语义漂移 |
| **G7** | 多重检验只做了部分修正 | 已回填 attempt/selected 计数，但 PBO/Reality Check/SPA 仍大量依赖 proxy | `application/submission_gate.py` + 调度链 | 可以提示过拟合风险，但还不是完整、可审计的生产级挖掘偏差控制 |

## 二、架构转型方向

### 2.1 核心抽象切换

从"任务中心"切换到"股票中心"，需要引入新的核心对象 **`StockStrategyPlan`**：

```json
{
  "stock_code": "600519",
  "family_fanout": ["momentum", "value_factor", "dsl_rule"],
  "holding_period_bucket": "medium",
  "alpha_source": "momentum",
  "regime_fit": ["trending", "ranging"],
  "risk_budget": "medium",
  "generation_priority": 0.87
}
```

这个对象代替当前的"任务上下文"，成为候选生成的最小单元。

### 2.2 三层新架构

```
┌─────────────────────────────────────────────────────────────┐
│  Layer 1: Stock Profiling（股票画像层）                      │
│  输入：全市场 5,000+ 只股票                                  │
│  输出：每只股票的技术面/基本面/情绪面特征向量               │
│  依赖：K 线批量预计算 + 财务数据 + 因子 IC 暴露度           │
│  运行：盘前离线，每日一次                                    │
├─────────────────────────────────────────────────────────────┤
│  Layer 2: Strategy Family Planner（策略家族规划层）          │
│  输入：股票画像 + 因子研究输出 + 市场 Regime                │
│  输出：每只股票的 StockStrategyPlan（3~5 个家族）           │
│  依赖：factor_research 升级为 per-stock 分配器              │
│  运行：盘前离线，每日一次                                    │
├─────────────────────────────────────────────────────────────┤
│  Layer 3: Candidate Generator（候选生成层）                  │
│  输入：StockStrategyPlan 批次                               │
│  输出：具体参数化候选策略（DSL + 标签）                     │
│  路径 A：LLM 自治（dsl_rule 类型，当前已有）               │
│  路径 B：规则模板（当前已扩展至 14 类，仍可继续扩展）      │
│  运行：盘中 + 盘后持续，批量并发                            │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│  Pre-Gate（廉价前置过滤，新增）                              │
│  流动性筛除 + 相似度去重 + 信号密度评估 + family 配额        │
│  目标：拦截 70~85% 低质候选，保护 Gate-1/2 资源            │
└─────────────────────────────────────────────────────────────┘
                              ↓
              现有 Gate-0 / Gate-1 / Gate-2 / Gate-3
```

**现有"主题驱动任务链路"（`opportunity.py` + `_opportunity_snapshot.py`）保留**，但角色从"主产能"降级为"事件/热点/因子候选的高优先级覆盖层"，不再承担全量生成职责。

### 2.3 AI 自由度的正确路径

不应通过移除 DSL 白名单来放开 AI——这会破坏策略可回测性。正确路径是：

```
当前：固定家族触发阈值（恐贪 30/70）→ 限制进入哪条 family 路径
目标：family 路径由 Stock Profiling + Family Planner 决定 → AI 在更丰富的 family prompt 里自由决定参数

"fear_greed=70 才允许动量"这种规则应降成 prior（权重偏移），而不是 gate（开关）
```

### 2.4 策略标签体系（全流程一致）

以下标签必须同时写入：`StrategySpec.metadata`、DSL `metadata`、Gate 报告、实验记录、孵化记录。

```json
{
  "holding_period_bucket": "short | medium | long",
  "holding_days_range": [5, 20],
  "strategy_family": "momentum",
  "alpha_source": "momentum | reversal | value | event | sentiment | structure",
  "direction_bias": "long | short | neutral",
  "risk_level": "low | medium | high",
  "regime_fit": ["trending", "ranging", "volatile"],
  "generator_mode": "llm | rule | hybrid",
  "validation_profile": "trade_rule_validation",
  "candidate_family_id": "momentum_medium_long_trend",
  "target_symbol_count": 3,
  "market_cap_preference": "large | mid | small | all",
  "liquidity_requirement": "high | medium | low"
}
```

### 2.5 “规模化 + 生产可用”双目标下的新最小闭环（新增）

后续改造不再只是“把候选数做大”，而是要同时满足两条链路：

```text
Layer A：规模化链路
  全市场 / 分页宇宙 → StockStrategyPlan → Bulk / Snapshot / Event 生成 → Pre-Gate → Gate-0/1/2/3

Layer B：生产可用链路
  完整 CandidateSchema
    → 目标池契约一致
    → 组合级回测
    → profile 分流验证（factor / trade / event / macro）
    → 真实执行成本与容量仿真
    → 多重检验修正
    → audit-only 创建 / strategy-pool 创建分流
```

“可直接实盘”的最小验收标准必须同时满足以下 5 条：

1. 候选对象必须包含完整交易要素：`holding_horizon`、`trade_plan`、`risk_rules`、`rebalance_rule`、`portfolio_spec`、`execution_assumptions`、`validation_profile`。
2. 多股票候选必须走组合级回测，而不是“逐股票回测后取中位数”。
3. Gate-3 必须按 `validation_profile` 分流，不能用因子 IC 逻辑去主审 event/DSL 交易策略。
4. 成本、滑点、冲击、容量、持仓约束必须真实进入成交与收益曲线，而不是只写入 audit 字段。
5. attempt lineage、PBO/Reality Check/SPA 必须升级为 task/family/universe 级别的正式记录，而不是仅 run-level proxy。

### 3.2 新增 Bulk Stock-Strategy Lane（P0 架构行动）

这是真正从"任务中心"切换到"股票中心"的起点。哪怕 P0 阶段只做到 `3,000 只 × 2 family`，原始产能也能达到 6,000+/日。

**新链路概要（盘后批处理）：**

```
① 从 stocks 表拉取全市场股票（按因子打分排序）
② 按行业分批（每批 50~100 只）
③ 为每批生成 StockStrategyPlan（每只股票 2~3 个 family）
④ 批量调用生成器（LLM + 规则混合）产出具体候选
```

```python
class PreGateFilter:
    """在 Gate-0 之前运行，零 LLM 调用，纯规则/向量。"""
    
    def filter(self, candidates: list[dict]) -> list[dict]:
        return [c for c in candidates if
            self._pass_liquidity(c)          # 目标股票日均成交额 > 阈值
```

```
  Gate 分层优化、孵化资源预算器、多重检验正式注册表、运行态联动
  预期：15,000~30,000 条/日，并逐步形成“规模化 + 生产可用”双闭环
```

## 七、风险控制矩阵

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|---------|

| 反馈回路过拟合 | 低 | 高 | 保留 10~15% 探索配额；定期重置 family 权重 |

## 九、核心结论

**最大的问题不再只是“产能不够”，而是“规模目标”和“实盘目标”仍未完全对齐”：**  
当前架构已经可以做出一个“任务驱动候选工厂”，也已经开始具备“全市场 / per-stock”放量入口；但如果不补上候选完整性、目标池一致性、组合级回测、profile 分流验证、真实执行成本和多重检验，工厂放大的仍然主要是“研究候选”，而不是“可直接用于交易的策略”。

**改动的正确顺序：**

```
第 1 步（立即）：冻结生产底线接口
  CandidateSchema + validation_profile + target-pool contract

第 2 步（本周）：先补 3 个 P0 阻塞项
  候选完整性硬门槛 + Gate-3 profile 分流 + 目标池契约统一

第 3 步（第 2~3 周）：继续做规模化放量
  Bulk Lane 基础版 + 解除硬上限 + Pre-Gate + Spawner 权重模式 + 类型扩展

第 4 步（第 4~5 周）：把回测和验证升级到“可交易”
  组合级回测 + 真实执行成本 + 事件窗验证 + LIVE_ADMISSION_THRESHOLDS

第 5 步（第 6~8 周）：形成长期稳定闭环
  per-stock family planner + Bulk Lane 完整版 + 多重检验注册表 + 孵化/运行态联动
```

**不应做的事：**  
- ❌ 不要通过移除 DSL 白名单来放开 AI 自由度（会破坏策略可回测性）
- ❌ 不要单纯抬高配置参数而不做架构切换（配置调整的天花板约 6,000 条/日）
- ❌ 不要在组合级回测和真实执行成本完成前，将多标的候选直接视为“可实盘”
- ❌ 不要在 Bulk Lane 数据预热问题解决之前盲目增大批次并发（会打爆 DB 连接池）

**最终判断：**  
这份方案现在应该被理解为一份“双主线实施文档”：

1. 规模化主线负责把全市场覆盖、family 展开、吞吐和筛选效率做起来。
2. 生产可用主线负责把候选完整性、目标池一致性、组合级回测、真实执行和多重检验补成真正的交易底座。

只有两条主线同时收敛，策略工厂产出的“created_strategy_pool”才会越来越接近“可直接进入实盘评审”的策略，而不只是“数量很多的研究候选”。
