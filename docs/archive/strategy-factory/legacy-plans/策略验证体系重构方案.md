# 策略验证体系重构方案

> 核心问题：交易策略千变万化，固定的 G0-G3 流水线用同一把尺子衡量本质不同的策略类型，导致系统性偏差。回测精度不足以支撑从研究到实盘的可靠过渡。
>
> 核心方向：**用 AI 替代固定阈值**——通过 LLM-as-Judge、学习型质量评分模型、多 Agent 辩论机制，实现自适应、可泛化的策略验证体系。

---

## 一、当前设计的根本缺陷

### 1.1 一刀切的评估维度

| 问题 | 表现 | 后果 |
|---|---|---|
| 所有策略共用 Sharpe 阈值 | momentum 0.35 / rsi 0.20 | 系统性偏好趋势策略，压制低频高胜率策略 |
| 固定最大回撤上限 | 统一 mdd_max | 事件驱动策略天然高波动被误杀 |
| 最少交易数要求 | trades_min = 3-4 | 宏观择时策略（年交易 2-3 次）永远无法通过 |
| 统一的 Sharpe 统计检验 | 对所有类型做 DSR | 小样本策略的 DSR 无统计意义 |

### 1.2 回测精度不足

| 层面 | 当前实现 | 缺失 |
|---|---|---|
| 数据粒度 | 日线 K 线 | 分钟线/Tick 级别 |
| 执行模型 | 固定滑点 4bp + 次日开盘价 | 订单簿冲击、部分成交、涨跌停 |
| 验证方法 | 单次全样本回测 | Walk-Forward、CPCV、Bootstrap |
| 成本模型 | 固定佣金率 | 非线性冲击成本、借券费用 |
| 市场约束 | tradability_filter 标记 | T+1 隔夜风险、涨跌停排队 |

### 1.3 缺少经济学意义验证

当前 Gate 体系只验证"统计上是否显著"，不验证"经济学上是否合理"：
- 没有因果推断（alpha 还是风险溢价？）
- 没有容量评估（能承载多少资金？）
- 没有衰减预测（alpha 半衰期多长？）

---

## 二、重构目标

```

到：每种策略 → 专属验证协议 → 自适应阈值 → 分层精度回测
```

### 4.2 Gate-2 升级：Walk-Forward + CPCV

```python
class EnhancedBacktestValidator:
    """Gate-2 升级版：多路径验证替代单次回测。"""

    async def validate(self, candidate, db) -> ValidationResult:
        # 1. Walk-Forward Analysis（滚动窗口）
        wf_results = await self._walk_forward(
            candidate, db,
            train_window=252,      # 1 年训练
            test_window=63,        # 3 个月测试
            step=21,               # 每月滚动
        )

        # 2. Combinatorial Purged Cross-Validation
        cpcv_results = await self._cpcv(
            candidate, db,
            n_splits=6,
            n_test_splits=2,
            purge_gap=5,           # 5 天净化期
        )

        # 3. Bootstrap 置信区间
        bootstrap_ci = await self._bootstrap_sharpe(
            candidate, db,
            n_bootstrap=1000,
            confidence=0.95,
        )

        # 4. 综合判定
        return ValidationResult(
            walk_forward_degradation=wf_results.oos_vs_is_ratio,
            cpcv_pbo=cpcv_results.probability_of_backtest_overfitting,
            bootstrap_ci_lower=bootstrap_ci.lower_bound,
            deflated_sharpe=self._compute_dsr(candidate, n_trials=20),
        )
```

### 4.3 执行模型升级

```python
class RealisticExecutionModel:
    """替代固定滑点的真实执行模型。"""

    def estimate_execution_cost(self, order_size, stock_code, timestamp):
        # 1. 基础佣金
        commission = order_size * 0.00025

        # 2. 印花税（卖出）
        stamp_tax = order_size * 0.001 if is_sell else 0

        # 3. 非线性市场冲击（Almgren-Chriss 模型）
        adv = self._get_average_daily_volume(stock_code)
        participation_rate = order_size / adv
        # 冲击 = σ × (order_size / ADV)^0.6 × 临时冲击系数
        temporary_impact = self._volatility(stock_code) * (participation_rate ** 0.6) * 0.1
        permanent_impact = self._volatility(stock_code) * (participation_rate ** 0.4) * 0.05

        # 4. 涨跌停约束
        if self._is_limit_up(stock_code, timestamp):
            return float('inf')  # 无法买入

        # 5. T+1 约束
        if self._bought_today(stock_code):
            return float('inf')  # 无法卖出

        return commission + stamp_tax + temporary_impact + permanent_impact
```

## 五、自适应阈值系统

### 5.1 Regime-Conditional 阈值

```python
class AdaptiveThresholdEngine:
    """根据市场环境动态调整验证阈值。"""

    def get_thresholds(self, strategy_type, protocol, market_state):
        base = protocol.PRIMARY_METRICS.copy()

        # 市场波动率调整
        vol_ratio = market_state.current_vol / market_state.historical_avg_vol
        if vol_ratio > 1.5:  # 高波动
            base["sharpe_min"] *= 1.2      # 高波动时 Sharpe 容易虚高
            base["mdd_max"] *= 1.3         # 允许更大回撤
        elif vol_ratio < 0.7:  # 低波动
            base["sharpe_min"] *= 0.7      # 低波动时降低 Sharpe 要求
            base["signal_frequency_min"] *= 0.6  # 信号更少是正常的

        # 历史通过率校准
        recent_pass_rate = self._get_recent_pass_rate(strategy_type, window=10)
        if recent_pass_rate > 0.8:  # 通过率过高 → 阈值可能太松
            for key in base:
                if key.endswith("_min"):
                    base[key] *= 1.1
        elif recent_pass_rate < 0.1:  # 通过率过低 → 阈值可能太紧
            for key in base:
                if key.endswith("_min"):
                    base[key] *= 0.9

        return base
```

### 5.2 多重测试校正升级

```python
class StrictMultipleTestingCorrection:
    """严格的多重测试校正，替代当前过于宽松的设置。"""

    def correct(self, candidates, results):
        n_trials = len(candidates)
        n_effective = self._effective_number_of_trials(candidates)  # 考虑相关性

        for result in results:
            # Deflated Sharpe Ratio（Bailey & López de Prado）
            result.dsr = self._deflated_sharpe(
                observed_sharpe=result.sharpe,
                n_trials=n_effective,
                skewness=result.return_skewness,
                kurtosis=result.return_kurtosis,
                T=result.n_observations,
            )

            # Probability of Backtest Overfitting
            result.pbo = self._compute_pbo(result.cpcv_paths)

            # 严格判定
            result.statistically_significant = (
                result.dsr > 0.05           # DSR > 5%（而非当前的 -10%）
                and result.pbo < 0.40       # PBO < 40%（而非当前的 75%）
            )
```

### 6.1 Alpha 来源分解

```python
class AlphaDecomposition:
    """分解策略收益来源：真 alpha vs 风险溢价 vs 噪声。"""

    def decompose(self, strategy_returns, factor_returns):
        # Fama-French 5 因子回归
        alpha, betas, r_squared = self._factor_regression(
            strategy_returns,
            factors=["market", "size", "value", "profitability", "investment"],
        )

        # 判定
        if r_squared > 0.8:
            return "risk_premium"  # 主要是因子暴露，非真 alpha
        if alpha > 0 and self._t_stat(alpha) > 2.0:
            return "genuine_alpha"  # 统计显著的真 alpha
        return "noise"
```

### 6.2 容量评估

```python
class CapacityEstimator:
    """估计策略可承载的最大资金量。"""

    def estimate(self, strategy, market_data):
        # 基于 ADV 的容量上限
        target_stocks = strategy.get("target_symbols", [])
        min_adv = min(self._get_adv(code) for code in target_stocks)

        # 假设参与率不超过 5%
        max_participation = 0.05
        daily_capacity = min_adv * max_participation

        # 考虑持仓周期
        avg_holding = strategy.get("avg_holding_days", 5)
        total_capacity = daily_capacity * avg_holding

        return {
            "max_capacity_yuan": total_capacity,
            "capacity_bucket": self._classify(total_capacity),
            "constraint": "adv_participation_5pct",
        }
```

## 七、实施路线图

### Phase 1（2 周）：协议注册表 + 维度分离

- 定义 5 种验证协议的 PRIMARY_METRICS
- 修改 Gate-1/2 根据 `validation_profile` 选择不同的评估维度
- 保持现有阈值作为 fallback

### Phase 2（4 周）：回测精度升级

- 实现 Walk-Forward 验证（替代单次全样本）
- 实现 CPCV（至少 6-fold）
- 升级执行模型（非线性冲击 + T+1 约束）

### Phase 3（4 周）：自适应阈值

- 实现 regime-conditional 阈值调整
- 实现历史通过率校准
- 严格化多重测试校正（DSR > 0.05, PBO < 0.40）

### Phase 4（2 周）：经济学验证

- 实现 Alpha 来源分解
- 实现容量评估
- 集成到 Gate-3 作为补充判定

## 十、AI 驱动的验证体系（核心创新）

> 以下方案基于深度研究得出结论：**完全可行，且是行业前沿方向**。
> 参考：LLM-as-Judge（arxiv:2411.15594）、Multi-Agent Debate（FinDebate, arxiv:2509.17395）、TradingAgents 框架、Learned Reward Model（FSPO）、AI Backtesting Agent（Jenova.ai 2026）。

### 10.1 为什么 AI 验证可行？

| 固定阈值的局限 | AI 验证的优势 |
|---|---|
| 无法理解策略逻辑 | LLM 可以阅读策略代码/描述，判断经济学合理性 |
| 不区分策略类型 | LLM 可以自动识别策略类型并选择对应评估维度 |
| 阈值不随环境变化 | 学习型模型可以从历史数据中学习"什么样的策略最终成功" |
| 无法检测过拟合模式 | ML 分类器可以从回测曲线形态中识别过拟合特征 |
| 无法评估策略新颖性 | LLM 可以判断策略是否与已知 alpha 来源重复 |

### 10.2 三层 AI 验证架构

```
┌─────────────────────────────────────────────────────────────────┐
│ Layer C: LLM 策略审查委员会（替代 Gate-3 的固定阈值）            │
│ - 多 Agent 辩论：Bull Agent vs Bear Agent vs Judge              │
│ - 经济学合理性审查                                               │
│ - 策略新颖性评估                                                 │
│ - 容量/衰减风险评估                                              │
├─────────────────────────────────────────────────────────────────┤
│ Layer B: 学习型质量评分模型（替代 Gate-1/2 的固定阈值）          │
│ - XGBoost/LightGBM 分类器：预测"策略是否会在实盘成功"           │
│ - 特征：回测曲线形态 + 统计指标 + 参数敏感性 + 市场环境          │
│ - 训练数据：历史策略的回测→孵化→实盘全生命周期数据               │
├─────────────────────────────────────────────────────────────────┤
│ Layer A: LLM 结构审查（替代 Gate-0 的硬编码规则）                │
│ - 代码逻辑审查：策略代码是否有 bug/逻辑错误                      │
│ - 参数合理性：参数值是否在经济学合理范围内                        │
│ - 策略分类：自动识别策略类型，选择对应验证协议                    │
├─────────────────────────────────────────────────────────────────┤
│ 底层：传统统计验证（保留，作为 AI 判断的输入特征）                │
│ - Walk-Forward、CPCV、DSR、PBO 等                                │
│ - 作为 AI 模型的输入，而非最终判定标准                            │
└─────────────────────────────────────────────────────────────────┘
```

### 10.3 Layer A：LLM 结构审查（替代 Gate-0）

**当前 Gate-0 的问题**：只检查字段是否存在，不理解策略逻辑。

**AI 方案**：用 LLM 审查策略的代码逻辑和参数合理性。

```python
class LLMStructuralReviewer:
    """用 LLM 替代硬编码的 Gate-0 结构校验。"""

    SYSTEM_PROMPT = """你是一位资深量化策略审查员。
    你的任务是审查策略候选的结构完整性和逻辑合理性。
    
    审查维度：
    1. 策略逻辑是否自洽（入场/出场条件是否矛盾）
    2. 参数值是否在经济学合理范围内
    3. 风控规则是否完整（止损/止盈/最大持仓）
    4. 是否存在前视偏差（look-ahead bias）风险
    5. 自动识别策略类型（动量/均值回归/事件驱动/因子/择时）
    
    输出 JSON：
    {
        "passed": true/false,
        "strategy_type_detected": "momentum_trend",
        "confidence": 0.85,
        "issues": [...],
        "suggestions": [...],
        "economic_rationale_score": 0.7
    }"""

    async def review(self, candidate: dict) -> dict:
        prompt = self._build_review_prompt(candidate)
        response = await self._llm_call(prompt)
        return self._parse_response(response)

    def _build_review_prompt(self, candidate):
        return f"""
        策略类型: {candidate.get('strategy_type')}
        参数: {candidate.get('params')}
        入场逻辑: {candidate.get('trade_plan', {}).get('entry_bias')}
        出场逻辑: {candidate.get('trade_plan', {}).get('exit_bias')}
        风控规则: {candidate.get('risk_rules')}
        持仓周期: {candidate.get('holding_horizon')}
        目标股票: {candidate.get('target_symbols', [])[:5]}
        
        请审查此策略的结构完整性和逻辑合理性。
        """
```

**优势**：
- 不需要预定义"合法策略类型列表"——LLM 可以理解任何新类型
- 可以检测逻辑矛盾（如"做多+看空信号"同时存在）
- 可以自动分类策略类型，无需硬编码映射

### 10.4 Layer B：学习型质量评分模型（替代 Gate-1/2 固定阈值）

**核心思想**：不用固定阈值判断策略好坏，而是训练一个模型来预测"这个策略在实盘中是否会成功"。

**模型选择**：XGBoost / LightGBM 分类器（非 LLM）

**为什么不用 LLM**：这一层需要处理大量数值特征（回测曲线、统计指标），树模型在结构化数据上远优于 LLM。

```python
class StrategyQualityPredictor:
    """学习型策略质量预测器——从历史数据中学习什么样的策略会成功。"""

    FEATURE_GROUPS = {
        # 回测曲线形态特征（30+维）
        "curve_shape": [
            "equity_curve_linearity",      # 权益曲线线性度
            "drawdown_recovery_speed",     # 回撤恢复速度
            "profit_concentration",        # 盈利集中度（是否依赖少数大赚）
            "tail_ratio",                  # 尾部比率
            "underwater_time_ratio",       # 水下时间占比
            "curve_smoothness",            # 曲线平滑度
            "regime_consistency",          # 不同 regime 下的一致性
        ],
        # 统计稳健性特征（20+维）
        "robustness": [
            "walk_forward_degradation",    # WF 衰减率
            "cpcv_pbo",                    # 过拟合概率
            "parameter_sensitivity",       # 参数敏感性
            "bootstrap_ci_width",          # Bootstrap 置信区间宽度
            "deflated_sharpe",             # 修正后 Sharpe
            "is_oos_gap",                  # IS vs OOS 差距
        ],
        # 策略结构特征（15+维）
        "structure": [
            "strategy_type_encoded",       # 策略类型 one-hot
            "param_count",                 # 参数数量（越多越容易过拟合）
            "signal_complexity",           # 信号复杂度
            "holding_period_days",         # 持仓周期
            "universe_size",              # 目标股票池大小
            "turnover_rate",              # 换手率
        ],
        # 市场环境特征（10+维）
        "market_context": [
            "backtest_period_volatility",  # 回测期间波动率
            "backtest_period_trend",       # 回测期间趋势强度
            "regime_diversity",            # 回测覆盖的 regime 多样性
            "market_breadth",             # 市场广度
        ],
    }

    def predict(self, candidate, backtest_result) -> float:
        """返回 0-1 的质量分数，替代固定阈值判定。"""
        features = self._extract_features(candidate, backtest_result)
        probability = self._model.predict_proba(features)[0][1]
        return probability

    def _train(self, historical_data):
        """用历史策略的全生命周期数据训练。
        
        标签：策略最终是否在孵化期/实盘中表现良好
        - 正样本：孵化期 Sharpe > 0.3 且未被淘汰
        - 负样本：孵化期被淘汰 或 实盘衰减 > 50%
        """
        X = self._extract_all_features(historical_data)
        y = self._compute_labels(historical_data)
        self._model = LGBMClassifier(n_estimators=200, max_depth=6)
        self._model.fit(X, y)
```

**训练数据来源**（项目已有）：
- `strategy_incubation_metrics` 表：孵化期表现
- `elimination_log` 表：被淘汰的策略
- `strategy_metrics` 表：实盘指标
- 回测结果中的完整曲线数据

**关键优势**：
- 模型会自动学习"什么样的回测曲线形态预示着实盘失败"
- 不需要人工设定阈值——阈值从数据中学习
- 可以发现人类难以察觉的过拟合模式（如"盈利过于集中在少数交易"）

### 10.5 Layer C：LLM 策略审查委员会（替代 Gate-3 固定准入）

**核心思想**：模拟专业投资委员会的辩论过程，用多个 AI Agent 从不同角度审查策略。

参考：FinDebate（arxiv:2509.17395）、TradingAgents 框架、Adversarial Multi-Agent Evaluation（arxiv:2410.04663）。

```python
class StrategyReviewCommittee:
    """多 Agent 策略审查委员会——通过辩论达成共识。"""

    AGENTS = {
        "bull_analyst": {
            "role": "寻找策略的优势和潜力",
            "focus": ["alpha来源", "市场时机", "独特性"],
        },
        "bear_analyst": {
            "role": "寻找策略的风险和缺陷",
            "focus": ["过拟合风险", "容量限制", "衰减风险", "尾部风险"],
        },
        "risk_manager": {
            "role": "评估风险敞口和极端情况",
            "focus": ["最大亏损", "相关性风险", "流动性风险", "黑天鹅"],
        },
        "quant_reviewer": {
            "role": "审查统计方法论的严谨性",
            "focus": ["多重测试", "数据窥探", "样本量", "稳健性"],
        },
        "judge": {
            "role": "综合各方意见做出最终判定",
            "focus": ["权衡利弊", "给出置信度", "建议改进方向"],
        },
    }

    async def review(self, candidate, backtest_result, quality_score) -> dict:
        # 1. 各 Agent 独立分析
        analyses = {}
        for agent_name, config in self.AGENTS.items():
            if agent_name == "judge":
                continue
            analyses[agent_name] = await self._agent_analyze(
                agent_name, config, candidate, backtest_result
            )

        # 2. 辩论轮（Bull vs Bear）
        debate_result = await self._run_debate(
            analyses["bull_analyst"],
            analyses["bear_analyst"],
            rounds=2,
        )

        # 3. Judge 综合判定
        final_verdict = await self._judge_verdict(
            analyses, debate_result, quality_score
        )

        return {
            "decision": final_verdict["decision"],  # approve / reject / revise
            "confidence": final_verdict["confidence"],
            "reasoning": final_verdict["reasoning"],
            "risk_flags": final_verdict["risk_flags"],
            "improvement_suggestions": final_verdict["suggestions"],
            "debate_summary": debate_result,
        }
```

**辩论流程**：
```
Round 1: Bull 提出策略优势 → Bear 反驳 → Risk Manager 补充风险
Round 2: Bull 回应反驳 → Bear 最终总结 → Quant Reviewer 方法论审查
Final:   Judge 综合所有意见 → 做出 approve/reject/revise 决策
```

## 十一、总结

**核心结论**：用 AI 替代固定阈值进行策略验证**完全可行**，且是 2025-2026 年量化行业的前沿方向。

**推荐的技术栈**：
- **结构审查**：LLM（Claude/GPT-4）— 理解策略逻辑
- **质量预测**：LightGBM — 从历史数据学习成功模式
- **综合判定**：Multi-Agent LLM Debate — 模拟投资委员会
- **过拟合检测**：Isolation Forest + 曲线形态分析
- **regime 感知**：HMM + 自适应阈值

**关键原则**：
1. AI 不是替代统计验证，而是**在统计验证之上增加一层智能判断**
2. 传统指标（Sharpe、PBO、DSR）作为 AI 模型的**输入特征**，而非最终判定标准
3. 保留人类可审计性——所有 AI 判断必须输出推理过程
4. 渐进式替换——先 shadow 模式运行，确认有效后再切换

### 12.1 各层级最佳模型选择

#### Layer A（结构审查）：Claude Opus 4.x

### 12.2 质量约束体系（六层防护）

#### 第一层：Schema 强制约束

```python
from pydantic import BaseModel, Field, validator

class GateAResult(BaseModel):
    """Layer A 输出的强制 Schema——LLM 必须输出此格式。"""
    passed: bool
    strategy_type_detected: str = Field(..., pattern=r"^(momentum_trend|mean_reversion|event_driven|factor_rank|macro_timing|multi_factor|unknown)$")
    confidence: float = Field(..., ge=0.0, le=1.0)
    issues: list[str] = Field(default_factory=list, max_items=10)
    economic_rationale_score: float = Field(..., ge=0.0, le=1.0)
    look_ahead_bias_risk: str = Field(..., pattern=r"^(none|low|medium|high)$")
    
    @validator('confidence')
    def confidence_must_be_reasonable(cls, v):
        if v > 0.99:
            raise ValueError('Confidence > 0.99 is suspicious')
        return v
```

**原则**：LLM 输出必须通过 Pydantic 验证，不合格直接拒绝并重试。

#### 第二层：数值计算外置

```python
# 关键原则：所有数值计算在 LLM 外部完成
# LLM 只负责"判断"和"推理"，不负责"计算"

class HybridValidator:
    async def validate(self, candidate, backtest_result):
        # 1. 数值指标由传统代码计算（精确）
        metrics = self._compute_metrics(backtest_result)  # Sharpe, PBO, DSR 等
        
        # 2. 将计算结果作为事实输入给 LLM
        llm_input = {
            "strategy_description": candidate,
            "computed_metrics": metrics,  # 已计算好的数值
            "market_context": self._get_market_context(),
        }
        
        # 3. LLM 只做定性判断（不做数值计算）
        judgment = await self._llm_judge(llm_input)
        
        # 4. 合并：数值硬约束 + LLM 软判断
        return self._merge_decisions(metrics, judgment)
```

**原则**：永远不让 LLM 做数学运算。Sharpe、PBO、DSR 等由代码计算，LLM 只解读含义。

#### 第三层：多数投票 + 一致性检查

```python
class ConsensusValidator:
    """多次调用 + 多数投票，降低单次幻觉风险。"""
    
    N_CALLS = 3          # 每个判断调用 3 次
    AGREEMENT_MIN = 2    # 至少 2/3 一致才采信
    
    async def validate_with_consensus(self, candidate):
        results = []
        for _ in range(self.N_CALLS):
            result = await self._single_validation(candidate)
            results.append(result)
        
        # 检查一致性
        decisions = [r["passed"] for r in results]
        agreement = max(decisions.count(True), decisions.count(False))
        
        if agreement < self.AGREEMENT_MIN:
            # 不一致 → 标记为"需要人工审查"
            return {"decision": "manual_review", "reason": "ai_disagreement"}
        
        # 多数投票
        final_decision = decisions.count(True) > decisions.count(False)
        
        # 额外检查：confidence 分数的方差
        confidences = [r["confidence"] for r in results]
        if max(confidences) - min(confidences) > 0.3:
            # 置信度波动大 → 降级为保守判断
            return {"decision": "conservative", "passed": False}
        
        return {"decision": "consensus", "passed": final_decision}
```

#### 第四层：硬约束兜底（不可被 AI 覆盖）

```python
class HardConstraints:
    """无论 AI 怎么判断，这些硬约束不可违反。"""
    
    ABSOLUTE_REJECT = {
        "max_drawdown_absolute": 0.50,     # 回撤 > 50% 绝对拒绝
        "negative_total_return": True,      # 总收益为负绝对拒绝
        "zero_trades": True,               # 零交易绝对拒绝
        "invalid_strategy_type": True,     # 无法识别的类型绝对拒绝
    }
    
    ABSOLUTE_REQUIRE = {
        "min_backtest_days": 60,           # 至少 60 天回测数据
        "min_stocks_tested": 1,            # 至少 1 只股票
        "risk_rules_present": True,        # 必须有风控规则
    }
    
    def check(self, candidate, backtest_result) -> tuple[bool, list[str]]:
        """硬约束检查——AI 判断之前执行，不可覆盖。"""
        violations = []
        metrics = backtest_result.get("metrics", {})
        
        if abs(float(metrics.get("max_drawdown", 0))) > 0.50:
            violations.append("absolute_drawdown_exceeded")
        if float(metrics.get("total_return", 0)) < 0:
            violations.append("negative_total_return")
        if int(metrics.get("trades_count", 0)) == 0:
            violations.append("zero_trades")
            
        return len(violations) == 0, violations
```

**原则**：AI 是"顾问"，硬约束是"法律"。AI 可以在合理范围内灵活判断，但不能违反绝对底线。

#### 第五层：人类审计轨迹

#### 第六层：持续校准（Calibration Loop）

```python
class ModelCalibrator:
    """持续监控 AI 判断质量，自动校准。"""
    
    async def calibrate(self):
        # 1. 收集最近 N 个 AI 判断 vs 实际结果
        recent = await self._db.get_recent_ai_decisions(limit=50)
        
        # 2. 计算准确率
        correct = sum(1 for r in recent if r["ai_decision"] == r["actual_outcome"])
        accuracy = correct / len(recent)
        
        # 3. 如果准确率下降 → 自动调整
        if accuracy < 0.6:
            # AI 判断不可靠 → 提高硬约束权重
            self._increase_hard_constraint_weight()
            logger.warning(f"AI accuracy dropped to {accuracy:.1%}, tightening constraints")
        
        if accuracy < 0.5:
            # AI 判断比随机还差 → 暂时禁用 AI，回退到规则
            self._disable_ai_layer()
            logger.critical(f"AI accuracy {accuracy:.1%} < 50%, falling back to rules")
        
        # 4. 检测 AI 偏差
        type_accuracy = self._accuracy_by_strategy_type(recent)
        for stype, acc in type_accuracy.items():
            if acc < 0.4:
                logger.warning(f"AI biased against {stype} (accuracy {acc:.1%})")
```

### 12.5 最终决策融合

```python
class FinalDecisionFusion:
    """融合三层 AI 判断 + 硬约束，产出最终决策。"""
    
    WEIGHTS = {
        "hard_constraints": float('inf'),  # 硬约束不可覆盖
        "layer_b_score": 0.45,             # ML 模型权重最高（数据驱动）
        "layer_c_decision": 0.35,          # 审查委员会次之（推理驱动）
        "layer_a_score": 0.20,             # 结构审查最低（预筛性质）
    }
    
    def fuse(self, hard_check, layer_a, layer_b, layer_c) -> dict:
        # 1. 硬约束一票否决
        if not hard_check["passed"]:
            return {"decision": "reject", "reason": "hard_constraint", "details": hard_check}
        
        # 2. 加权融合
        composite_score = (
            layer_b["quality_score"] * self.WEIGHTS["layer_b_score"]
            + (1.0 if layer_c["decision"] == "approve" else 0.0) * self.WEIGHTS["layer_c_decision"]
            + layer_a["economic_rationale_score"] * self.WEIGHTS["layer_a_score"]
        )
        
        # 3. 决策
        if composite_score >= 0.6:
            return {"decision": "approve", "score": composite_score}
        elif composite_score >= 0.4:
            return {"decision": "observe", "score": composite_score}  # 进入观察期
        else:
            return {"decision": "reject", "score": composite_score}
```

### 12.6 总结：模型选择决策树

```
策略候选进入验证
    │
    ├── 硬约束检查（代码，0ms）
    │     └── 违反 → 直接拒绝（AI 不参与）
    │
    ├── Layer A: LLM 结构审查（Claude Opus, ~3s）
    │     ├── Schema 强制 + 数值外置
    │     ├── 自动识别策略类型
    │     └── 经济学合理性初判
    │
    ├── Layer B: ML 质量预测（LightGBM, ~50ms）
    │     ├── 75+ 维特征（曲线形态 + 统计 + 结构 + 环境）
    │     ├── 输出 0-1 质量分数
    │     └── SHAP 解释"为什么"
    │
    ├── Layer C: 多 Agent 审查（Claude Opus × 5 Agent, ~25s）
    │     ├── Bull/Bear/Risk/Quant/Judge 辩论
    │     ├── 2 轮辩论 + 最终裁决
    │     └── 仅对 Layer B > 0.5 的候选触发
    │
    └── 决策融合
          ├── 硬约束：一票否决
          ├── Layer B × 0.45 + Layer C × 0.35 + Layer A × 0.20
          └── ≥ 0.6 通过 / 0.4-0.6 观察 / < 0.4 拒绝
```
