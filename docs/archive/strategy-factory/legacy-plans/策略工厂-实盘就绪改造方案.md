## 命中率（Hit Rate / Win Rate）的真正含义

### 定义

> **命中率 = 盈利交易次数 ÷ 总交易次数 × 100%**

行业内 Hit Rate、Win Rate、Success Rate、Profitability 是**同一个概念**（来源：[Binance Academy](https://academy.binance.com/en/glossary/win-rate)、[TradesViz](https://www.tradesviz.com/glossary/hit-ratio/)、[FXStreet](https://learningcenter.fxstreet.com/education/learning-center/unit-3/chapter-2/stability-statistics/index.html)）。

### 致命的认知陷阱

**命中率 > 50% ≠ 赚钱。命中率 < 50% ≠ 亏钱。**

2023 年对 25,000 名散户、400 万笔交易的实证研究（Cohen, Makov & Schwartz）发现：
- **65% 的散户**赢的交易次数比输的多（命中率 > 50%）
- 但 **82% 的人全年仍然亏损**
- 原因：平均盈利仅 1.2%，平均亏损 2.8%，盈亏比 1:2.3 反向

来源：[RiskPublishing 综述](https://riskpublishing.com/best-stock-indicators-top/)

### 命中率必须和盈亏比一起看

**保本命中率公式**：

```
保本命中率 = 1 ÷ (1 + 盈亏比)

盈亏比 1:1  → 需要命中率 ≥ 50%
盈亏比 2:1  → 只需要命中率 ≥ 33%
盈亏比 3:1  → 只需要命中率 ≥ 25%
```

**期望值公式（决定策略是否赚钱）**：

```
期望值 = 命中率 × 平均盈利 - (1 − 命中率) × 平均亏损
```

期望值 > 0 才是正期望系统。

来源：[Quantcrawler](https://quantcrawler.com/learn/win-rate-calculator)、[LiberatedStockTrader](https://www.liberatedstocktrader.com/break-even-win-rate-calculator/)、[TradeZella](https://www.tradezella.com/blog/win-rate)

### 不同策略类型的命中率行业标准

| 策略类型 | 典型命中率 | 盈亏比要求 | 利润因子 |
|---|---|---|---|
| 趋势跟踪 / 突破 | 35-45% | ≥ 2:1（甚至 3:1） | ≥ 1.8 |
| 均值回归 / RSI | 55-70% | 1:1 ~ 1.5:1 | ≥ 1.5 |
| 多因子选股（月度） | 50-60% | ≥ 1.5:1 | ≥ 1.5 |
| 高频 / 剥头皮 | 70-80% | 0.3:1 ~ 0.5:1 | ≥ 1.4 |

来源：[HorizonTrading 综述](https://horizontrading.ai/learn/backtesting-metrics-explained)、[QuantifiedStrategies SPY 回测](https://www.quantifiedstrategies.com/rsi-trading-strategy/)

## 0. 当前策略为什么不能上实盘

### 核心问题：策略逻辑是"伪因子"

审查 `multi_factor_strategy.py` 和 `single_factor_strategy.py` 后发现：

```python
# ValueFactorStrategy._compute_factor()
ret = (closes[i] - closes[i - lb]) / closes[i - lb]  # 过去60日收益率
deviation = (closes[i] - ma) / ma                      # 均值偏离度
factor[i] = -(ret * 0.5 + deviation * 0.5)             # 取反 = "跌得多的分高"
```

**这不是真正的价值因子**。真正的价值因子需要 PE/PB/股息率等基本面数据。当前实现只是用价格动量的反转作为"价值"的近似——这在学术上叫 **reversal factor**，不是 value factor。

同样：
- "质量因子" = 收益率标准差的负值（低波动）+ 正收益率占比
- "成长因子" = 短期收益率 - 长期收益率（动量加速度）

**这三个"因子"本质上都是价格动量的变体**，没有使用任何基本面数据（PE/PB/ROE/营收增速），尽管数据库里有 11.2 万条财务数据。

### 行业标准对比

根据联网搜索结果（[HorizonTrading 综述](https://horizontrading.ai/learn/backtesting-metrics-explained)、[RiskPublishing 实证研究综述](https://riskpublishing.com/best-stock-indicators-top/)）：

| 指标 | 行业最低标准（"可交易"门槛） | 当前策略工厂 |
|---|---|---|
| 利润因子（Profit Factor） | ≥ 1.5（理想 ≥ 2.0） | 未计算 |
| 命中率（Win Rate） | 趋势策略 ≥ 40%，均值回归 ≥ 55% | 已计算但未做门禁 |
| 盈亏比（Avg Win / Avg Loss） | 数学上 win_rate × payoff_ratio > 1 | 未计算 |
| 期望值（Expectancy） | > 2× 交易成本 | 未计算 |
| 最大回撤 | ≤ 25%（理想 ≤ 15%） | 已计算 |
| Sharpe Ratio（样本外） | ≥ 1.0 | 已计算（仅样本内） |
| Walk-Forward 效率 | ≥ 50% | 未做 |
| 交易次数 | ≥ 50（理想 ≥ 100） | 10-32（不足） |
| 样本外验证 | 必须（保留 20-30% 数据） | 未做 |
| 多股票泛化 | ≥ 5 只 | 仅 1 只 |

关键引用（已为许可合规改写）：
- 量化研究综述显示："超过 90% 的回测有效的机器学习策略，在实盘中失败，主要源于数据窥探与过拟合"（[tradealgo.com](https://www.tradealgo.com/trading-guides/ai-trading/machine-learning-backtesting-guide)）
- 实测案例："回测胜率 87%，实盘两个月后跌到 43%"（[markaicode.com](https://markaicode.com/gold-trading-walk-forward-optimization/)）
- "Walk-Forward Efficiency 大于 50% 通常被视为可接受"（[tradingstrategy.ai](https://tradingstrategy.ai/glossary/walk-forward-analysis)）
- 25,000 名散户、400 万笔交易实证："65% 的散户命中率高于 50%，但 82% 仍亏损，因平均亏损是平均盈利的 2.3 倍"（[RiskPublishing](https://riskpublishing.com/best-stock-indicators-top/) 引述 Cohen et al. 2023）

## 1. 要让策略工厂产出"可交易"策略需要解决的问题

> **目标修正**：不是单纯追求"≥ 50% 命中率"，而是产出**正期望（Expectancy > 0）+ 利润因子 ≥ 1.5 + 命中率超过保本线 5 个百分点以上**的策略。这是行业内被反复验证的"可交易"标准。

### 1.1 命中率门禁缺失（最紧急）

**当前**：Gate-3 完全不检查 `win_rate`、`profit_factor`、`payoff_ratio`、`expectancy`
**应该**：在 `_evaluate_trade_profile` 中按策略类型加入命中率/盈亏比联合检查（见 2.3）

### 1.2 回测引擎不输出关键指标

**当前**：回测结果中**没有** `profit_factor`、`avg_win`、`avg_loss`、`payoff_ratio`、`expectancy` 这些字段。SQLite schema 里有这些列但回测引擎从未写入。
**应该**：在 `_finalize_backtest_payload` 中，从 `round_trip_positions` 计算并写回这些字段。

### 1.3 使用真实基本面因子（而非价格近似）

**当前**：`ValueFactorStrategy` 用价格反转近似价值因子；`QualityFactorStrategy`、`GrowthFactorStrategy` 同样是价格动量变体
**应该**：用 `financials` 表中的 PE/PB/ROE/营收增速（数据库已有 112,546 条但未被使用）

### 1.4 多股票组合验证（而非单股票）

**当前**：每个策略只在 1 只股票上回测，统计意义不足（< 50 笔交易）
**应该**：在 ≥ 10 只同行业/同因子暴露的股票上验证，取中位数表现

### 1.5 Walk-Forward 验证（而非全样本回测）

**当前**：用 5 年全部数据做回测（in-sample），存在严重过拟合风险
**应该**：
- 训练期：前 60% 数据 → 优化参数
- 验证期：中间 20% 数据 → 选择最优参数
- 测试期：最后 20% 数据 → 完全样本外评估
- Walk-Forward 效率（样本外 Sharpe / 样本内 Sharpe）≥ 50%

### 1.6 交易成本真实化（A 股特殊规则）

**当前**：`backtest/engine.py` 默认 commission=0.0003，未默认开启 T+1 / 印花税 / 涨跌停过滤
**应该**：策略工厂下发到回测时强制传入 `market_ruleset="cn_equity"`，触发：
- 佣金：万 2.5（双边）
- 印花税：千 1（卖出）
- 滑点：至少 2-5 bps（`implementation_shortfall_proxy`）
- T+1：当日买入次日才能卖出
- 最小交易单位：100 股
- 涨跌停过滤（10% / 20%）

### 2.3 PR-A3：命中率/盈亏比/期望值门禁（P0）

**位置**：`packages/strategy-factory/src/strategy_factory/application/submission_gate/runner_parts/multiple_testing.py::_evaluate_trade_profile`。

**现状**：
- `_evaluate_trade_profile` 检查 `post_cost_sharpe`、`total_return`、`max_drawdown`、`trade_count`、`event_window_hit_ratio`、`trade_density`、`parameter_perturbation_trade_stability`，**但不检查 `win_rate` 和 `profit_factor`**。
- `elimination.py` 有事后红旗检查 `win_rate < 0.30`，但这是**已提交策略的淘汰机制**，不是提交前门禁。
- `_trade_gate_thresholds` 中没有 `win_rate_min` 或 `profit_factor_min` 字段。

**改动**（在 `_evaluate_trade_profile` 的 `reasons` / `warnings` 检查块中新增）：

```python
strategy_type = str(strategy.get("strategy_type") or "").lower()
win_rate = safe_metric_value(metrics, "win_rate")
profit_factor = safe_metric_value(metrics, "profit_factor")
expectancy = safe_metric_value(metrics, "expectancy")
breakeven_wr = safe_metric_value(metrics, "breakeven_win_rate")

# 按策略类型设置阈值
if strategy_type in {"momentum", "ma_cross", "volatility_breakout", "breakout"}:
    min_wr, min_pf = 0.40, 1.8   # 趋势：低胜率高盈亏比
elif strategy_type in {"rsi", "mean_reversion", "mean_reversion_short", "gap_fill"}:
    min_wr, min_pf = 0.55, 1.5   # 均值回归：高胜率
elif strategy_type in {"multi_factor", "value_factor", "quality_factor", "growth_factor"}:
    min_wr, min_pf = 0.50, 1.5   # 多因子：月度胜率
else:
    min_wr, min_pf = 0.45, 1.5   # 兜底

if win_rate < min_wr:
    reasons.append(f"win_rate {win_rate:.3f} < {min_wr:.3f}")
if profit_factor < min_pf:
    reasons.append(f"profit_factor {profit_factor:.3f} < {min_pf:.3f}")
if expectancy <= 0:
    reasons.append(f"expectancy {expectancy:.4f} <= 0")
if breakeven_wr > 0 and (win_rate - breakeven_wr) < 0.05:
    warnings.append(f"win_rate_margin_over_breakeven {win_rate - breakeven_wr:.3f} < 0.05")
```

### 2.4 PR-B1：真实基本面多因子策略（P1）

**位置**：新建 `packages/akshare-mcp/src/akshare_mcp/services/backtest/fundamental_factor_strategy.py`，并在 `strategy_registry` 中注册为 `multi_factor_v2`。

**关键点**：信号生成时**从数据库异步取本股票最近一期 financials**，不再用价格近似。下发到回测前由 strategy-factory 注入 `fundamentals_snapshot` 到 `params`。

```python
class FundamentalMultiFactorStrategy(IStrategy):
    """真正的多因子策略 — 使用 financials 表中的 PE/PB/ROE/营收增速。"""

    def __init__(self):
        self._weights = {"value": 0.25, "quality": 0.30, "growth": 0.25, "momentum": 0.20}
        self._buy_threshold = 0.60
        self._sell_threshold = 0.30

    def set_parameters(self, params):
        self._fundamentals = dict(params.get("fundamentals_snapshot") or {})
        # ...

    def generate_signals(self, closes, volumes=None):
        f = self._fundamentals
        # 价值：PE 在 [0, 20]、PB 在 [0, 3]
        pe, pb = float(f.get("pe_ttm") or 0), float(f.get("pb_mrq") or 0)
        value = (0.5 if 0 < pe < 20 else 0.0) + (0.5 if 0 < pb < 3 else 0.0)
        # 质量：ROE_TTM > 10%
        roe = float(f.get("roe_ttm") or 0)
        quality = min(1.0, max(0.0, (roe - 0.10) / 0.10))
        # 成长：营收同比 > 10%
        rev_g = float(f.get("revenue_growth") or 0)
        growth = min(1.0, max(0.0, (rev_g - 0.10) / 0.20))
        # 动量：技术确认（20 日斜率为正）
        momentum = self._momentum_score(closes)
        composite = (self._weights["value"] * value + self._weights["quality"] * quality
                     + self._weights["growth"] * growth + self._weights["momentum"] * momentum)
        # composite > buy_threshold AND momentum > 0 → 买入；composite < sell_threshold → 卖出
        # ...
```

**Spawner 集成**：`runner.py` 在生成候选时，调用 `db.fetchrow_financials(target_code)` 取最近一期 PE/PB/ROE/revenue_growth，注入到 `params["fundamentals_snapshot"]`。

### 2.5 PR-B2：Walk-Forward 验证框架（P1）

**位置**：新建 `packages/strategy-factory/src/strategy_factory/application/research/walk_forward.py`，由 `_evaluate_reports` 在 Gate-3 之前调用。

```python
class WalkForwardValidator:
    """5-fold rolling Walk-Forward。"""

    def validate(self, code, klines, strategy_type, params,
                 *, train_ratio=0.6, val_ratio=0.2, n_windows=5):
        from akshare_mcp.services.backtest.engine import backtest_engine as eng
        n = len(klines)
        if n < 252:  # 至少 1 年
            return {"passed": False, "reason": "insufficient_klines"}
        win = n // n_windows
        in_sample, out_sample = [], []
        for i in range(n_windows):
            s = i * win
            train_end = s + int(win * train_ratio)
            val_end = train_end + int(win * val_ratio)
            test_end = min(s + win, n)
            train = klines[s:train_end]
            test = klines[val_end:test_end]
            r_in = eng.run_backtest(code, train, strategy_type, params)
            r_out = eng.run_backtest(code, test, strategy_type, params)
            in_sample.append(r_in["data"])
            out_sample.append(r_out["data"])
        in_sharpe = float(np.mean([r["sharpe_ratio"] for r in in_sample]))
        out_sharpe = float(np.mean([r["sharpe_ratio"] for r in out_sample]))
        out_wr = float(np.mean([r["win_rate"] for r in out_sample]))
        out_pf = float(np.mean([r.get("profit_factor", 0.0) for r in out_sample]))
        wfe = out_sharpe / max(in_sharpe, 0.01)
        return {
            "walk_forward_efficiency": round(wfe, 4),
            "out_of_sample_sharpe": round(out_sharpe, 4),
            "out_of_sample_win_rate": round(out_wr, 4),
            "out_of_sample_profit_factor": round(out_pf, 4),
            "passed": wfe >= 0.5 and out_sharpe >= 0.5 and out_pf >= 1.5,
        }
```

由 Gate-3 在 `_evaluate_trade_profile` 通过后追加调用，写入 `metrics["walk_forward_*"]` 字段，未通过则 `passed=False`。

### 2.6 PR-B3：多股票泛化验证（P2）

**位置**：新建 `packages/strategy-factory/src/strategy_factory/application/research/generalization.py`。

逻辑：
1. 通过 `vector_profiles` 找目标股票的 top-10 同行业 + 同因子暴露的近邻
2. 对每只 peer 跑同参数回测
3. 要求：
   - ≥ 60% 的 peer 上 Sharpe > 0
   - peer 中位数 win_rate ≥ max(0.45, breakeven_wr)
   - peer 中位数 profit_factor ≥ 1.3

```python
async def validate_generalization(candidate, db, *, peer_count=10):
    target = candidate["target_symbols"][0]
    peers = await db.find_peer_stocks_by_vector(target, limit=peer_count)
    results = []
    for pc in peers:
        klines = await db.get_klines(pc, limit=750)
        if len(klines) < 252:
            continue
        r = backtest_engine.run_backtest(pc, klines,
            candidate["strategy_type"], candidate["params"])
        if r.get("success"):
            results.append(r["data"])
    if len(results) < 5:
        return {"passed": False, "reason": "insufficient_peers"}
    sharpes = [r["sharpe_ratio"] for r in results]
    wrs = sorted(r["win_rate"] for r in results)
    pfs = sorted(r.get("profit_factor", 0.0) for r in results)
    pos_sharpe_rate = sum(1 for s in sharpes if s > 0) / len(sharpes)
    median_wr = wrs[len(wrs) // 2]
    median_pf = pfs[len(pfs) // 2]
    return {
        "passed": pos_sharpe_rate >= 0.6 and median_wr >= 0.45 and median_pf >= 1.3,
        "peer_count": len(results),
        "positive_sharpe_ratio": round(pos_sharpe_rate, 4),
        "median_win_rate": round(median_wr, 4),
        "median_profit_factor": round(median_pf, 4),
    }
```

## 4. 现实预期与最终验收标准

### 4.1 为什么"50% 命中率"不是真正的目标

经过深度调研后修正认知：

- 实证研究显示，**单纯追求命中率会害死策略**：65% 散户命中率 > 50%，但 82% 仍亏损
- 真正决定盈亏的是 **期望值 = 命中率 × 平均盈利 - (1 - 命中率) × 平均亏损**
- 一个 40% 命中率 + 3:1 盈亏比的趋势策略（利润因子 ≈ 2.0），优于 60% 命中率 + 0.8:1 盈亏比的策略（利润因子 ≈ 1.2）

### 4.2 不同策略类型的命中率预期

| 策略类型 | 回测命中率 | 实盘预期命中率 | 衰减原因 |
|---|---|---|---|
| 趋势跟踪 | 35-45% | 30-40% | 滑点、假突破 |
| 均值回归 | 55-65% | 50-58% | 流动性、涨跌停 |
| 多因子选股（月度） | 50-60% | 45-55% | 因子衰减、拥挤 |

来源：综合 [HorizonTrading](https://horizontrading.ai/learn/backtesting-metrics-explained)、[QuantifiedStrategies](https://www.quantifiedstrategies.com/rsi-trading-strategy/)、[MarketClutch](https://marketclutch.com/real-world-performance-the-truth-behind-algorithmic-trading-results/)（实盘相对回测的衰减幅度通常在 20-50%）

### 4.3 最终验收标准（替代单一"50% 命中率"目标）

策略上实盘前必须**全部满足**：

| 条件 | 阈值 | 来源说明 |
|---|---|---|
| 期望值（Expectancy） | > 0，且 > 2× 单笔交易成本 | [HorizonTrading](https://horizontrading.ai/learn/backtesting-metrics-explained) |
| 利润因子（Profit Factor） | ≥ 1.5（理想 ≥ 2.0） | 行业惯例最低门槛 |
| 命中率超过保本线幅度 | win_rate − 1/(1+payoff) ≥ 5% | 期望值正向安全垫 |
| 样本外 Walk-Forward 效率 | ≥ 50% | [TradingStrategy.ai](https://tradingstrategy.ai/glossary/walk-forward-analysis) |
| 样本外 Sharpe | ≥ 0.5 | 回测到实盘通常衰减 30-50% |
| 样本外最大回撤 | ≤ 25% | 散户心理可承受上限 |
| 交易次数（样本外） | ≥ 30 | 统计显著性 |
| 多股票泛化通过率 | ≥ 60% 的同类股票 Sharpe > 0 | 排除单一股票过拟合 |
| 模拟盘验证 | ≥ 30 天，实际命中率 ≥ 回测的 80% | 实盘前最后一关 |

> 已为符合许可改写关键引述。

## 6. AI 生成准确率保障

### 6.0 为什么 AI 准确率必须独立成章

当前策略工厂 5 阶段 Pipeline（`event_recognition → theme_propagation → exposure_mapping → market_confirmation → strategy_generation`）的 LLM 调用，**完全没有用到本地数据库与向量索引做 grounding**——尽管基础设施早已就绪。这导致：

- LLM 凭训练记忆生成股票代码，可能输出已退市/ST 股
- LLM 引用"PE 低、ROE 高"等论据时无法核验
- 5 个 prompt 全部用 600519、000858 等大盘股做示例，强化了"大盘股偏好"幻觉
- 训练数据可能跨过 backtest 期，等于"提前看了答案"（look-ahead bias）

行业研究普遍认为（[ML4T 第 22 章](https://www.ml4trading.io/third-edition/chapters/22_rag_financial_research/)、[CFA Institute](https://rpc.cfainstitute.org/research/the-automation-ahead-content-series/retrieval-augmented-generation)、[arXiv 2506.06622 QuantMCP](https://arxiv.org/html/2506.06622v1)）：

> 金融场景中未经 grounding 的 LLM 不可接受，必须把生成限制在"可验证的证据"上，而不是依赖事后的事实核查。
>
> 来源说明：原文已为符合内容许可改写。

```python
async def get_stock_whitelist(db) -> set[str]:
    """启动时缓存全 A 股代码白名单。"""
    rows = await db.fetch("SELECT code FROM stocks WHERE list_status='L'")
    return {str(r["code"]).strip() for r in rows if r.get("code")}


def filter_unknown_symbols(candidates, whitelist):
    """剔除 target_symbols 中不在白名单的代码；全空则丢弃整个候选。"""
    kept, dropped = [], []
    for c in candidates:
        syms = [str(s).strip() for s in (c.get("target_symbols") or [])]
        valid = [s for s in syms if s in whitelist]
        if valid:
            c["target_symbols"] = valid
            kept.append(c)
        else:
            dropped.append(c.get("name") or "unknown")
    return kept, dropped
```

### 6.8 PR-AI5：历史策略相似度检索（关卡 3 RAG，P2）

**位置**：`strategy_pipeline.py::run_stage("strategy_generation", ...)`

**现状**：项目已有 `CandidateDedupDecision` 去重机制（在 DEDUP 阶段，gate_2 和 gate_3 之间），基于 `similarity_score` 判断重复。但这个去重是**候选之间的互相去重**，不是"与历史已失败策略的去重"。219 条 `strategy_artifact_text_embeddings` 仍然闲置。

**改动**：在 DEDUP 阶段增加"与历史失败策略的相似度检查"——如果新候选与已被 Gate-3 拒绝的历史策略相似度 > 0.85，直接标记为 `novel=False` 并跳过：

```python
async def check_strategy_novelty(db, candidate, embedding_service):
    """检索历史相似策略，避免重复无效策略。"""
    text = f"{candidate.get('name')} {candidate.get('strategy_type')} {' '.join(candidate.get('target_symbols', []))}"
    query_embedding = await embedding_service.embed(text)
    result = await db.search_vector_collection(
        collection_name="strategy_artifact_text_embeddings",
        query_embedding=query_embedding,
        top_k=3,
    )
    similar = [item for item in (result.get("items") or []) if item.get("similarity", 0) > 0.85]
    if similar:
        # 检查这些相似策略的历史表现
        for s in similar:
            meta = json.loads(s.get("metadata") or "{}")
            if meta.get("validation_grade") == "D" or meta.get("status") == "rejected":
                return {"novel": False, "reason": f"与已拒绝策略 {s.get('entity_id')} 相似度 {s['similarity']:.2f}"}
    return {"novel": True, "similar_count": len(similar)}
```

**效果**：避免 LLM 反复生成同类失败策略，提高 Gate-3 通过率。

### 6.9 PR-AI6：数值断言核验（关卡 6，P1）

**位置**：新建 `packages/strategy-factory/src/strategy_factory/application/research/evidence_verifier.py`

**问题**：LLM 在 `evidence_chain` 中可能声称"贵州茅台 PE = 25"，但 `financials` 表实际 PE = 30。当前无核验。

**改动**：在 Gate-3 之前对 `evidence_chain.evidences` 中的数值断言做数据库核验：

```python
async def verify_evidence_claims(candidate, db):
    """核验 evidence_chain 中的数值断言是否与数据库一致。"""
    evidence_chain = candidate.get("evidence_chain") or {}
    evidences = evidence_chain.get("evidences") or []
    verified, failed = 0, 0
    for ev in evidences:
        source_type = str(ev.get("source_type") or "").lower()
        if source_type not in ("fundamental", "financial", "factor"):
            continue
        code = str(ev.get("stock_code") or ev.get("symbol") or "").strip()
        if not code:
            continue
        # 从 financials 表取最近一期
        row = await db.fetchrow(
            "SELECT pe_ttm, pb_mrq, roe_ttm, revenue_yoy FROM financials "
            "WHERE ts_code LIKE $1 ORDER BY end_date DESC LIMIT 1",
            f"%{code}%",
        )
        if not row:
            continue
        # 核验 LLM 声称的方向是否与真实数据一致
        claimed_direction = str(ev.get("direction") or "").lower()
        pe = float(row.get("pe_ttm") or 0)
        roe = float(row.get("roe_ttm") or 0)
        if claimed_direction == "bullish":
            # 看涨论据：PE 应合理（< 50）且 ROE 应正
            if pe > 80 or roe < 0:
                failed += 1
                ev["_verification"] = "FAILED: bullish claim but PE>80 or ROE<0"
                continue
        verified += 1
        ev["_verification"] = "PASSED"
    return {
        "total_evidences": len(evidences),
        "verified": verified,
        "failed": failed,
        "verification_rate": verified / max(len(evidences), 1),
        "passed": failed == 0,
    }
```

**集成点**：在 `_evaluate_trade_profile` 之前调用，`failed > 0` 时加入 `reasons`。

### 6.10 PR-AI7：AI 生成准确率 KPI 看板（关卡 7，P2）

**位置**：新建 `packages/strategy-factory/src/strategy_factory/application/research/ai_accuracy_kpi.py`

**问题**：当前不知道 LLM 生成的策略中有多少通过了 Gate-3，无法衡量 AI 准确率。

**改动**：在每个 cycle 结束后统计并写入 `strategy_generation_experiments` 表：

```python
async def compute_ai_accuracy_kpi(db, cycle_result):
    """计算本轮 AI 生成准确率 KPI。"""
    autonomy_candidates = cycle_result.get("autonomy_candidates") or []
    total_ai = len(autonomy_candidates)
    if total_ai == 0:
        return {"ai_candidate_count": 0}

    passed_gate3 = sum(1 for c in autonomy_candidates if c.get("gate3_passed"))
    passed_backtest = sum(1 for c in autonomy_candidates if c.get("backtest_win_rate", 0) > 0)
    evidence_complete = sum(1 for c in autonomy_candidates
                           if (c.get("evidence_chain") or {}).get("evidences"))
    symbol_valid = sum(1 for c in autonomy_candidates
                       if all(s in stock_whitelist for s in (c.get("target_symbols") or [])))

    kpi = {
        "ai_candidate_count": total_ai,
        "gate3_pass_rate": round(passed_gate3 / total_ai, 4),
        "backtest_positive_rate": round(passed_backtest / total_ai, 4),
        "evidence_completeness_rate": round(evidence_complete / total_ai, 4),
        "symbol_validity_rate": round(symbol_valid / total_ai, 4),
        "overall_ai_accuracy": round(
            (passed_gate3 + evidence_complete + symbol_valid) / (total_ai * 3), 4
        ),
    }
    await db.save_ai_accuracy_kpi(kpi)
    return kpi
```

**KPI 目标**：

| 指标 | 当前预估 | 目标（3 个月内） |
|---|---|---|
| Gate-3 通过率 | ~20%（14/39 submitted 中大部分 D 级） | ≥ 50% |
| 证据链完整率 | ~5%（几乎全空） | ≥ 80% |
| 股票代码有效率 | ~90%（偶有无效） | 100% |
| 数值断言核验通过率 | 未知 | ≥ 90% |
| 综合 AI 准确率 | ~30% | ≥ 70% |

## 附录 A. 命中率口径在策略工厂中的精确定义

为避免歧义，本方案对"命中率"的口径做明确约定：

| 口径 | 定义 | 用在哪里 |
|---|---|---|
| **trade_win_rate**（交易级胜率） | 已平仓 round_trip 中盈利笔数 ÷ 总平仓笔数 | 单股票回测、PR-A3 门禁 |
| **bar_win_rate**（持仓日胜率） | 持仓期间正收益日数 ÷ 持仓总日数 | 不直接做门禁，仅记录 |
| **monthly_hit_rate**（月度命中率） | 月度收益为正的月份数 ÷ 总月份数 | 多因子选股专用 |
| **peer_median_win_rate**（横截面命中率） | 同类股票池中 trade_win_rate 的中位数 | PR-B3 泛化门禁 |
| **out_of_sample_win_rate**（样本外胜率） | Walk-Forward 测试期上的 trade_win_rate 均值 | PR-B2 验收 |

策略工厂当前（PR-A1 之前）只输出 `win_rate` 一个口径，等价于 `trade_win_rate`。PR-A1 落地后字段保持不变，仅补齐 `profit_factor` / `expectancy` / `payoff_ratio` / `breakeven_win_rate`。
