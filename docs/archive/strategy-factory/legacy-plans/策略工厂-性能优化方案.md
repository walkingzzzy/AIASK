## 方案 A：事件驱动任务接入主流程

### 问题

事件已注入（`strategy_factory_event_injections` 有 1 条 active 事件），主题传播算法验证通过（5 个主题受影响），但 `run_once` 中 `manual_event_task_count=0`。

### 根因

`opportunity.py` 调用 `generate_tasks_from_active_events(db)` 时，`db` 是 `MCPStrategyFactoryRepositoryAdapter` 实例，它没有代理以下方法：
- `list_event_injections`
- `list_theme_edges`
- `get_theme_node`
- `list_theme_exposure`

这些方法在 `strategy_ai_parts/queries.py` 中已实现，但 adapter 没有转发。

### 修复

在 `packages/strategy-factory/src/strategy_factory/infrastructure/mcp_adapters.py` 的 `MCPStrategyFactoryRepositoryAdapter` 类中新增：

```python
async def list_event_injections(self, status=None, source=None, limit=50):
    return await self._call("list_event_injections", status=status, source=source, limit=limit)

async def list_theme_edges(self, source=None, target=None, is_active=True, limit=50):
    return await self._call("list_theme_edges", source=source, target=target, is_active=is_active, limit=limit)

async def get_theme_node(self, theme_code):
    return await self._call("get_theme_node", theme_code)

async def list_theme_exposure(self, theme_code=None, min_exposure=0.3, limit=30):
    return await self._call("list_theme_exposure", theme_code=theme_code, min_exposure=min_exposure, limit=limit)

async def upsert_event_task_lineage(self, payload):
    return await self._call("upsert_event_task_lineage", payload)
```

同时需要在 `akshare_mcp/storage/sqlite/` 的 DB 类中确保这些方法存在（已在 `strategy_ai_parts/queries.py` 末尾实现）。

### 预期效果

- 每个 active 事件产出 5 个传播任务
- 每个任务通过 LLM 生成 3-4 个候选
- 单个事件增加 15-20 个高质量候选
- 这些候选有明确的方向（bullish/bearish）和目标股票池，Gate-2 通过率预期 > 30%

### 工时

15 分钟

## 方案 B：factor_research 冷启动优化

### 问题

`FactorResearchBuilder.build()` 耗时 5-13s，其中：
- `_load_budget_feedback`：3.3s（遍历 incubating 策略做反馈计算）
- `_load_stock_family_allocation`：2.0s（调用 quant_manager 做股票-家族分配）

当前 incubating 策略数 = 0，这两个步骤在做无意义的计算。

### 根因

这两个方法是为"成熟期"设计的：
- `budget_feedback`：当有 50+ 个 incubating 策略时，需要根据它们的表现调节生成预算
- `stock_family_allocation`：当有多个策略家族时，需要平衡各家族的股票分配

在冷启动期（0 个 incubating 策略），它们仍然执行完整的初始化流程（DB 查询、quant_manager 调用、默认值构建），浪费 5+ 秒。

### 修复

在 `FactorResearchBuilder.build()` 中增加冷启动快速路径：

```python
@classmethod
async def build(cls, db, snapshot: dict[str, Any]) -> dict[str, Any]:
    # ... existing code ...
    
    # 冷启动优化：incubating 策略数 = 0 时跳过重量级计算
    incubating_count = int(snapshot.get("incubating_count") or 0)
    
    if incubating_count == 0:
        budget_feedback = {
            "strategy_count": 0,
            "zero_signal_strategy_count": 0,
            "zero_signal_ratio": 0.0,
            "forward_window_coverage_ratio": 1.0,
            "promotion_ready_count": 0,
            "promotion_ready_ratio": 1.0,
            "evidence_debt_ratio": 0.0,
            "_cold_start_skip": True,
        }
    else:
        budget_feedback = await cls._load_budget_feedback(db, snapshot)
    
    if incubating_count == 0 and not governed_top_candidates:
        stock_allocation = {
            "allocation": {},
            "entropy": 0.0,
            "source_mode": "cold_start_skip",
            "_cold_start_skip": True,
        }
    else:
        stock_allocation = await cls._load_stock_family_allocation(...)
```

### 预期效果

- factor_research 阶段从 5-13s 降到 < 1s
- 单轮总耗时从 37-46s 降到 32-40s（节省 5s）
- 当 incubating 策略积累到 > 0 时，自动恢复完整计算

### 工时

30 分钟

## 方案 C：Spawner 参数自适应

### 问题

本地规则 Spawner 产出 11 个候选，Gate-2 通过率 0%。

### 根因

Spawner 使用**硬编码参数模板**：
```python
# 当前：固定参数
{"strategy_type": "ma_cross", "params": {"short_period": 5, "long_period": 20}}
{"strategy_type": "momentum", "params": {"lookback": 20, "hold_days": 5}}
{"strategy_type": "rsi", "params": {"period": 14, "oversold": 30, "overbought": 70}}
```

这些"通用默认值"在任何特定市场环境下大概率不是最优的。5 年 K 线回测中，MA(5,20) 的 Sharpe 可能只有 0.1-0.2，达不到 Gate-2 的 0.30 阈值。

### 修复方向

**从因子库和历史回测中学习最优参数范围**：

```python
class AdaptiveParameterRegistry:
    """根据因子 IC 和历史回测结果动态调整参数范围。"""
    
    @classmethod
    async def get_optimal_params(cls, db, strategy_type: str, snapshot: dict) -> list[dict]:
        """返回当前市场环境下最可能通过 Gate-2 的参数组合。"""
        
        if strategy_type == "ma_cross":
            # 从 factor_ic_history 找当前最有效的动量窗口
            # momentum IC 在 60d 窗口最高 → 用 MA(20, 60) 而非 MA(5, 20)
            best_window = await cls._find_best_momentum_window(db)
            return [
                {"short_period": best_window // 3, "long_period": best_window},
                {"short_period": best_window // 4, "long_period": best_window},
            ]
        
        if strategy_type == "momentum":
            # 从 factor_values 找当前 IC 最高的 lookback
            # factor_memory_seed_mom_60d IC=0.15 > mom_10d IC=0.14
            return [
                {"lookback": 60, "hold_days": 10},
                {"lookback": 20, "hold_days": 5},
            ]
        
        # ... 其他策略类型
    
    @classmethod
    async def _find_best_momentum_window(cls, db) -> int:
        """从因子 IC 历史找当前最有效的动量窗口。"""
        windows = {"mom_1d": 1, "mom_5d": 5, "mom_10d": 10, "mom_60d": 60}
        best_ic = -999
        best_window = 20
        for seed_name, window in windows.items():
            rows = await db.get_factor_ic_history(
                f"factor_candidate:factor_memory_seed_{seed_name}", "20", 10
            )
            if rows:
                avg_ic = sum(r.get("ic_value", 0) for r in rows) / len(rows)
                if avg_ic > best_ic:
                    best_ic = avg_ic
                    best_window = window
        return best_window
```
