- 过时/夸大描述：文档若只说“不返回分配理由”需要补充限定：当前 plans 已返回很多机器可读解释字段，但没有面向人工审计的 `allocation_reason` 文案。
- 仍然成立的问题：核心权重硬编码；探索性替换从 observe 尾部反向找非探索候选，不按最低质量/最低分精确替换；缺人类可读分配理由。
- 建议优先级：P0 标明机器可读反馈已丰富；P1 权重 profile 化；P2 替换策略按质量损失最小化；P3 `allocation_reason`。下方优化建议中的代码块为概念示例。

## 职责

孵化预算分配器决定哪些候选获得正式孵化槽位、哪些进入观察队列、哪些被延迟。它是策略工厂与孵化工厂之间的"桥梁"——通过读取孵化反馈来调整分配策略。

@classmethod
def plan(cls, candidates, snapshot):
    formal_slots = FACTORY_INCUBATION_FORMAL_SLOT_COUNT  # 12
    observe_slots = FACTORY_INCUBATION_OBSERVE_SLOT_COUNT  # 24
    total_budget = formal_slots + observe_slots  # 36

    # 1. 加载反馈根
    budget_feedback_root = cls._resolve_budget_feedback_root(snapshot)

    # 2. 对每个候选计算优先级分数
    entries = []
    for candidate in candidates:
        score = cls._priority_score(candidate, snapshot, budget_feedback_root=budget_feedback_root)
        feedback = cls._candidate_feedback(candidate, snapshot, budget_feedback_root=budget_feedback_root)
        entries.append({"candidate": candidate, "priority_score": score, "feedback": feedback, ...})

    # 3. 按分数排序
    sorted_entries = sorted(entries, key=lambda x: -x["priority_score"])

    selectable = [e for e in sorted_entries if e["feedback_control_mode"] == "normal"]

## 优先级评分（`_priority_score`）

```python
@classmethod
def _priority_score(cls, candidate, snapshot, *, budget_feedback_root=None):
    score = 0.0

    # ── 基础指标 ──
    score += max(-1.0, min(sharpe, 3.0)) * 10.0        # Sharpe
    score += max(-0.2, min(total_return, 0.6)) * 3.0   # 总收益
    score -= min(max_drawdown, 0.6) * 8.0              # 回撤惩罚
    score += min(max(validation_score, 0), 100) * 0.25 # 验证分数
    score += max(task_priority, 0) * 0.18              # 任务优先级
    score += max(stock_family_priority, 0) * 12.0      # 股票家族优先级

    # ── 市场环境匹配 ──
    score += cls._regime_match_bonus(candidate, snapshot)  # 5-6 分

    # ── 注册阶段加分 ──
    if registry_stage == "champion": score += 5.0
    elif registry_stage == "challenger": score += 4.0
    elif registry_stage == "governed": score += 3.0

    # ── 风险等级 ──
    if risk_level == "low": score += 3.0
    elif risk_level == "high": score -= 4.0

    # ── 活跃 family 加分 ──
    if family_name in active_family_names: score += 4.0

    # ── ★ 孵化反馈（核心权重）──
    if feedback_available:
        score += paper_skill_lcb * 55.0                    # 技能下界
        score += paper_recent_skill_lcb * 34.0             # 近期技能下界
        score -= max(paper_stability_gap - 0.05, 0) * 40.0 # 稳定性惩罚
        score += (paper_coverage_ratio - 0.50) * 14.0      # 覆盖率奖励
        score += execution_conversion_efficiency * 28.0     # 执行转化效率
        # 预算乘数
        combined_multiplier = feedback_budget_multiplier * 0.35 + skill_budget_multiplier * 0.65
        score *= max(0.68, min(1.35, 0.45 + combined_multiplier * 0.55))
    else:
        score += feedback_priority_adjustment
        score *= max(0.7, min(1.3, 0.7 + feedback_budget_multiplier * 0.3))

    # ── 控制模式惩罚 ──
    if control_mode == "cooldown": score -= 9.0
    elif control_mode == "suppress": score -= 24.0
    elif control_mode == "freeze": score -= 36.0
    if skill_control_mode == "cooldown": score -= 6.0
    elif skill_control_mode == "suppress": score -= 16.0
    elif skill_control_mode == "freeze": score -= 28.0

    # ── P2-D 兼容：family EMA 反馈 ──
    if not feedback_available:
        ema_submit = family_gate_feedback[family]["ema_submit_count"]
        if ema_submit > 3.0: score += 5.0
        elif ema_submit > 1.0: score += 2.5
        elif ema_submit < 0.3: score -= 2.0

    return round(score, 4)
```

## 市场环境匹配奖励

```python
@classmethod
def _regime_match_bonus(cls, candidate, snapshot):
    # 恐惧贪婪指数 → 市场环境
    fg = snapshot.get("fear_greed_index", 50)
    if fg >= 60: market_regime = "trend"
    elif fg <= 40: market_regime = "mean_reversion"
    else: market_regime = "rotation"

    # 候选的 expected_regime 匹配当前环境 → +5~6 分
    if market_regime == "trend" and "trend" in expected_regimes: return 6.0
    if market_regime == "mean_reversion" and "mean_reversion" in expected_regimes: return 6.0
    if market_regime == "rotation" and "rotation" in expected_regimes: return 5.0
    return 0.0
```

## 反馈来源（`_resolve_budget_feedback_root`）

```python
@staticmethod
def _resolve_budget_feedback_root(snapshot):
    factor_research = snapshot.get("factor_research") or {}
    # 优先级：
    # 1. factor_research.lifecycle_feedback_input（孵化工厂产出）
    # 2. factor_research.budget_feedback
    # 3. snapshot.family_gate_feedback（调度器 EMA）
    for payload in (
        factor_research.get("lifecycle_feedback_input"),
        factor_research.get("budget_feedback"),
        snapshot.get("family_gate_feedback"),
    ):
        if isinstance(payload, dict):
            feedback_root = normalize_feedback_input_contract(payload).get("feedback")
            if feedback_root:
                return feedback_root
    return {}
```

# 非主导 family 的候选被视为"探索性候选"
def _is_exploration_candidate(cls, candidate, *, dominant_families, active_family_names):
    family = cls._candidate_family(candidate)
    if family not in dominant_families: return True
    if family not in active_family_names: return True
    if registry_stage not in {"champion", "challenger", "governed"}: return True
    return False

## 已识别的优化方向

---

### 优化 1：优先级评分权重硬编码（🔴 高优先级）

**现状问题**：`_priority_score` 中的权重（Sharpe×10, total_return×3, max_drawdown×8, paper_skill_lcb×55 等）全部硬编码。无法根据不同市场环境或策略阶段动态调整。

**建议方案**：将权重提取为可配置的 profile，支持按市场环境切换：

```python
PRIORITY_WEIGHT_PROFILES = {
    "trend_market": {"sharpe": 12.0, "total_return": 5.0, "max_drawdown": 6.0},
    "volatile_market": {"sharpe": 8.0, "total_return": 2.0, "max_drawdown": 12.0},
    "default": {"sharpe": 10.0, "total_return": 3.0, "max_drawdown": 8.0},
}
```

**影响**：不同市场环境下自动调整分配偏好，提高资源利用效率。

---

### 优化 2：探索性候选替换逻辑过于简单（🟡 中优先级）

**现状问题**：探索性候选替换仅从观察槽位末尾移除主导 family 候选。不考虑被替换候选的质量——可能替换掉高质量候选。

**建议方案**：替换时优先移除分数最低的主导 family 候选。

**影响**：在保持多样性的同时最小化质量损失。

---

### 优化 3：plan() 方法不返回分配理由（🟢 低优先级）

**现状问题**：`plan()` 返回的 plans 字典包含大量反馈指标，但不包含人类可读的分配理由（为什么某个候选被分配到 formal vs observe vs deferred）。

**建议方案**：为每个分配决策添加 `allocation_reason` 字段。

**影响**：提高分配决策的可解释性，便于调试和审计。

---

### 优化总结

| # | 改进项 | 影响 | 实现难度 | 优先级 |
|---|---|---|---|---|
| 1 | 权重可配置化 | 环境自适应分配 | 中 | 🔴 高 |
| 2 | 智能探索替换 | 最小化质量损失 | 低 | 🟡 中 |
| 3 | 分配理由记录 | 提高可解释性 | 低 | 🟢 低 |
