- 准确性状态：基本准确。

- 过时/夸大描述：冷启动优化不是待做项，当前代码已实现；反馈体系比早期文档更丰富，包含 target pool、generator mode、skill control 等维度。

### 优化 1：因子 IC 历史加载串行化（🔴 高优先级）

**现状问题**：`load_factor_history_meta()` 对每个因子名称逐一串行调用 `db.get_factor_ic_history()`。当活跃因子数量为 6-19 个时，串行 IO 累积延迟显著。

```python
# 当前代码（串行）
for factor_name in unique_factor_names:
    rows = await _call_optional_async(db, "get_factor_ic_history", factor_name, ...)
```

**建议方案**：并发加载所有因子历史：

```python
import asyncio

async def load_factor_history_meta(builder_cls, db, factor_names):
    unique_factor_names = list(dict.fromkeys([...]))

    async def _load_one(factor_name: str):
        rows = await _call_optional_async(db, "get_factor_ic_history", factor_name, "20", builder_cls.HISTORY_LIMIT, default=[])
        return factor_name, builder_cls._history_summary(rows or [])

    results = await asyncio.gather(*[_load_one(name) for name in unique_factor_names])

    history_meta = {}
    latest_dates = []
    for factor_name, meta in results:
        if meta.get("history_count"):
            history_meta[factor_name] = meta
        latest_date = builder_cls._parse_date(meta.get("latest_ic_date"))
        if latest_date is not None:
            latest_dates.append(latest_date)
    return history_meta, max(latest_dates) if latest_dates else None
```

**影响**：因子历史加载从 O(n) 串行降为 O(1) 并发，典型场景节省 3-8s。

### 优化 2：孵化反馈加载串行化（🔴 高优先级）

**现状问题**：`load_budget_feedback()` 对每个 incubating/listed 策略逐一串行加载 5 种数据（incubation_metric、risk_events、alerts、evidence_overview、promotion_review）。当有 50+ 策略时，串行 IO 可能耗时 10-30s。

**建议方案**：

```python
async def load_budget_feedback(builder_cls, db, snapshot):
    strategy_rows = await builder_cls._list_feedback_source_strategies(db)

    # 并发加载所有策略的反馈数据
    sem = asyncio.Semaphore(10)  # 限制并发度避免 DB 过载

    async def _load_strategy_feedback(strategy):
        async with sem:
            strategy_id = str(strategy.get("id") or "").strip()
            # 5 个 IO 操作并发
            metric_task = _call_optional_async(db, "list_strategy_incubation_metrics", strategy_id, limit=1, default=[])
            risk_task = _call_optional_async(db, "list_strategy_runtime_risk_events", strategy_id=strategy_id, status="open", limit=20, default=[])
            alert_task = _call_optional_async(db, "list_strategy_runtime_alerts", strategy_id=strategy_id, status="open_or_ack", limit=20, default=[])
            evidence_task = builder_cls._load_feedback_evidence_overview(db, strategy)
            review_task = _call_optional_async(db, "get_latest_strategy_promotion_review", strategy_id, default=None)

            metrics, risks, alerts, evidence, review = await asyncio.gather(
                metric_task, risk_task, alert_task, evidence_task, review_task
            )
            return strategy, metrics, risks, alerts, evidence, review

    results = await asyncio.gather(*[_load_strategy_feedback(s) for s in strategy_rows])
    # ... 聚合逻辑 ...
```

**影响**：50 个策略的反馈加载从 ~25s 降为 ~3-5s（10 并发 × 5 个 IO 并发）。

### 优化 3：因子 IC 过期判定过于简单（🟡 中优先级）

**现状问题**：`STALE_AFTER_DAYS = 2`，超过 2 天即视为过期。但不同因子的衰减速度差异很大：
- 动量因子（momentum）衰减快，2 天合理
- 价值因子（value）衰减慢，可能 5-7 天仍有效
- 周末/节假日不应计入过期天数

**建议方案**：按因子类型设置差异化过期阈值：

```python
FACTOR_STALE_DAYS_BY_TYPE = {
    "momentum": 2,
    "reversal": 2,
    "capital_flow": 2,
    "sentiment": 3,
    "volatility": 3,
    "growth": 5,
    "quality": 5,
    "value": 7,
    "multi_factor": 5,
}
DEFAULT_STALE_DAYS = 2

@classmethod
def _is_factor_stale(cls, factor_name: str, latest_date: date, snapshot_date: date) -> bool:
    # 计算交易日差（排除周末/节假日）
    trading_days_gap = cls._count_trading_days_between(latest_date, snapshot_date)
    stale_threshold = FACTOR_STALE_DAYS_BY_TYPE.get(factor_name, DEFAULT_STALE_DAYS)
    return trading_days_gap > stale_threshold
```

**影响**：避免价值/质量等慢衰减因子被过早标记为 stale，减少不必要的 readiness 阻断。

### 优化 4：搜索路由缺少因子拥挤度检测（🟡 中优先级）

**现状问题**：`resolve_search_route_action` 仅基于孵化反馈质量决定 family 动作（explore/cooldown/freeze/retire），不考虑因子拥挤度。当某个 family 的策略数量过多时，即使质量分数高，也应该降低配额以避免集中风险。

研究表明，因子拥挤是 alpha 衰减的主要驱动因素之一（参考 [arxiv:2512.11913](https://arxiv.org/abs/2512.11913)）。

**建议方案**：

```python
def _resolve_search_route_action(cls, plan, feedback_metrics):
    # 现有质量评估逻辑...
    action = cls._base_route_action(plan, feedback_metrics)

    # 新增：拥挤度检测
    family = plan.get("family")
    incubating_count = feedback_metrics.get("incubating_strategy_count", 0)
    listed_count = feedback_metrics.get("listed_strategy_count", 0)
    total_family_count = incubating_count + listed_count

    # 如果单 family 策略数超过总量的 30%，降级为 cooldown
    total_strategies = feedback_metrics.get("total_strategy_count", 1)
    concentration_ratio = total_family_count / max(total_strategies, 1)

    if concentration_ratio > 0.30 and action == "family_explore":
        action = "family_cooldown"
        plan["cooldown_reason"] = "concentration_risk"
    elif concentration_ratio > 0.45:
        action = "family_freeze"
        plan["freeze_reason"] = "extreme_concentration"

    return action
```

**影响**：防止单一 family 过度集中，降低系统性风险；促进策略多样性。

### 优化 5：stock_family_allocation 缺少时间衰减（🟡 中优先级）

**现状问题**：股票-family 分配基于当前快照的静态属性（行业、市值、换手率），不考虑分配的时效性。同一只股票可能连续多轮被分配给同一 family，导致 Spawner 反复生成相似策略。

**建议方案**：引入分配历史衰减，避免重复分配：

```python
async def _load_stock_family_allocation(cls, db, snapshot, ...):
    # 加载最近 N 轮的分配历史
    recent_allocations = await db.get_recent_stock_allocations(limit=5)

    for code, allocation in new_allocation.items():
        # 如果该股票最近 3 轮都被分配给同一 family，降低优先级
        recent_families = [h.get("families", []) for h in recent_allocations.get(code, [])]
        repeat_count = sum(1 for f in recent_families if set(f) == set(allocation["families"]))

        if repeat_count >= 3:
            allocation["priority"] *= 0.6  # 衰减 40%
            allocation["decay_reason"] = "repeated_allocation"
```

**影响**：增加目标股票的轮换频率，避免对同一股票反复生成相似策略。

### 优化 6：FACTOR_STRATEGY_MAPPING 静态不可扩展（🟡 中优先级）

**现状问题**：因子到策略类型的映射是硬编码的字典，新增因子或策略类型需要修改代码。无法通过配置或运行时学习来调整映射关系。

**建议方案**：

```python
# 方案 A：支持环境变量/配置文件覆盖
FACTOR_STRATEGY_MAPPING_OVERRIDES = json.loads(
    os.environ.get("STRATEGY_FACTORY_FACTOR_MAPPING_OVERRIDES", "{}")
)
EFFECTIVE_FACTOR_STRATEGY_MAPPING = {**FACTOR_STRATEGY_MAPPING, **FACTOR_STRATEGY_MAPPING_OVERRIDES}

# 方案 B：基于历史表现动态学习映射权重
@classmethod
def _dynamic_factor_strategy_mapping(cls, factor_name, feedback_root):
    """基于孵化反馈动态调整因子→策略映射权重。"""
    base_types = FACTOR_STRATEGY_MAPPING.get(factor_name, ())
    if not feedback_root:
        return base_types

    # 按各策略类型的历史 Sharpe 排序
    type_scores = {}
    for strategy_type in base_types:
        family_feedback = feedback_root.get(strategy_type, {})
        type_scores[strategy_type] = family_feedback.get("paper_skill_lcb", 0.0)

    # 按分数重排，但保留所有类型
    sorted_types = sorted(base_types, key=lambda t: -type_scores.get(t, 0.0))
    return tuple(sorted_types)
```

**影响**：无需代码变更即可调整映射；基于实际表现自动优化因子→策略的对应关系。

### 优化 7：构建流程缺少增量更新能力（🟢 低优先级）

**现状问题**：每次 `build()` 都从零开始构建完整的 artifact，即使大部分数据（如 governed_candidate_pool、model_registry_lineage）在短时间内不会变化。

**建议方案**：引入增量构建 + TTL 缓存：

```python
class FactorResearchBuilder:
    _cache: dict[str, tuple[float, Any]] = {}  # {key: (expire_time, value)}
    CACHE_TTL_SEC = {
        "governed_pool": 300,        # 5 分钟
        "model_lineage": 600,        # 10 分钟
        "stock_allocation": 1800,    # 30 分钟
        "factor_history": 120,       # 2 分钟
    }

    @classmethod
    async def _cached_load(cls, key: str, loader_coro):
        now = time.time()
        if key in cls._cache:
            expire, value = cls._cache[key]
            if now < expire:
                return value
        value = await loader_coro
        ttl = cls.CACHE_TTL_SEC.get(key.split(":")[0], 120)
        cls._cache[key] = (now + ttl, value)
        return value
```

**影响**：连续多轮运行时减少重复 IO；governed_pool 等重量级数据不必每轮重新加载。

### 优化 8：反馈路由缺少 A/B 实验支持（🟢 低优先级）

**现状问题**：`rewrite_family_preference_order_by_feedback` 的排序逻辑是确定性的，无法进行 A/B 实验来验证不同排序策略的效果。

**建议方案**：

```python
def rewrite_family_preference_order_by_feedback(family_preference_order, *, family_plans, experiment_id=None):
    if experiment_id == "random_explore_10pct":
        # 实验组：10% 概率随机打乱前 3 名
        if random.random() < 0.10:
            top_3 = sorted_families[:3]
            random.shuffle(top_3)
            sorted_families[:3] = top_3

    elif experiment_id == "ucb_exploration":
        # 实验组：使用 UCB1 算法平衡探索与利用
        for i, family in enumerate(sorted_families):
            exploration_bonus = math.sqrt(2 * math.log(total_rounds) / max(family_rounds[family], 1))
            scores[i] += exploration_bonus * EXPLORATION_WEIGHT

    # 记录实验分组到 artifact
    return sorted_families, {"experiment_id": experiment_id, "variant": variant}
```

**影响**：支持数据驱动的排序策略优化；避免陷入局部最优。

### 优化 9：Shannon 熵监控缺少告警阈值（🟢 低优先级）

**现状问题**：`stock_family_allocation_entropy` 已经计算了 Shannon 熵来衡量分配多样性，但没有设置告警阈值。当熵值过低（分配过于集中）时，系统不会发出警告。

**建议方案**：

```python
# 在 build_factor_research_artifact_payload 中添加
allocation_entropy = stock_family_allocation_summary.get("allocation_entropy", 0.0)
max_possible_entropy = math.log2(max(len(family_preference_order), 1))
normalized_entropy = allocation_entropy / max(max_possible_entropy, 0.001)

quality_flags = []
if normalized_entropy < 0.4:
    quality_flags.append("allocation_concentration_critical")
elif normalized_entropy < 0.6:
    quality_flags.append("allocation_concentration_warning")

# 写入 summary
summary["normalized_allocation_entropy"] = round(normalized_entropy, 4)
summary["allocation_concentration_level"] = (
    "critical" if normalized_entropy < 0.4
    else "warning" if normalized_entropy < 0.6
    else "healthy"
)
```

**影响**：提前发现分配集中度问题；为 ReadinessService 提供额外的阻断信号。

### 优化总结

| # | 改进项 | 影响 | 实现难度 | 优先级 |
|---|---|---|---|---|
| 1 | 因子 IC 历史并发加载 | 加载耗时降低 70-80% | 低 | 🔴 高 |
| 2 | 孵化反馈并发加载 | 反馈加载从 ~25s 降为 ~3-5s | 中 | 🔴 高 |
| 3 | 差异化因子过期阈值 | 减少不必要的 readiness 阻断 | 低 | 🟡 中 |
| 4 | 因子拥挤度检测 | 防止单 family 过度集中 | 中 | 🟡 中 |
| 5 | 分配历史衰减 | 增加目标股票轮换 | 中 | 🟡 中 |
| 6 | 动态因子映射 | 基于表现自动优化映射 | 中 | 🟡 中 |
| 7 | 增量构建 + TTL 缓存 | 减少重复 IO | 中 | 🟢 低 |
| 8 | A/B 实验支持 | 数据驱动的排序优化 | 中 | 🟢 低 |
| 9 | 熵值告警阈值 | 提前发现集中度问题 | 低 | 🟢 低 |

建议从 #1 和 #2 开始实施——这两项纯粹是 IO 并发化改造，不改变业务逻辑，风险极低但性能收益显著。#3（差异化过期）和 #4（拥挤度检测）是业务逻辑层面的重要改进，建议紧随其后。
