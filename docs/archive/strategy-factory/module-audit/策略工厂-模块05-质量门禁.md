## 代码审计结论

- 准确性状态：基本准确。
- 代码证据：`quality_gates.py` 组装门禁；`quality_gates_parts/evaluation.py` 实现 Pre-Gate 与 Gate-0；`quality_gates_parts/reporting.py` 执行 Gate-0/Pre-Gate/Gate-1/Gate-2；提交侧 Gate A/B/C payload 在 submitter/gate report 中落地。
- 已实现能力：Pre-Gate 任务类型/目标覆盖/配额/流动性代理/信号密度预筛；Gate-0 结构校验与 DSL 编译；Gate-1 K 线预加载和并发 fast screen；Gate-2 priority score；Gate A/B/C artifact。
- 过时/夸大描述：早期把质量门禁简化为 Gate-0/1/2/3，未充分说明 Pre-Gate 与新版 Gate A/B/C 已经存在；Gate-2 priority adjustment 比固定 Sharpe 排序更丰富。
- 仍然成立的问题：Gate-0 缺参数值域检查；Gate-1 preload 失败只记录并降级，没有 retry；信号密度估算仍是公式近似，缺市场波动/制度环境校正；Gate-2 调整权重未从历史通过率学习。
- 建议优先级：P0 补 Pre-Gate/Gate A/B/C 现状；P1 K 线预加载 retry；P2 自适应 Gate-2 权重；P3 参数值域与密度校正。下方优化建议中的代码块为概念示例。

## 职责

质量门禁通过 Pre-Gate + Gate-0/1/2/3 递进式筛选，从 ~20 个候选中淘汰不合格者。实际执行由 `CandidatePipeline` 编排。

---

## 门禁架构（实际代码）

```
候选池（~20个）
    │
    ▼
Pre-Gate 预筛 ─── pre_gate_screen()
    │ 廉价同步检查
    ▼
Gate-0 结构校验 ── gate_0_structural()
    │ 纯同步，无 IO
    ▼
Gate-1 快速回测 ── BacktestFilter（2 只代表性股票）
    │ Top 45% 进入 Gate-2
    ▼
Gate-2 完整回测 ── BacktestFilter（10 只代表性股票）
    │ 按类型阈值筛选
    ▼
Deduplicator ──── 去重
    │
    ▼
Gate-3 提交门禁 ── run_submission_quality_gate()
    │ 质量报告 + 风险报告 + 验证
    ▼
Submitter ──────── 提交
```

## Gate-0：结构校验（`gate_0_structural`）

```python
def gate_0_structural(candidate: dict) -> GateResult:
    reasons = []

    # 1. strategy_type 合法性
    if strategy_type not in _VALID_STRATEGY_TYPES:  # 16 种
        reasons.append(f"invalid_strategy_type:{strategy_type}")

    # 2. params 有效性
    if not isinstance(params, dict):
        reasons.append("params_not_dict")

    # 3. 必需交易字段完整性
    _REQUIRED_TRADE_FIELDS = {
        "holding_horizon", "trade_plan", "risk_rules",
        "rebalance_rule", "portfolio_spec",
        "execution_assumptions", "validation_profile",
    }
    missing = [key for key in _REQUIRED_TRADE_FIELDS if not candidate.get(key)]
    if missing:
        reasons.append(f"missing_trade_fields:{','.join(missing)}")

    # 4. DSL 编译检查（dsl_rule 类型）
    if strategy_type == "dsl_rule":
        try:
            compile_strategy_blueprint(candidate, tune_for_factory=True)
        except Exception as exc:
            reasons.append(f"dsl_compile_failed:{type(exc).__name__}")

    return GateResult(passed=len(reasons) == 0, gate="gate_0", reasons=reasons)
```

## 已识别的优化方向

> 以下为经过代码审计和行业最佳实践对比后识别的改进点，按优先级排列。

---

### 优化 1：Gate-1 K 线预加载缺少失败重试（🔴 高优先级）

**现状问题**：`preload_klines` 失败后仅记录日志，Gate-1 回退到逐个加载模式，显著增加延迟。无重试机制。

**建议方案**：添加单次重试 + 部分成功降级：

```python
try:
    await backtest_filter.preload_klines(db, gate_1_preload_codes)
except Exception as exc:
    # 重试一次（缩小范围到代表性股票）
    try:
        await backtest_filter.preload_klines(db, REPRESENTATIVE_STOCKS)
        gate_1_preload_status = "partial_retry"
    except Exception:
        gate_1_preload_status = f"failed:{type(exc).__name__}"
```

**影响**：减少因瞬时 IO 错误导致的 Gate-1 全量串行回退。

---

### 优化 2：Pre-Gate 信号密度估算过于粗糙（🟡 中优先级）

**现状问题**：`_estimate_signal_density` 使用简化公式估算交易频率，不考虑实际市场波动率。例如 `ma_cross` 的密度仅基于均线周期，不考虑当前市场是趋势还是震荡。

**建议方案**：注入市场波动率修正因子：

```python
def _estimate_signal_density(strategy_type, params, *, volatility_index=50):
    base_density = _base_signal_density(strategy_type, params)
    # 高波动市场 → 信号更频繁
    vol_multiplier = 0.8 + (volatility_index / 100) * 0.4  # 0.8-1.2x
    return round(base_density * vol_multiplier, 4)
```

**影响**：减少低波动市场中的误判（将正常低频策略错误标记为"信号过稀"）。

---

### 优化 3：Gate-2 优先级调整缺少自适应学习（🟡 中优先级）

**现状问题**：`_gate_2_priority_adjustments` 中的惩罚/奖励分值是硬编码的（如 coverage_zero_penalty=-12, turnover_penalty=-10）。这些值不根据历史 Gate-2 通过率自动调整。

**建议方案**：基于历史数据动态校准惩罚权重。

**影响**：避免过度惩罚或惩罚不足，提高 Gate-2 选择的精准度。

---

### 优化 4：Gate-0 结构校验不检查参数值域（🟢 低优先级）

**现状问题**：`gate_0_structural` 仅检查字段存在性和类型，不验证参数值是否在合理范围内（如 `lookback=-5` 或 `threshold=100`）。

**建议方案**：添加轻量级值域检查。

**影响**：在最早阶段拦截明显不合理的参数，避免浪费后续 Gate-1/2 的回测资源。

---

### 优化总结

| # | 改进项 | 影响 | 实现难度 | 优先级 |
|---|---|---|---|---|
| 1 | K 线预加载重试 | 减少 Gate-1 串行回退 | 低 | 🔴 高 |
| 2 | 信号密度波动率修正 | 减少低波动市场误判 | 低 | 🟡 中 |
| 3 | Gate-2 优先级自适应 | 提高选择精准度 | 中 | 🟡 中 |
| 4 | Gate-0 参数值域检查 | 最早拦截不合理参数 | 低 | 🟢 低 |
