## 代码审计结论

- 准确性状态：部分不准。
- 代码证据：`research/runner.py` 实现 `ResearchPlaneRunner.run_generation()`；`services/task_orchestrator.py` 的 `TaskOrchestrator.run()` 只是调用 `scheduler._run_autonomy_batches(db, snapshot)` 并转换为 `ResearchBatchResult`；`research/runner.py` 的 `_filter_invalid_symbols()` 每轮查询 `stocks` 白名单。
- 已实现能力：本地 Spawner、自适应参数候选、目标股票 K 线清洗、autonomy batch 包装、A 股交易规则默认值、自动命名、LLM 无效股票代码过滤、full market Top-N/score rows 透传。
- 过时/夸大描述：早期文档暗示 TaskOrchestrator 自己完成任务获取、排序、并发执行，这不是当前 `TaskOrchestrator.run()` 的真实职责；真实任务执行仍在 scheduler 私有方法内。
- 仍然成立的问题：TaskOrchestrator 缺独立任务优先级/重试/资源预算控制；股票白名单每轮重新加载；本地 Spawner 与 autonomy 生成缺覆盖摘要共享，可能重复生成相似候选。
- 建议优先级：P0 修正 TaskOrchestrator 为 thin wrapper/类型转换边界；P1 白名单 TTL cache；P2 Spawner/LLM 协调上下文；P3 将 scheduler 私有 autonomy 执行迁移到显式编排服务。下方优化建议中的代码块为概念示例。

自主研究任务模块负责通过 LLM 和自适应参数算法生成策略候选，与 Spawner 的本地规则生成互补。

## 核心方法 `async run_generation(db, snapshot) -> ResearchGenerationResult`

```python
async def run_generation(self, db, snapshot):
    # 1. 本地规则生成（Spawner）
    spawner = self._factory_pkg.StrategySpawner()
    local_candidates = list(spawner.spawn(snapshot) or [])

    # 2. 自适应参数候选
    from ...domain.adaptive_parameters import get_adaptive_candidates
    adaptive_candidates = await get_adaptive_candidates(db, preferred_types, snapshot)
    local_candidates.extend(adaptive_candidates)

    # 3. 目标股票清洗（确保有足够 K 线历史）
    local_candidates, target_sanitization = await self._sanitize_local_spawn_targets(local_candidates, db)
    # 检查每只目标股票是否有 ≥250 根 K 线
    # 不足的从候选中移除

    # 4. LLM 自主任务（TaskOrchestrator）
    autonomy_batch = await TaskOrchestrator(self._scheduler).run(db, snapshot)
    autonomy_candidates = autonomy_batch.generated_candidates
    experiments = autonomy_batch.experiments

    # 5. 应用策略配置文件 + 候选信封
    profiled_local = [apply_candidate_strategy_profile(c, snapshot=snapshot) for c in local_candidates]
    profiled_autonomy = [apply_candidate_strategy_profile(c, snapshot=snapshot) for c in autonomy_candidates]

    # 6. 自动命名
    for candidate in all_candidates:
        candidate["name"] = _auto_name(strategy_type, params)

    # 7. 注入 A 股交易规则默认值
    _A_SHARE_BACKTEST_DEFAULTS = {
        "market_ruleset": "cn_equity",
        "commission": 0.00025,
        "sell_tax_rate": 0.001,
        "min_trade_lot": 100,
        "t_plus_one": True,
        "tradability_filter": True,
        "arrival_price_policy": "next_open_proxy",
    }

    # 8. 过滤 LLM 幻觉出的无效股票代码
    generated_candidates = await self._filter_invalid_symbols(all_candidates, db)
    # 从 stocks 表加载白名单（list_status='L'）
    # 剔除不存在/已退市的代码

    return ResearchGenerationResult(
        local_candidates=profiled_local,
        autonomy_candidates=profiled_autonomy,
        generated_candidates=generated_candidates,
        local_spawn_report=spawn_report,
        autonomy_stage=autonomy_stage,
        experiments=experiments,
    )
```

@staticmethod
async def _filter_invalid_symbols(candidates, db):
    """过滤 LLM 幻觉出的无效股票代码。"""
    # 从 stocks 表加载白名单
    rows = await db.fetch("SELECT code FROM stocks WHERE list_status = 'L'")
    whitelist = {row["code"] for row in rows}

    for candidate in candidates:

## 已识别的优化方向

---

### 优化 1：TaskOrchestrator 仍是 thin wrapper（🔴 高优先级）

**现状问题**：`TaskOrchestrator.run()` 仅调用 `scheduler._run_autonomy_batches(db, snapshot)` 并转换返回类型。没有添加任何编排逻辑（如任务优先级排序、失败任务重试、资源预算控制）。

**建议方案**：增加任务级编排能力：

```python
async def run(self, db, snapshot):
    tasks = self._task_board.get_pending_tasks()
    # 按优先级排序
    tasks.sort(key=lambda t: -t.get("priority", 0))
    # 资源预算控制
    budget_remaining = AUTONOMY_TASK_HARD_CAP
    selected = tasks[:budget_remaining]
    # 失败任务重试（最多 1 次）
    results = await self._execute_with_retry(selected, db, snapshot, max_retries=1)
    return self._build_batch_result(results)
```

**影响**：提高任务执行的可控性和容错能力。

---

### 优化 2：无效股票代码过滤每轮重新加载白名单（🟡 中优先级）

**现状问题**：`_filter_invalid_symbols` 每次调用都执行 `SELECT code FROM stocks WHERE list_status = 'L'`。白名单在短时间内不会变化。

**建议方案**：缓存白名单（TTL 1 小时）。

**影响**：减少一次全表扫描的数据库查询。

---

### 优化 3：本地 Spawner 和 LLM 生成缺少协调（🟡 中优先级）

**现状问题**：`run_generation` 中 Spawner 和 TaskOrchestrator 独立运行，不共享信息。可能产生高度重叠的候选（如 Spawner 生成了 momentum 策略，LLM 也生成了几乎相同的 momentum 策略）。

**建议方案**：将 Spawner 的输出摘要传递给 TaskOrchestrator，作为"已覆盖"的上下文。

**影响**：减少 Spawner 和 LLM 之间的候选重叠，提高整体多样性。

---

### 优化总结

| # | 改进项 | 影响 | 实现难度 | 优先级 |
|---|---|---|---|---|
| 1 | TaskOrchestrator 编排增强 | 提高容错和可控性 | 中 | 🔴 高 |
| 2 | 股票白名单缓存 | 减少 DB 查询 | 低 | 🟡 中 |
| 3 | Spawner-LLM 协调 | 减少候选重叠 | 中 | 🟡 中 |
