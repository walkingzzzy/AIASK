## 一、结论先行

截至 2026-04-11，策略工厂的真实状态可以概括为：

1. 主链能力已经大体落地，不再是“只有页面和榜单”的半成品。
2. 当前最大的缺口不是模块缺失，而是默认 steady-state、质量右移、strict 到 live 的转化，以及研究主链复杂度。
3. 下一阶段不应继续把重点放在“再扩更多生成能力”，而应优先把默认运行面、质量结果与架构复杂度收口。

因此，下一阶段开发优先级明确收敛为：

1. `P0`：恢复并稳定默认 steady-state
2. `P1`：继续把 raw 质量分布向右推
3. `P2`：缩小 strict 与 live 的断层
4. `P3`：继续做物理架构与平台边界收口

## 二、当前真实基线

当前可以视为“已完成基础工程、未完成结果验收”的事项：

- `strategy_manager` 统一控制面已完整承载 `factory_status / factory_run_once / factory_runs / factory_run_detail / lifecycle_scan / runtime / vector / promotion / projection`
- `packages/strategy-factory` 已是当前主实现包，旧 `akshare_mcp.services.strategy_factory.*` 主要承担兼容层职责
- L1/L2 主链已经可对上：
  - `ParameterDistributionRegistry`
  - `LLMHypothesisGenerator`
  - `HypothesisLoweringCompiler`
  - feedback reward/debt/search routing
  - strict/cohort 化 Gate-3
  - raw/effective/strict/live 质量口径
- BFF/Web 已能消费工厂运行态、可观测性、运行时风控、向量治理与领域投影能力

当前仍未完成的关键结果：

1. 默认 `factory_run_once` 还没有在默认门控下证明连续稳定成功
2. 总体 raw 质量分布仍然明显偏向 `D`
3. `quality_factor` 默认路径仍弱于 `momentum / ma_cross`
4. `strict_incubation_ready_rate` 改善快于 `live_candidate_ready_rate`
5. 外部 provider 稳定性仍会影响 hypothesis 生成与开放探索
6. `factor_research_builder.py` 仍然承担过多职责，后续改动回归风险高

### 2026-04-11 当日补充核验结果

本日对当前工作区在途改动补做了代码与构建核验，以下原本列为 `P0` 的代码侧收口项，可以从“待做”下调为“已落地、待运行验收”：

1. readiness 已补齐 recoverable governed shortfall 判定，不再把所有 governed shortfall 一律打成硬阻断

4. Web 与 BFF 的类型检查、生产构建，以及相关 Python 契约测试均通过，说明这一批跨层字段已经收口

因此，`P0` 当前真正剩余的重点，已经收敛为“默认 steady-state 的连续真实运行验收”，而不是继续补这批诊断字段本身。

## 三、下一阶段优先级

### P0：先恢复默认 steady-state

目标：

1. 默认运行不再频繁被 readiness 或 governed pool 门控挡成 `skipped`
2. 默认 run 能连续进入 `submit` 链路，而不是依赖受控 run 才证明系统可用
3. 让“默认工厂是否稳定产出”成为头号验收指标

优先动作：

1. 拆解默认 `readiness=blocked` 的构成，明确区分：
   - governed candidate pool shortfall
   - evidence debt backlog
   - external provider suppress/degraded
   - bulk cursor / run window / budget 侧原因
2. 将默认 run 的 `skipped / partial / success` 趋势做成稳定观察口径，不再只看单轮最好结果
3. 对默认 run 中被 `feedback_control_mode=suppress/freeze` 的 family、generator_mode、target pool 做逐项审计

其中已完成的代码侧收口：

1. `factory_status`、`factory_runs`、`factory_run_detail` 的 provider / governance / evidence debt 诊断字段已补齐
2. readiness 对 recoverable governed shortfall、高 evidence debt 但可恢复场景、provider suppress/cooldown 已有细粒度 warning 与测试覆盖
3. `/strategy-market` dashboard 已新增默认运行阻断与 provider 诊断面板

优先改动模块：

- `packages/strategy-factory/src/strategy_factory/application/_factory_scheduler_loop.py`
- `packages/strategy-factory/src/strategy_factory/application/services/readiness_service.py`
- `packages/strategy-factory/src/strategy_factory/application/research/factor_research_builder.py`
- `packages/akshare-mcp/src/akshare_mcp/tools/managers/strategy_mgr_lifecycle.py`
- `packages/akshare-mcp/src/akshare_mcp/tools/managers/strategy_mgr_helpers.py`

验收口径：

1. 默认工厂连续 3 次真实 run 都不被 readiness 挡住
2. 默认工厂连续 3 次真实 run 都能进入 `submit`
3. `factory_status` 能稳定输出可解释的阻断原因 Top N

### P1：继续把 raw 质量分布向右推

目标：

1. 把优化主目标锁定为 `raw_validation_grade_distribution` 与 `raw_b_or_above_rate`
2. 减少“提交了但 raw 仍偏弱”的样本
3. 让重点 family 的提升从边缘桶位推进到默认主桶位

优先动作：

1. 按 `family × holding_bucket × validation_focus × target_universe` 继续拆质量面板，定位默认路径最弱桶位
2. 继续推进 `quality_factor` 默认主桶，把受控 run 的改善推到默认 run 可复现
3. 让 `momentum / ma_cross / quality_factor` 的 reward/debt 路由真正与 raw A/B 率正相关
4. 继续收紧低质量 lineage 的 `refresh_existing / spawn_revision_from_existing`
5. 对长期只产出 `raw D/C` 的 family 强制降低预算、优先级与探索密度

优先改动模块：

- `packages/strategy-factory/src/strategy_factory/application/research/factor_research_builder.py`
- `packages/strategy-factory/src/strategy_factory/application/_budget_feedback.py`
- `packages/strategy-factory/src/strategy_factory/domain/targets.py`
- `packages/strategy-factory/src/strategy_factory/application/hypothesis_lowering_compiler.py`
- `packages/akshare-mcp/src/akshare_mcp/tools/managers/strategy_mgr_helpers.py`

验收口径：

1. 最近 3 次默认真实 run 的 `raw_b_or_above_rate` 都高于当前 cohort 基线
2. `momentum / ma_cross / quality_factor` 至少 2 条在默认路径稳定出现 raw `B`
3. `refresh_existing / spawn_revision_from_existing` 不再集中出现在长期 `D` 级 lineage

### P2：缩小 strict 与 live 的断层

目标：

1. 把“strict 可过但 live 过不去”的样本断层变成可审计、可优化的问题
2. 让 live-ready 提升建立在真实质量改善上，而不是只靠有效等级修正

优先动作：

1. 对 `strict_incubation_ready=true && live_candidate_ready=false` 的样本做专题审计
2. 统计 live 侧最常见阻断因子：
   - `PBO`
   - `White Reality Check`
   - `Hansen SPA`
   - trade quality / density
   - execution / capacity / cost 假设
3. 把 live gate 的失败原因回灌到 feedback，而不是只停留在 review 结果里
4. 在工厂状态页与 run detail 中增加 strict-live gap 的趋势指标

优先改动模块：

- `packages/strategy-factory/src/strategy_factory/application/submission_gate.py`
- `packages/strategy-factory/src/strategy_factory/application/quality_gates.py`
- `packages/akshare-mcp/src/akshare_mcp/tools/managers/strategy_mgr_helpers.py`
- `packages/akshare-mcp/src/akshare_mcp/tools/managers/strategy_mgr_runtime.py`
- `packages/akshare-mcp/src/akshare_mcp/services/promotion_pipeline.py`

验收口径：

1. `live_candidate_ready_rate` 在默认真实 run 中持续高于当前基线
2. strict-live gap 的主因可以稳定归类并映射到反馈动作
3. raw `B/A` 样本的 `live_ready_given_raw_b_rate` 持续改善

### P3：继续做物理架构与平台边界收口

目标：

1. 降低研究主链集中复杂度
2. 让控制面和上层业务逐步减少零散 DB 能力探测
3. 在不打断现有兼容面的前提下，继续完成主包收口

优先动作：

1. 继续拆 `factor_research_builder.py`，至少分出：

   - active pool / governance snapshot summary
2. 把运行时、向量、投影等散落的 DB capability 探测逐步替换为稳定 service boundary
3. 保持 `strategy_manager` 与 BFF/Web surface 不变，优先在内部收口
4. 新逻辑继续优先落在 `packages/strategy-factory`，兼容层只做桥接

优先改动模块：

- `packages/strategy-factory/src/strategy_factory/application/research/factor_research_builder.py`
