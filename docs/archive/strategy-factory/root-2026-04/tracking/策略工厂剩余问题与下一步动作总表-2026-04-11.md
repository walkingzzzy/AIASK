## 一、结论摘要

截至 2026-04-11，策略工厂的真实状态更接近下面这个判断：

- 主链能力已经基本落地，不再是“只有页面、没有工厂”
- 观测、接口、存储、质量口径也已经成链，能够承载 run 级别与 cohort 级别诊断
- 候选生成已经不是单纯规则补位，而是包含 `hypothesis -> lowering -> candidate` 的双阶段路径
- feedback 已经不只是预算节流，而是进入了搜索路由与 family 调度层
- strict / live 的质量口径与 formal multiple-testing 约束已经进入提交门禁
- 但默认 steady-state 是否稳定、质量是否持续右移、live-ready 是否能默认路径持续产出，仍然主要是运行验收问题，而不是代码存在性问题
- 物理架构上仍有明显未收口点，核心是 `factor_research_builder.py` 复杂度仍然过高

如果只按“实际进度”分层看，当前更适合写成下面这张表：

| 维度 | 当前状态 | 判断 |
|---|---|---|
| 工厂主链能力 | 候选生成、research、readiness、gate、submit 主链已存在 | 高 |
| 观测与产品承载 | BFF / Web / DB / DTO / dashboard 已承接主要工厂指标 | 高 |
| 默认 steady-state | 有门控、诊断与修复能力，但连续成功仍待运行证明 | 中低 |
| 质量右移 | 质量分布、family 面板、strict/live 统计口径已具备，但持续右移待运行证明 | 中低 |
| live-ready 稳定产出 | live gate 规则已具备，但默认路径持续产出待运行证明 | 低到中 |
| 架构收口 | 模块边界已有改善，但 builder 集中复杂度仍明显 | 中 |

| B1 | 默认工厂 steady-state 仍未完成验收 | 代码已具备 readiness 诊断、governed pool 判定与恢复分流，但“默认连续成功”仍未形成稳定运行证据 | 容易出现单轮成功被误读成默认稳态恢复 | 以“最近 3 次默认真实 run 连续进入 submit，且不被 readiness 挡住”作为第一验收口径 |

## 五、重构后的下一步动作优先级

### P0：先做默认 steady-state 验收，而不是继续凭单轮样本乐观判断

1. 用真实 `factory_run_once` 连续跑 3 轮，核对 `readiness_decision`、`submit_stage_entered`、`submitted`、`status`
2. 拆默认阻断构成，重点看 governed pool、evidence debt、provider control 三类原因
3. 把“默认路径是否持续产出”设为第一验收门，而不是先做更多局部 family 美化

### P1：继续推进质量分布右移

1. 盯住 `raw_validation_grade_distribution`
2. 盯住 `raw_b_or_above_rate`
3. 盯住 `raw_validation_total_score_mean / p50 / p90`
4. 不再把 `submitted` 或 `gate_3_passed` 当成质量改善的替代指标

### P2：把 family 优化从“大类讨论”切到“默认路径复现”

1. 保持 `momentum` 的 `raw A/B` 可复现
2. 继续扩大 `ma_cross` 的非零 `raw B` 样本，避免只停留在边缘桶位
3. 重点补 `quality_factor` 默认路径，让它从“专项可打”推进到“默认可复现”

### P3：缩小 strict 与 live 的断层

1. 对已经 `strict_incubation_ready=true` 但 `live_candidate_ready=false` 的样本做专题审计
2. 统计最常见的 live 拦截因子：`PBO`、`White RC`、`SPA`、trade quality、multiple-testing mode
3. 让优化目标从“打出 raw B”进一步升级为“打出可持续 live-ready”

### P4：继续做运行与架构收口

1. 把外部 LLM provider 稳定性作为单独治理对象
2. 继续拆 `factor_research_builder.py`
3. 把复杂度风险从“可解释”推进到“可消除”

## 六、统一验收口径

后续建议不要再只看单轮最优 run，而应统一以这 4 组指标验收：

1. 默认工厂最近 3 次真实 run 都不被 readiness 挡住，并能进入 `submit`
2. 最近 3 次默认真实 run 的 `raw_b_or_above_rate` 都显著高于当前基线
3. `momentum / ma_cross / quality_factor` 至少有 2 条在默认路径稳定出现 `raw B`，且 `quality_factor` 不再主要依赖专项 run
4. `live_candidate_ready_rate` 不只非零，而且能在默认真实 run 中持续高于当前基线

只有这 4 组指标一起成立，才能更接近下面这句判断：

“策略工厂已经完成了从能力主链落地，到默认路径稳定产出高质量策略的改造。”
