## 2. 架构对比

### 2.1 OpenClaw 架构模型

OpenClaw 采用三层架构：Gateway → Reasoning Engine → Execution Environment。

- **Gateway**：单一长驻 Node.js 进程，通过 Channel 适配器连接 20+ 消息平台
- **Channel**：每个平台一个 Channel 实例，负责协议转换和消息标准化
- **Agent Core**：ReAct 循环，工具调用通过 MCP 协议标准化
- **Skills**：可学习的技能包，类似 Plugin 但支持自我进化
- **Heartbeat**：定时任务系统，支持 cron 调度

核心特点：所有外部应用统一抽象为 Channel（通信）或 MCP Server（工具），Agent 无需感知底层协议差异。

### 2.2 Hermes Agent 架构模型

Hermes Agent 由 Nous Research 开发，架构：

- **Messaging Gateway**：单一后台进程，长轮询/WebSocket 连接所有平台
- **Platform Adapters**：每个平台独立适配器（Telegram/Discord/WeChat/QQ/WeCom 等）
- **Tool Registry**：内置工具 + MCP Server + 外部 API
- **Learning Loop**：自我学习循环，从经验中创建 Skills
- **Session Manager**：跨平台会话管理

关键能力：
- 个人微信通过 iLink Bot API 长轮询接入（无需公网 IP）
- 企业微信通过 WebSocket 双向通信
- QQ 通过官方 Bot API v2 支持 C2C/群/频道
- 所有平台支持语音、图片、文件双向传输

### 2.3 AIASK Agent 当前架构

```
Desktop / CLI / 外部客户端
        │
AIASK Agent HTTP API (FastAPI)

AgentRuntime + SessionStore + ToolRegistry
```

## 3. 核心差距

### 3.1 入站消息守护进程（双向通信）

**问题**：当前系统只能主动推送消息到各平台，无法持续监听平台的入站消息。用户在微信/QQ/Telegram 发送的消息无法自动触发 Agent 响应。

**OpenClaw/Hermes 的做法**：运行一个长驻后台进程（Gateway Daemon），通过长轮询或 WebSocket 持续监听所有已连接平台，收到消息后路由到 Agent 处理，Agent 响应后通过 DeliveryRouter 回复。

**当前系统的基础**：
- `GatewayRuntime` 已有 `write_runtime_status`、锁文件机制（设计上预留了守护进程位置）
- `DeliveryRouter.record_inbound` 已实现入站消息记录和路由解析
- `BasePlatformAdapter.handle_inbound` 已实现入站消息标准化
- 缺少的是：持续运行的轮询/WebSocket 事件循环

### 3.2 个人微信适配器

**问题**：当前 `WeixinAdapter` 基于微信公众号 API（需认证服务号），无法连接个人微信账号。

**Hermes 的做法**：使用腾讯 iLink Bot API，通过长轮询方式连接个人微信，无需公网 IP，支持文字/图片/视频/文件/语音。

**解决路径**：
- 方案 A：实现 iLink Bot 适配器（与 Hermes 同款）
- 方案 B：集成 wechat-mcp（作为 MCP Server 通过 MCPAggregator 接入）
- 方案 C：使用 CowAgent 兼容后端

### 3.3 金融软件连接器

**问题**：OpenClaw 和 Hermes 都没有金融软件连接能力。这是 AIASK 的独特机会。

**目标软件**：
- 通达信（行情 + 交易）
- 同花顺（行情 + 交易 + iFinD 数据）
- 东方财富（行情 + 数据）
- MiniQMT / 迅投 QMT（量化交易）

**解决路径**：封装为 MCP Server，通过已有的 MCPAggregator 动态注册。

### 3.4 统一连接器生命周期管理

**问题**：当前各类连接（MCP/Plugin/Gateway Platform）分散管理，缺少统一的"连接器"概念和 UI。

**目标**：提供类似 OpenClaw 的统一连接器视图——用户可以在一个界面看到所有已绑定的应用，一键启用/禁用/配置。

## 5. 通信平台集成方案

### 5.1 个人微信（iLink Bot）

**目标**：实现与 Hermes Agent 同等的个人微信连接能力。

**技术方案**：

腾讯 iLink Bot API 是官方提供的个人微信机器人接口，通过长轮询方式工作，无需公网 IP。

**实现路径**：

```python
# packages/agent/src/aiask_agent/adapters/weixin_ilink.py

class WeixinILinkAdapter:
    """个人微信 iLink Bot 适配器 — 长轮询模式"""
    
    def __init__(self, *, app_id: str, app_secret: str):
        self.app_id = app_id
        self.app_secret = app_secret
        self.base_url = "https://api.weixin.qq.com/ilink/v1"
        self._running = False
    
    async def start_polling(self, callback):
        """启动长轮询，持续接收消息"""
        self._running = True
        while self._running:
            messages = await self._poll()
            for msg in messages:
                await callback(self.normalize(msg))
    
    async def send(self, *, target: str, message: str, media: list = None):
        """发送消息到指定用户/群"""
        pass
    
    async def send_media(self, *, target: str, path: str, media_type: str):
        """发送图片/视频/文件/语音"""
        pass
```

### 5.2 企业微信 WebSocket 双向通信

**目标**：将当前仅出站的 WeComAdapter 升级为 WebSocket 双向通信。

**技术方案**：

Hermes 使用 WeCom AI Bot WebSocket Gateway，无需公网端点。

```python
# 升级 WeComAdapter，增加 WebSocket 入站能力

class WeComWebSocketAdapter(WeComAdapter):
    """企业微信 WebSocket 双向通信适配器"""
    
    async def start_websocket(self, callback):
        """连接 WeCom AI Bot WebSocket Gateway"""
        ws_url = await self._get_ws_url()
        async with websockets.connect(ws_url) as ws:
            while True:
                raw = await ws.recv()
                event = self._parse_event(raw)
                if event["type"] == "message":
                    await callback(self.normalize_inbound(event))
                elif event["type"] == "heartbeat":
                    await ws.send(self._heartbeat_ack())
```

### 5.3 QQ Bot v2 完整实现

**目标**：扩展当前 QQBotAdapter，支持 C2C 私聊、群 @提及、频道消息。

**技术方案**：

```python
class QQBotV2Adapter(QQBotAdapter):
    """QQ Bot API v2 完整适配器"""
    
    async def start_websocket(self, callback):
        """连接 QQ Bot WebSocket Gateway"""
        gateway_url = await self._get_gateway()
        async with websockets.connect(gateway_url) as ws:
            await self._identify(ws)
            while True:
                event = await self._receive_event(ws)
                if event["t"] == "MESSAGE_CREATE":      # 频道消息
                    await callback(self._normalize_channel_msg(event))
                elif event["t"] == "C2C_MESSAGE_CREATE": # 私聊
                    await callback(self._normalize_c2c_msg(event))
                elif event["t"] == "GROUP_AT_MESSAGE_CREATE": # 群@
                    await callback(self._normalize_group_msg(event))
```

### 6.2 核心类定义

```python
# packages/agent/src/aiask_agent/gateway_daemon.py

import asyncio
from typing import Any, Callable, Awaitable

InboundCallback = Callable[[dict[str, Any]], Awaitable[None]]


class GatewayDaemon:
    """入站消息守护进程 — 持续监听所有已配置平台的入站消息"""

    def __init__(
        self,
        *,
        runtime: "AgentRuntime",
        config: GatewayConfigStore,
        router: DeliveryRouter,
        messages: GatewayMessageStore,
    ):
        self.runtime = runtime
        self.config = config
        self.router = router
        self.messages = messages
        self._tasks: dict[str, asyncio.Task] = {}
        self._running = False

    async def start(self):
        """启动所有已配置平台的入站监听"""
        self._running = True
        self.runtime.gateway_runtime.write_runtime_status(state="starting")
        
        for platform_status in self.config.platforms():
            if platform_status["enabled"] and platform_status["configured"]:
                name = platform_status["name"]
                listener = self._get_listener(name)
                if listener:
                    self._tasks[name] = asyncio.create_task(
                        self._run_listener(name, listener)
                    )
        
        self.runtime.gateway_runtime.write_runtime_status(state="running")

    async def stop(self):
        """停止所有监听"""
        self._running = False
        for task in self._tasks.values():
            task.cancel()
        self._tasks.clear()
        self.runtime.gateway_runtime.write_runtime_status(state="stopped")

    async def _run_listener(self, name: str, listener):
        """运行单个平台的监听，自动重连"""
        while self._running:
            try:
                await listener(callback=self._on_inbound_message)
            except Exception as exc:
                # 记录错误，等待后重连
                await asyncio.sleep(30)

    async def _on_inbound_message(self, event: dict[str, Any]):
        """处理入站消息：记录 → 路由 → Agent 处理 → 回复"""
        platform = event.get("platform", "local")
        
        # 1. 记录入站消息
        record = self.router.record_inbound(
            platform=platform,
            payload=event,
        )
        
        # 2. 检查是否为控制命令
        metadata = record.get("metadata", {})
        if metadata.get("control_action"):
            await self._handle_control(metadata["control_action"], record)
            return
        
        # 3. 路由到 Agent 处理
        content = record.get("content", "")
        if not content.strip():
            return
        
        result = await self.runtime.run(
            message=content,
            session_id=self._resolve_session(record),
        )
        
        # 4. 回复到原平台
        reply_target = event.get("chat_id") or event.get("target")
        if reply_target and result.content:
            await self.router.send(
                platform=platform,
                target=reply_target,
                message=result.content,
                thread_id=event.get("thread_id"),
                session_id=result.session_id,
            )

    def _get_listener(self, platform: str):
        """获取平台对应的监听器"""
        listeners = {
            "weixin": self._poll_weixin,
            "wecom": self._ws_wecom,
            "qqbot": self._ws_qqbot,
            "telegram": self._poll_telegram,
            "discord": self._ws_discord,
            "email": self._poll_email,
        }
        return listeners.get(platform)
```

## 9. 安全与风控

### 9.1 凭证管理

**原则**：所有敏感凭证通过环境变量管理，不存储在代码或配置文件中。

**凭证分级**：

| 级别 | 说明 | 存储方式 | 示例 |
|------|------|---------|------|
| L1 只读 | 行情数据 API Key | `.env` 文件 | TDX_SERVER_IP |
| L2 通信 | 消息平台 Token | `.env` + 加密 | WEIXIN_ILINK_APP_SECRET |
| L3 交易 | 交易账户凭证 | 加密 Keychain | THS_TRADE_PASSWORD |
| L4 资金 | 资金划转权限 | HSM / 硬件密钥 | BANK_TRANSFER_KEY |

**实现方案**：

```python
class CredentialStore:
    """分级凭证管理"""
    
    def get(self, key: str, level: str = "L1") -> str:
        if level in ("L3", "L4"):
            return self._from_keychain(key)  # macOS Keychain / Linux Secret Service
        return os.getenv(key, "")
    
    def set(self, key: str, value: str, level: str = "L1"):
        if level in ("L3", "L4"):
            self._to_keychain(key, value)
        else:
            self._update_env_file(key, value)
```

### 9.3 消息安全

**入站消息安全**：

1. **签名验证**：所有平台入站消息必须通过签名验证（已实现 `verify_signature`）
2. **去重机制**：通过 `external_id` 防止重复处理（已实现 `find_by_external_id`）
3. **速率限制**：单用户消息频率限制，防止滥用
4. **内容过滤**：敏感指令（如交易）需要额外身份验证
5. **会话隔离**：不同平台/用户的会话严格隔离

**出站消息安全**：

1. **敏感信息脱敏**：账户余额、持仓详情等信息在非安全通道中脱敏
2. **消息审计**：所有出站消息记录到 `GatewayMessageStore`
3. **平台权限**：不同平台可配置不同的信息暴露级别
