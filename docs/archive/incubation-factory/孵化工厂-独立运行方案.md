# 孵化工厂 · 独立运行方案

> 日期：2026-05-15（v3，基于深度代码审查 + 联网调研重写）
> 目标：孵化工厂作为独立进程运行，自动识别和接纳策略工厂产出的合格策略，按孵化周期不同阶段验证 AI 生成策略的真实命中率
> 核心价值：**孵化工厂是 AI 生成策略从"回测幻象"到"实盘真实"的唯一桥梁**

---

## 0. 孵化工厂的两大核心使命

### 使命 1：审查策略质量与准确性

策略工厂产出的策略只是"理论上可能有效"，孵化工厂要回答的核心问题是：

> **这个 AI 生成的策略，在真实市场条件下能不能赚钱？**

具体审查维度：
- **信号质量**：信号方向是否真实预测了股价方向（前向收益验证）
- **执行质量**：信号转为订单时是否被滑点、涨跌停、流动性吞噬
- **稳定性**：表现是否在不同时间段一致（不是单一行情下的运气）
- **统计显著性**：交易次数是否足够（≥ 30 笔），命中率是否有统计意义
- **抗衰减**：策略 IC 是否随时间衰减，是否需要再优化

### 使命 2：体现 AI 生成策略的真实命中率

**这是孵化工厂存在的核心理由**。回测中的命中率会因 look-ahead bias、survivorship bias、过拟合而虚高。孵化工厂提供"无偏的命中率证据"：

- **回测命中率** ≠ **实盘命中率**（行业实证：AlphaCrafter 研究在 CSI 300 上 LSTM 回测 22.93% → 实盘 -7.74%；MACD 回测 20.35% → 实盘 -38.69%。来源：[arXiv 2603.09219](https://arxiv.org/abs/2603.09219v1)，已改写）
- **孵化期命中率** = 真实市场条件下的前向收益验证 = AI 生成策略的"真实成绩单"
- 没有孵化期，AI 生成的策略命中率全部都是"未经验证的自我宣称"

## 1. 策略工厂 vs 孵化工厂的职责边界

### 1.1 两个工厂的本质区别

| 维度 | 策略工厂（生产线） | 孵化工厂（验证线） |
|---|---|---|
| **职责** | 生产策略候选 | 验证策略真实性 |
| **输入** | 市场快照 + 因子研究 + LLM | DB 中 status="incubating" 的策略 |
| **输出** | strategies 表新增记录 | 状态变更（incubating → listed/deprecated） |
| **验证方式** | 历史回测（in-sample） | 前向测试（out-of-sample 真实市场） |
| **数据来源** | kline_1d + financials（历史） | 每日新产生的市场数据 |
| **命中率** | 回测命中率（可能虚高） | 真实命中率（无偏） |
| **失败成本** | 低（只是被拒绝） | 高（占用孵化资源 + 时间） |
| **运行频率** | continuous（12 分钟循环） | 每日 18:30 |
| **核心指标** | Sharpe / profit_factor（回测） | hit_rate / skill_lcb / forward_sharpe（实盘） |

### 1.2 交互协议（唯一接口：数据库）

```
策略工厂                                   孵化工厂
   │                                          │
   │ 生产候选 → Gate-3 → 写入 DB              │
   │ status = "incubating"                    │
   │ paper_account 已创建并绑定                │
   ├──────────► strategies 表 ◄───────────────┤
   │                                          │
   │                                          │ 每日 18:30 自动扫描
   │                                          │ 1. 加载 status=incubating
   │                                          │ 2. 生成当日信号
   │                                          │ 3. 验证前向收益
   │                                          │ 4. 推进孵化阶段
   │                                          │ 5. 自动晋升/淘汰
   │                                          │
   │ 读取 budget_feedback                     │
   │ （哪些 family 在孵化中表现好）             │
   ◄─────── strategy_incubation_metrics ──────┤
   │                                          │
   │ 调整 Spawner 偏好 → 进化                 │
```

**关键设计原则**：
- 两个工厂**不直接调用对方的代码**
- 唯一的交互是 SQLite 数据库
- 任一工厂宕机不影响另一个工厂
- 通过 `strategies.status` 字段流转

### 1.3 反馈闭环（"相辅相成、相互进化"）

孵化工厂的输出反馈给策略工厂，形成进化闭环：

```
孵化工厂输出                       策略工厂吸收
─────────────────                  ─────────────────
strategy_incubation_metrics  ───►  IncubationBudgeter._candidate_feedback()
  ├─ momentum 策略 hit_rate=58%    │  → paper_skill_lcb / paper_stability_gap
  ├─ value 策略 hit_rate=42%       │  → budget_multiplier / priority_adjustment
  └─ growth 策略 hit_rate=51%      │  → control_mode (cooldown/suppress/freeze)
                                    ▼
                                   下次 Spawner 增加 momentum/growth 配额，
                                   减少 value 配额（freeze 直接冻结）
                                    │
                                    ▼
                                   生成更多 momentum 策略 → 进入孵化
                                    │
                                    ▼
                                   孵化工厂再次验证 → 进一步反馈
```

这个反馈机制**已经在代码中实现**：
- `IncubationBudgeter._candidate_feedback()` 读取 `strategy_incubation_metrics`
- `_priority_score()` 中 `paper_skill_lcb` 权重 55.0，`paper_recent_skill_lcb` 权重 34.0
- 控制模式：cooldown(-9分) / suppress(-24分) / freeze(-36分) 直接压制低质量 family

### 2.2 孵化工厂的三重价值

#### 价值 1：信任基础设施（Trust Infrastructure）

孵化工厂产出的 `strategy_incubation_metrics` 表是整个系统的"信任锚点"：

| 指标 | 含义 | 为什么重要 |
|---|---|---|
| `hit_rate_5d` | 5 日前向命中率 | 策略信号是否真的预测了方向 |
| `skill_lcb_5d` | 技能下界（95% 置信区间） | 排除运气成分后的真实能力 |
| `forward_sharpe` | 前向 Sharpe | 风险调整后的真实收益 |
| `max_drawdown` | 最大回撤 | 最坏情况下的损失 |
| `coverage_ratio` | 信号覆盖率 | 策略是否活跃产出信号 |
| `stability_gap` | 稳定性缺口 | 近期表现 vs 历史表现的差距 |

**没有这些指标，用户看到的一切都是"回测幻象"。**

#### 价值 2：进化引擎（Evolution Engine）

孵化工厂的反馈直接驱动策略工厂的进化方向：

```python
# 代码实证：IncubationBudgeter._priority_score() 中的反馈权重
score += max(-0.12, min(paper_skill_lcb, 0.18)) * 55.0        # 孵化技能下界
score += max(-0.12, min(paper_recent_skill_lcb, 0.18)) * 34.0  # 近期技能下界
score -= max(paper_stability_gap - 0.05, 0.0) * 40.0           # 稳定性惩罚
score += max(min(paper_coverage_ratio, 1.0) - 0.50, -0.50) * 14.0  # 覆盖率奖励
# execution_conversion_efficiency 权重 28.0
```

这意味着：
- 孵化中表现好的 family → 策略工厂自动增加该 family 的生产配额
- 孵化中表现差的 family → 被 cooldown/suppress/freeze 压制
- **没有孵化工厂，策略工厂就是"盲人摸象"，不知道该往哪个方向进化**

#### 价值 3：风险防火墙（Risk Firewall）

孵化工厂是用户资金的最后一道防线：

```
策略工厂产出 100 个策略
        │
        ▼
   孵化工厂验证（30-60 天）
        │
        ├── 70% 淘汰（deprecated）→ 保护用户免受亏损
        ├── 20% 继续观察（observe）→ 需要更多证据
        └── 10% 晋升（listed）→ 真正有效的策略
```

**行业数据佐证**：Alpha Arena 竞赛中 AI 模型 32 组结果仅 6 次盈利（18.75% 成功率）。如果没有孵化工厂的过滤，81.25% 的策略会直接亏损用户资金。

### 4.2 核心流程（每日执行）

```python
async def run_daily_incubation_cycle():
    """孵化工厂每日主循环"""
    
    # Phase 1: 自动识别和接纳新策略
    new_strategies = await intake_new_strategies(db)
    # 扫描 status='incubating' 且尚未绑定 paper_account 的策略
    # 自动创建 paper_account 并绑定
    
    # Phase 2: 信号生成与前向收益验证
    incubating = await db.list_strategies('incubating', limit=200)
    for strategy in incubating:
        # 2a. 根据策略 DSL 生成当日信号
        signals = await generate_today_signals(strategy)
        # 2b. 验证历史信号的前向收益（T+5, T+10, T+20）
        forward_returns = await verify_forward_returns(strategy)
        # 2c. 记录到 strategy_incubation_metrics
        await record_daily_metrics(strategy, signals, forward_returns)
    
    # Phase 3: 孵化阶段评估与推进
    pipeline_result = await incubation_pipeline.run_batch(
        db,
        statuses=['incubating'],
        source='incubation_factory',
        auto_apply_review=True,  # 自动晋升 graduation_ready 的策略
    )
    
    # Phase 4: 命中率报告生成
    report = await generate_hit_rate_report(incubating, pipeline_result)
    
    # Phase 5: 反馈写入（供策略工厂读取）
    await write_budget_feedback(report)
    
    return report
```

### 4.3 自动识别与接纳机制

```python
    自动识别策略工厂新产出的合格策略。
    
    识别条件：
    1. status = 'incubating'（策略工厂 Gate-3 通过后设置）
    2. 尚未有 incubation_account 绑定
    3. 有有效的 paper_account
    
    接纳动作：
    1. 确认 paper_account 存在且 active
    2. 创建 incubation_account 记录
    3. 初始化 pipeline_snapshot（stage='warmup'）
    4. 记录 domain_event（incubation.strategy_accepted）
    """
    incubating = await db.list_strategies('incubating', limit=500)
    accepted = []
    
    for strategy in incubating:
        sid = strategy['id']
        # 检查是否已有孵化账户
        account = await db.get_strategy_incubation_account(sid)
        if account:
            continue  # 已接纳，跳过
        
        # 自动创建孵化账户
        ensure_result = await incubation_service.ensure_account(
            db, strategy, stage='warmup',
            source_run_id='incubation_factory_intake'
        )
        accepted.append({
            'strategy_id': sid,
            'account': ensure_result.get('account'),
            'accepted_at': datetime.now(timezone.utc).isoformat(),
        })
    
    return accepted
```

### 5.3 核心 Runner 类

```python
class IncubationFactoryRunner:
    """孵化工厂独立运行器。"""
    
    def __init__(self, *, run_time=dt_time(18, 30), dry_run=False):
        self.run_time = run_time
        self.dry_run = dry_run
        self._intake = IncubationIntake()
        self._signal_gen = SignalGenerator()
        self._forward_verifier = ForwardVerifier()
        self._metrics_recorder = MetricsRecorder()
        self._reporter = HitRateReporter()
        self._feedback_writer = FeedbackWriter()
    
    async def run_once(self) -> dict:
        """单次执行完整孵化周期。"""
        db = await self._get_db()
        
        # 1. 自动识别和接纳新策略
        intake_result = await self._intake.scan_and_accept(db)
        
        # 2. 信号生成 + 前向验证 + 指标记录
        incubating = await db.list_strategies('incubating', limit=200)
        metrics_results = []
        for strategy in incubating:
            signals = await self._signal_gen.generate(db, strategy)
            forward = await self._forward_verifier.verify(db, strategy)
            metric = await self._metrics_recorder.record(db, strategy, signals, forward)
            metrics_results.append(metric)
        
        # 3. 孵化流水线评估（复用已有实现）
        from akshare_mcp.services.incubation_pipeline import (
            get_strategy_incubation_pipeline_service,
        )
        pipeline = get_strategy_incubation_pipeline_service()
        pipeline_result = await pipeline.run_batch(
            db,
            statuses=['incubating'],
            source='incubation_factory',
            auto_apply_review=True,
        )
        
        # 4. 命中率报告
        report = await self._reporter.generate(
            incubating, metrics_results, pipeline_result
        )
        
        # 5. 反馈写入
        if not self.dry_run:
            await self._feedback_writer.write(db, report)
        
        # 6. 健康检查心跳
        await self._heartbeat(db, report)
        
        return report
    
    async def run_daemon(self):
        """守护进程模式：每日定时运行。"""
        while True:
            now = datetime.now()
            target = now.replace(
                hour=self.run_time.hour,
                minute=self.run_time.minute,
                second=0, microsecond=0
            )
            if now >= target:
                target += timedelta(days=1)
            
            wait_seconds = (target - now).total_seconds()
            logger.info(f"下次运行: {target}, 等待 {wait_seconds:.0f}s")
            await asyncio.sleep(wait_seconds)
            
            try:
                result = await self.run_once()
                logger.info(f"孵化周期完成: {result.get('summary', {})}")
            except Exception as exc:
                logger.error(f"孵化周期失败: {exc}", exc_info=True)
                await asyncio.sleep(300)  # 失败后等待 5 分钟
```

## 7. 与策略工厂的隔离保证

### 7.1 代码隔离

```
packages/strategy-factory/          # 策略工厂代码
packages/akshare-mcp/services/      # 孵化工厂代码（incubation_factory/）
```

- 策略工厂 **不 import** 孵化工厂的任何模块
- 孵化工厂 **不 import** 策略工厂的任何模块
- 唯一共享：数据库表 + `akshare_mcp` 基础设施（DB 连接、数据获取）

### 7.2 进程隔离

```bash
# 策略工厂进程（已有）
python -m strategy_factory.application.factory_scheduler

# 孵化工厂进程（新建）
python scripts/run_incubation_factory.py --daemon
```

- 两个进程独立启停
- 任一进程崩溃不影响另一个
- 通过 DB 的 ACID 保证数据一致性

### 7.3 故障隔离

| 故障场景 | 策略工厂影响 | 孵化工厂影响 |
|---|---|---|
| 策略工厂宕机 | 停止生产新策略 | 无影响，继续验证已有策略 |
| 孵化工厂宕机 | 无影响，继续生产 | 停止验证，策略堆积在 incubating |
| 数据库不可用 | 两者都停止 | 两者都停止 |
| 市场数据延迟 | 策略生成延迟 | 前向验证延迟（可容忍） |

## 9. 关键设计决策

| 决策 | 选择 | 理由 |
|---|---|---|
| 运行时间 | 18:30 | A 股 15:00 收盘 + 数据同步约 2h + 缓冲 |
| 调度方式 | asyncio sleep loop | 轻量，无外部依赖（不需要 cron/celery） |
| 与 SignalTracker 的关系 | 并行独立 | SignalTracker 仍可触发 Phase E，孵化工厂是额外保障 |
| 晋升决策 | 自动 | `auto_apply_review=True`，无需人工干预 |
| 淘汰决策 | 自动 | `failed` 阶段自动 deprecate |
| 反馈写入 | 每日 | 策略工厂下次运行时自动读取最新反馈 |
| 命中率计算 | skill_lcb（95% CI 下界） | 排除运气成分，统计严谨 |
