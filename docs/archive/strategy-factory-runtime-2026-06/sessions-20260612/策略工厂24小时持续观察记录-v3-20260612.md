## 6. 终极死锁诊断（2026-06-12，策略 observe→formal 的证据生产闸门）

### 现象
今日 53 信号 → 仅 1 个 paper_order；3211 个 observe 策略 `effective_n_5d` 全 = 0、
`skill_lcb` 无正值。策略侧无法做"存量复评盘活"——因为**根本没有前向证据可复评**
（不同于因子有 73 行累计 IC 历史）。

### 代码级根因（incubation.py:130-135 `_runtime_execution_guard`）
```python
allow_signal_entries = (
    not diagnostic_only and not proxy_runtime_used
    and semantic_runtime_match
    and execution_readiness_tier == "formal_runtime_ready"
)
```
- observe 样本普遍 `diagnostic_only=True` / `execution_readiness_tier=observe_diagnostic_only`
  → `allow_signal_entries=False`
- `sync_signals_to_orders`(specs.py:261)：买信号遇 `not allow_signal_entries` → `blocked_by_execution_guard`
- 链：observe 买信号被全拦 → 无纸面买单 → 无成交 → 无 forward returns → effective_n=0
  → 不满足 formal readiness → 永远 observe

### 死锁本质
**要前向证据才能转 formal，但只有 formal 样本才被允许下单产生证据。**
这与 observe-first 设计自相矛盾——observe 本意是"零资本诊断性纸面交易"积累证据，
但 guard 把 observe 完全挡在交易门外。与前序所有"单轮瞬时证据当门"死锁同构，
且是最靠后、最致命的一环（证据生产闸门）。

### 修法方向（有产品含义，待决策）
给 execution_guard 增加 `allow_observe_paper_entries`：
- formal_runtime_ready 样本：正常交易（现状不变）
- observe/diagnostic 样本：允许**诊断性纸面交易**（零资本模拟），积累 forward returns → effective_n，
  但不因此改变 formal 资格判定
- 结构性损坏样本（invalid 契约/semantic 硬伤）：仍禁止
- 需限流：observe 池 3211 样本，不宜全员每轮下单，应限最近/高分子集
属产品级决策 + 较大改动，待用户确认范围后实施。
