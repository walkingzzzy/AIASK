# 开发周期计划：倒置架构与因子路由 Gate 漏斗删除调整方案

日期：2026-06-04
版本：SF-GATE-REMOVAL-ADJUSTMENT-V2
放置位置：项目根目录

本版更新重点：

- 把“删除 Gate 漏斗”拆成可执行工程阶段。
- 明确哪些 Gate 行为删除，哪些 Guard 行为保留。
- 补充代码触点、数据契约、artifact 指标、测试矩阵、灰度上线和回滚方案。
- 明确首批实现必须先解决 `profile_summary` 缺失和 router 静默 fallback，否则 observe-first 没有意义。

## 0. 最终决策

**删除策略工厂的 Gate 漏斗。**

这里的“删除 Gate 漏斗”指：

- 删除候选进入 `observe` / `incubation` 前的串行硬阻断链路。
- `Gate-1` / `Gate-2` / `Gate-3` 不再作为进入观察池的前置盈利筛选。
- `Gate-3` 不得再以 `win_rate`、`walk-forward`、`DSR` 等历史/回测指标在前向样本形成前杀死候选。
- `candidate_governance` 不再是 `quality_gate -> backtest -> deduplicate -> submit` 的线性漏斗。

但这不是删除所有控制。必须保留的是非漏斗化护栏：

- `ContractGuard`：结构完整、字段合法、target symbols 正确。
- `LeakageGuard`：防未来函数、防数据泄漏。
- `RiskGuard`：流动性、仓位、交易风险、实盘边界。
- `DedupeGuard`：防重复策略污染观察池。
- `PromotionBoundary`：只有从观察池晋升到正式策略池或实盘候选时，才允许硬性质量门槛。

一句话：**observe 前删除盈利 Gate，promotion 前保留风险与晋升边界。**

## 1. 为什么必须删除 Gate 漏斗

Stock-First 架构的核心目标是：

```text
逐股画像 -> 类型路由 -> 多策略候选 -> observe -> 前向收益 -> 命中率矩阵 -> 晋升
```

当前 Gate 漏斗的实际效果是：

```text
候选生成 -> Gate-0 -> Pre-Gate -> Gate-1 -> Gate-2 -> Gate-3 -> 大量被杀 -> success_no_strategy
```

这会造成闭环失败：

1. 候选在进入 observe 前被杀，前向样本无法积累。
2. 没有前向样本，`hit_rate_by_regime` / `type x regime x holding_bucket` 命中率矩阵长期为空。
3. 命中率矩阵为空，Router 没有真实反馈可学。
4. Router 没有反馈，策略工厂继续依赖旧的 family 分配和回测门槛。
5. 最终表现为“看似跑通，实际没有策略进入观察和孵化”。

因此，Gate 漏斗和 Stock-First 目标是冲突的。

## 2. 当前代码事实

已经确认的代码事实：

- `FactoryCyclePipeline` 当前仍声明 `candidate_governance`，并把它映射为 `quality_gate` / `backtest` / `deduplicate` / `submit`。
- `V2_PRIMARY` 当前只是同一个 `FactoryCycleRunner` 的别名，不是新的非漏斗引擎。
- `STRATEGY_FACTORY_EXECUTION_MODE` 默认仍是 `legacy_primary`。
- `STRATEGY_FACTORY_STOCK_FIRST_ROUTER_ENABLED=1` 只代表允许 router，不代表强制 router 生效。
- 当前 Router 依赖 row 上的 `stock_profile.profile_summary`；缺失时静默 fallback 到旧 family 分配。
- 最近一次验证 run 的任务来源已经是 `bulk_stock_matrix`，不是旧 snapshot，但任务 payload 没有 `stock_profile/profile_summary`，所以 Router 没有真正接管 family 选择。

结论：当前系统只是“部分进入逐股矩阵”，还没有完成“删除 Gate 漏斗 + Stock-First 强制路由”。

## 3. 新目标架构

目标运行链路：

```text
Stock Universe / Target Codes
  -> StockRegimeProfile
  -> StockStrategyRouter
  -> 多 family / 多 holding bucket 候选
  -> Observe Pool
  -> Forward Measurement: 5D / 10D / 20D / 40D
  -> Hit-Rate Matrix
  -> PromotionBoundary
  -> 正式策略池 / 实盘候选
```

新的边界定义：

| 阶段 | 是否允许硬阻断 | 说明 |
|---|---:|---|
| ContractGuard | 是 | 只挡结构错误、字段缺失、目标股票错误 |
| LeakageGuard | 是 | 只挡未来函数和数据泄漏 |
| RiskGuard | 是 | 只挡风险越界、实盘风险、不可执行 |
| DedupeGuard | 部分 | 重复策略合并或降权，不应直接吞掉观察样本 |
| BacktestScore | 否 | 只打分、标注、影响观察预算，不阻断 observe |
| Gate-3 盈利筛选 | 否 | 从 observe 前移除 |
| PromotionBoundary | 是 | 只在晋升正式策略池/实盘前执行 |

## 4. 改造阶段

### P0：文档与语义基线

目标：

- 在开发周期计划中明确“删除 Gate 漏斗”。
- 将“Gate”拆成两类概念：
  - `PreObserveGateFunnel`：删除。
  - `Guard / PromotionBoundary`：保留。

验收：

- 文档不再把 `Gate-1/2/3` 描述为 observe 前置准入。
- 文档明确 `Gate-3` 不得阻断观察样本形成。

### P1：Stock-First Router 强制生效

目标：

- 增加严格模式，例如：
  - `STRATEGY_FACTORY_STOCK_FIRST_ROUTER_STRICT=1`
  - `STRATEGY_FACTORY_OBSERVE_FIRST_ENABLED=1`
- 当 strict 开启时，缺少 `profile_summary` 不允许静默 fallback。
- 对 `--codes` 显式目标股票，必须生成或挂载 `StockRegimeProfile`。

验收：

- `router_applied_count > 0`
- `router_fallback_reason_counts` 可见
- strict 模式下 `missing_profile_summary` 直接标记为配置/数据错误，而不是回退旧 family 分配
- 任务 payload 包含 `stock_profile` 或等价 `profile_summary`

### P2：删除 observe 前盈利 Gate

目标：

- 从 observe 入口移除 `Gate-1/2/3` 的硬阻断。
- Backtest、quality scoring、AI review 改为异步评分器，只产生 evidence，不阻断入池。
- `diagnostic_observation` 不再被视为失败或 Gate-3 failed 的副产品，而是正式 observe lane。

验收：

- `pre_observe_hard_reject_count=0`
- `gate3_pre_observe_block_count=0`
- `observed_candidate_count > 0`
- `success_no_strategy` 不再是正常 Stock-First observe run 的主结果

### P3：PromotionBoundary 后置

目标：

- 把严格盈利/稳定性要求放到 observe 之后。
- 晋升正式策略池时才检查：
  - 前向收益样本数
  - hit rate
  - skill_lcb
  - drawdown
  - regime stability
  - leakage/risk/dedupe

验收：

- observe 样本不足时状态为 `observing`，不是 `failed`
- 只有申请 `promoted` / `live_ready` 时才触发硬 PromotionBoundary
- Promotion 失败不删除观察历史，只标注失败原因

### P4：运行模式去 legacy 化

目标：

- 增加明确的新执行模式，例如：
  - `stock_first_observe_primary`
  - `stock_first_observe_shadow`
- 不再用 `legacy_primary` 承载新架构。
- `v2_primary` 不再只是同一个 runner 的别名，或直接弃用这个模式名。

验收：

- run summary 中 `execution_mode=stock_first_observe_primary`
- `cycle_pipeline_stage_order` 不再包含漏斗式 `candidate_governance`
- run artifacts 能清晰区分：
  - router plane
  - observe plane
  - scoring plane

## 7. 风险与控制

风险：删除 Gate 后垃圾候选进入 observe。

控制：

- Contract/Leakage/Risk 仍可硬阻断。
- Backtest/AI review 仍打分，但只影响观察预算和优先级。
- 低分候选进入低预算 observe lane，不进入正式策略池。

风险：observe 样本暴增。

控制：

- 每轮按 stock/router/family/bucket 限额。
- 低置信度候选走 `diagnostic_observation` 或 `low_budget_observe`。
- 重复候选合并为同一 observation thread。

风险：无前向数据时无法晋升。

控制：

- 状态保持 `observing`，不标记失败。
- 等待 5/10/20/40 日前向收益回填。
- PromotionBoundary 只在样本足够后触发。

## 8. 最终验收定义

本调整方案完成的最低标准：

1. Stock-First strict run 不再静默 fallback 到旧 family 分配。
2. 显式目标股票 run 能看到 Router 生效证据。
3. 候选能进入 observe，不被 Gate-3 在前置阶段杀死。
4. run summary 不再以 `success_no_strategy` 掩盖 observe 样本形成失败。
5. Promotion 仍有硬边界，但只发生在 observe 之后。

达到以上标准后，才能说“倒置架构与因子路由”真正摆脱 Gate 漏斗。

## 10. 关键术语定义

### 10.1 必须删除的 Gate Funnel

`PreObserveGateFunnel` 定义为：

```text
candidate generated
  -> quality gate
  -> backtest hard pass
  -> AI validation hard pass
  -> Gate-3 profitability pass
  -> submit / incubate
```

只要一个候选在进入 observe 前因为盈利、胜率、DSR、walk-forward、历史回测稳定性被硬拒，就属于需要删除的 Gate 漏斗。

### 10.2 必须保留的 Guard

`Guard` 不是盈利筛选，而是系统安全边界：

```text
candidate generated
  -> contract / leakage / target / risk / duplicate guard
  -> observe intake
```

Guard 允许硬拒的原因必须限定为：

- 结构不合法，无法序列化或无法执行。
- 数据泄漏、未来函数、时间边界错误。
- target symbols 缺失、越界或与任务不一致。
- 明确交易风险越界，例如实盘风险、仓位越界、流动性不可执行。
- 完全重复且可合并到已有 observation thread。

Guard 不允许因为以下原因硬拒 observe：

- 当前历史回测胜率不足。
- 当前 DSR 不足。
- 当前 walk-forward 不稳定。
- 当前 AI 评分偏低。
- 当前样本不足。

这些只能进入 scoring / budget / priority，不得阻断观察样本形成。

### 10.3 PromotionBoundary

`PromotionBoundary` 只在观察后触发：

```text
observing
  -> enough forward samples
  -> promotion review
  -> promoted / rejected / keep_observing
```

Promotion 可以硬拒，但不得删除 observe 历史，也不得把 observe 失败等同于 candidate 生成失败。

## 11. P1 详细方案：Router Strict 与画像接线

P1 是最高优先级。没有 P1，P2 observe-first 只会扩大旧 family 分配的噪声。

### 11.1 新增 toggle

建议新增：

```text
STRATEGY_FACTORY_STOCK_FIRST_ROUTER_STRICT=0
STRATEGY_FACTORY_OBSERVE_FIRST_ENABLED=0
STRATEGY_FACTORY_ROUTER_TELEMETRY_ENABLED=1
```

语义：

- `STOCK_FIRST_ROUTER_ENABLED=1`：允许 router。
- `STOCK_FIRST_ROUTER_STRICT=1`：router 必须生效，缺画像不得静默 fallback。
- `OBSERVE_FIRST_ENABLED=1`：候选进入 observe 前不执行盈利硬 Gate。
- `ROUTER_TELEMETRY_ENABLED=1`：即使非 strict，也输出 fallback 原因。

### 11.2 profile_summary 契约

每个进入 Stock-First Router 的 row 至少需要：

```json
{
  "stock_profile": {
    "metadata": {
      "profile_summary": {
        "profile_quality": "good|partial|low_confidence|failed",
        "regime": {
          "trend_regime": "trend_up|trend_down|range|unknown",
          "vol_regime": "high_vol|normal_vol|low_vol|unknown",
          "sentiment_regime": "fear|greed|neutral|unknown"
        },
        "factor_dimension_scores": {
          "trend": 0.0,
          "reversal": 0.0,
          "valuation": 0.0,
          "quality": 0.0,
          "growth": 0.0
        },
        "feature_coverage": {
          "technical_price_volume": "ok|partial|missing",
          "valuation_financial": "ok|partial|missing",
          "alternative_sentiment_capital_flow": "ok|partial|missing",
          "event_news_notice_research_theme": "ok|partial|missing"
        },
        "recommended_families": [],
        "candidate_factor_families": []
      }
    }
  }
}
```

兼容老结构：

```json
{
  "stock_profile": {
    "profile_summary": {}
  }
}
```

但新代码应优先写入 `metadata.profile_summary`。

### 11.3 strict 模式行为

| 条件 | 非 strict | strict |
|---|---|---|
| router toggle off | 使用旧逻辑 | 不允许进入 stock-first strict run |
| profile missing | fallback，记录原因 | 当前股票任务标记 profile_missing，不生成旧 family 任务 |
| profile_quality=failed | fallback，记录原因 | 当前股票任务进入 profile_failed，不生成旧 family 任务 |
| router exception | fallback，记录异常类型 | 当前 run 标记 router_error，失败或降级为 shadow |
| routed families empty | fallback multi_factor | 生成 conservative observe task，并记录 low_confidence |

strict 模式不能静默退回：

```text
sector bias -> base family order -> feedback allocation
```

否则运行结果仍会表现成旧漏斗。

### 11.4 P1 必须新增指标

```json
{
  "router_enabled": true,
  "router_strict": true,
  "router_applied_count": 0,
  "router_candidate_stock_count": 0,
  "profile_summary_present_count": 0,
  "profile_summary_missing_count": 0,
  "router_fallback_reason_counts": {
    "missing_profile_summary": 0,
    "profile_failed": 0,
    "router_exception": 0,
    "empty_routed_families": 0
  },
  "router_family_counts": {},
  "router_holding_bucket_counts": {}
}
```

P1 验收失败条件：

- strict run 里出现旧 family fallback 但没有 reason。
- `router_applied_count=0` 且 run 仍然标记 success。
- `profile_summary_missing_count>0` 但任务仍生成 `macro_timing` / `quality_factor` 等旧 allocation 任务。

## 12. P2 详细方案：Observe-First Intake

P2 的目标不是绕过所有评估，而是把评估从“阻断”改成“证据”。

### 12.1 新 stage 语义

旧 stage：

```text
research_generation -> candidate_governance -> elimination -> finalize
```

新 stage：

```text
research_generation
  -> observe_intake
  -> evidence_scoring
  -> promotion_review
  -> elimination
  -> finalize
```

其中：

- `observe_intake`：只做 ContractGuard / LeakageGuard / RiskGuard / DedupeGuard。
- `evidence_scoring`：运行 backtest、AI validation、target alignment，但只写 evidence。
- `promotion_review`：只处理已有足够前向样本并申请晋升的 observation。

### 12.2 Observe lane

建议引入或稳定以下 lane：

| lane | 含义 | 是否正式观察样本 |
|---|---|---:|
| `observe` | 正常观察 | 是 |
| `low_budget_observe` | 低置信度、小预算观察 | 是 |
| `diagnostic_observation` | 诊断观察，用于数据/路由验证 | 是 |
| `blocked_contract` | 结构错误 | 否 |
| `blocked_leakage` | 数据泄漏 | 否 |
| `blocked_risk` | 风险越界 | 否 |
| `merged_duplicate` | 合并到已有观察线程 | 视合并结果 |

`diagnostic_observation` 必须从“Gate 失败残余 lane”改成“正式观察 lane”。

### 12.3 BacktestScorer 输出

Backtest 不再输出 hard pass/fail 给 observe intake，而是输出：

```json
{
  "backtest_score": 0.0,
  "backtest_confidence": "high|medium|low|insufficient",
  "backtest_warnings": [],
  "historical_metrics": {},
  "budget_recommendation": "normal|low|diagnostic|hold",
  "promotion_ready_hint": false
}
```

注意：

- `budget_recommendation=hold` 只能影响预算或优先级。
- 不能阻止 candidate 进入 observe，除非同时触发 Contract/Leakage/Risk。

```json
  "dedupe_guard": {}
}
```

### 13.2 晋升结果

```json
{
  "promotion_status": "promoted|rejected|keep_observing",
  "promotion_reasons": [],
  "sample_sufficiency": "enough|insufficient",
  "next_review_after": "2026-06-10",
  "preserve_observation_history": true
}
```

Promotion 拒绝不等于策略生成失败：

- `rejected`：不晋升，但保留历史。
- `keep_observing`：样本不足，继续观察。
- `promoted`：进入正式策略池或实盘候选后，再受交易风控约束。

## 14. P4 详细方案：新执行模式

当前 `legacy_primary` 会继续制造误解。建议新增：

```python
class FactoryExecutionMode(str, Enum):
    LEGACY_PRIMARY = "legacy_primary"
    SHADOW_READONLY = "shadow_readonly"
    V2_PRIMARY = "v2_primary"
    STOCK_FIRST_OBSERVE_PRIMARY = "stock_first_observe_primary"
    STOCK_FIRST_OBSERVE_SHADOW = "stock_first_observe_shadow"
```

行为：

| execution mode | 用途 | 是否允许旧 Gate 漏斗 |
|---|---|---:|
| `legacy_primary` | 旧兼容 | 是 |
| `v2_primary` | 兼容别名或弃用 | 不建议继续使用 |
| `stock_first_observe_shadow` | 影子验证，不写正式池 | 否 |
| `stock_first_observe_primary` | 正式新路径 | 否 |

新模式启动时必须自动设置或校验：

```text
STOCK_FIRST_ROUTER_ENABLED=1
STOCK_FIRST_ROUTER_STRICT=1
OBSERVE_FIRST_ENABLED=1
```

若缺少这些条件，run 应返回配置错误，而不是悄悄进入 legacy 路径。

## 17. 灰度上线与回滚

### 17.1 灰度顺序

| 阶段 | toggle | 范围 |
|---|---|---|
| G0 | telemetry only | 只记录 router fallback 和 gate block |
| G1 | router strict shadow | `--codes` 小样本，不写正式池 |
| G2 | observe-first shadow | observe artifact 落库，但不影响正式 submit |
| G3 | observe-first primary | 小股票池正式启用 |
| G4 | full stock-first primary | 扩大 universe |

### 17.2 回滚策略

任何阶段出现以下情况应回滚到上一阶段：

- Contract/Leakage/Risk 被绕过。
- observation 写入异常导致数据库污染。
- `profile_summary_missing_count` 大面积上升。
- observe 样本数暴涨超过预算上限。
- promotion 错误地绕过硬边界。

回滚方式：

```text
STRATEGY_FACTORY_OBSERVE_FIRST_ENABLED=0
STRATEGY_FACTORY_STOCK_FIRST_ROUTER_STRICT=0
STRATEGY_FACTORY_EXECUTION_MODE=legacy_primary
```

回滚不删除已生成 observe 历史，只停止新路径继续写入。

## 18. 依赖顺序与不可跳过项

不可跳过：

1. `profile_summary` 接线。
2. router strict telemetry。
3. observe lane 落库语义。
4. Gate-3 前置阻断解除。
5. PromotionBoundary 后置。

可以后置：

- 新 execution mode 的完整 UI 展示。
- 大规模 universe 启用。
- 40D 长周期命中率报表。
- LLM 路由增强。

不能先做：

- 不能先删除 submitter / submission_gate 模块。
- 不能先把所有 candidate 直接写正式策略池。
- 不能在没有 router telemetry 的情况下启用 observe-first。
- 不能在 profile 缺失时把旧 family fallback 结果当作 Stock-First 成功。

## 19. 最小可交付切片

第一批最小可交付应只包含：

1. 新增 strict toggle。
2. `profile_summary` 缺失显式计数。
3. Router 成功/失败/fallback artifact。
4. `--codes 600519 000001` 能生成 router-applied 任务。
5. observe 前 Gate-3 不再硬拒这批任务。
6. run summary 明确输出 observe-first 指标。

第一批不追求：

- 全市场启用。
- 立即有策略晋升。
- 立即有 20D/40D 命中率。
- 完全删除旧 legacy 流程。

第一批目标只有一个：**证明 Stock-First 候选可以不经过 Gate 漏斗进入观察，并留下可复核证据。**
