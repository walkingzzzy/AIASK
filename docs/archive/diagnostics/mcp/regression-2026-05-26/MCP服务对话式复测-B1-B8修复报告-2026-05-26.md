## 🔍 根因合并

8 个 bug 实际上是 **3 类** 同源问题:

### 类一:`stocks` 表列名错配(B3 + B4 + B8)
- **真实 schema**: `stock_code, stock_name, ...`(无 `code` 列)
- **错误代码**: `SELECT code FROM stocks` / `WHERE code <> $1`
- **影响**: 所有同行业查询、relative_pe、search LIKE fallback 全部 silent OperationalError

### 类二:数据库 schema 假设错误(B6 + B7)
- B6: `dragon_tiger_list` 表不存在(实际 `dragon_tiger`)+ `date`/`period` 列名错(实际全是 `trade_date`)
- B7: `users` 表无 `user_id` `source` 列(实际 `id, username, email, settings, ...`)
- **共同点**: 旧代码用了"假设的 schema"而非真实 schema,silent except 让错误隐身

### 类三:边界条件缺失(B1 + B2 + B5)
- B1: 6 位代码同时是个股+指数(000001 = 平安银行 + 上证指数),缺路由
- B2: EM 仅返回 1 条数据时,`prev_shares=0` 导致 `change=latest_shares`
- B5: ACTION_MAPPING 缺 `avoid` / `strong_sell` / `reject` 等高频上游 raw_action

# 修复:
#   1. 接受 sh000001 / sz399001 / 000001.sh / 000001.SH 等带前缀格式
