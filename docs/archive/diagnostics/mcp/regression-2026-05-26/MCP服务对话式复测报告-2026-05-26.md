## 🆕 新发现的 8 个 bug(原 76 项之外)

### B1: `get_kline("000001")` 返回平安银行而非上证指数 🔴 严重
- **现象**: 返回 close=10.68 / 10.86(平安银行价)而非上证指数 ~4112
- **根因**: schema 层格式校验只接受 6 位数字,`get_kline("sh000001")` 被拒;AI 用 "000001" 永远拿到平安银行
- **影响**: 所有市场情绪 / 指数对标 / 大盘判断工具全部错位
- **复现**: §2.2 跨场景 2 次复现(S20-F04 / S22-F03)
- **建议**: schema 增加 `code_type` enum (stock / index),或前缀路由(sh/sz)

### B2: `get_north_fund_holding.change` 在仅 1 条数据时计算错误 🟠
- **现象**: `change=58733069` 等于 `shares=58733069`(应是季度环比变化值)
- **根因**: EM 接口仅返回最新季度 1 条数据时,no prior period for diff,代码 fallback 把 change 设为 shares 而非 None
- **建议**: 当 prior_period_data is None 时,`change` 应为 null + `change_semantics: "no_prior_period"`

### B3: `valuation_consensus.relative_pe` 报 `OperationalError: no such column: code` 🔴
- **现象**: meta-tool 框架 OK,但 3 个估值器中 relative_pe 报 db schema 列名错误
- **根因**: 表 schema 列名变更(可能是 `stock_code` 改 `code` 或反向),代码与 db 不同步
- **建议**: 检查 `relative_valuation` 涉及的表,统一列名 + 加入 migration

### B4: `get_factor_profile.industry_total = 1` 🟡
- **现象**: 应为酿酒行业 ~36 只,实际只算到 1 只(自身)
- **根因**: §5.12 的 search_stocks fallback 没生效(可能是 industry 字段空字符串 / "酿酒" 没匹配到 industry_classification 表)
- **建议**: 排查 industry name 标准化(全行业字典表)

### B5: `decision_consensus` 4/5 决策工具 unavailable + raw_action 映射不全 🟠
- **现象**:
  - `tools_queried=2 / tools_available=1`,4 个 decision 工具没启用
  - `should_i_buy` 标 `available: false` 但 raw_action="avoid"(应该 normalize 到 sell)
- **根因**: meta-tool 的 raw_action mapping 表只有 buy/sell/hold,没处理 avoid/strong_buy/strong_sell
- **建议**: 扩展 ACTION_MAPPING,加入 `avoid → sell` / `strong_buy → buy` / `strong_sell → sell`

### B6: `data_sync_manager.status.critical_table_stale_alerts` query_failed 5/5 🟠
- **现象**: 5 个表 (north_fund_flow / north_fund_holding / margin_market_flow / margin_detail / dragon_tiger_list) 全报 `reason: "query_failed:OperationalError"`
- **根因**: 表 schema 不匹配查询 SQL(可能是 max(date) 字段名不同),alerts 列表逻辑生效但执行失败
- **建议**: 检查 `_get_critical_tables_max_date()` 函数对每张表的 SQL,统一日期字段名(date / trade_date / report_date)

### B7: `update_user_profile.user_upserted=true` 但 `user_manager.list` 看不到 🟡
- **现象**:
  - `update_user_profile(user_id=codex_full_mcp_20260522)` 报 `user_upserted: true`
  - 但 `user_manager.list` 只显示 1 个 user (default)
- **根因**: update_user_profile 的 user_upserted 写到 `user_profile_snapshots` 表 而非 `users` 表
- **建议**: update_user_profile 入口应先 ensure user 存在于 users 表,再写 snapshot

### B8: `search_stocks("五粮液")` 0 命中,`search_stocks("五 粮 液")` 才命中 🔴
- **现象**: 中文公司名 db 里存为 `"五 粮 液"`(带空格),用户搜 `"五粮液"`(无空格)0 命中
- **根因**: `search.search_stocks` LIKE 查询没做空白字符 normalization
- **建议**: 数据库 stock_name 加 normalized 列(`REPLACE(name, ' ', '')`),或 query 同步 normalize
