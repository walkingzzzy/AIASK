# 因子挖掘工厂 (Factor Mining Factory) 设计方案

> 定位：与策略工厂 (Strategy Factory)、孵化工厂 (Incubation Factory) 并行的第三大核心引擎
> 设计理念：借鉴 Chain-of-Alpha 双链架构、Hubble AST 沙箱、AlphaAgent 抗衰减正则化、CogAlpha 多Agent进化搜索
> 目标：从"LLM 猜测 + 统计验证"升级为"多引擎自动化搜索 + 进化优化 + 闭环反馈"的工业级因子生产线

### 4.2 LLM 搜索引擎（升级现有实现）

```python
class LLMSearchEngine(SearchEngine):
    """
    升级方向：
    1. 多模型支持（不再单一 provider）
    2. Chain-of-Alpha 双链：Generation Chain + Optimization Chain
    3. 反馈注入：将验证结果作为 few-shot 示例
    4. temperature 自适应：初期高探索(0.7)，后期低精炼(0.2)
    """

    async def generate(self, context: MiningContext, budget: SearchBudget) -> list[FactorCandidate]:
        # Phase 1: Generation Chain — 高 temperature 广泛探索
        raw_candidates = await self._generation_chain(context, temperature=0.6)

        # Phase 2: Optimization Chain — 低 temperature 精炼优化
        refined = await self._optimization_chain(raw_candidates, context, temperature=0.2)

        return refined

    async def _generation_chain(self, context, temperature):
        """生成链：市场假设 → 因子表达式。"""
        # 1. 市场状态分析 → 生成研究假设
        hypotheses = await self._generate_hypotheses(context)
        # 2. 假设 → DSL 表达式
        candidates = await self._hypotheses_to_factors(hypotheses, temperature=temperature)
        return candidates

    async def _optimization_chain(self, candidates, context, temperature):
        """优化链：验证反馈 → 迭代精炼。"""
        for round_idx in range(3):  # 最多 3 轮精炼
            # 快速验证
            scores = await self._quick_validate(candidates, context)
            # 将验证结果反馈给 LLM 精炼
            candidates = await self._refine_with_feedback(candidates, scores, temperature)
        return candidates
```

```python
class GeneticProgrammingEngine(SearchEngine):
    """
    遗传规划因子搜索 — 参考 AlphaGen + WorldQuant BRAIN。

    核心思想：将因子表达式表示为表达式树，通过变异/交叉/选择进化。
    优势：无需 LLM，可在巨大搜索空间中自动发现非直觉因子。
    """

    def __init__(self, population: int = 200, generations: int = 50):
        self.population_size = population
        self.max_generations = generations
        self.operators = list(SUPPORTED_FACTOR_FUNCTIONS)
        self.terminals = list(SUPPORTED_FACTOR_FIELDS)

    async def generate(self, context: MiningContext, budget: SearchBudget) -> list[FactorCandidate]:
        # 1. 初始化种群（随机表达式树 + 种子因子）
        population = self._initialize_population(context.seed_factors)

        # 2. 进化循环
        for gen in range(self.max_generations):
            # 适应度评估（快速 IC 计算）
            fitness = await self._evaluate_fitness(population, context.validation_data)

            # 选择（锦标赛选择 + 精英保留）
            parents = self._tournament_select(population, fitness)

            # 交叉 + 变异
            offspring = self._crossover(parents)
            offspring = self._mutate(offspring)

            # 新颖性压力：惩罚与已有因子过于相似的个体
            offspring = self._apply_novelty_pressure(offspring, context.active_pool)

            # 替换
            population = self._survivor_selection(population, offspring, fitness)

        # 3. 返回 top-K
        return self._extract_top_candidates(population, k=budget.candidate_count)

    def _mutate(self, individuals):
        """变异操作：
        - 点变异：替换一个节点（算子/终端）
        - 子树变异：替换一个子树
        - 常数扰动：微调数值常数
        - 收缩变异：简化过复杂的子树
        """

    def _crossover(self, parents):

        - 子树交叉：交换两个父代的子树
        - 语义交叉：基于输出相似度的智能交叉
```

### 4.4 强化学习引擎

```python
class RLAlphaGenEngine(SearchEngine):
    """
    强化学习因子生成 — 参考 AlphaGen (RL-MLDM)。

    将因子生成建模为序列决策问题：
    - State: 当前部分表达式 + 市场特征
    - Action: 选择下一个 token（算子/字段/常数）
    - Reward: 因子的 IC/ICIR + 新颖性奖励 - 复杂度惩罚

    优势：可以学习"什么样的因子结构更容易成功"。
    """

    async def generate(self, context: MiningContext, budget: SearchBudget) -> list[FactorCandidate]:
        # 使用训练好的 policy 网络生成因子
        candidates = []
        for _ in range(budget.candidate_count * 3):  # 过采样
            expression = self._rollout_policy(context.state_features)
            if self._is_valid_expression(expression):
                candidates.append(expression)
        return candidates[:budget.candidate_count]
```

### 4.5 MCTS 引导搜索引擎

```python
class MCTSSearchEngine(SearchEngine):
    """
    蒙特卡洛树搜索 — 参考 AlphaCFG 框架。

    使用上下文无关文法 (CFG) 定义搜索空间，
    MCTS 在语法树上进行探索，LLM 提供 value/policy 先验。

    优势：结构化搜索，避免无效表达式，LLM 引导加速收敛。
    """

    async def generate(self, context: MiningContext, budget: SearchBudget) -> list[FactorCandidate]:
        root = self._build_grammar_tree()

        for sim in range(self.simulations):
            # Selection: UCB1 选择
            node = self._select(root)
            # Expansion: 按文法规则展开
            child = self._expand(node)
            # Simulation: LLM 评估 + 快速回测
            reward = await self._simulate(child, context)
            # Backpropagation
            self._backpropagate(child, reward)

        # 频繁子树回避：避免重复搜索已知区域
        return self._extract_best_paths(root, k=budget.candidate_count)
```

### 5.1 进化循环设计

```python
class EvolutionaryOptimizer:
    """
    因子进化优化器 — 参考 CogAlpha 多Agent进化 + AlphaAgent 抗衰减正则化。

    核心机制：
    1. 新颖性压力 (Novelty Pressure): AST 结构相似度惩罚
    2. 假设-因子对齐 (Hypothesis-Factor Alignment): LLM 评估语义一致性
    3. 复杂度控制 (Complexity Control): AST 结构约束防止过拟合
    4. 多样性维护 (Diversity Maintenance): MAP-Elites 风格的行为空间覆盖
    """

    async def evolve(
        self,
        candidates: list[FactorCandidate],
        context: MiningContext,
        generations: int = 5,
    ) -> list[FactorCandidate]:
        population = candidates

        for gen in range(generations):
            # 1. 适应度评估（多目标）
            fitness = await self._multi_objective_fitness(population, context)

            # 2. 新颖性过滤：AST 相似度 < 0.85 才保留
            population = self._novelty_filter(population, context.active_pool)

            # 3. 变异操作（多种变异算子）
            mutants = self._apply_mutations(population, context)

            # 4. LLM 精炼（对 top 候选做语义优化）
            if gen < 3:
                top_k = sorted(population, key=lambda x: x.fitness, reverse=True)[:5]
                refined = await self._llm_refine(top_k, context)
                mutants.extend(refined)

            # 5. 选择（NSGA-II 多目标选择）
            population = self._nsga2_select(population + mutants, size=len(candidates))

        return population

    def _multi_objective_fitness(self, population, context):
        """多目标适应度：
        - Objective 1: Rank IC (越高越好)
        - Objective 2: IC IR (越高越好)
        - Objective 3: 与活跃池的最大相关性 (越低越好 → 新颖性)
        - Objective 4: 复杂度 (越低越好 → 简洁性)
```

### 7.1 活跃因子池

```python
class ActiveFactorPool:
    """
    活跃因子池 — 因子挖掘工厂的核心产出物。

    生命周期：candidate → validated → active → decaying → retired
    """

    MAX_POOL_SIZE = 200          # 最大活跃因子数
    ORTHOGONALITY_THRESHOLD = 0.7  # 因子间最大相关性
    DECAY_ALERT_THRESHOLD = 0.3    # IC 衰减 30% 触发警报
    RETIRE_THRESHOLD = 0.5         # IC 衰减 50% 自动退役

    async def admit(self, candidate: ValidatedFactor) -> AdmissionResult:
        """因子入池审核。"""
        # 1. 正交化检查：与池中所有因子的相关性 < 0.7
        max_corr = await self._max_correlation_with_pool(candidate)
        if max_corr > self.ORTHOGONALITY_THRESHOLD:
            return AdmissionResult(admitted=False, reason="redundant", max_correlation=max_corr)

        # 2. 增量信息比检查：加入后组合 IR 是否提升
        marginal_ir = await self._marginal_information_ratio(candidate)
        if marginal_ir < 0.05:
            return AdmissionResult(admitted=False, reason="no_marginal_value")

        # 3. 容量检查：池未满或可替换最弱因子
        if len(self.active_factors) >= self.MAX_POOL_SIZE:
            weakest = self._find_weakest_factor()
            if candidate.score > weakest.score:
                await self._retire(weakest, reason="replaced")
            else:
                return AdmissionResult(admitted=False, reason="pool_full")

        # 4. 入池
        await self._add_to_pool(candidate)
        return AdmissionResult(admitted=True)

    async def daily_maintenance(self):
        """每日维护：衰减检测 + 自动退役。"""
        for factor in self.active_factors:
            decay = await self._measure_decay(factor)
            if decay > self.RETIRE_THRESHOLD:
                await self._retire(factor, reason="decay_exceeded")
            elif decay > self.DECAY_ALERT_THRESHOLD:
                await self._alert_decay(factor, decay)
                # 触发因子挖掘工厂补充搜索
                await self._request_replacement_search(factor)
```

### 7.2 因子正交化器

```python
class FactorOrthogonalizer:
    """因子正交化 — 确保因子池中的因子提供独立信息。"""

    async def orthogonalize(self, new_factor: pd.Series, pool_factors: pd.DataFrame) -> OrthogonalResult:
        """
        Gram-Schmidt 正交化：
        将新因子对池中所有因子做回归残差，
        残差即为新因子的独立信息贡献。
        """
        residual = new_factor.copy()
        projections = {}

        for col in pool_factors.columns:
            existing = pool_factors[col].dropna()
            aligned = pd.concat([residual, existing], axis=1).dropna()
            if len(aligned) < 30:
                continue
            # 回归残差
            beta = aligned.iloc[:, 0].corr(aligned.iloc[:, 1])
            residual = residual - beta * existing
            projections[col] = beta

        # 残差的 IC 即为增量贡献
        residual_ic = residual.corr(context.forward_returns, method='spearman')

        return OrthogonalResult(
            residual=residual,
            residual_ic=residual_ic,
            projections=projections,
            independent_ratio=residual.std() / new_factor.std(),
        )
```

```python
class DecayMonitor:
    """
    因子衰减监控 — 持续追踪活跃因子的预测力变化。

    当检测到衰减时，自动触发因子挖掘工厂的补充搜索。

    async def daily_check(self, pool: ActiveFactorPool) -> DecayReport:
        decaying_factors = []
        for factor in pool.active_factors:
            # 计算滚动 IC
            recent_ic = await self._rolling_ic(factor, window=20)
            historical_ic = factor.admission_ic

            decay_rate = 1.0 - (recent_ic / historical_ic) if historical_ic > 0 else 0.0

            if decay_rate > 0.3:
                decaying_factors.append(DecayAlert(
                    factor=factor,
                    decay_rate=decay_rate,
                    estimated_half_life=self._estimate_half_life(factor),
                    replacement_urgency=self._urgency_score(factor, decay_rate),
                ))

        # 触发补充搜索
        if decaying_factors:
            await self._trigger_replacement_mining(decaying_factors)

        return DecayReport(decaying=decaying_factors)
```

## 十四、关键设计决策

### 14.1 为什么放在 akshare-mcp 内部而非独立包？

1. **对齐孵化工厂**：`incubation_factory/` 已经是 akshare-mcp 的子包，因子工厂应保持同级
2. **数据依赖**：因子挖掘的所有数据源（K线、财务、新闻、资金流）都在 akshare-mcp 中
3. **避免循环依赖**：如果独立包，需要同时被 akshare-mcp（数据）和 strategy-factory（消费）依赖，形成菱形依赖
4. **共享存储**：使用同一个 SQLite 数据库，无需跨包 DB 访问
5. **现有模式**：策略工厂通过 `mcp_services.py` 懒加载 akshare-mcp 服务，因子工厂沿用此模式

### 14.2 为什么需要多引擎而非只用 LLM？

| 引擎 | 优势 | 劣势 | 适用场景 |
|------|------|------|----------|
| LLM | 理解经济学语义，可解释性强 | 搜索空间受限于训练知识 | 假设驱动的因子设计 |
| GP | 搜索空间巨大，可发现非直觉因子 | 可解释性差，收敛慢 | 广泛探索未知区域 |
| RL | 可学习"什么结构更好"，效率高 | 需要训练数据，冷启动难 | 稳定期的高效搜索 |
| MCTS | 结构化搜索，避免无效表达式 | 计算量大 | 深度搜索特定方向 |

## 十五、代码审查发现的额外约束

### 15.1 `_fragment_loader` 模式要求

现有大类（如 `FactorScheduler`、`StrategyIncubationMixin`）使用 `_fragment_loader.exec_block()` 拆分为多文件。因子挖掘工厂的大类也应遵循此模式：

```python
# factor_mining_factory/scheduler.py
from akshare_mcp._fragment_loader import exec_block as _exec_block

_exec_block(
    globals(),
    'scheduler_parts',
    'class FactorMiningFactoryScheduler:\n',
    ['context.py', 'mining_cycle.py', 'maintenance.py'],
    future_annotations=False,
)
```

### 15.2 因子种子系统兼容

现有 `factor_candidate_seed.py` 维护了一套核心因子的 DSL 表达式映射（`_EXPRESSION_BY_FACTOR`），包含 momentum、trend、reversal 等。因子挖掘工厂的 `rule_engine.py` 应复用此种子池作为初始种群。

### 15.3 `factor_enrichment.py` 复用

现有 `factor_enrichment.py` 已实现：
- `_compute_originality_score()` — 基于 Jaccard 的新颖性评分
- `_compute_complexity_score()` — 复杂度评分
- `_estimate_crowding_proxy()` — 拥挤度估计
- `_compute_hypothesis_alignment()` — 假设对齐度

这些功能与进化优化层的新颖性压力、复杂度控制高度重叠。应直接复用而非重新实现。

### 15.4 `quant_manager` 动作注册

现有因子操作通过 `quant_manager(action="llm_factor_mining")` 等动作暴露。因子挖掘工厂应注册新动作：

```python
# 新增动作

"factor_pool_admit"         # 手动入池
"factor_pool_retire"        # 手动退役
"factor_mining_cycle"       # 触发一次挖掘周期
"factor_evolution_run"      # 触发进化优化
```
