# 文档维护规范

本文用于防止仓库再次回到“主入口混杂、历史长文平铺、读者不知道先看哪份”的状态。

## 文档状态

| 状态 | 放置位置 | 用途 |
| --- | --- | --- |
| 当前导读 / 规范 | `docs/` | 项目入口、接入说明、协作规范 |
| 当前协议 | `docs/plans/` | 稳定对象协议、当前仍需直接引用的契约 |
| 当前专题入口 | 根目录专题目录（如 `策略工厂/`） | 某条主线仍在持续演进的导读与当前清单 |
| 历史方案 | `docs/plans/archive/` | 旧方案、旧规划、研究蓝图 |
| 时点性审计 / 阶段记录 | `docs/archive/` | 带日期的审计、修复说明、阶段复盘、根目录迁入材料 |
| 静态资源 | `docs/screenshots/` 等资源目录 | 截图、JSON 输出、附件 |

## 新文档准入规则

只有满足下面任一条件，才建议新建独立文档：

1. 需要沉淀稳定协议或跨团队约束。
2. 需要承载一条当前仍在执行的独立主线。
3. 需要保留可复核的审计或盘点证据。
4. 现有文档无法通过增量更新覆盖该主题。

以下情况不要新开长文：

1. 只是某次临时讨论记录。
2. 只是把已有方案换种说法重写一遍。
3. 只是某个 PR 的局部 TODO。

## 新文档必须具备的信息

每篇文档开头建议至少包含：

1. 文档角色：导读、规范、协议、方案、审计、研究蓝图中的哪一种。
2. 适用范围：面向哪个目录、模块、时间窗口。
3. 校准说明：哪些结论是时点性的，哪些需要和当前代码重新核实。
4. 阅读方式：谁应该读，先读什么，再读什么。

当文档超过约 `400` 行时，必须在开头给出简短摘要，不要让读者先掉进细节。

## 放置规则

1. `docs/README.md` 只做导读，不承载长篇实施细节。
2. `docs/plans/README.md` 只做方案导航，不承载完整方案正文。
3. 当前仍直接执行的协议放 `docs/plans/`。
4. 已经退到背景材料的方案放 `docs/plans/archive/`。
5. 带日期的专项审计、阶段修复记录、根目录迁入材料放 `docs/archive/`。
6. 截图和自动产物放资源目录，不和主文档混排。

## 归档触发条件

出现以下任一情况时，应考虑归档：

1. 文档已经被新入口替代。
2. 文档明显依赖某个历史代码快照或审计日期。
3. 文档不再作为当前任务拆解入口，只剩背景价值。
4. 主入口开始出现“新同学不知道先看哪份”的现象。

## 链接规则

1. 被其他目录广泛引用的文档，移动前先核对引用方。
2. 如果某个历史文档必须保留原路径，应在导读中明确标记其历史身份。
3. 路径变更后，优先更新导读和 README，不要只移动文件不修入口。
