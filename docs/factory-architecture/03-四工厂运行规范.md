# 四工厂运行规范

## Supervisor 定位

当前正式 supervisor 是 `scripts/factories/run_three_factories.py`。虽然文件名仍为 `three_factories`，它实际启动四个运行体：

- `strategy_factory`
- `factor_mining_factory`
- `incubation_factory`
- `market_event_ingest`

`scripts/factories/run_all_factories.py` 是兼容入口，保留旧 operator 习惯，但委托给 `run_three_factories.py`。Supervisor 只负责进程生命周期，不拥有业务补偿逻辑。

命名现状需要诚实记录：`run_three_factories.py` 是历史文件名，当前代码注释和 `REQUIRED_SCRIPTS` 已按四运行体工作。规范推荐后续新增或迁移到 `run_four_factories.py`，并保留旧文件作兼容 wrapper；在代码未迁移前，文档引用必须同时说明“文件名是历史债，实际启动四运行体”。

## Strategy Factory

### 业务使命

Strategy Factory 是策略生产线的主编排者。它把市场上下文、事件、因子、LLM/staged pipeline、历史孵化反馈转化为候选策略，并决定候选进入 formal、observe、paper、diagnostic 还是 rejected。

### 工程目标

- 持续生成可追溯 candidate artifact。
- 执行 admission、quality gate、dedupe、readiness 和 submission。
- 保持 observe-first、stock-first、strict-gated 等模式的状态语义一致。
- 把 lifecycle handoff 写成证据，而不是只写日志。

### 输入输出契约

| 项 | 规范 |
| --- | --- |
| runner | `scripts/factories/run_strategy_factory.py` |
| 领域包 | `packages/strategy-factory` |
| 主要输入 | 市场数据、事件 anchor、因子池、incubation feedback、runtime providers、target codes/universe、LLM provider |
| 主要输出 | factory run result、candidate artifacts、strategy rows、submission/admission metadata、observe/paper/diagnostic handoff |
| 成功标准 | cycle status 可解释；candidate/gate/readiness 漏斗完整；底层 partial/timeout 不被 success 掩盖 |
| 非目标 | AKShare 具体数据源实现、SignalTracker sidecar 调度、production live trading 默认写入 |

### 健康 SLO

- 每轮必须输出 run status、candidate counts、gate counts、admission counts、error/timeout/partial reason。
- `partial_infra`、`failed`、runtime timeout、LLM fallback 必须进入质量报告。
- `submitted` 必须拆分口径，不能用一个 0 掩盖 observe/paper/audit-only 入口。
- 若 factor mining 被跳过，必须标注 fresh factor generation/consumption 未验证。

### 失败模式

| 失败 | 定位 |
| --- | --- |
| LLM timeout/fallback | `strategy_pipeline.py`、LLM provider runtime、generation budget |
| Gate 通过但无 handoff | admission/submission coordinator 与 lifecycle coordinator |
| `success=True` 覆盖 partial | run status resolver / quality collector |
| formal evidence debt | statistical robustness、deflated sharpe、PBO、WRC、SPA、win rate 证据缺口 |

## Factor Mining Factory

### 业务使命

Factor Mining Factory 是策略生产线的 alpha 原料工厂。它不直接晋级策略，而是持续发现、验证、维护可复用因子，让 Strategy Factory 的生成和解释不只依赖 LLM 叙事。

### 工程目标

- 使用多引擎搜索候选因子，包括 LLM、GP、MCTS、RL、rule seed 等当前实现。
- 对候选执行 schema/sandbox/quick evidence/strict validation/QC。
- 维护 active factor pool，保留 family、regime/profile、IC、forward horizon、freshness 和 admission/rejection reason。

### 输入输出契约

| 项 | 规范 |
| --- | --- |
| runner | `scripts/factories/run_factor_mining_factory.py` |
| 服务目录 | `packages/akshare-mcp/src/akshare_mcp/services/factor_mining_factory/` |
| 主要输入 | SQLite-backed 市场数据、factor catalog、profile/regime、engine 配置、validation universe |
| 主要输出 | factor candidates、validation evidence、QC labels、active factor pool、rejection/quarantine reason |
| 成功标准 | 每轮报告 engine 使用、raw/quick/validated/accepted 数、QC/validation 结果、pool 状态和 degraded reason |
| 非目标 | Strategy Factory 候选准入、promotion gate、live trading |

### 健康 SLO

- 不能静默零产出；零候选、零验证、零入池都必须有原因。
- LLM 生成因子不能绕过 schema/sandbox/QC/validation 直接进入 active pool。
- 数据不足、profile/regime 缺失、engine timeout 应标为 degraded/skipped reason。
- active pool 维护必须能解释 promoted、quarantine、decaying、retired。

### 失败模式

| 失败 | 定位 |
| --- | --- |
| `factor_mining_not_run` | supervisor/quality session 是否跳过，runner 是否启动 |
| raw candidates 多但 accepted 为 0 | quick evidence、strict validation、QC thresholds |
| 因子入池但 Strategy 不消费 | factor pool provider 与 Strategy runtime provider |
| 因子证据过时 | active pool maintenance / freshness |

## Incubation Factory

### 业务使命

Incubation Factory 是策略生产线的验证工厂。它接收 Strategy Factory 进入 observe/paper/diagnostic 的策略，把它们推进为 signal、paper order、trade、forward return、hit-rate、execution audit 和 promotion feedback。

### 工程目标

- 运行 intake、paper/diagnostic observation、forward verifier、hit-rate、feedback、audit acceptance。
- 批量消化 signal-only backlog，但不能取代 SignalTracker 的每日执行宇宙职责。
- 把 warmup 堆积治理成 diagnostic/archive/pending_evidence，而不是无限占用 active pool。

### 输入输出契约

| 项 | 规范 |
| --- | --- |
| runner | `scripts/factories/run_incubation_factory.py` |
| 服务目录 | `packages/akshare-mcp/src/akshare_mcp/services/incubation_factory/` |
| 主要输入 | Strategy Factory handoff、paper accounts、signals/orders/trades/positions、forward returns、audit snapshots |
| 主要输出 | incubation accounts、metrics、pipeline snapshots、hit-rate report、feedback domain events、audit acceptance |
| 成功标准 | phase-level status 可解释；signal/order/trade/evidence 不断链；promotion gate 只基于真实 evidence |
| 非目标 | Strategy Factory 候选生成主编排、因子 active pool governance、live trading readiness shortcut |

### 当前 phase 规范

| Phase | 职责 | 必须报告 |
| --- | --- | --- |
| 1 | Intake | identified/accepted/rejected、stage 分布 |
| 1.5 | observe remediation / formal transition | remediated、promoted、skip reason |
| 2 | 加载孵化/paper/diagnostic 策略 | strategy counts、stage tags |
| 3 | 信号生成、前向验证、指标 | signals、filled、verified、recorded、errors |
| 3b | trade prediction outcomes | evaluated、outcome counts |
| 3c | signal-only paper execution backlog | selected、orders/trades/metrics、skip reasons |
| 3d | stale paper position closure | stale positions、exit orders、settlement |
| 3e | native execution evidence backfill | trades_without_signal_evidence、saved evidence |
| 3f | execution audit acceptance | gate status counts、real/bootstrap round-trips、sample debt |
| 3g | execution audit remediation | remediation action、post gate status |
| 4 | pipeline evaluation | snapshots、auto_promoted、blockers |
| 5 | hit-rate report | matrix coverage、LCB/forward blockers |
| 6 | feedback write | domain events、budget feedback |
| 7 | acceleration check | acceleration candidate/action |
| 8 | alert check | alerts、severity |
| 9 | heartbeat | health/status |

### 健康 SLO

- `missing`、`needs_remediation`、`bootstrap_pending`、`insufficient_samples`、`pending_evidence` 必须清晰区分。
- 有 signal/order/trade 时，`saved_signal_evidence=0` 必须暴露为 blocker 或 backfill 待执行。
- 有 open positions 时，必须能解释 aging/exit policy。
- `hard_gate_passed=0` 若来自真实 round-trip 样本不足，应标为 pending evidence；若来自 audit missing，应标为 blocked/degraded。

## Market Event Ingest

### 业务使命

Market Event Ingest 是策略生产线的事件入口。它把官方/可信事件源转化为 normalized market events 和 Strategy Factory event bridge，让策略发现有外部市场事实 anchor。

### 工程目标

- 接入 CNINFO/SSE 等当前已实现官方源，以及配置存在且实现完成的可信源。
- 标注 source tier、reliability、cross-source count、status/reject reason 和 degraded reason；provider chain 的完整度取决于当前 mapper 和 source adapter。
- 通过 `bridge_normalized_events_to_strategy_factory` 将 Tier A/B 且验证通过的事件桥接到 Strategy Factory；该 bridge 依赖 DB 具备 `list_market_events_normalized`、`save_factory_event_cluster`、`save_factory_event_signal` 等方法。
- Tier C/news/media 或 source degraded 事件只能作为诊断辅助，不应直接成为 production 策略晋级证据。

### 输入输出契约

| 项 | 规范 |
| --- | --- |
| runner | `scripts/factories/run_market_event_ingest.py` |
| 服务入口 | `packages/akshare-mcp/src/akshare_mcp/services/market_event_sources.py` |
| 主要输入 | CNINFO/SSE 等官方源，已配置可信事件源 |
| 主要输出 | normalized market events、event task anchors、source reliability metadata、Strategy Factory event signals |
| 成功标准 | source adapter status 可解释；已实现源能写入 normalized events；bridge 前置 DB 方法存在且 Tier A/B 事件被桥接；未实现/未配置 source 显式 degraded |
| 非目标 | 策略生成决策、LLM 解释、准入 gate、paper evidence |

### 健康 SLO

- source adapter 必须报告 configured/available/degraded/reason。
- bridge 必须区分 bridged events 和 diagnostic events。
- low-tier 或 source_degraded 事件不得直接进入 production 策略晋级证据。

当前实现边界：source tier 和 reliability 相关常量、mapper、validation、bridge 逻辑已经存在，但 adapter 覆盖范围和 bridge 可用性受配置、网络、DB 方法存在性影响。文档不得把“目标上的多源事件治理”写成“所有源和 bridge 在任意环境都已完整可用”。

## Supervisor 健康口径

Supervisor 只负责：

- child command 构造
- log 文件管理
- heartbeat
- restart policy
- preflight
- stop/restart lifecycle

Supervisor 不负责：

- 修复 strategy lifecycle
- 回填 evidence
- 放宽 gate
- 把某个 child 的局部成功提升为系统健康

四工厂整体健康必须由生命周期证据判断，而不是仅由进程存活判断。
