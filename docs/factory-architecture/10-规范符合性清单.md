# 规范符合性清单

## 使用方法

任何涉及策略工厂、因子挖掘、孵化、SignalTracker、Market Event Ingest、quality session 或 execution audit 的实现/评审，都应按本清单检查。未通过项必须在 PR、运行报告或修复记录中说明原因。

状态列含义：

| 状态 | 含义 |
| --- | --- |
| `current` | 当前代码已经有对应实现，可直接检查 |
| `manual` | 当前可通过脚本、SQL 或报告手工检查，但没有统一自动化入口 |
| `target` | 规范目标，当前代码尚未完整实现 |
| `documented` | 文档口径已裁决，但代码仍可能有历史命名或兼容入口 |
| `review` | 评审时逐项检查，结果取决于本次改动或本次运行 |

## 运行入口

| 检查项 | 必须满足 | 状态 |
| --- | --- | --- |
| 四工厂 supervisor | 使用 `scripts/factories/run_three_factories.py` 或兼容入口委托它 | current |
| 文件命名历史债 | `run_three_factories.py` 实际四运行体；迁移前必须显式说明 | documented |
| 兼容入口 | `run_all_factories.py` 不重新混合 SignalTracker | current |
| SignalTracker | 作为 sidecar 单独运行或被显式验证，不被默认假设已运行 | manual |
| quality session | 只定义为脚本级验证会话，不是生产 supervisor | current |
| live trading | 默认不进入 live order；受 ActionIntent/control token/guardrail 保护 | manual |

## 四工厂职责

| 检查项 | 必须满足 | 状态 |
| --- | --- | --- |
| Strategy Factory | 拥有策略生成、准入、submission、生命周期契约 | current |
| Factor Mining Factory | 候选因子不能绕过 validation/QC 直接入池 | current |
| Incubation Factory | paper/diagnostic/live readiness 边界清楚 | current |
| Market Event Ingest | source reliability 与 strategy generation 分离 | current |
| SignalTracker sidecar | 不被称为第四工厂，但被视为闭环必需依赖 | documented |

## 生命周期

| 检查项 | 必须满足 | 状态 |
| --- | --- | --- |
| physical state | 先记录 `strategies.status`、incubation stage/status、pipeline stage | current |
| lifecycle overlay | 每个 active strategy 能映射到证据派生覆盖层状态 | target |
| rejected/diagnostic | 必须有 reason，不可静默丢弃 | manual |
| pending_evidence | 必须说明 sample debt 或窗口未成熟 | manual |
| blocked | 必须说明缺表、缺关联、组件未运行或 timeout | manual |
| promotion_ready | 只能来自真实 paper closed round-trip + audit/risk/governance | manual |

## 证据链

| 检查项 | 必须满足 | 状态 |
| --- | --- | --- |
| signal | 非零 `strategy_signals` 有 order 或 skip reason | manual |
| order | `paper_orders` 可追溯 strategy/account，尽量追溯 signal/position | manual |
| trade | `paper_trades` 可追溯 source order | manual |
| position | open/closed 状态、entry/exit、PnL、shares 可解释 | manual |
| forward | `signal_forward_returns` 覆盖 horizon 或说明未成熟 | manual |
| signal evidence | 有 trade 时 native evidence 不应长期为 0 | manual |
| audit | execution audit gate 不长期全量 `missing` | manual |

## Gate 与证据口径

| 检查项 | 必须满足 | 状态 |
| --- | --- | --- |
| hard gate | production hard gate 只认真实 paper closed round-trip | current |
| bootstrap | `bootstrap_pending/bootstrap_ready` 只用于诊断/样本债，不能等同 `passed` | current |
| missing | `missing` 是链路缺失，不是 pending 样本债 | current |
| insufficient_samples | 表示 audit 已跑但真实样本不足 | current |
| needs_remediation | 必须列出 remediation category 和 owner | manual |

## 健康模型

| 检查项 | 必须满足 | 状态 |
| --- | --- | --- |
| health enum | `healthy/pending_evidence/degraded/blocked/unsafe` 统一枚举 | target |
| local health fields | 当前局部 `healthy/degraded/partial` 不得冒充统一健康结论 | manual |
| quality session health | 质量会话健康只代表验证会话结果，不代表生产 supervisor 健康 | manual |

## 可观测性

| 检查项 | 必须满足 | 状态 |
| --- | --- | --- |
| phase result | 每个 phase 有 processed、elapsed、errors、skip reason、metric deltas | manual |
| timeout | phase timeout 不吞 completed phase result | current |
| submitted | 拆分 live/formal/observe/audit-only | manual |
| factor mining | 跳过时标为未验证，不报整体健康 | manual |
| MCP resource | resource 读取失败标为 degraded/blocked | target |
| diagnostics automation | SQL/runbook 可手工复核；统一只读诊断命令仍属目标 | target |

## 文档维护

| 检查项 | 必须满足 | 状态 |
| --- | --- | --- |
| README | 新文档被 README 索引 | review |
| source-index | 新引用的源码、测试、Graphify、外部资料被记录 | review |
| 命名口径 | 四工厂不混用历史闭环口径 | review |
| 安全 | 不写 `.env` 值、凭证值、数据库 dump、broker 状态 | review |
| thinking MCP | 若环境可见，审查结论追加到 `09`；不可见时不得声称调用 | review |

## 禁止事项

- 禁止只改报表让 `healthy=true`。
- 禁止把 quality session 补偿逻辑写成生产事实。
- 禁止把 bootstrap/backtest 写入 production hard gate 的证据集合。
- 禁止把 SignalTracker 缺席归因给 Incubation Factory。
- 禁止让 open positions 长期堆积而没有 aging/exit/diagnostic/archive 规则。
- 禁止把 MCP resource 读取失败吞掉。
- 禁止在默认策略工厂路径触发 live trading。

## 最小通过标准

一次修复或验证至少应满足：

1. 能说清问题属于哪个物理状态和业务生命周期覆盖层状态。
2. 能列出缺失 evidence 和责任组件。
3. 能用只读查询或报告复核结果。
4. 没有泄露敏感配置。
5. 没有改变 hard gate 的真实 paper 口径。
