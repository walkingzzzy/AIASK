## 1. 物理状态机

**来源**: `strategy_lifecycle_shared/common.py`

### 1.1 状态定义

```python
class StrategyStatus(str, Enum):
    DRAFT = "draft"
    SUBMITTED = "submitted"
    INCUBATING = "incubating"
    LISTED = "listed"
    RETIRED = "retired"
    REJECTED = "rejected"
    SUSPENDED = "suspended"
    DEPRECATED = "deprecated"
    ARCHIVED = "archived"
    PUBLISHED = "published"  # 规范化为listed
```

### 1.2 状态转换

```
draft → submitted → incubating → listed
                 ↘ rejected
incubating → deprecated
          → suspended
listed → deprecated
      → suspended
      → archived
suspended → listed
         → deprecated
         → incubating
published → listed (规范化)
```

### 1.3 状态持久化

**表**: `strategies`  
**字段**: `status`  
**约束**: NOT NULL, 必须是枚举值之一

## 2. 业务生命周期覆盖层

**定义**: 从证据表派生的业务状态，用于诊断和验收，**不新增数据库主状态枚举**

### 2.1 覆盖层状态

```
generated → admitted_observe → paper_signalled → paper_ordered
  → paper_filled_open → forward_window_matured → paper_exited
  → round_trip_closed → audit_ready → promotion_ready
```

### 2.2 失败分支

```
generated → rejected (gate/admission失败)
admitted_observe → diagnostic (诊断观察)
paper_signalled → blocked (链路断裂)
paper_ordered → blocked (成交失败)
paper_filled_open → pending_evidence (样本债)
audit_ready → pending_evidence (样本不足)
```

## 3. 映射规则

| 覆盖层状态 | 物理状态/表证据 | 进入条件 | 常见Blocker |
|-----------|----------------|----------|-------------|
| `generated` | candidate artifact、factory run payload | 候选已生成 | payload不合约、LLM timeout |
| `admitted_observe` | `status='submitted/incubating'` + active account | 已进入observe/paper轨道 | account缺失、stage不一致 |
| `paper_signalled` | `strategy_signals` 非零记录 | 策略产生信号 | SignalTracker未运行 |
| `paper_ordered` | `paper_orders` 可追溯strategy_id | 信号已转订单 | 价格缺失、账户缺失 |
| `paper_filled_open` | `paper_trades` + open positions | 订单已成交形成持仓 | settlement未跑 |
| `forward_window_matured` | `signal_forward_returns` 覆盖horizon | 前向窗口有样本 | horizon未到、行情缺失 |
| `paper_exited` | exit order/trade 或 stale close | 持仓发生退出动作 | stale close未启用 |
| `round_trip_closed` | closed positions + realized_trade_count>0 | 完成真实round-trip | 只有open positions |
| `audit_ready` | `strategy_execution_audit_snapshots` | audit已运行 | missing、needs_remediation |
| `promotion_ready` | `execution_audit_gate_status='passed'` | 通过Hard Gate | production样本不足 |

## 4. Gate语义

### 4.1 Execution Audit Gate

**函数**: `evaluate_execution_audit_gate`  
**位置**: `application/incubation/execution_audit_gate.py`

| Gate Status | 含义 | Production Hard Gate |
|------------|------|---------------------|
| `missing` | 无audit summary或无realized trade | ❌ 不通过 |
| `bootstrap_pending` | 有runtime evidence但realized_trade_count=0 | ❌ 不通过 |
| `insufficient_samples` | realized trades>0但低于bootstrap floor | ❌ 不通过 |
| `failed_metrics` | 样本达标但指标失败 | ❌ 不通过 |
| `bootstrap_ready` | 通过bootstrap floor但低于production floor | ❌ 不通过 |
| `passed` | realized_trade_count≥20 且指标通过 | ✅ 通过 |

**Production Trade Floor**: 20个真实paper closed round-trip

## 5. 失败状态

| 状态 | 含义 | 必须暴露的Blocker |
|------|------|------------------|
| `rejected` | 候选未通过准入 | gate reason、validation reason |
| `diagnostic` | 仅诊断观察，不可晋级 | diagnostic reason |
| `blocked` | 当前状态无法推进 | 缺失表、组件未运行 |
| `pending_evidence` | 证据方向正确但样本未成熟 | sample debt、forward window |

**注意**: `pending_evidence`不是错误，表示链路正确但样本还不够。`blocked`才表示链路断裂。

## 8. 指标解释

| 指标 | 正确解释 | 错误解释 |
|------|----------|----------|
| `submitted=0` | 必须拆成live_submitted、formal_incubation、observe、audit-only | ❌ 直接判断为失败 |
| `signals_generated>0` | 只说明产生过信号 | ❌ 不代表paper execution闭环健康 |
| `paper_orders>0` | 只说明有下单入口 | ❌ 不代表有成交、持仓、前向 |
| `paper_trades>0` | 若只有buy，不代表round-trip成熟 | ❌ 不能判断为完成 |
| `saved_signal_evidence=0` | 有signal/order/trade时是blocker | ❌ 无signal时是上游未运行 |
| `hard_gate_passed=0` | 真实样本不足时是诚实结果 | ❌ 不是代码bug |
| `execution_audit_gate_status=missing` | 链路缺失或audit未运行 | ❌ 不能当作pending样本债 |

## 9. 晋级规则

1. **Production Hard Gate只认`passed`**: realized_trade_count≥20 且指标通过
2. **Bootstrap/Backtest不进入Production**: 只用于诊断和样本债估算
3. **`success=True`不能覆盖底层失败**: 必须检查phase timeout、evidence missing
4. **Quality Session是验证会话**: 不是生产生命周期状态机

## 10. 最小验收

一次健康的短验证不要求立刻`hard_gate_passed>0`，但必须能说明:

- [x] 哪些策略映射到哪个业务生命周期覆盖层状态
- [x] 覆盖层状态能由物理字段和证据表复核
- [x] 非零signal是否转成order；未转时skip reason是什么
- [x] order是否转成trade；未转时settlement blocker是什么
- [x] open positions是否有aging/exit policy
- [x] forward returns或effective_n是否在增长
- [x] execution audit不是全量missing
- [x] hard gate未通过时，是真实round-trip样本债，不是链路断裂

## 11. 状态查询SQL

### 11.1 物理状态分布

```sql
SELECT status, COUNT(*) as count,
       ROUND(100.0 * COUNT(*) / SUM(COUNT(*)) OVER (), 2) as percentage
FROM strategies
GROUP BY status
ORDER BY count DESC;
```

### 11.2 孵化阶段分布

```sql
SELECT stage, COUNT(*) as count
FROM strategy_incubation_accounts
WHERE status = 'active'
GROUP BY stage;
```

### 11.3 覆盖层状态派生

```sql
-- 示例: 判断paper_signalled
SELECT s.strategy_id,
       CASE 
           WHEN EXISTS(SELECT 1 FROM strategy_signals sig WHERE sig.strategy_id = s.strategy_id) 
           THEN 'paper_signalled'
           ELSE 'admitted_observe'
       END as lifecycle_overlay
FROM strategies s
WHERE s.status IN ('submitted', 'incubating');
```
