## 2. 健康诊断

### 2.1 诊断脚本

**位置**: `scripts/factories/diagnose_factory_health.py`

**用法**:
```bash
# 执行完整诊断
python scripts/factories/diagnose_factory_health.py

# 指定数据库路径
python scripts/factories/diagnose_factory_health.py --db data/db/akshare_mcp.sqlite3

# 输出到文件
python scripts/factories/diagnose_factory_health.py --output health_report.json
```

### 2.2 8项健康检查

| # | 检查项 | 检查内容 | 通过标准 |
|---|--------|----------|----------|
| 1 | Supervisor进程 | 检查4个工厂进程 | 至少3个进程运行 |
| 2 | SignalTracker运行 | 最近运行时间 | <24小时 |
| 3 | 信号→订单转换 | 转换率 | >95% |
| 4 | 订单→成交转换 | 成交率 | >95% |
| 5 | 持仓状态 | Open/closed比例 | closed>1% |
| 6 | 前向收益证据 | 记录数量 | >10,000 |
| 7 | Execution Audit | Audit快照数量 | >1,000 |
| 8 | 策略生命周期 | Listed策略数量 | ≥1 |

### 2.3 健康状态定义

| 状态 | 含义 | 典型场景 | 应对措施 |
|------|------|----------|----------|
| `healthy` | 所有检查通过 | 生产环境稳定运行 | 无需操作 |
| `pending_evidence` | 有警告但不阻塞 | 样本积累中，正常状态 | 继续运行，等待样本成熟 |
| `degraded` | 有失败项 | 部分功能异常 | 查看失败项并修复 |
| `blocked` | 有阻塞项 | 无法正常运行 | 立即修复阻塞项 |

## 3. 常见问题排查

### 3.1 整体状态BLOCKED

**症状**: 诊断脚本显示BLOCKED

**可能原因**:
1. 数据库路径错误
2. 数据库文件损坏
3. 所有工厂进程未启动

**排查步骤**:
```bash
# 1. 检查数据库文件
ls -lh data/db/akshare_mcp.sqlite3

# 2. 检查数据库可读
sqlite3 data/db/akshare_mcp.sqlite3 "SELECT COUNT(*) FROM strategies;"

# 3. 检查工厂进程
ps aux | grep factory

# 4. 查看工厂日志
tail -f logs/strategy_factory.log
```

### 3.2 SignalTracker未运行

**症状**: 检查项2显示FAIL

**可能原因**:
1. SignalTracker进程未启动
2. SignalTracker崩溃
3. Phase timeout

**排查步骤**:
```bash
# 1. 检查SignalTracker进程
ps aux | grep signal_tracker

# 2. 查看SignalTracker日志
tail -f logs/signal_tracker.log

# 3. 手动运行SignalTracker
python scripts/factories/run_signal_tracker.py

# 4. 查询最近运行记录
sqlite3 data/db/akshare_mcp.sqlite3 "
SELECT MAX(timestamp) as last_run
FROM strategy_signals;"
```

### 3.3 信号不转订单

**症状**: 检查项3显示WARNING或FAIL

**可能原因**:
1. Incubation Factory未运行
2. 账户状态异常
3. 价格数据缺失

**排查步骤**:
```sql
-- 1. 查找有信号但无订单的策略
SELECT DISTINCT s.strategy_id
FROM strategy_signals s
WHERE NOT EXISTS (
    SELECT 1 FROM paper_orders o
    WHERE o.strategy_id = s.strategy_id
);

-- 2. 检查这些策略的账户状态
SELECT a.strategy_id, a.stage, a.status
FROM strategy_incubation_accounts a
WHERE a.strategy_id IN (...);

-- 3. 查看Incubation日志
tail -f logs/incubation_factory.log
```

### 3.4 持仓不退出

**症状**: 检查项5显示WARNING，99%持仓open

**可能原因**:
1. Stale close policy未执行
2. 策略持有周期较长
3. 退出信号不足

**排查步骤**:
```sql
-- 1. 检查持仓aging分布
SELECT 
    CASE 
        WHEN JULIANDAY('now') - JULIANDAY(entry_time) < 7 THEN '<1周'
        WHEN JULIANDAY('now') - JULIANDAY(entry_time) < 30 THEN '1-4周'
        WHEN JULIANDAY('now') - JULIANDAY(entry_time) < 90 THEN '1-3月'
        ELSE '>3月'
    END as period,
    COUNT(*) as count
FROM strategy_trade_positions
WHERE status = 'open'
GROUP BY period;

-- 2. 检查Incubation Phase 3d日志
grep "stale_close" logs/incubation_factory.log

-- 3. 手动触发stale close
python scripts/factories/trigger_stale_close.py
```

### 3.5 Hard Gate不通过

**症状**: 检查项7显示hard_gate_passed=0

**判断**: 这是**正常状态**！

**原因**:
- Hard Gate要求≥20个真实closed round-trip
- 大量策略仍在积累样本
- 通过率0.005%符合严格标准

**确认方法**:
```sql
-- 1. 检查gate status分布
SELECT verdict_status, COUNT(*)
FROM strategy_execution_audit_snapshots
GROUP BY verdict_status;

-- 2. 检查realized trade count分布
SELECT 
    CASE 
        WHEN realized_trade_count = 0 THEN '0'
        WHEN realized_trade_count < 5 THEN '1-4'
        WHEN realized_trade_count < 20 THEN '5-19'
        ELSE '≥20'
    END as trade_count_bucket,
    COUNT(*) as count
FROM strategy_execution_audit_snapshots
GROUP BY trade_count_bucket;
```

**禁止**: 放宽Hard Gate标准！

## 4. 监控指标

### 4.1 关键指标

| 指标 | 查询方法 | 正常范围 | 告警阈值 |
|------|----------|----------|----------|
| 策略总数 | `SELECT COUNT(*) FROM strategies` | >10,000 | <5,000 |
| Listed策略 | `SELECT COUNT(*) FROM strategies WHERE status='listed'` | ≥1 | 0 |
| 信号生成速率 | 每天新增signal数 | >100 | <10 |
| 订单成交率 | orders→trades转换率 | >95% | <90% |
| 持仓退出率 | closed/(open+closed) | >10% | <1% |
| Hard Gate通过率 | passed/total | <1% | >5% (异常) |

## 5. 性能优化

### 5.1 数据库优化

```sql

CREATE INDEX IF NOT EXISTS idx_signals_strategy_id ON strategy_signals(strategy_id);
CREATE INDEX IF NOT EXISTS idx_orders_strategy_id ON paper_orders(strategy_id);
CREATE INDEX IF NOT EXISTS idx_trades_order_id ON paper_trades(order_id);
CREATE INDEX IF NOT EXISTS idx_positions_strategy_id ON strategy_trade_positions(strategy_id);
```
