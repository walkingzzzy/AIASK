## 1. 功能设计

### 1.1 需求背景与价值

| 项 | 内容 |
|---|---|
| 问题陈述 | 策略生成需要经过候选生成、质量门禁、去重检查、准入决策等多个环节，每个环节都可能失败或降级 |
| 解决方案 | 建立标准化的策略生成流程，明确每个环节的输入输出、成功标准和失败处理 |
| 业务价值 | 1. 确保策略质量<br>2. 避免重复策略<br>3. 提供可审计的生成过程<br>4. 支持批量生成和增量优化 |

### 1.2 用户故事

| 编号 | 优先级 | 用户故事 | 成功标准 |
|---|---|---|---|
| SF-CORE-US-001 | P0 | 作为量化研究员，我需要生成新的策略候选 | 候选生成成功，包含完整payload |
| SF-CORE-US-002 | P0 | 作为风控人员，我需要确保策略通过质量门禁 | Gate评估执行，拒绝低质量候选 |
| SF-CORE-US-003 | P0 | 作为系统管理员，我需要避免重复策略 | 去重检查执行，标记重复候选 |
| SF-CORE-US-004 | P0 | 作为运维人员，我需要追踪策略生成过程 | 每个环节有日志和状态记录 |

### 1.3 功能分解与优先级

| 功能编号 | 功能点 | 优先级 | 当前代码依据 | 待开发事项 | 验收标准 |
|---|---|---|---|---|---|
| SF-CORE-F001 | 候选生成 | P0 | `application/candidate_generation/` | 无 | 生成包含完整payload的候选 |
| SF-CORE-F002 | Quality Gate | P0 | `application/gates/quality_gate.py` | 无 | 评估回测指标、风险指标 |
| SF-CORE-F003 | Governance Gate | P0 | `application/gates/governance_gate.py` | 无 | 评估合规性、治理规则 |
| SF-CORE-F004 | 去重检查 | P0 | `application/deduplication/` | 无 | 标记重复或相似候选 |
| SF-CORE-F005 | Admission决策 | P0 | `application/admission/` | 无 | 决定是否进入孵化 |
| SF-CORE-F006 | 状态持久化 | P0 | `infrastructure/persistence/` | 无 | 策略状态写入数据库 |
| SF-CORE-F007 | 批量处理 | P1 | `application/batch_processor.py` | 需优化性能 | 支持批量生成和评估 |

### 1.4 业务规则与边界

| 规则 | 说明 | 验收 |
|---|---|---|
| 候选必须包含完整payload | payload包含策略规则、参数、回测结果、风险指标 | 检查payload schema |
| Gate失败不进入孵化 | 任何gate失败或降级，候选标记为rejected | 查询rejected原因 |
| 去重基于特征相似度 | 使用策略特征向量计算相似度，超过阈值标记重复 | 验证去重逻辑 |
| Admission可覆盖Gate | 特殊情况下admission可批准gate失败的候选 | 记录覆盖原因 |

## 2. 流程设计

### 2.1 核心流程图

```
市场上下文 + 因子池
    ↓
[1] 候选生成 (Candidate Generation)
    ↓
候选Payload
    ↓
[2] Quality Gate评估
    ├→ PASS → [3]
    └→ FAIL → rejected
    ↓
[3] Governance Gate评估
    ├→ PASS → [4]
    └→ FAIL → rejected
    ↓
[4] 去重检查 (Deduplication)
    ├→ UNIQUE → [5]
    ├→ DUPLICATE → rejected
    └→ SIMILAR → warning
    ↓
[5] Admission决策
    ├→ ADMITTED → submitted
    └→ REJECTED → rejected
    ↓
[6] 持久化到数据库
    ↓
策略记录 (strategies表)
```

### 2.2 状态流转

| 当前状态 | 触发事件 | 下一状态 | 条件 |
|----------|----------|----------|------|
| - | 候选生成 | generated | 生成成功 |
| generated | Gate评估 | gate_passed | 所有gate通过 |
| generated | Gate评估 | rejected | 任何gate失败 |
| gate_passed | 去重检查 | dedup_passed | 无重复 |
| gate_passed | 去重检查 | rejected | 重复 |
| dedup_passed | Admission | submitted | 准入通过 |
| dedup_passed | Admission | rejected | 准入拒绝 |
| submitted | Intake | incubating | 进入孵化 |

### 2.3 异常处理

| 异常类型 | 处理方式 | 恢复策略 |
|----------|----------|----------|
| LLM timeout | 标记partial_infra=True | 重试或降级 |
| 市场数据缺失 | 跳过该候选 | 记录缺失原因 |
| Payload不合约 | 标记validation_failed | 不重试 |
| Gate评估超时 | 默认FAIL | 人工审查 |
| 去重向量计算失败 | 跳过去重 | 警告日志 |
| 数据库写入失败 | 重试3次 | 失败后告警 |

## 3. 架构设计

### 3.1 分层架构

```
┌─────────────────────────────────────┐
│   Application Layer                 │
│   - Candidate Generation            │
│   - Gates (Quality, Governance)     │
│   - Deduplication                   │
│   - Admission                       │
└─────────────────────────────────────┘
            ↓ uses
┌─────────────────────────────────────┐
│   Domain Layer                      │
│   - Strategy Entity                 │
│   - Candidate Payload               │
│   - Gate Result                     │
└─────────────────────────────────────┘
            ↓ persisted by
┌─────────────────────────────────────┐
│   Infrastructure Layer              │
│   - SQLite CRUD                     │
│   - Vector Store                    │
│   - AKShare MCP                     │
└─────────────────────────────────────┘
```

### 3.2 组件关系

| 组件 | 依赖 | 提供 | 代码路径 |
|------|------|------|----------|
| Candidate Generator | 因子池、市场数据 | 候选Payload | `application/candidate_generation/` |
| Quality Gate | 候选Payload | Gate Result | `application/gates/quality_gate.py` |
| Governance Gate | 候选Payload、合规规则 | Gate Result | `application/gates/governance_gate.py` |
| Deduplicator | 候选特征、向量存储 | 去重Result | `application/deduplication/` |
| Admission | Gate Results、去重Result | Admission Decision | `application/admission/` |
| Strategy CRUD | 数据库连接 | 持久化接口 | `infrastructure/persistence/sqlite/_strategy_crud_core.py` |

### 3.3 数据流

```
[AKShare MCP] → [Market Context]
```

## 5. 状态与错误处理

### 5.1 状态枚举

| 状态 | 触发条件 | 下一状态 | 错误处理 |
|------|----------|----------|----------|
| generated | 候选生成成功 | gate_passed/rejected | 重试或记录失败 |
| gate_passed | 所有gate通过 | dedup_passed/rejected | 记录gate结果 |
| dedup_passed | 去重检查通过 | submitted/rejected | 记录去重结果 |
| submitted | Admission通过 | incubating | 写入数据库 |
| rejected | 任何环节失败 | - | 记录拒绝原因 |

### 5.2 错误码

| 错误码 | 含义 | HTTP状态码 | 处理 |
|--------|------|------------|------|
| SF-CORE-001 | 候选生成失败 | 500 | 检查市场数据和因子池 |
| SF-CORE-002 | Payload不合约 | 400 | 检查payload schema |
| SF-CORE-003 | Gate评估失败 | 422 | 记录gate失败原因 |
| SF-CORE-004 | 去重检查失败 | 500 | 检查向量存储 |
| SF-CORE-005 | Admission拒绝 | 422 | 记录拒绝原因 |
| SF-CORE-006 | 数据库写入失败 | 500 | 重试或告警 |

### 5.3 降级策略

| 场景 | 降级策略 | 影响 |
|------|----------|------|
| LLM超时 | 使用模板策略 | 策略多样性降低 |
| 市场数据缺失 | 跳过该候选 | 生成数量减少 |
| Gate评估超时 | 默认FAIL | 严格门禁 |
| 去重失败 | 跳过去重 | 可能重复 |
| 向量存储不可用 | 跳过去重 | 可能重复 |

## 7. 验收标准

### 7.1 功能验收

| 编号 | 验收项 | 验收方法 | 通过标准 |
|------|--------|----------|----------|
| TC-CORE-001 | 候选生成成功 | 调用生成接口 | 返回至少1个候选 |
| TC-CORE-002 | Gate评估执行 | 检查gate结果 | 每个候选有gate结果 |
| TC-CORE-003 | 去重检查执行 | 检查去重结果 | 每个候选有去重结果 |
| TC-CORE-004 | Admission决策执行 | 检查admission结果 | 每个候选有admission决策 |
| TC-CORE-005 | 状态持久化 | 查询数据库 | 策略状态正确写入 |
| TC-CORE-006 | 拒绝原因记录 | 查询rejected策略 | 有明确拒绝原因 |

### 7.2 性能验收

| 指标 | 基准 | 测量方法 |
|------|------|----------|
| 候选生成速度 | >10候选/分钟 | 批量生成计时 |
| Gate评估时间 | <5秒/候选 | 单候选评估计时 |
| 去重检查时间 | <2秒/候选 | 向量相似度计算计时 |
| 端到端延迟 | <30秒/候选 | 从生成到持久化总时长 |

### 7.3 质量验收

| 指标 | 基准 | 测量方法 |
|------|------|----------|
| Gate拒绝率 | 10-30% | 统计rejected比例 |
| 去重命中率 | 5-15% | 统计duplicate比例 |
| Admission通过率 | 70-90% | 统计submitted比例 |

## 8. 已知问题与限制

### 8.1 当前限制

- 候选生成依赖LLM，可能超时或降级
- Gate评估规则需要人工配置和调优
- 去重基于特征向量，可能误判
- 批量生成性能受限于LLM并发

### 8.2 未来优化

- 支持增量候选生成
- 支持Gate规则动态调整
- 支持去重阈值自适应
- 支持分布式批量生成
