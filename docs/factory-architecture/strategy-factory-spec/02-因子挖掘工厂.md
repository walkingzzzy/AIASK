### 术语定义

| 术语 | 定义 | 代码证据 |
|---|---|---|
| 因子候选 | LLM生成或规则生成的因子表达式 | `factor_candidates` 表 |

| 因子晋级 | 从候选到active pool的过程 | `factor_promotion.py` |

## 1. 功能设计

### 1.1 需求背景与价值

| 项 | 内容 |
|---|---|
| 问题陈述 | 策略质量依赖因子质量，需要持续挖掘和验证新因子 |
| 解决方案 | 建立因子挖掘工厂，自动生成、验证、晋级因子 |
| 业务价值 | 1. 扩展因子库<br>2. 提升策略多样性<br>3. 发现alpha来源 |

### 1.2 核心流程

```
市场数据 + 技术指标
    ↓
[1] 因子生成 (LLM/规则)
    ↓
因子候选
    ↓
[2] 回测验证
    ↓
[3] IC计算
    ↓
[4] 稳定性检查
    ↓
[5] QC Pipeline
    ├→ PASS → Active Pool
    └→ FAIL → Rejected
    ↓
Active Pool → 策略生成
```

## 2. 数据模型

### 2.1 因子候选表

| 字段 | 类型 | 说明 |
|------|------|------|
| factor_id | UUID | 因子唯一标识 |
| expression | TEXT | 因子表达式 |
| status | ENUM | candidate/active/rejected |
| ic_mean | FLOAT | IC均值 |
| ic_std | FLOAT | IC标准差 |
| sharpe | FLOAT | 因子Sharpe比率 |
| qc_result | JSON | QC结果详情 |

## 3. 接口说明

### 3.1 生成因子

```
POST /v1/factor-factory/generate
{
    "market": "A-share",
    "count": 10,
    "constraints": {
        "max_complexity": 5,
        "min_coverage": 0.8
    }
}
```

### 3.2 查询Active Pool

```
GET /v1/factor-factory/active-pool
Response:
{
    "factors": [
        {
            "factor_id": "f001",
            "name": "momentum_enhanced",
            "ic_mean": 0.05,
            "sharpe": 1.2,
            "status": "active"
        }
    ],
    "count": 150
}
```

## 4. 验收标准

| 编号 | 验收项 | 通过标准 |
|------|--------|----------|
| TC-FACTOR-001 | 因子生成成功 | 生成至少1个因子候选 |
| TC-FACTOR-002 | QC Pipeline执行 | 每个候选有QC结果 |
| TC-FACTOR-003 | Active Pool增长 | 通过QC的因子进入pool |

## 5. 已知问题

- LLM生成因子可能语法错误或无效
- IC计算需要足够历史数据
- QC Pipeline执行时间较长
