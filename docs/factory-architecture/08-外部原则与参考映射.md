# 外部原则与参考映射

## 使用边界

外部资料只作为架构原则参考，不覆盖本项目当前代码事实。策略工厂的最终事实来源仍是源码、测试、Graphify、运行入口和证据表。

本轮联网只读结果：

- `https://ml-ops.org/content/mlops-principles` 可读取，内容强调 MLOps 的迭代开发、自动化、CI/CD、版本化、测试、可复现和监控。
- `https://www.nist.gov/itl/ai-risk-management-framework` 可读取页面内容，公开介绍 NIST AI RMF、Playbook、Roadmap、Crosswalk 和 Generative AI Profile。
- Federal Reserve SR 11-7 类旧链接在本环境返回 404 或连接失败，因此本文不基于其正文做具体断言，只保留“模型风险管理原则”作为行业参考方向。

## MLOps 原则映射

| 外部原则 | 对本项目的映射 | 应落地的契约 |
| --- | --- | --- |
| Versioning | 策略、因子、事件、信号、audit 都要有版本/lineage | candidate artifact、factor catalog、event anchor、signal evidence |
| Testing | 不只测代码，还要测数据、模型/策略、基础设施 | quality session、contract tests、evidence-chain tests |
| Reproducibility | 同一输入应可复核同一候选或证据 | strategy_id、factor_id、event_id、run_id、snapshot |
| Monitoring | 生产运行要监控数据漂移、性能退化、预测质量 | lifecycle ledger、hit-rate、forward returns、audit gate |
| Automation | 生产线可以自动运行，但自动化不能绕过 gate | supervisor + sidecar + explicit gates |
| Technical debt control | 避免临时脚本和局部补偿累积成隐形系统 | 统一控制面、禁止 quality-session-only 修复 |

映射结论：策略工厂应该被当作“研究 + MLOps + 量化证据”的混合生产线，而不是脚本集合。

## AI 风险治理映射

NIST AI RMF 的公开页面围绕可信与负责任 AI 风险管理，配套 Playbook、Roadmap、Crosswalk 和 Generative AI Profile。落到本项目，不是简单贴标签，而是形成可执行治理：

| 治理方向 | 本项目要求 |
| --- | --- |
| Govern | 明确四工厂职责、sidecar 边界、quality session 边界和 live trading guardrail |
| Map | 把策略生命周期映射到 state、evidence、owner、blocker |
| Measure | 用 forward returns、paper round-trip、hit-rate、audit gate 测量，而不是只看 LLM 输出 |
| Manage | 对 timeout、missing evidence、样本债、unsafe live path 进行分级处置 |

策略工厂里最重要的风险不是“LLM 生成错字”，而是错误地把未验证策略当作可晋级资产。因此 hard gate 必须坚持真实 paper closed round-trip。

## 模型风险管理映射

虽然本轮未成功抓取 SR 11-7 正文，但模型风险管理的通用原则仍适用于策略工厂：

- 开发与验证分离：Strategy Factory 生成候选，Incubation/Audit 验证，不应由生成方自证晋级。
- 独立验证：backtest、forward、paper、audit 应提供不同层次证据，且 production hard gate 只认真实 paper evidence。
- 持续监控：策略不是一次通过就永久有效，需要 runtime risk、hit-rate、forward returns 和 lifecycle feedback。
- 文档与可追溯：每个策略的假设、输入、参数、证据和变更必须可回溯。

映射到代码就是：admission、SignalTracker、Incubation、execution audit 必须是可查询证据链，而不是日志叙事。

## 量化研发闭环映射

量化策略研发通常遵循假设、数据、回测、稳健性、前向、paper/live、监控、退役的闭环。本项目的规范映射为：

| 量化研发环节 | 本项目组件 | 不可接受的替代 |
| --- | --- | --- |
| Hypothesis | Strategy Factory candidate / factor hypothesis | 纯 LLM 叙事 |
| Data | AKShare MCP / Quant Core storage | 无 source/freshness 的临时数据 |
| Feature/Factor | Factor Mining Factory | 未验证因子直接入池 |
| Backtest/OOS | Strategy Factory quality gates / validation runtime | 单次 in-sample 结果 |
| Forward | SignalTracker / ForwardVerifier | 伪造 forward return |
| Paper | SignalTracker + Incubation paper runtime | 只有 signal 无 order/trade |
| Audit | Quant Core execution audit | bootstrap/backtest 当 production hard gate |
| Feedback | Incubation feedback / budget feedback | 人工口头结论 |

## 对当前架构的直接要求

- 任何 `success` 必须有证据表支持。
- 任何 `degraded` 必须有明确 phase、reason、owner。
- 任何 `pending_evidence` 必须说明样本债，而不是混成失败。
- 任何 `missing` 都是阻塞或链路缺失，不能自动解释为 pending。
- 任何 live readiness 都不能来自 paper/diagnostic/bootstrap 单一证据。
