# 策略工厂策略对象协议

> 校准说明：本文描述的是当前策略工厂 candidate / submission payload 的协议分层，不代表代码里已经导出同名 Python dataclass。当前运行时主要通过 `StrategySpec.metadata`、candidate dict 和 submitter 持久化 payload 承载这些字段。

## 目标

统一策略工厂在生成、回测、提交、评审、孵化阶段使用的策略对象协议，避免各阶段对“策略候选”理解不一致。

## 当前承载方式

- 运行时实体：`packages/akshare-mcp/src/akshare_mcp/services/strategy_spec.py::StrategySpec`
- 候选展开：`StrategySpec.to_candidate()`
- 生成侧注入：`packages/akshare-mcp/src/akshare_mcp/services/strategy_generators.py`
- 提交侧落库：`packages/strategy-factory/src/strategy_factory/application/submitter.py`
- `task_signature` 当前由 `packages/strategy-factory/src/strategy_factory/domain/targets.py::_build_task_signature()` 生成，不建议手写拼接

## 候选 / 提交阶段建议显式提供的核心字段

说明：

- 当前运行时真正的硬要求仍是 `strategy_type` 和 `params`
- 下面这些字段不是 Python dataclass 层面的硬校验必填，而是当前候选生成、提交落库、质量门禁和产品展示阶段最容易依赖的核心字段
- 若这些字段长期缺失，系统通常会用默认空结构或已有策略参数回填，但会显著降低目标池一致性、验证解释性和审计可读性

## 对象分层

以下名称是协议层分段，不是当前仓库中已经单独导出的类名。

### 1. StrategyResearchContract

研究任务与候选绑定的任务合同。

关键字段：

- `task_id`
- `task_source`
- `opportunity_type`
- `preferred_strategy_types`
- `allowed_strategy_types`
- `preference_strength`
- `target_symbols`
- `stock_pool`
- `target_symbol_policy`
- `universe_expansion_policy`
- `validation_focus`
- `event_window`
- `estimation_window`
- `holding_window`
- `task_signature`

### 2. StrategyTargetingPolicy

描述候选目标池与研究任务目标池的关系。

关键字段：

- `target_symbol_policy`
- `universe_expansion_policy`
- `validation_focus`
- `constraint_violation`
- `expansion_applied`
- `expansion_reason`
- `expansion_source`
- `coverage_ratio`
- `intersection_ratio`

### 3. StrategyPortfolioSpec

描述组合或仓位语义。

关键字段：

- `position_assumption`
- `target_weight_scheme`
- `max_position_pct`
- `target_weight_map`

### 4. StrategyExecutionAssumptions

描述执行与成本口径。

关键字段：

- `commission_rate`
- `slippage_bps`
- `slippage_model`
- `market_impact_bps`
- `tradability_filter`
- `capacity_participation_rate`
- `adv_ratio_limit`
- `capacity_bucket`

### 5. StrategyValidationProfile

描述 Gate-1 / Gate-2 / Gate-3 的主验证协议。

关键字段：

- `profile`
- `validation_focus`
- `primary_validation_layer`

### 6. StrategySubmissionAudit

描述提交与审计结果。

关键字段：

- `constraint_check`
- `attempt_adjustment`
- `task_signature`
- `refresh_mode`
- `primary_validation_layer`
- `event_window_config`
- `cost_assumptions`
- `explicit_cost_breakdown`
- `implicit_cost_breakdown`
- `position_assumption`

### 映射规则

- `research_task.target_symbols` 与 `constraint_check.target_symbols_after_normalize` 共同决定最终 `target_symbols`
- `execution_assumptions`、`portfolio_spec`、`risk_rules` 会在回测与评审阶段转为执行审计和容量审计字段
- `validation_profile` 决定 Gate-3 主判定逻辑
- `task_signature` 与 `refresh_mode` 共同决定是刷新旧策略还是派生新实验

- 若后续把这些协议正式提升为独立 dataclass / pydantic model，应以本文字段为基线，但仍需以运行时代码为最终依据。
