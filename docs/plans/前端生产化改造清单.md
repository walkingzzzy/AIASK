# 前端生产化改造清单（apps/web）

> 目标：将当前"以数据展示为主"的前端，升级为"可直接使用的生产级产品"。
> 范围：`apps/web`，以 Next.js App Router + React Query + Zustand 为核心。
> 版本：v2（代码审计后更新，含严重性评估）
> 审计日期：2026-02-23

> 校准说明：本文是 2026-02-23 的前端审计与改造清单，主要用于记录当时发现的问题、严重性评估和建议治理路径。
>
> 其中“全部真实存在”“生产级产品”等表述应按该次审计时点理解；当前是否仍成立，需要结合 `apps/web` 最新实现、构建结果与回归测试重新确认。若与当前代码不一致，应以后者为准。

## 〇、代码审计总结

经过对 `apps/web` 全量代码审查，清单中列出的问题**全部真实存在**，且部分比预期更严重：

| 问题域 | 严重性 | 核心发现 |
|--------|--------|----------|
| 数据层架构 | 🔴 严重 | 全站 ~100 个读请求 100% 使用 `useMutation`，`useQuery` 使用量为零，React Query 缓存体系完全架空 |
| 闪空问题 | 🔴 严重 | `useApiMutation` 每次 `trigger()` 先 `setData(null)`，首页 7 请求 + 60s 自动刷新 = 每分钟全页闪空 |
| Cookie 安全 | 🔴 严重 | `document.cookie` 设置 token，无 `Secure`、无 `HttpOnly`，XSS 即可窃取 |
| 交易确认 | 🔴 严重 | 模拟交易下单无二次确认弹窗，无价格/仓位校验，撤单按钮无防重复 |
| 错误监控 | 🔴 严重 | 全站无 Sentry 或任何错误上报，线上错误完全不可见 |
| 错误处理 | 🟠 高 | `error.tsx` 仅 14 行，直接暴露 `error.message`；API 错误为原始 `"HTTP 500"` 文本 |
| 可访问性 | 🟠 高 | 全站零 `aria-label`/`role`/`tabIndex`/`focus-visible`/`sr-only` |
| 请求生命周期 | 🟠 高 | 除 chat 外无 AbortController，无超时保护，组件卸载后仍回写状态 |
| Loading 体验 | 🟡 中 | 仅一个根级 `loading.tsx`（纯文字），无 Skeleton，无路由级 loading |
| CSP 配置 | 🟡 中 | 允许 `unsafe-eval` + `unsafe-inline`，`connect-src` 仍为 `localhost` |
| 幂等性 | 🟡 中 | 所有 mutation 无 `mutationKey`、无 `X-Idempotency-Key` |
| Toast 系统 | 🟡 中 | 已接入 `ToastProvider` 但全站零调用 |

## 二、P0（必须先完成）

### 1) 数据层改造 🔴 严重

**现状**：全站 24 个页面、~100 个数据请求全部通过 `useApiMutation`（`hooks/use-api-mutation.ts`）发起，`useQuery` 使用量为零。`QueryClient` 配置的 `staleTime: 30_000` / `retry: 1` / `refetchOnWindowFocus: false` 仅对 `useQuery` 生效，当前全部作废。

**关键代码位置**：
- `hooks/use-api-mutation.ts:27` — 自动推断 GET 方法：`const method = options?.method ?? (body ? 'POST' : 'GET')`
- `hooks/use-api-mutation.ts:43-44` — 每次 trigger 先 `setData(null)` 导致闪空
- `lib/query-provider.tsx:7-9` — QueryClient 配置（仅 queries 生效）
- `lib/api.ts:14` — `cache: 'no-store'` 硬编码，浏览器 HTTP 缓存完全禁用

**影响范围**（按页面 mutation 数量）：
| 页面 | 读请求 mutation 数 |
|------|-------------------|
| market/page.tsx | 10 |
| fund-flow/page.tsx | 10 |
| paper-trading/page.tsx | 8（另有 2 个写操作） |
| strategy/page.tsx | 9 |
| page.tsx（首页） | 7 |
| portfolio/page.tsx | 7 |
| stock/page.tsx | 6 |
| factor/page.tsx | 6 |
| 其余 13 个页面 | 各 1-5 个 |

**改造项**：
- [ ] 建立 Query Key 工厂（按模块：`market/stock/backtest/trading/chat`）
- [ ] 将全部读请求从 `useMutation` 迁移到 `useQuery`（优先：首页、行情、个股、模拟交易）
- [ ] 制定统一缓存策略，使 `staleTime` / `gcTime` / `retry` / `refetchOnWindowFocus` 真正生效
- [ ] 删除 `trigger()` 中的 `setData(null)`，改用 `keepPreviousData` + 局部 loading 指示
- [ ] 为关键查询增加 `AbortSignal`（`authedFetch` 需支持 signal 透传）和超时保护
- [ ] 移除 `cache: 'no-store'` 硬编码，按场景决定缓存策略

### 2) 安全漏洞修复 🔴 严重

**现状**：
- `lib/auth.ts:12` 和 `app/login/page.tsx:34-35` 通过 `document.cookie` 设置 access_token，无 `Secure` 标志、无 `HttpOnly` 标志 — 任意 XSS 即可窃取 token
- `next.config.mjs` CSP 允许 `'unsafe-eval'` + `'unsafe-inline'`，XSS 防护被削弱
- CSP `connect-src` 仍为 `'self' http://localhost:* ws://localhost:*`，未适配生产

**改造项**：
- [ ] Token 改由后端通过 `Set-Cookie: HttpOnly; Secure; SameSite=Strict` 下发
- [ ] 前端移除 `document.cookie` 直接操作 token 的代码
- [ ] CSP 移除 `unsafe-eval`（排查 Next.js 依赖后逐步收紧）
- [ ] CSP `connect-src` 按环境变量区分开发/生产域名

### 3) 状态与错误体验统一 🟠 高

**现状**：
- `app/error.tsx` 仅 14 行，直接暴露 `error.message`，无错误分级、无 Trace ID、仅一个"重试"按钮
- `app/not-found.tsx` 存在但极简（仅标题 + 返回首页链接）
- `app/loading.tsx` 仅一个根级文件，纯文字"加载中..."，无 Skeleton、无动画
- 无路由级 `error.tsx` 或 `loading.tsx`
- `components/status-state.tsx` 提供 `LoadingState/ErrorState/EmptyState`，但 `ErrorState` 无重试按钮、无错误码
- `useApiMutation:36` 抛出 `"HTTP 500"` 原始文本，无 response body 解析
- `components/ui/toast.tsx` 已接入 `ToastProvider` 但全站零调用

**改造项**：
- [ ] 升级 `error.tsx`：错误分级（网络/401/403/5xx/未知）、多种恢复动作、Trace ID 展示
- [ ] 为高频路由增加独立 `loading.tsx`，引入 Skeleton 组件
- [ ] `ErrorState` 增加 `onRetry` 回调和错误码展示
- [ ] `useApiMutation`（或迁移后的 `useQuery`）解析 response body 中的错误信息
- [ ] 建立 API 错误码 → 前端文案映射表
- [ ] 启用 Toast 系统，在 mutation 成功/失败时调用

### 4) 模拟交易安全 🔴 严重

**现状**：
- `paper-trading/page.tsx:113` — `handleOrder` 表单提交直接发请求，无确认弹窗
- `paper-trading/page.tsx:201` — 下单按钮有 `disabled={placeApi.isPending}`（好）
- `paper-trading/page.tsx:260` — 撤单按钮无 `disabled` 状态，可重复点击
- `paper-trading/page.tsx:119` — 仅校验 `qty > 0`，无最大数量、无价格合理性检查
- `components/ui/confirm-dialog.tsx` — 已实现但全站未使用，且缺少 Escape 关闭、焦点陷阱、ARIA 角色
- 无幂等性保护（无 `X-Idempotency-Key`、无 `mutationKey`）

**改造项**：
- [ ] 下单前弹出 `ConfirmDialog`，展示：标的、方向、数量、价格、预估金额、风险提示
- [ ] 撤单按钮增加 `disabled={cancelApi.isPending}`
- [ ] 增加前端校验：最大下单量、价格偏离市价阈值、可用资金检查
- [ ] 为写操作增加 `X-Idempotency-Key` 请求头
- [ ] 升级 `ConfirmDialog`：Escape 关闭、焦点陷阱、`role="alertdialog"`、`aria-modal`

### 5) 错误监控接入 🔴 严重

**现状**：全站无 Sentry、LogRocket、Datadog 或任何错误上报。`error.tsx` 中的错误仅展示给用户，不上报。

**改造项**：
- [ ] 接入 Sentry（`@sentry/nextjs`），配置 DSN 和 source map 上传
- [ ] `error.tsx` 中调用 `Sentry.captureException(error)`
- [ ] `useApiMutation`（或迁移后的 query `onError`）中上报 API 错误
- [ ] 配置错误采样率和 PII 过滤规则

### 6) 可访问性底线 🟠 高

**现状**：
- 全站零 `aria-label`、零 `role`、零 `tabIndex`、零 `focus-visible`、零 `sr-only`
- `globals.css:154-160` 对 input/select/textarea 设置了 `outline: none` + box-shadow 替代，但按钮和链接无任何焦点样式
- `app/login/page.tsx:51-65` — 用户名/密码输入框仅有 `placeholder`，无 `<label>`
- `paper-trading/page.tsx:179-199` — 下单表单（代码、数量、价格）无 `<label>`
- `chat-config-modal.tsx` 和 `valuation/page.tsx` 有正确的 `<label>` 包裹（少数正面案例）

**改造项**：
- [ ] 所有表单 input 关联 `<label>` 或 `aria-label`
- [ ] 按钮/链接增加 `focus-visible` 样式（`globals.css` 补充规则）
- [ ] 弹窗组件增加 `role="dialog"` / `aria-modal="true"` / `aria-labelledby`
- [ ] 错误提示增加 `role="alert"` 或 `aria-live="polite"`
- [ ] 核心操作（下单、筛选、分页、弹窗关闭）支持键盘可达

- [ ] 迁移至 `useQuery`，配合 `refetchInterval: 60_000` 替代手动 `useAutoRefresh`
- [ ] 改为"任务入口 + 异常提醒 + 待处理动作"

- [ ] 拆分筛选、结果、动作三区域，减少单页状态耦合
- [ ] 提供"保存筛选条件"和"常用视图"
