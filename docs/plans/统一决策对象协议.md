# 统一决策对象协议

> 校准说明：本文按当前 `packages/akshare-mcp/src/akshare_mcp/services/decision_contracts.py` 与 `tools/decision.py` 的实际 payload 结构整理；若后续字段变更，应以后者为准。

## 目标

统一决策流水线首版遵循两个输出层级：

1. `summary`
   用于前端卡片、助手主回复、低延迟场景。
2. `details`
   用于证据下钻、调试、回放、灰度比对。

不引入“一个超大工具同时返回所有字段”的耦合接口，而是保持：

- `get_unified_decision_summary`
- `get_unified_decision_details`
- `get_unified_decision`（兼容包装器，可按 `detail_level` 选择）

## Details 协议

`details` 在 `summary` 基础上追加原始上下文与融合细节：

```json
{
  "...summary_fields": "...",
  "details": {
    "requested": {
      "code": "600519",
      "user_id": "u_demo",
      "investment_style": "balanced"
    },
    "meta": {
      "updated_at": "2026-03-19T12:00:00+08:00",
      "cached": false,
      "fallback_reason": null,
      "data_quality": {
        "grade": "mixed"
      }
    },
    "stock_context": {},
    "quant_context": {},
    "event_context": {},
    "user_context": {},
    "gate_result": {},
    "fusion": {}
  }
}
```

## 设计约束

- `summary` 中不塞大块原始上下文，只保留决策必要字段。
- `details` 必须能复盘 `summary` 的形成路径。
- `user_id` 允许为空；空时降级为匿名用户上下文，不阻塞主流程。
- 当前运行时 `details` 使用 `gate_result` 作为完整闸门对象字段名，不是 `gate`。
- `gate_flags` 与 `veto_reason` 分离：
  - `gate_flags` 表达所有闸门状态。
  - `veto_reason` 仅在硬阻断时填写。
- `data_provenance` 只记录来源链与时间戳，不复制原始数据。
- 首版允许 `app_users / users / user_profile_snapshots` 并存读取，但 `user_gate` 必须为可选能力，不能因用户画像缺失直接失败。

## 灰度原则

- 前端默认消费 `summary`。
- `details` 仅在用户点开时加载。
- 统一决策与既有 `should_i_buy`、`smart_stock_diagnosis` 并存一段时间，便于灰度对比与回归检查。
