### 1.3 存储层现状（TimescaleDBAdapter）
- 代码：`storage/timescaledb.py`
- 关键已落地表（节选）：
  - 时序与行情：`kline_1d`, `stock_quotes`, `stocks`, `financials`
  - 投研与策略：`backtest_results/backtest_trades/backtest_equity`, `screener_strategies`
  - 交易与组合：`portfolios`, `holdings`, `paper_accounts/paper_positions/paper_trades/paper_orders`
  - 运维与业务：`alerts*`, `watchlist*`, `sync_tasks/sync_schedules`, `events`
  - 扩展能力：`stock_embeddings/pattern_vectors/vector_documents`, `market_blocks/block_stocks`, `dragon_tiger`, `block_trades`, `research_reports`, `users`
- 稳定性机制：连接池绑定事件循环，循环变化或 pool 失效时自动重建（避免 `Event loop is closed` 类错误）。

### 1.4 安全与传输机制
- `start_server.py`：默认 `MCP_HOST=127.0.0.1`、`MCP_ALLOW_TOKEN_PASSTHROUGH=false`；日志走 stderr（避免 stdio 协议污染）。
- `server.py`：
  - `stdio`：只给提示，不阻断启动；
  - `http/streamable-http/sse`：必须满足 host/origin/auth/token 4 项基线，否则拒绝启动。
- 文档对齐：`MCP_CONFIG_GUIDE.md` 与代码一致。

### 1.5 现状优势与技术债
- **优势**：能力全、数据源降级链成熟、Manager 编排完善、可直接支撑中高复杂度金融前端。
- **技术债**：
  1) 历史 schema 命名不一致（`pre_close/prev_close`, `change/change_amt`, `stock_code/code`）；
  2) 文档与实际 DB 演进分散在多个 SQL 脚本；
  3) 用户体系虽有 `users`，但缺少完整 RBAC/会话/审计闭环。

## 2. 应用端总体架构设计（Node.js 强约束版）

```mermaid
flowchart TB
  U[Web/移动端用户] --> FE[Next.js 14 前端]
  FE --> BFF[NestJS BFF API 网关]
  BFF --> AUTH[JWT/Refresh + Session]
  BFF --> ACL[RBAC/数据权限]
  BFF --> MCPG[MCP Client Gateway\n(streamable-http/sse)]
  MCPG --> MCP[packages/akshare-mcp FastMCP]
  MCP --> DB[(PostgreSQL + TimescaleDB)]
  MCP --> DS[Tushare/AkShare/东财/新浪/腾讯]
  BFF --> REDIS[(Redis 缓存/限流/会话)]
  BFF --> AUDIT[(审计日志/追踪)]
```

> 强约束：**应用端仅使用 Node.js 技术栈实现**（Web + BFF），并且**必须依托现有 `packages/akshare-mcp` 服务能力**，通过 MCP 协议调用；禁止在应用端直接复制/重写 Python 业务能力。

## 3. 应用端技术方案（详细，按现状修订）

### 3.1 技术选型（最终版）
- 前端：**Next.js 14** + TypeScript + TanStack Query + Zustand + ECharts
- BFF：**Node.js + NestJS（必选）**（可用 Fastify Adapter）
- MCP 对接：`@modelcontextprotocol/sdk`（或等价 MCP Client），传输协议使用 `streamable-http`（首选）/`sse`（备选）
- 身份：JWT（Access 15m + Refresh 7/30d）
- 缓存：Redis（行情短 TTL、会话、限流）
- 数据库：PostgreSQL 16 + TimescaleDB（复用现有库，增量扩展）

### 3.2 前端模块划分（不变，改为 Node 单栈落地）
1. 用户中心：登录、偏好、风险等级、API Key 管理
2. 市场看板：实时行情、K线、盘口、资金流、公告研报
3. 研究回测：策略编辑、回测任务、绩效对比、因子页
4. 组合风控：持仓、优化建议、压力测试、风险暴露
5. 智能助手：自然语言入口 + 卡片化解释（对齐 `DEMO.md` 第 8 节 JSON 协议）
6. 提醒与结果联动：告警、报告、策略结果展示

### 3.3 BFF 统一 DTO（示例）
```ts
// /api/decision/buy-card
export type BuyCardDTO = {
  version: '1.0';
  scene: 'buy_decision';
  action: 'buy' | 'watch' | 'sell';
  confidence: number;
  summary: string;
  reasons: string[];
  execution_plan: { position: string; buy_zone?: string; stop_loss?: string };
  risks: string[];
  data_provenance: Array<{ source: string; dataset: string; timestamp: string }>;
  compliance_notice: string;
};
```

### 3.4 MCP 集成边界（新增，解决“独立应用端悖论”）
1. **能力边界**：行情、财务、回测、选股、诊断等业务能力全部来自 `packages/akshare-mcp`。
2. **协议边界**：BFF 通过 MCP Client Gateway 调用工具，不直接 `import` Python 模块。
3. **演进边界**：应用端只做“编排/鉴权/缓存/审计/前端呈现”，不重复实现工具逻辑。
4. **可靠性边界**：MCP 不可用时，BFF 返回标准降级结构（含 `fallback_reason/source_chain`）。

### 3.5 配置模板（生产最小集）

## 4. 数据库扩展与迁移方案（DDL）

> 原则：**不破坏现有表**，采用增量扩展；历史差异通过 migration/fix 脚本吸收。

```sql
-- 1) 账户与会话
CREATE TABLE IF NOT EXISTS app_users (
  id BIGSERIAL PRIMARY KEY,
  username VARCHAR(64) UNIQUE NOT NULL,
  email VARCHAR(128) UNIQUE,
  password_hash TEXT NOT NULL,
  status VARCHAR(16) DEFAULT 'active',
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW()
);

CREATE TABLE IF NOT EXISTS app_sessions (
  id BIGSERIAL PRIMARY KEY,
  user_id BIGINT NOT NULL REFERENCES app_users(id) ON DELETE CASCADE,
  refresh_token_hash TEXT NOT NULL,
  user_agent TEXT,
  ip INET,
  expires_at TIMESTAMPTZ NOT NULL,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

-- 2) RBAC
CREATE TABLE IF NOT EXISTS roles (
  id BIGSERIAL PRIMARY KEY,
  role_code VARCHAR(32) UNIQUE NOT NULL,
  role_name VARCHAR(64) NOT NULL
);
CREATE TABLE IF NOT EXISTS permissions (
  id BIGSERIAL PRIMARY KEY,
  perm_code VARCHAR(64) UNIQUE NOT NULL,
  perm_name VARCHAR(128) NOT NULL
);
CREATE TABLE IF NOT EXISTS user_roles (
  user_id BIGINT REFERENCES app_users(id) ON DELETE CASCADE,
  role_id BIGINT REFERENCES roles(id) ON DELETE CASCADE,
  PRIMARY KEY (user_id, role_id)
);

-- 3) 用户与业务对象映射
CREATE TABLE IF NOT EXISTS user_portfolios (
  id BIGSERIAL PRIMARY KEY,
  user_id BIGINT NOT NULL REFERENCES app_users(id) ON DELETE CASCADE,
  portfolio_id INTEGER,
  created_at TIMESTAMPTZ DEFAULT NOW()
);
CREATE TABLE IF NOT EXISTS user_strategies (
  id BIGSERIAL PRIMARY KEY,
  user_id BIGINT NOT NULL REFERENCES app_users(id) ON DELETE CASCADE,
  strategy_name VARCHAR(64) NOT NULL,
  strategy_config JSONB NOT NULL,
  created_at TIMESTAMPTZ DEFAULT NOW()
);
CREATE TABLE IF NOT EXISTS user_watchlists (
  id BIGSERIAL PRIMARY KEY,
  user_id BIGINT NOT NULL REFERENCES app_users(id) ON DELETE CASCADE,
  code VARCHAR(16) NOT NULL,
  created_at TIMESTAMPTZ DEFAULT NOW(),
  UNIQUE(user_id, code)
);

-- 4) 审计日志
CREATE TABLE IF NOT EXISTS audit_logs (
  id BIGSERIAL PRIMARY KEY,
  user_id BIGINT,
  action VARCHAR(64) NOT NULL,
  resource VARCHAR(64) NOT NULL,
  resource_id VARCHAR(128),
  status VARCHAR(16) NOT NULL,
  trace_id VARCHAR(64),
  detail JSONB DEFAULT '{}'::jsonb,
  created_at TIMESTAMPTZ DEFAULT NOW()
);
CREATE INDEX IF NOT EXISTS idx_audit_logs_user_time ON audit_logs(user_id, created_at DESC);
```

## 5. 安全与合规落地

1. **传输安全**：对齐 `_enforce_http_security_baseline`，默认本地绑定 + Origin 白名单 + Bearer/API Key + 禁止 token passthrough。
2. **访问控制**：BFF 层强制注入 `user_id` 过滤条件；管理操作二次鉴权（角色 + 资源权限）。
3. **数据保护**：密码/refresh token 哈希化；敏感配置仅服务端持有；日志脱敏。
4. **审计可追溯**：请求链路统一 `trace_id`，关键动作写入 `audit_logs`。
5. **合规提示**：前端卡片固定输出“不构成投资建议”声明。

## 8. 风险与回滚预案

- **风险1：上游数据源抖动** → 启用降级链、缓存兜底、展示数据时效。
- **风险2：迁移影响历史数据** → 迁移前快照备份，先影子环境校验后生产执行。
- **风险3：权限误配导致越权** → 最小权限原则 + 关键接口白名单 + 审计回放。
- **风险4：重建过程偏离边界** → 代码评审强制检查“禁止重复实现 MCP 业务逻辑”。
- **回滚**：按 migration 批次回滚；BFF 保留 DTO 兼容窗；前端特性开关降级。
