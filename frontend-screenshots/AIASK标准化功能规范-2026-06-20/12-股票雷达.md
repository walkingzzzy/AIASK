## 1. 功能设计

### 1.1 需求背景与价值

| 项 | 内容 |
|---|---|
| 问题陈述 | 股票发现过去容易与 factory-events 混在一起，V1 需要独立、只读、受控的雷达入口。 |
| 解决方案 | Stock Radar 独立页面展示 status、candidates、digest；run/push/schedule 只创建 ActionIntent。 |
| 业务价值 | 金融发现能力可演示，同时不展示四工厂。 |

### 1.2 用户故事

| 编号 | 优先级 | 用户故事 | 成功标准 |
|---|---|---|---|
| RADAR-US-001 | P0 | 作为金融研究用户，我希望查看候选和筛选原因。 | candidates 表含 symbol、reason、risk。 |
| RADAR-US-002 | P0 | 作为用户，我希望运行雷达前进入审批。 | run 只创建 intent。 |
| RADAR-US-003 | P0 | 作为 PM，我希望雷达不出现工厂事件文案。 | 页面不包含 factory-events/工厂事件入口。 |

### 1.3 功能分解与优先级

### 1.4 业务规则与边界

| 规则 | 说明 | 验收 |

## 2. 流程设计

| 步骤 | 用户操作 | 前端行为 | Agent/API | 异常 |
|---|---|---|---|---|
| 1 | 打开雷达 | 加载 status/candidates/digest | stock-radar GET routes | 数据缺失 degraded |
| 2 | 筛选候选 | 本地过滤/刷新 | candidates route | 无结果 empty |
| 3 | 运行雷达 | 创建 run intent | `/intents` | 无 token gated |
| 4 | 推送摘要 | 创建 push intent | `/intents` | 不直接投递 |
| 5 | 调度更新 | 创建 schedule intent | `/intents` | 不直接创建 job |

状态机：`loading -> ready|empty|degraded|error -> intent_creating -> intent_created|failed|gated`。

## 3. 架构设计

Desktop StockRadarWorkspace 调 Agent desktop_finance stock-radar routes；受控动作通过 ActionIntent；不调用 factory-events UI。

## 10. 代码实证与成熟实现补强

### 10.1 当前代码审计

| 对象 | 代码证据 | 当前行为 | 文档结论 |
|---|---|---|---|
| 页面 | `desktop/src/features/stock-radar/StockRadarWorkspace.tsx` | 加载 status、candidates、digest，按 tier 筛选，创建 run/push/schedule intent | 股票雷达是独立 V1 页面，不依赖 factory-events |
| 字段 | `candidate_id`、`symbol`、`stock_name`、`tier`、`radar_score`、`summary`、`source_chain`、`confirmations`、`risk_flags` | 候选表和详情要展示 reason/risk/source | 不能只显示股票代码和分数 |
| API | `services/api/finance.ts` 的 `stockRadarStatus/Candidates/Digest/*Intent` | GET routes + `/intents` | 读是 API token，动作是 control token |
| Agent routes | `desktop_finance.py` 的 `/v1/desktop/stock-radar/*` | status/candidates/digest 只读 | 文档要区分 read 和 intent |
| 测试 | `StockRadarWorkspace.test.tsx`、`capabilities.spec.ts` | 覆盖加载、无 token gated、创建三类 intent、V1 独立页面 | QA 必须扫 factory-events 文案 |

### 10.2 成熟实现要求

| 区域 | 需要展示 | 验收 |
|---|---|---|
| 状态 | latest_run、counts、degraded_flags、candidate count | degraded_flags 不为空时黄灯 |
| 候选 | symbol、name、tier、score、event_type、direction、summary、risk_flags | 候选为空显示 empty，不伪造数据 |
| 摘要 | digest preview、渠道、生成时间 | 推送前只预览，不外发 |
| 受控动作 | run、push preview、schedule update | 每个动作返回 intent_id |

### 10.3 成熟技术采用

金融信息展示参考 Lightweight Charts 和金融数据源文档的“数据来源/时间/风险说明”原则；OWASP 要求外部投递和调度动作走审批。AIASK 采用候选发现 + 风险标记 + ActionIntent，不采用投资建议、交易按钮或 Factory Events 跳转。

### 11.3 状态和响应式

- `stale/degraded`：数据源或市场状态过期时，候选仍可只读但 run/push/schedule 按门禁处理。
- `blocked`：任何金融风险或策略阻断只展示 reason，不跳转四工厂。
- 窄屏候选表卡片化，字段优先级为 symbol、tier、score、risk、reason；digest 和 raw JSON 下置。

## 功能目标

股票雷达是第一版必须保留的独立金融能力，不属于 Factory Events。它负责候选发现、观察摘要、风险标记、运行意图、摘要推送意图和调度更新意图。

| Agent adapter | `packages/agent/src/aiask_agent/adapters/stock_radar.py` |

## 用户流程

1. 打开股票雷达，读取 status、candidates、digest。
2. 用户按 tier、行业、风险、来源筛选候选。
3. 点击候选查看理由、证据、风险、source chain。
4. 点击“创建雷达运行意图”，生成 ActionIntent，不直接执行。
5. 点击“推送摘要意图”，选择 Gateway/Webhook 目标。
6. 点击“调度更新意图”，进入自动化/Jobs。

## 验收规则

1. 页面标题、按钮、路由不出现 Factory Events 依赖文案。
2. 只读读取用 API token；运行/推送/调度走 intent/control token。
3. 候选必须显示数据来源和风险标记。
4. 输出必须包含“非投资建议”或同等风险提示。
5. 数据不可用时显示缺失数据源/数据库修复入口。

## 详细落地规范

### 问题场景与技术方案

| 问题 | 前端表现 | 技术方案 | 代码落点 | 验收 |
|---|---|---|---|---|
| 用户不知道雷达是否跑过 | status 卡显示 last_run、candidate_count、data_freshness | `/v1/desktop/stock-radar/status` | `desktop_finance.py` | 无 run 显示空态 |
| 候选太多无法判断 | 表格支持 tier/industry/risk/source 筛选 | candidates endpoint query | `adapters/stock_radar.py` | 筛选参数进入请求 |
| 候选理由不可信 | 详情抽屉展示 source chain、confirmations、risk_flags | payload 保留 evidence | `services/stock_radar/*` | 不是只有 score |
| 用户想重新运行雷达 | 创建 run intent，不直接执行 | `stockRadarRunIntent` -> `/intents` | `AiaskApi`、`routes/intents.py` | intent id 可见 |
| 用户想推送摘要 | 选择 channels，进入 Gateway approval | push digest intent | `stock_radar.py`、Gateway | 未确认不推送 |
| 雷达依赖数据缺失 | 显示 Data & Sync 修复入口 | status 返回 readiness/degraded | `routes/desktop_data.py` | 不显示空白候选成功 |

### 不做什么

- 不把雷达候选写成投资建议。
- 不依赖 Factory Events route 或文案。
- 不提供一键外部推送。
- 不在数据缺失时伪造候选。

### 状态机补充

`status_loading -> ready -> candidates_loading -> candidates_ready/candidates_empty/candidates_error`

受控动作为 `intent_draft -> intent_created -> awaiting_approval -> approved/denied -> executed/failed`。推送和调度都不得跳过 intent。
