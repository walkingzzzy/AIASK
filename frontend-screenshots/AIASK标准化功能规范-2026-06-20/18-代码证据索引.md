## 1. 功能设计

### 1.1 需求背景与价值

| 项 | 内容 |
|---|---|
| 问题陈述 | 文档如果不绑定代码，就会把想象、旧方案、mock 和真实实现混在一起。 |
| 解决方案 | 本索引按 Desktop、Agent、Tools、AKShare、Finance、Tests 分层列证据，并定义使用规则。 |
| 业务价值 | 让每个功能文档和开发任务都有可核验证据。 |

### 1.2 用户故事

| 编号 | 优先级 | 用户故事 | 成功标准 |
|---|---|---|---|
| EVIDENCE-US-001 | P0 | 作为开发，我希望快速找到功能入口。 | 代码路径按层分组。 |
| EVIDENCE-US-002 | P0 | 作为 PM，我希望知道“已实现”是否有代码支撑。 | 已实现必须回指路径。 |
| EVIDENCE-US-003 | P0 | 作为 QA，我希望知道该测哪里。 | 提供测试路径和命令。 |

### 1.3 功能分解与优先级

| 功能编号 | 功能点 | 优先级 | 当前代码依据 | 待开发事项 | 验收标准 |
|---|---|---|---|---|---|
| EVIDENCE-F001 | Desktop 证据 | P0 | `desktop/src` | 持续更新 | view/API/page/test 可找 |
| EVIDENCE-F002 | Agent route 证据 | P0 | `routes/*` | 持续更新 | endpoint 可找 |
| EVIDENCE-F003 | Tool 证据 | P0 | tools/catalog/registry/policy | 持续更新 | `agent_*` 可查 |
| EVIDENCE-F004 | 测试证据 | P0 | desktop/agent tests | 持续更新 | 验收命令明确 |

### 1.4 业务规则与边界

文档不是证据本身；mock 不是 live；后端存在不是产品入口；四工厂兼容代码不是 V1 展示。

## 2. 流程设计

流程：`读需求 -> 查证据索引 -> rg 核验代码 -> 判断已实现/待开发/deferred -> 写功能文档 -> 写测试`。状态机：`unverified -> evidence_found|missing -> classified -> documented -> tested`。

## 3. 架构设计

本索引按 Desktop、Agent、MCP/Data、Finance servers、Tests 分层，遵守 Desktop -> Agent HTTP 的单向边界。

## 4. 功能说明：接口与数据

证据字段模板：`能力`、`代码路径`、`证明什么`、`不能证明什么`、`关联测试`、`V1 状态`。

## 5. 前端设计

本文件不定义 UI，但新增页面必须能在 `views.ts`、`routes.ts`、`App.tsx` 和 feature folder 找到证据。

## 6. 开发规范

开发前先查本文；新增能力后同步更新本文或专项文档中的代码证据表。

## 9. 不做什么

- 不接受截图、旧方案、mock 作为唯一实现证据。
- 不把四工厂兼容代码当 V1 产品证据。

## 10. 代码实证与成熟实现补强

### 10.1 当前仓库证据快照

| 证据类别 | 当前路径 | 证明什么 | 不能证明什么 |
|---|---|---|---|
| 前端栈 | `desktop/package.json` | React/Vite/Tauri、Vitest、Playwright、TanStack、Lightweight Charts 已是当前依赖 | 不能证明页面体验已完整 |
| 页面挂载 | `desktop/src/App.tsx` | V1 页面 lazy renderer 存在 | 不能证明后端 live 可用 |
| 导航/路由 | `desktop/src/views.ts`、`desktop/src/routes.ts` | 视图注册、canonical route、deferred factory fallback | 不能证明 legacy 页面是 V1 产品入口 |
| API client | `desktop/src/services/aiaskApi.ts`、`desktop/src/services/api/*` | Desktop 通过 Agent HTTP 调用 | 不能证明页面没有缺状态，需要看组件测试 |
| Mock | `desktop/src/mockApi.ts`、`desktop/src/mock/*` | mock/e2e 数据路径存在 | 不能证明 provider 生产可用 |
| Agent routes | `packages/agent/src/aiask_agent/routes/*` | HTTP endpoint 存在 | 不能证明前端已展示 |
| Tool policy | `tools/policy.py`、`tools/catalog.py`、`tool_registry.py` | `agent_*` facade 和 toolset 规则 | 不能允许 raw manager 上屏 |
| 测试 | `desktop/src/**/*.test.*`、`desktop/e2e/*`、`packages/agent/tests/*` | 行为和契约覆盖范围 | 不能替代人工产品验收 |

### 10.2 必须引用的代码行级证据

| 结论类型 | 至少引用 |
|---|---|
| “页面已存在” | `App.tsx` lazy import + `views.ts` registry + feature component + test |
| “路由已存在” | `routes.ts` mapping 或 Agent `@router` endpoint |
| “受控动作” | API method 使用 control token 或 `/intents`、`/v1/approvals` |
| “secret 已保护” | 页面清空/不回显逻辑 + redaction test |
| “四工厂不展示” | `V1_DEFERRED_VIEWS`、`v1Scope.ts`、`views.test.ts`、`routes.test.ts`、e2e 负向 |

### 10.3 成熟技术采用

证据索引遵循 OpenAPI/JSON Schema 的契约思想和 Testing Library 的用户可见行为原则：代码路径必须可追溯，测试必须覆盖用户看见和能点击的行为。索引本身不替代源码审计，每次发布前必须重新 `rg` 当前仓库。

## 证据使用规则

1. 文档中写“已具备后端能力”必须能在本索引找到文件或 endpoint。
2. 文档中写“前端已实现”必须能找到对应 `desktop/src/features` 或组件。
3. 文档中写“V1 不展示”必须同时有 route/view/tool 负向测试或人工验收项。
4. mock 证据不能替代 live smoke。

## 详细落地规范

### 如何使用本索引生成开发任务

开发团队拿到一个需求后，按以下顺序使用本索引：

1. 找到对应功能域。
2. 判断是否已有 Agent route。
3. 判断是否已有 `AiaskApi` 方法。
4. 判断是否已有前端页面。
5. 判断是否已有 mock 和测试。
6. 缺哪一层，就只补哪一层，不跨边界偷懒。

### 缺口判断矩阵

| 现状 | 结论 | 开发任务 |
|---|---|---|
| 有后端 route，无 API client | 前端不能直接调 URL | 补 `aiaskApi.ts` 方法和测试 |
| 有 API client，无页面 | 能力未产品化 | 补 feature page/panel |
| 有页面，无 mock | 测试不可持续 | 补 `mockApi.ts` 或 `desktop/src/mock/*` |
| 有 mock，无 live smoke | 只能证明前端流程 | 标注 mock-only，补 live smoke |
| 有 MCP tool，无 Agent facade | Desktop 不能直接用 | 补 Agent route 或 `agent_*` wrapper |
| 有 raw manager | 不能模型可见 | 经 tool policy 审核后包装 |

### 代码生成顺序

```text
Agent route / agent_* facade
  -> AiaskApi method
  -> mock payload
  -> feature component
  -> unit test
  -> e2e path
  -> documentation update
```

### 证据更新要求

每次新增功能后必须更新：

- 本索引对应表格。
- 对应专项文档的代码证据。
- `16-安全门禁与验收矩阵.md` 中的门禁或验收。
- README 索引，如新增文档。

### 不接受的证据

- 只有口头说明。
- 只有截图，没有代码/API。
- 只有 mock，没有标注 mock。
- 只有后端私有函数，没有 Agent HTTP 或 `agent_*` facade。
- 只有旧文档，没有当前代码路径。
