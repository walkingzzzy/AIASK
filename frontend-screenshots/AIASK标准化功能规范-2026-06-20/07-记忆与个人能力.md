## 1. 功能设计

### 1.1 需求背景与价值

| 项 | 内容 |
|---|---|
| 问题陈述 | AIASK 需要长期使用体验，但用户必须知道哪些个人数据被记录、能否导出/删除、是否进入学习。 |
| 解决方案 | 本地用户页展示 profile、activity、policy、export/delete、learning dataset 和 recommendations，并清楚区分 dry-run 与真实写入。 |
| 业务价值 | 建立可解释的个人化能力和隐私边界。 |

### 1.2 用户故事

| 编号 | 优先级 | 用户故事 | 成功标准 |
|---|---|---|---|
| USER-US-001 | P1 | 作为用户，我希望查看本地画像和活动，以便理解系统如何记住我。 | profile/activity 可见且 secret redacted。 |
| USER-US-002 | P1 | 作为用户，我希望导出或删除自己的数据，以便控制隐私。 | export/delete dry-run 和真实动作边界清楚。 |
| USER-US-003 | P1 | 作为用户，我希望决定是否允许学习，以便避免未经同意的数据写回。 | data policy 可查看和保存。 |

### 1.3 功能分解与优先级

| 功能编号 | 功能点 | 优先级 | 当前代码依据 | 待开发事项 | 验收标准 |
|---|---|---|---|---|---|
| USER-F001 | 本地画像 | P1 | `/v1/desktop/users/local-profile` | 空态和错误态 | profile 可读可编辑受控 |
| USER-F002 | 活动/分析 | P1 | `/activity`、`/analytics/summary` | 筛选和摘要 | 活动来源可见 |
| USER-F003 | 数据策略 | P1 | `/data-policy` | 保存门禁 | 学习授权明确 |
| USER-F004 | 导出/删除/retention | P1 | export/delete/retention routes | dry-run 标记 | 不误删、不误写 |

### 1.4 业务规则与边界

| 规则 | 说明 | 验收 |
|---|---|---|
| 个人数据操作受控 | 删除、retention sweep、policy save 需要门禁 | control token 或确认可见 |
| 学习写回需授权 | `allow_learning` 必须可见 | 未授权不进入 dataset |
| Secret 不回显 | 活动和导出不包含 token/key | `secrets_redacted` |

## 2. 流程设计

| 步骤 | 用户操作 | 前端行为 | Agent/API | 异常 |
|---|---|---|---|---|
| 1 | 打开本地用户页 | 加载 profile/activity/policy | desktop_user routes | 无数据 empty |
| 2 | 修改策略 | 编辑 retention/learning | PATCH policy | 无 token gated |
| 3 | 导出数据 | 点击 export | export route | 大数据或失败显示 error |
| 4 | 删除/清理 | dry-run 后确认 | delete/retention routes | market_data_affected 明确 |

状态机：`loading -> ready|empty|error -> editing_policy|exporting|deleting -> success|failed|gated`。

## 3. 架构设计

Desktop 用户页只通过 Agent desktop_user routes 读取和写入本地用户数据；Agent 负责 redaction、retention 和 learning authorization。

## 6. 开发规范

新增用户数据字段必须同步 redaction、导出、删除和 retention 规则，不能只加 UI。

## 7. 错误说明

| 错误码 | 用户提示 | 技术原因 | 处理 |
|---|---|---|---|
| USER-201 | 数据策略保存需要授权 | control token missing | 禁用保存 |
| USER-301 | 活动数据加载失败 | route error | 可重试 |
| USER-401 | 学习未授权 | allow_learning false | 禁止写回 |

## 9. 不做什么

- 不静默保存个人学习数据。
- 不展示 secret。
- 不把 dry-run 写成真实删除。

## 10. 代码实证与成熟实现补强

### 10.1 当前代码审计

| 对象 | 代码证据 | 当前行为 | 文档结论 |
|---|---|---|---|
| 用户页面 | `desktop/src/features/user/LocalUserWorkspace.tsx` | 管理本地 profile、activity、feedback、analytics、export/delete、retention、learning dataset、recommendations、data policy | 个人能力要覆盖数据权利和治理，不只是“记忆” |
| Settings profile | `SettingsWorkspace.tsx` | 保存 local profile，展示用户 ID/名称和 token 状态 | profile 是设置和工作台共享上下文 |
| Agent routes | `routes/desktop_user.py` | 提供 `/local-profile`、events、feedback、activity、analytics、export、delete、retention、learning-dataset、recommendations、data-policy | 删除/retention/policy save 是受控动作 |
| Memory tools | `AiaskApi.memoryStatus()`、`memorySearch()` | 通过 `agent_memory_*` 工具查询状态和搜索 | memory 结果要可解释，不自动写入敏感信息 |

### 10.2 功能细节

| 功能 | 产品含义 | 开发落点 | QA 断言 |
|---|---|---|---|
| Local Profile | 本地操作者身份和显示名 | `localProfileGet/Save()` | 保存后设置页和用户页一致 |
| Activity/Feedback | 用户行为和反馈进入可审计事件 | `recordEvents()`、`recordFeedback()` | 不记录 secret 原值 |
| Export/Delete | 用户数据导出、删除预览、硬删除边界 | `/export`、`/delete` | destructive 默认 dry_run |
| Data Policy | 记忆、学习、retention 策略 | `/data-policy` | 无 control token 不保存策略 |

### 10.3 成熟技术采用

OWASP ASVS 和 API Security 要求个人数据操作可追踪、可导出、可删除、权限清晰。AIASK 采用 Desktop 显示治理状态、Agent route 执行数据操作、control token 保护状态写入；不采用在前端直接改数据库或缓存。

### 11.3 状态和响应式

- `blocked`：后端策略拒绝删除/导出时展示 reason，不提供强制执行。
- `mock/degraded`：记忆服务未启用时显示功能降级，而不是隐藏入口。
- 窄屏优先显示 profile 和 search，治理区折叠到底部并增加二次确认。

## 原有内容保留

## 功能目标

个人能力不是一个简单资料页，而是 AIASK 理解用户的长期上下文：个人画像、用户习惯、用户标签、我的股票、我的策略、风险偏好、实际情况、历史反馈、记忆保存和记忆读取。第一版要把这些做成可见、可控、可导出、可删除的数据域。

## 代码证据

| 能力 | 代码位置 |
|---|---|
| memory | `packages/agent/src/aiask_agent/memory.py`、`memory_providers.py` |
| user data routes | `packages/agent/src/aiask_agent/routes/desktop_user.py` |

| 前端页面 | `desktop/src/features/user/LocalUserWorkspace.tsx`、Settings 相关 panels |

## 用户流程

1. 用户打开个人能力，看到当前 user_id、画像名、数据范围。
2. 用户编辑基本画像：职业/角色、研究偏好、风险偏好、常用市场、常用股票。
3. 页面展示用户习惯和用户标签：常用模型、常用工具、常问问题、偏好任务、关注行业、风险偏好标签。
4. 用户可保存反馈，形成学习数据。
5. 用户可搜索记忆，查看 AIASK 保存过的事实。
6. 用户可导出个人数据，或按 dry-run 预览删除影响后再删除。
7. 数据策略允许设置 retention、是否允许学习、是否包含会话。

## 验收规则

1. 保存个人信息必须显示数据范围和是否参与学习。
2. 删除必须先 dry-run，展示影响范围。
3. 记忆搜索不能返回其他用户数据。
4. “我的策略”在 V1 不链接四工厂。
5. Workbench 右侧能引用个人画像和记忆，但用户可关闭。

## 详细落地规范

### 问题场景与技术方案

| 问题 | 表现 | 技术方案 | 代码落点 | 验收 |
|---|---|---|---|---|
| AI 不记得用户偏好 | 画像和记忆可保存/检索 | memory providers + local profile | `memory.py`、`desktop_user.py` | 搜索能命中 |
| 用户担心隐私 | 数据策略、导出、dry-run 删除 | user data policy/export/delete | `session_store_user_data.py` | 删除前展示影响 |
| 用户标签不透明 | 标签来源和更新时间可见 | activity/analytics summary | `desktop_user.py` | 标签可解释 |
| 我的股票/策略混入工厂 | 只展示个人关注和偏好 | watchlist/profile 字段 | LocalUserWorkspace | 不链接四工厂 |
| 记忆污染当前对话 | 右侧显示引用记忆，可关闭 | Workbench context toggle | AppContextPanel | 关闭后不注入 |

### 字段设计

| 字段 | 说明 |
|---|---|
| `user_id` | 本地用户标识 |
| `profile_name` | 画像名 |
| `habits` | 常用工具、模型、任务类型 |
| `tags` | 用户标签，必须可解释来源 |
| `watchlist` | 我的股票 |
| `strategy_preferences` | 我的策略偏好，不是策略工厂入口 |
| `memory_policy` | 是否允许保存、检索、学习 |

### 代码生成/修改步骤

1. 新增个人字段先扩展 Agent user payload，再更新 Desktop 类型。
2. 所有删除类动作必须先 dry-run。
3. 记忆搜索必须带 user_id/scope。
4. mock 覆盖：无画像、有画像、删除 dry-run、policy disabled。
5. 测试覆盖跨用户隔离和四工厂负向。

### 不做什么

- 不默认保存敏感个人信息。
- 不把用户画像分享给外部平台。
- 不把“我的策略”链接到 V1 不展示的工厂。

### 状态机补充

`profile_loading -> profile_ready -> editing -> saving -> saved/save_failed`

记忆检索为 `memory_idle -> memory_searching -> memory_results/memory_empty/memory_error`。删除为 `delete_dry_run -> awaiting_confirm -> deleting -> deleted/delete_failed`。
