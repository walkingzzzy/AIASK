## 1. 功能设计

### 1.1 需求背景与价值

| 项 | 内容 |
|---|---|
| 问题陈述 | 如果只按页面写文档，会漏掉跨模块问题，如模型不可用、数据过期、外部投递、secret、四工厂边界。 |
| 解决方案 | 用全局矩阵按问题驱动映射到技术方案、代码落点、接口、门禁和验收。 |
| 业务价值 | PM 可按问题排期，开发可按技术闭环拆任务，QA 可按风险覆盖用例。 |

### 1.2 用户故事

| 编号 | 优先级 | 用户故事 | 成功标准 |
|---|---|---|---|
| MATRIX-US-001 | P0 | 作为 PM，我希望从问题反查功能和方案。 | 问题行有功能编号和文档链接。 |
| MATRIX-US-002 | P0 | 作为开发，我希望知道问题落在哪些文件。 | 每行有代码落点。 |
| MATRIX-US-003 | P0 | 作为 QA，我希望每个问题有验收方法。 | 每行有测试/检查方式。 |

### 1.3 功能分解与优先级

| 功能编号 | 功能点 | 优先级 | 当前代码依据 | 待开发事项 | 验收标准 |
|---|---|---|---|---|---|
| MATRIX-F001 | 问题分类 | P0 | 本目录专项文档 | 持续维护 | 覆盖基础、模型、MCP、数据、金融、集成、安全 |
| MATRIX-F002 | 技术方案映射 | P0 | 代码证据索引 | 持续维护 | 每个问题有方案和文件 |
| MATRIX-F003 | 验收映射 | P0 | 测试/安全矩阵 | 持续维护 | 每个问题有验收 |

### 1.4 业务规则与边界

矩阵不是替代专项文档；它是入口和排期工具。任何问题如果涉及写入、外部平台、金融风险或四工厂，必须显式写安全边界。

## 2. 流程设计

流程：`提出问题 -> 分类 -> 定位专项文档 -> 查代码证据 -> 定义方案 -> 写验收 -> 更新矩阵`。状态机：`new -> classified -> mapped -> scheduled -> verified -> closed`。

## 3. 架构设计

矩阵跨 Desktop、Agent、MCP、金融数据、外部平台、安全门禁，不新增运行时架构。

## 4. 功能说明：接口与数据

矩阵字段模板：`问题`、`用户表现`、`技术方案`、`代码落点`、`接口/工具`、`安全门禁`、`验收`、`关联文档`。

## 5. 前端设计

本文件不定义 UI，但矩阵中涉及 UI 的问题必须回指具体页面、route 和组件。

## 6. 开发规范

新增跨模块问题必须先进入矩阵，再拆到专项文档和任务。

## 7. 错误说明

| 错误码 | 用户提示 | 技术原因 | 处理 |
|---|---|---|---|
| MATRIX-101 | 问题未分类 | missing area | 补分类 |
| MATRIX-301 | 代码落点缺失 | no evidence | 查证据索引 |
| MATRIX-401 | 安全边界缺失 | no gate | 补 token/intent/blocked |

## 8. 功能测试

| 用例编号 | 场景 | 预期 |
|---|---|---|
| TC-MATRIX-001 | 随机抽样问题 | 能找到专项文档和代码落点 |
| TC-MATRIX-002 | 高风险问题 | 有安全门禁 |
| TC-MATRIX-003 | 四工厂问题 | 标记 deferred |

## 9. 不做什么

- 不用矩阵代替详细功能文档。
- 不写无代码落点的空泛方案。
- 不省略安全验收。

## 10. 代码实证与成熟实现补强

### 10.1 当前矩阵使用方式

| 输入问题 | 必查代码 | 输出方案 |
|---|---|---|
| 页面是否已存在 | `App.tsx` lazy import、`views.ts` registry、`routes.ts` mapping、feature component、test | 写“已实现/待补 UI/待补测试/Deferred” |
| API 是否已存在 | `AiaskApi` 方法、`services/api/*`、Agent `routes/*.py` | 写 endpoint、method、token、request/response |
| 是否安全 | `useAppConnectionSettings`、`controlToken`、`tools/policy.py`、`intents.py`、`approvals.py` | 写 gated/blocked/approval/redaction |
| 是否成熟 | `99-外部规范参考.md` 联网来源 | 写采用原则、不采用内容、验收影响 |
| 是否 V1 | `routes.ts`、`v1Scope.ts`、`views.test.ts`、e2e | 写 V1/Deferred/Legacy Diagnostic |

### 10.2 问题拆解模板

| 问题 | 产品答案 | 开发答案 | QA 答案 |
|---|---|---|---|
| 用户看不到模型为什么不可用 | Models 页面要显示 provider/config/smoke 状态 | `ModelsWorkspace.tsx` + `/v1/ai/*` | 缺 key 不泄露 secret，保存需 token |
| 数据过期导致金融分析不可信 | Data 页面显示 missing/stale/freshness/sync plan | `DataSyncWorkspace.tsx` + `/v1/desktop/data/*` | 同步只创建 intent |
| 外部消息不能误发 | Gateway 只创建 send intent | `GatewayPage.tsx` + `/v1/gateway/send` + `/intents` | 无 approval 不外发 |
| 四工厂不能进入 V1 | 路由和工具都过滤 | `routes.ts` + `v1Scope.ts` | e2e/route/view 负向 |

### 10.3 成熟技术采用

矩阵采用“问题 -> 证据 -> 方案 -> 验收”的工程决策模式，结合 OpenAPI、OWASP、Testing Library 和 Playwright。任何没有代码证据或外部成熟依据的问题，不能直接进入开发承诺。

## 原有内容保留

## 目的

本文件把 AIASK 常见产品问题直接映射到技术方案，避免开发时只凭感觉做页面。每个专项文档都应该引用或细化这里的矩阵。

## 基础能力

| 问题 | 应该怎么设计 | 技术方案 | 代码落点 | 验收 |
|---|---|---|---|---|
| 用户不知道从哪里开始 | 默认进入 Workbench，新建任务按钮明显 | App route 默认 `workbench`，左侧最近会话 | `desktop/src/App.tsx`、`WorkbenchView.tsx` | 打开应用首屏可发起任务 |
| 模型不可用导致发送失败 | 输入框可写，发送按钮显示不可用原因 | 拉取 `/v1/ai/status` 和 `/v1/ai/smoke` | `routes/ai.py`、`ModelsWorkspace.tsx` | 红灯、错误分类、跳转配置 |
| AI 调用了工具但用户看不懂 | 回复拆成正文、工具、证据、下一步 | run events/tool invocation 卡片 | `run_history.py`、`InspectorPanel.tsx` | 工具名、参数摘要、结果摘要可见 |
| 用户需要上传文件 | 输入框支持上传/拖拽，文件进入上下文 | 文件解析作为 artifact/source 或上下文引用 | Workbench + artifacts/sources routes | 文件名、大小、解析状态可见 |
| 用户要求编辑代码 | 先生成 diff 和影响范围，不静默写入 | `agent_file_patch` + confirmation | `capabilities.py`、tool registry | 缺 full/control 时 blocked |
| 用户要求运行终端 | 显示命令、backend、风险，再执行 | `agent_terminal`、`/v1/terminal/*` | full controls routes | stdout/stderr/exit code 可见 |

## 模型与配置

| 问题 | 应该怎么设计 | 技术方案 | 代码落点 | 验收 |
|---|---|---|---|---|
| 用户只想官方直连 | 只填 key 和 model，base_url 可隐藏 | provider preset = official | `model_providers.py`、`routes/ai.py` | 保存后 smoke 绿灯 |
| 用户使用中转商 | 显示 base_url、兼容协议、模型名 | OpenAI-compatible provider | `model_client.py` | base_url 错误显示 network/provider |
| key 错误 | 不泄露 key，只显示认证失败 | 错误分类 auth | `ai_payloads.py` | 页面红灯 auth failed |
| 模型列表拉不出 | 支持手动模型名，状态黄灯 | `/v1/ai/models` 失败 fallback | `ModelsWorkspace.tsx` | 不能阻塞保存 |
| prompt cache 不确定 | 显示是否启用和影响范围 | config 字段 + readiness | `ai_payloads.py` | 状态说明清楚 |

## MCP、Skills、Plugins

| 问题 | 应该怎么设计 | 技术方案 | 代码落点 | 验收 |
|---|---|---|---|---|
| 用户要接内置股票 MCP | 预置服务单独分区 | Agent MCP aggregation | `routes/mcp.py`、AKShare MCP server | 服务、工具、资源、Prompt 可见 |
| MCP 服务启动失败 | 红灯和错误详情 | discover/register 返回结构化错误 | `mcp_client.py` | 不影响其他服务 |
| 动态 MCP 工具风险不明 | 不直接进模型工具列表 | 通过 `agent_*` 审核 facade | `tools/policy.py` | raw manager 不可见 |
| 用户安装 skill | 显示来源、版本、可执行性 | `/v1/skills` 写入门禁 | `routes/plugins_skills.py` | 无 control token 禁用 |
| 插件工具要测试 | 先 test，再启用到工作流 | plugin tool/command test routes | `plugin_runtime.py` | 测试结果和错误可见 |

## 数据与金融

| 问题 | 应该怎么设计 | 技术方案 | 代码落点 | 验收 |
|---|---|---|---|---|
| 数据源不知道通不通 | 每个源红黄绿灯 | stock-data-sources test | `routes/desktop_data.py` | 免费/付费/本地状态清楚 |
| 数据库过期 | 显示 stale_days 和同步建议 | DB freshness + sync plan | `db_freshness.py`、`data_sync.py` | stale 不被当 success |
| 用户点同步 | 先展示影响范围，再创建意图 | `/v1/desktop/data/sync-plan` + intent | Agent desktop data routes | 无 token 不写入 |
| 股票雷达无候选 | 显示空态和数据修复路径 | status/candidates/digest | `stock_radar.py` | 不跳工厂事件 |
| 热力图样本不足 | 显示 degraded 和样本数 | market temperature readiness | `market_temperature/*` | 不画误导热力图 |
| 量化研究缺数据 | data gate blocked | `agent_quant_data_gate` | quant routes | 不生成假报告 |
| Broker 连接可用但有交易风险 | 只读同步，不提供下单 | broker readiness/read-only routes | `desktop_finance.py` | 无下单按钮 |

## 集成与自动化

| 问题 | 应该怎么设计 | 技术方案 | 代码落点 | 验收 |
|---|---|---|---|---|
| 用户想发到飞书/Discord | 先预览目标和内容，再确认 | Gateway send intent | `routes/gateway.py` | 外部投递有 approval |

## 安全与发布

| 问题 | 应该怎么设计 | 技术方案 | 代码落点 | 验收 |
|---|---|---|---|---|
| 页面能点但后端拒绝 | 前端提前显示 gated，后端仍权威 | control token + structured error | `requestJson`、routes | 缺 token 禁用且后端拒绝 |
| secret 泄露 | 只显示 configured/redacted | payload redaction | `ai_payloads.py`、connector payloads | 文档/页面/test 无 key |
| mock 被当 live | 页面标识 mock/live | settings/mode + health | `useAppConnectionSettings` | PM 演示能区分 |
| 四工厂回流 | 主导航和推荐入口负向断言 | route fallback + v1Scope filter | `routes.ts`、`v1Scope.ts` | e2e 不出现四工厂入口 |
