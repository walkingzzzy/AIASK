## 1. 功能设计

### 1.1 需求背景与价值

| 项 | 内容 |
|---|---|
| 问题陈述 | 用户需要一个默认工作面发起任务，而不是先理解工具、MCP、金融、审批等内部模块。 |
| 解决方案 | Workbench 作为 V1 默认入口，统一承载 prompt、模型状态、上下文、运行事件、工具证据、产物、来源和审批。 |
| 业务价值 | 让用户从“输入任务”进入全链路，而 PM/QA 可以从一条任务追踪到后端证据。 |

### 1.2 用户故事

| 编号 | 优先级 | 用户故事 | 成功标准 |
|---|---|---|---|
| WB-US-001 | P0 | 作为用户，我希望打开应用即可输入任务，以便不需要先选择技术页面。 | `/` 默认进入 Workbench，输入区可见。 |
| WB-US-002 | P0 | 作为用户，我希望知道模型是否可用，以便发送前修复配置。 | 模型/Agent/token 异常时发送按钮说明原因。 |
| WB-US-003 | P0 | 作为研究用户，我希望 AI 回复展示工具、产物和来源，以便验证结论。 | 回复和右侧面板显示 run events、tools、artifacts、sources。 |

### 1.4 业务规则与边界

| 规则 | 说明 | 验收 |
|---|---|---|
| 不直接执行高权限 | 文件、终端、浏览器、外部投递、金融风险必须走门禁 | 无 control token 时 disabled/gated |
| 不隐藏工具调用 | 工具结果不能只混在 Markdown | 工具卡可见 |
| 文件上传不假装完成 | 当前未确认完整 upload contract | 文档和 UI 不写“已支持真实上传闭环” |

## 2. 流程设计

| 步骤 | 用户操作 | 前端行为 | Agent/API | 异常 |
|---|---|---|---|---|
| 1 | 打开应用 | 加载 settings、health、summary | `/health`、`/v1/desktop/workbench/summary` | Agent 离线显示 degraded |
| 2 | 输入任务 | 保存 draft，选择模型/上下文 | 无或预检 | 模型缺失禁用发送 |
| 3 | 点击发送 | 调用 `AiaskApi.response()` | `POST /v1/responses` | HTTP 失败显示 `WB-301` |
| 4 | 查看结果 | 展示回复、事件、工具、产物、来源 | run history routes | 工具失败显示 `WB-401` |
| 5 | 继续动作 | 创建或确认 intent | `/intents`、`/v1/approvals` | 缺 control token 显示 gated |

状态机：`idle -> drafting -> preflight_failed|submitting -> running -> tool_waiting|completed|failed -> archived`。

## 3. 架构设计

| 层 | 职责 | 代码证据 |
|---|---|---|
| Workbench UI | 输入、消息流、上下文、右侧证据 | `WorkbenchView.tsx`、`InspectorPanel.tsx` |
| Hook | summary、response、runs、events 状态 | `useAgentWorkbench.ts` |
| API | Responses、sessions、runs、artifacts、sources、intents | `aiaskApi.ts` |
| Agent | response 生成、run history、session store | `routes/responses.py`、`routes/run_history.py` |

核心决策：Workbench 是任务入口，不直接调用 MCP/manager/数据库；所有能力通过 Agent HTTP 和 `agent_*` 工具证据显式呈现。

## 4. 功能说明：接口与数据

| 操作 | Endpoint | Method | Token | 前端方法 | 关键字段 |
|---|---|---|---|---|---|
| 发送任务 | `/v1/responses` | POST | API | `response()` | `response_id`、`run_id`、`session_id` |
| 获取回复 | `/v1/responses/{id}` | GET | API | `responseGet()` | `output`、`status` |
| 运行事件 | `/v1/runs/{id}/events` | GET | API | `runEvents()` | `event_type`、`payload` |
| 产物/来源 | `/v1/runs/{id}/artifacts|sources` | GET | API/control | `runArtifacts()`、`runSources()` | `artifact_id`、`source_id` |
| 归档/控制 | `/v1/runs/{id}/stop|cancel|steer`、`/v1/sessions/{id}/archive` | POST | control | run/session methods | `status`、`error_code` |

组件树：`WorkbenchView -> ConversationComposer -> MessageTimeline -> ToolCallCard -> RunStatusStrip -> WorkbenchContextPanel`。状态必须覆盖 loading、empty、error、degraded、gated、blocked、mock、success。

新增工作台能力必须先检查 `AiaskApi` 是否已有方法；缺 Agent route 时先补 `packages/agent/src/aiask_agent/routes/*`，再补 mock、组件和测试。

## 7. 错误说明

| 错误码 | 用户提示 | 技术原因 | 处理 |
|---|---|---|---|
| WB-201 | 模型或 token 未就绪 | preflight failed | 引导 Models/Settings |
| WB-301 | Agent 不可用 | network/health failed | 保留输入并可重试 |
| WB-401 | 动作需要审批或被阻断 | gated/blocked | 展示 intent 或 blocked reason |

### 10.2 需要写给产品和开发的真实功能细节

| 功能 | 具体说明 | 必须验收 |
|---|---|---|
| 任务输入 | 输入区要显示当前后端模式、API token、control token、full mode 能力；模型不可用时不能静默发送 | 缺模型/缺 token 时保留草稿并给修复入口 |
| 工具证据 | 从 run events/tool invocations/artifacts/sources 形成卡片，展示工具名、参数摘要、输出摘要、错误码、耗时和 side_effect | 工具失败不吞掉，错误可复制/可定位 |
| 受控动作 | 文件写入、终端、浏览器、外部投递、金融动作只能作为 ActionIntent/approval 或 full/control gated 操作 | 无 control token 不发写入请求 |

### 10.3 成熟技术采用

OpenAI Tools 和 Conversation State 官方文档用于确定工作台形态：工具调用、会话状态和上下文窗口必须可见、可追踪、可恢复。AIASK 采用方式是 `POST /v1/responses` 创建 response/run/session，通过 `run_history.py` 暴露事件、产物、来源，通过 `TaskPanels` 和 `InspectorPanel` 展示证据。不采用“把工具调用压扁成一段自然语言”的做法。

## 功能目标

AI 对话是第一版默认入口。用户应能新建任务、输入问题、上传文件或引用文件、选择模型、查看 AI 回复、查看工具调用、继续历史会话、归档会话，并把金融数据、MCP、Skills、记忆和自动化任务接入同一条任务线。

## 代码证据

| 能力 | 代码位置 |
|---|---|
| Workbench 页面 | `desktop/src/components/WorkbenchView.tsx` |
| 对话 hook | `desktop/src/hooks/useAgentWorkbench.ts` |
| Responses API | `packages/agent/src/aiask_agent/routes/responses.py`，`/v1/responses`、`/v1/chat/completions` |
| 会话/运行摘要 | `packages/agent/src/aiask_agent/routes/desktop_workbench.py`，`/v1/desktop/workbench/summary` |
| runs/events/artifacts/sources | `packages/agent/src/aiask_agent/routes/run_history.py` |
| run 控制 | `packages/agent/src/aiask_agent/routes/run_control.py` |
| API client | `desktop/src/services/aiaskApi.ts` 的 `response`、`runsList`、`runEvents`、`sessionMessages`、`sessionArchive` |

## 用户流程

1. 用户点击“新建任务/新会话”，前端创建本地草稿状态。
2. 用户输入文本，可上传文件，也可附加已有文件、股票、数据源、MCP 资源或历史会话上下文。
3. 用户在对话窗口选择 provider/model；若模型不可用，显示红灯并引导到模型配置。
4. 点击发送后调用 `/v1/responses`，创建 run/session 记录。
5. AI 回复应以“正文 + 工具调用 + 证据 + 后续动作”呈现。
6. 工具调用失败时展示工具名、错误码、参数摘要和重试/修复入口。
7. 会话可进入历史，可归档，可恢复上下文，可 undo 最近 turn。

## 前端展现

页面建议分三栏：

| 区域 | 展示内容 |
|---|---|
| 左侧 | 最近会话、归档入口、搜索、任务类型筛选 |
| 中间 | 对话流、输入框、模型选择、附件/数据/MCP/Skills 入口 |
| 右侧 | 运行状态、工具调用、Artifacts、Sources、金融上下文、审批项 |

AI 回复不应只是 Markdown。必须结构化显示：

- 使用了哪个模型。
- 调用了哪些工具。
- 哪些工具只读，哪些有副作用。
- 生成了哪些文件/代码/报告。
- 需要用户审批的下一步是什么。

上传文件的前端规范：

- 输入框旁显示文件按钮，支持拖拽上传和点击选择。
- 上传后显示文件名、大小、类型、解析状态、是否进入本次上下文。
- 文件解析失败时显示原因，不阻塞纯文本对话。
- 文件写入、编辑代码、运行终端、运行代码等高权限后续动作必须在工具调用区和右侧栏显示门禁状态。

| 操作 | Endpoint | Token |
|---|---|---|
| 发送对话 | `POST /v1/responses` | API token |
| 获取回复 | `GET /v1/responses/{id}` | API token |
| 删除回复 | `DELETE /v1/responses/{id}` | control token |

| 会话归档 | `POST /v1/sessions/{id}/archive` | control token |
| run events | `GET /v1/runs/{id}/events` | API token |
| stop/cancel/steer | `/v1/runs/{id}/stop|cancel|steer` | control token |

## 验收规则

1. 缺模型配置时，对话输入可写但发送按钮显示不可用原因。
2. 成功发送后必须产生 run/session/event 可追踪证据。
3. 工具调用必须进入右侧证据区，不只混在自然语言里。
4. 归档后默认历史列表不展示，开启 include archived 才展示。
5. 文件/终端/浏览器/外部平台动作必须有门禁，不能从普通对话静默执行。

## 详细落地规范

### 问题场景与技术方案

| 问题 | 用户看到什么 | 技术方案 | 代码落点 | 验收 |
|---|---|---|---|---|
| 用户不知道如何开始 | 首屏只有一个明确的新建任务和输入区 | Workbench 作为默认 route，最近会话放左侧 | `desktop/src/App.tsx`、`desktop/src/components/WorkbenchView.tsx` | 打开应用不需要跳转即可输入 |
| 模型不可用 | 发送按钮显示原因，模型区红灯 | 读取 `/v1/ai/status`，失败时引导到 Models | `useAgentWorkbench.ts`、`ModelsWorkspace.tsx` | 缺 key 时不能发出 `/v1/responses` |
| 上传文件失败 | 文件卡片显示解析失败但文本仍可发送 | 上传文件先进入本地附件队列，再作为 source/artifact 或上下文引用 | Workbench 输入区、`runArtifacts`、`runSources` | 文件失败不影响纯文本对话 |
| AI 调用了工具但用户看不懂 | 回复下方出现工具卡，右侧出现详细证据 | 从 run events/tool invocations 生成结构化卡片 | `routes/run_history.py`、`InspectorPanel.tsx` | 工具名、参数摘要、结果摘要可见 |
| 用户要求修改文件/代码 | AI 给出计划和 diff，按钮显示需要确认 | 使用 `agent_file_patch`/`agent_file_write`，写入前走 full/control 门禁 | `capabilities.py`、tool registry、右侧 ActionPanel | 无 control token 时 blocked |
| 用户要求运行终端/代码 | 显示命令、解释器、风险提示 | `agent_terminal`/`agent_execute_python` 只在 full mode 下执行 | `routes/full_controls.py`、工具目录 | stdout/stderr/exit code 可见 |
| 会话太多找不到历史 | 左侧支持搜索、归档筛选、恢复上下文 | `/v1/hermes/sessions`、`/v1/search`、resume context | `routes/hermes.py`、`routes/responses.py` | 归档会话默认隐藏，可按开关显示 |

### 完整流程

1. 进入 Workbench：前端加载 settings、health、recent sessions、recent runs。
2. 新建任务：清空当前 draft，生成本地临时 task id，保留已选模型和 profile。
3. 输入内容：支持文本、上传文件、引用历史会话、引用股票/数据源/MCP 资源。
4. 发送前检查：模型状态、API token、是否 full mode、是否有未解析附件。
5. 发送请求：调用 `AiaskApi.response()` -> `POST /v1/responses`。
6. 运行中：显示 loading、run id、事件流、可 stop/cancel/steer。
7. 回复完成：展示正文、工具调用、产物、来源、下一步建议。
8. 需要审批：右侧显示 ActionIntent/approval，不在回复里只放文字。
9. 用户后续操作：继续追问、归档、恢复上下文、打开产物、进入金融/数据/模型修复页面。

### 状态机

| 状态 | 触发 | UI |
|---|---|---|
| `idle` | 首次进入或新建任务 | 空输入框、最近会话 |
| `drafting` | 用户输入或上传文件 | 草稿保存、附件队列 |
| `preflight_failed` | 模型/token/附件检查失败 | 禁用发送，显示修复入口 |
| `submitting` | 点击发送 | 输入区锁定，显示请求中 |
| `running` | 后端创建 run | 事件流、stop/cancel/steer |
| `tool_waiting` | 工具需要确认或 full mode | 右侧审批卡 |
| `completed` | response 完成 | 正文、证据、产物 |
| `failed` | HTTP 或工具失败 | 错误码、重试、修复入口 |
| `archived` | 用户归档 | 从默认历史隐藏 |

| `AttachmentQueue` | 上传文件、解析状态、上下文开关 |
| `MessageTimeline` | 用户消息、AI 回复、工具摘要 |
| `ToolCallCard` | tool name、参数摘要、结果摘要、错误 |
| `RunStatusStrip` | run/session/status、stop/cancel/steer |
| `WorkbenchContextPanel` | 右侧证据、金融、审批、记忆 |

如果当前代码没有这些组件名，可以先在 `WorkbenchView.tsx` 内部拆出局部组件，再按复杂度迁移到 `desktop/src/components/workbench/*`。

### 代码生成/修改步骤

1. 先检查 `desktop/src/services/aiaskApi.ts` 是否已有方法；已有则禁止绕过。
2. 如果缺上传文件 API，不允许 Desktop 直接写本地文件，应先设计 Agent HTTP route 或 artifact/source 合约。
3. 在 `desktop/src/mockApi.ts` 和 `desktop/src/mock/*` 增加 response、run events、artifacts、sources mock。
4. 在 `WorkbenchView.test.tsx` 补：模型不可用、上传失败、工具调用展示、归档、stop/cancel。
5. 在 e2e 中补：首屏发起任务、右侧工具证据、四工厂不回流。

### 不做什么

- 不在 Workbench 里直接调用 MCP、Python、AKShare manager 或数据库。
- 不把工具执行隐藏在纯 Markdown 中。
- 不在普通用户模式暴露文件写入、终端、浏览器控制的一键执行。
- 不把 Strategy Factory、Factor Factory、Incubation Factory、Factory Events 作为 AI 推荐入口。
