## 1. 功能设计

### 1.1 需求背景与价值

| 项 | 内容 |
|---|---|
| 问题陈述 | 自动化盯盘会产生调度和外部动作风险，用户需要知道任务是否启用、运行历史和审批状态。 |
| 解决方案 | Automation 页面展示 jobs、runs、启停、运行、删除和 workflow map；调度/写入动作受 control token 或 intent 约束。 |
| 业务价值 | 自动化可追踪，避免静默执行高风险任务。 |

### 1.2 用户故事

| 编号 | 优先级 | 用户故事 | 成功标准 |
|---|---|---|---|
| AUTO-US-001 | P1 | 作为用户，我希望查看自动化任务和运行历史。 | jobs 和 runs 可见。 |
| AUTO-US-002 | P1 | 作为用户，我希望手动运行任务前知道风险。 | run/toggle/delete 需要 control token。 |
| AUTO-US-003 | P1 | 作为 PM，我希望 Workflows 表达 V1 流程而不是四工厂。 | 工作流无四工厂入口。 |

### 1.3 功能分解与优先级

| 功能编号 | 功能点 | 优先级 | 当前代码依据 | 待开发事项 | 验收标准 |
|---|---|---|---|---|---|
| AUTO-F001 | Jobs 列表 | P1 | `GET /v1/jobs` | 空态补强 | job 状态可见 |
| AUTO-F002 | Job runs | P1 | `/v1/jobs/{id}/runs` | 详情展示 | 运行历史可追踪 |
| AUTO-F003 | 创建/更新/删除/运行 | P1 | jobs POST/PATCH/DELETE/RUN | intent/control 明确 | 无 token gated |
| AUTO-F004 | Workflows V1 地图 | P1 | `WorkflowsWorkspace.tsx` | 四工厂清理 | 只展示 V1 流程 |

### 1.4 业务规则与边界

| 规则 | 说明 | 验收 |
|---|---|---|
| 调度修改受控 | create/update/delete/run 需要 control token 或 intent | 按钮 gated |
| 外部投递转 Gateway | 自动化投递不直接发送 | preview/intent |
| 不包含四工厂工作流 | strategy/factor/incubation/factory-events 不作为 V1 流程 | 文案扫描 |

## 2. 流程设计

| 步骤 | 用户操作 | 前端行为 | Agent/API | 异常 |
|---|---|---|---|---|
| 1 | 打开自动化 | 加载 jobs | `/v1/jobs` | empty |
| 2 | 查看运行 | 加载 job runs | `/v1/jobs/{id}/runs` | run missing |
| 3 | 运行/暂停/删除 | 调用受控 route | jobs mutation routes | 无 token gated |
| 4 | 外部投递 | 跳 Gateway | `/intents` | 不直接发送 |

状态机：`loading -> ready|empty|error -> mutating|running -> success|failed|gated`。

## 3. 架构设计

Desktop 自动化页只通过 Agent jobs routes 管理任务；外部投递通过 Gateway/ActionIntent，不在 Automation 中直接投递。

## 4. 功能说明：接口与数据

| 操作 | Endpoint | Method | Token | 前端方法 |
|---|---|---|---|---|

## 7. 错误说明

### 10.2 功能细节

| 功能 | 字段/动作 | UI 要求 | 验收 |
|---|---|---|---|
| Job 创建 | `name`、`prompt`、`schedule`、`interval_seconds`、`toolset`、`enabled` | 表单校验 + control token 状态 | 无 token 不 POST |
| Job 列表 | id、status、schedule、last_run、next_run | 可刷新、可选中 | 失败 job 不影响列表 |
| 运行历史 | `/v1/jobs/{id}/runs` | 展示 run status/error/output summary | run 失败可见 error_code |
| 手动运行 | `/v1/jobs/{id}/run` | 受控按钮 | 不绕过 ActionIntent/approval 规则 |

### 10.3 成熟技术采用

Playwright 用于覆盖自动化页面的真实按钮流程；OWASP 和 Tauri Security 要求本地高权限、外部投递和定时任务都可审计。AIASK 采用 Agent Jobs route + token gate + run history，不采用前端 setInterval 或本地直接启动脚本。

## 功能目标

自动化不是简单定时器。第一版要支持创建任务、运行任务、暂停/恢复、查看运行历史、处理失败，并把自动化盯盘、消息投递、数据同步、股票雷达等任务统一到 Jobs/Workflows。

## 用户流程

1. 打开自动化，看到任务列表、状态、下次运行、最近结果。
2. 创建任务时选择模板：盯盘、数据同步、雷达摘要、消息推送、研究报告。
3. 设置 schedule、enabled、参数、通知目标。
4. 保存任务需要 control token。
5. 手动运行任务时显示确认，运行后进入 job runs。
6. 失败任务展示错误、重试、禁用建议。

| 历史 | `GET /v1/jobs/{job_id}/runs` |

## 验收规则

1. 没有 control token 时创建/修改/删除不可点击。
2. 自动化盯盘必须能关联股票雷达或市场温度，不链接四工厂。
3. 外部消息投递任务必须进入 Gateway/Webhook 门禁。
4. job run 结果必须可追踪到 run/event。
5. 删除任务必须确认，且保留审计记录。

## 详细落地规范

### 问题场景与技术方案

| 问题 | 前端表现 | 技术方案 | 代码落点 | 验收 |
|---|---|---|---|---|
| 用户想自动盯盘 | 模板选择“市场温度/股票雷达/数据同步/消息推送” | Job template + schedule | `routes/jobs.py`、`AutomationWorkspace.tsx` | 模板参数清晰 |
| 用户误删任务 | 删除按钮二次确认 | DELETE `/v1/jobs/{id}` 需要 control token | `routes/jobs.py` | 无 token 不显示删除 |
| 定时任务运行失败 | Job row 红灯，历史里显示错误 | `/v1/jobs/{id}/runs` | `_runtime_jobs.py` | 错误和输出可见 |
| 盯盘要推送外部平台 | 创建 Gateway send intent，不直接发送 | `gatewaySendIntent` | `routes/gateway.py` | 外部投递需审批 |
| 任务参数不合法 | 表单即时校验，后端返回 structured error | schema validation | `adapters/desktop_ops.py` | 不创建坏任务 |
| 用户要临时运行 | Run now 按钮显示风险和输出 | `POST /v1/jobs/{id}/run` | `routes/jobs.py` | run_id/status 可追踪 |

### 自动化模板

| 模板 | 输入 | 输出 | 门禁 |
|---|---|---|---|
| 市场温度盯盘 | as_of、top_n、threshold | 热/冷行业摘要 | 只读，可推送时需 intent |
| 股票雷达更新 | tier、limit、channels | 候选摘要 | run/push/schedule 需 intent |
| 数据同步 | codes、range、source | 同步结果 | control token + confirm |
| 每日报告 | watchlist、sections | artifact/report | 只读生成，外发需 intent |
| Webhook 触发 | webhook_id、payload | delivery status | ActionIntent/approval |

### 代码生成/修改步骤

1. 新增模板先定义 job schema，不在 UI 硬编码 payload。
2. Agent `routes/jobs.py` 保持 CRUD/run/history 合约。
3. `AutomationWorkspace.tsx` 拆分 TemplatePicker、ScheduleEditor、RunHistory、OutputPanel。
4. mock 覆盖 created、updated、paused、completed、failed、deleted。
5. e2e 验证 run/delete/token gate 和四工厂不出现。

### 不做什么

- 不把策略工厂任务作为 V1 推荐模板。
- 不让外部推送绕过 Gateway/approval。
- 不隐藏失败历史。
- 不让删除无确认。

### 状态机补充

任务状态：`draft -> enabled -> scheduled -> running -> completed/failed -> paused -> deleted`

运行历史状态：`queued -> started -> output_streaming -> success/error/cancelled`。删除必须经过 `awaiting_delete_confirm`。
