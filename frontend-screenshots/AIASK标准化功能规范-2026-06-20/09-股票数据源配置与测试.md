## 1. 功能设计

### 1.1 需求背景与价值

| 项 | 内容 |
|---|---|
| 问题陈述 | 金融功能依赖数据源，不同来源有免费/付费、token、限流、字段缺失和稳定性差异。 |
| 解决方案 | 设置页展示 presets、sources、配置状态、必填字段、env 名和测试结果。 |
| 业务价值 | 用户能判断数据是否可用，QA 能验证 secret redaction 和降级。 |

### 1.2 用户故事

| 编号 | 优先级 | 用户故事 | 成功标准 |
|---|---|---|---|
| DATA-US-001 | P0 | 作为金融用户，我希望看到数据源是否配置，以便知道分析能否运行。 | configured/ready/missing 可见。 |
| DATA-US-002 | P0 | 作为配置用户，我希望测试数据源，以便确认 token 和网络可用。 | test result 有 latency/sample/error。 |
| DATA-US-003 | P0 | 作为安全负责人，我希望 token 不回显。 | 只展示 env name 和 configured。 |

| 规则 | 说明 | 验收 |

| 付费源单独测试 | Tushare 等 token/积分状态可见 | 缺 token 显示 missing |

## 2. 流程设计

| 步骤 | 用户操作 | 前端行为 | Agent/API | 异常 |
|---|---|---|---|---|
| 1 | 打开配置 | 加载 presets/sources | `/v1/desktop/stock-data-sources` | 无配置 empty |
| 2 | 编辑来源 | 填 provider/token/base_url | 本地表单 | 必填字段校验 |
| 3 | 保存 | POST 配置 | stock-data-sources route | 无 token gated |
| 4 | 测试 | POST test | test route | timeout/auth/field error |

状态机：`loading -> ready|empty|error -> editing -> saving|testing -> success|failed|gated`。

## 3. 架构设计

Desktop 只负责配置 UI；Agent desktop_data routes 负责持久化和测试；AKShare/Tushare/TDX/TQCenter 由后端封装，不直接暴露给前端。

- 不让前端直连数据源。

## 10. 代码实证与成熟实现补强

### 10.1 当前代码审计

| 对象 | 代码证据 | 当前行为 | 文档结论 |
|---|---|---|---|
| 数据源面板 | `desktop/src/features/settings/StockDataSourcesPanel.tsx` | 支持 preset、form payload、secret status、save、test、search/market data source | 数据源配置不是简单 key/value，要有 preset、redaction、test |
| Settings 入口 | `SettingsWorkspace.tsx` 的 `stockDataSources` section | 入口在设置中，和模型/API key/数据路径分开 | PM 文档要说明用户从哪里配置 |
| Agent routes | `routes/desktop_data.py` | `/v1/desktop/stock-data-sources` GET/POST 和 `/test` | 保存和测试都走 Agent HTTP |
| 测试 | `StockDataSourcesPanel.test.tsx`、`SettingsWorkspace.test.tsx` | 覆盖保存、测试、search source、market source、redacted stored secrets | QA 必须验证不展示 secret |

### 10.2 数据源细节

| 数据源类型 | 用户需要看到 | 技术处理 | 验收 |
|---|---|---|---|
| AKShare/free source | 可用性、失败原因、字段缺失、限流风险 | Agent/AKShare MCP 返回 degraded/missing/stale | 免费源不可用时不写 ready |
| Tushare/付费源 | token 是否配置、积分/权限提示、测试结果 | 只展示 env 名和 configured/missing | token 原值不出现在 DOM/raw JSON |
| TDX/TQCenter/本地源 | 主机/路径/端口/账号状态 | redacted config + test endpoint | 本地连接失败显示 error_code |
| 搜索源 | Brave/Tavily/SerpAPI/Exa 等配置状态 | preset 区分 search API provider | 不把搜索 API 当行情源 |

### 10.3 成熟技术采用

AKShare 和 Tushare 官方文档用于定义数据来源、权限、字段和可用性风险；OWASP 用于 secret redaction。AIASK 采用“配置状态 + 连通测试 + 数据质量闸门”的模式，不采用前端保存 token 或把免费源失败伪装成生产可用。

### 11.3 状态和响应式

- `gated`：保存配置、删除配置、连接测试在缺 control token 时禁用或展示门禁。
- `stale/degraded`：数据源可连但数据质量不足时显示黄灯，并跳转 Data Sync 而不是写成 ready。
- 窄屏下 preset 改为横向 pills，表单单列，测试结果折叠在表单下方。

## 原有内容保留

## 功能目标

股票数据源配置要让用户明确知道：哪些数据来自免费源、哪些来自付费源、哪些来自本地数据库，当前是否连通，字段是否完整，能否支撑雷达/热力图/量化研究。

## 外部参考

AKShare 提供大量免费金融数据接口，但可用性、字段和频率会受源站影响。Tushare 是配置 token 的付费/积分型数据源。前端必须把免费/付费、本地/在线、成功/失败讲清楚。

## 用户流程

1. 打开股票数据源页面，读取所有数据源状态。
2. 用户看到免费源 AKShare、付费源 Tushare、本地源 TDX/TQCenter/SQLite。
3. 每个数据源都有“测试连接”按钮，测试后更新红黄绿状态。
4. 保存配置需要 control token；secret 只显示已配置/未配置。
5. 数据源失败时给出错误分类：缺 token、网络失败、字段缺失、源不可用、限流。

## 前端展现

| 数据源 | 类型 | 状态 |
|---|---|---|
| AKShare | 免费在线 | 可用/降级/源站失败 |
| Tushare | 付费/积分 | token 缺失/可用/权限不足 |
| TDX local vipdoc | 本地 | 路径存在/缺数据/过期 |
| TQCenter/TDX proxy | 本地/在线代理 | 连接成功/失败 |
| SQLite cache | 本地数据库 | 新鲜/过期/空 |

## API 合约

| 操作 | Endpoint |
|---|---|
| 读取数据源 | `GET /v1/desktop/stock-data-sources` |
| 保存数据源 | `POST /v1/desktop/stock-data-sources` |
| 测试数据源 | `POST /v1/desktop/stock-data-sources/test` |
| 桌面数据状态 | `GET /v1/desktop/data/status` |

## 验收规则

1. 每个数据源必须有明确红黄绿灯。
2. 免费/付费标签必须可见。
3. 保存后响应必须 `secrets_redacted` 或同等字段。
4. 测试失败不能影响其他源的状态。
5. 雷达、市场温度、量化页面要引用数据源状态，避免假装数据可用。

## 详细落地规范

### 问题场景与技术方案

| 问题 | 前端表现 | 技术方案 | 代码落点 | 验收 |
|---|---|---|---|---|
| 用户不知道用免费还是付费源 | 数据源卡标注 free/paid/local | provider metadata | `stock_data_sources.py` | 免费/付费标签可见 |
| Tushare token 错误 | 红灯，显示权限/认证失败 | test endpoint 分类 auth/permission | `routes/desktop_data.py` | 不展示 token |
| AKShare 源站不可用 | 黄/红灯，提示 fallback 或稍后重试 | 结构化 optional-source unavailable | AKShare tools/data_source | 不把失败写成空数据 |
| TDX 本地路径不存在 | 红灯，显示路径未配置/不可读 | 本地路径只显示环境变量名 | `data_source/tdx_local.py` | 不泄露敏感路径细节 |
| 数据源测试慢 | 按源独立 loading，不阻塞全页 | 每个 source 独立请求/状态 | Settings 数据源 panel | 一个源失败不影响其他源 |
| 金融页面误用不可用数据 | 页面引用数据源 readiness | Finance pages 读取 data status | `DataSyncWorkspace.tsx`、Finance Lab | 数据不可用时显示修复入口 |

### 字段设计

| 字段 | 类型 | 说明 |
|---|---|---|
| `source_id` | string | akshare/tushare/tdx_local/tqcenter/sqlite |
| `kind` | enum | free/paid/local/cache |
| `configured` | boolean | 是否配置 |
| `reachable` | boolean | 是否连通 |
| `status` | enum | green/yellow/red/gray |
| `last_test_at` | datetime | 最近测试 |
| `error_code` | string | auth/network/permission/source_unavailable |
| `secrets_redacted` | boolean | 必须为 true 或不返回 secret |

### 代码生成/修改步骤

1. 新增数据源先在 Agent `stock_data_sources.py` 定义 metadata、secret 字段和 test 行为。
2. `routes/desktop_data.py` 提供 GET/POST/test，不让前端直接测第三方。
3. 前端 Settings 增加卡片、测试按钮、状态灯、错误分类。
4. mock 覆盖：AKShare 绿、Tushare 缺 token、TDX 路径缺失、SQLite stale。
5. Data/Finance/Quant/Radar 页面读取数据源状态，不能各自重复造判断。

### 不做什么

- 不要求免费源稳定等同生产级。
- 不展示 token/path 原文。
- 不在数据源红灯时仍让雷达/量化显示成功。
- 不把测试通过等同于数据完整。

### 状态机补充

`unconfigured -> configured -> testing -> connected/test_failed -> stale/degraded`

保存配置为 `editing -> saving -> saved/save_failed`。测试失败只影响当前数据源，不改变其他数据源状态。
