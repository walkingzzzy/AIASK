## 1. 功能设计

### 1.1 需求背景与价值

| 项 | 内容 |
|---|---|
| 问题陈述 | AI 金融结论如果没有右侧证据和上下文，用户难以判断来源、数据新鲜度和后续动作风险。 |
| 解决方案 | 右侧扩展栏统一展示模型、toolset、MCP、skills、files/artifacts、sources、finance context、approvals。 |
| 业务价值 | 让金融任务从对话延伸到可验证证据链。 |

### 1.2 用户故事

| 编号 | 优先级 | 用户故事 | 成功标准 |
|---|---|---|---|
| CTX-US-001 | P0 | 作为用户，我希望右侧看到当前任务的数据和证据。 | artifacts/sources/tools 可见。 |
| CTX-US-002 | P0 | 作为金融用户，我希望看到数据新鲜度和股票上下文。 | stale/missing/source 可见。 |
| CTX-US-003 | P0 | 作为用户，我希望需要审批的动作在右侧出现。 | intent/approval 卡片可见。 |

### 1.3 功能分解与优先级

| 功能编号 | 功能点 | 优先级 | 当前代码依据 | 待开发事项 | 验收标准 |
|---|---|---|---|---|---|
| CTX-F001 | 工具证据 | P0 | `TaskPanels.tsx` | 工具摘要统一 | tool name/input/output/error 可见 |
| CTX-F002 | 产物来源 | P0 | artifact/source methods | 打开失败提示 | artifact/source 可打开 |
| CTX-F003 | 金融上下文 | P0 | finance workspace APIs | 字段标准化 | symbol/data/freshness 可见 |
| CTX-F004 | 审批入口 | P0 | `/intents`、approvals | 右侧联动 | 受控动作可追踪 |

### 1.4 业务规则与边界

| 规则 | 说明 | 验收 |
|---|---|---|
| 证据不可隐藏 | 工具、数据、来源必须结构化 | 不只放自然语言 |
| 金融风险可见 | 实盘/外部/调度动作显示门禁 | intent/blocked 可见 |
| 不展示四工厂入口 | 工厂字段只能折叠为 deferred/internal | 无跳转 |

## 2. 流程设计

| 步骤 | 用户操作 | 前端行为 | Agent/API | 异常 |
|---|---|---|---|---|
| 1 | 发送任务 | 右侧绑定 run/session | run history | 无 run 显示 empty |
| 2 | 工具调用完成 | 生成工具卡 | tool invocation route | 工具失败显示 error |
| 3 | 查看产物/来源 | 打开 detail | artifact/source routes | 外部 URL 分开处理 |
| 4 | 后续动作 | 显示 intent/approval | `/intents` | 无 token gated |

状态机：`empty -> bound_to_run -> loading_evidence -> ready|error|degraded -> approval_pending|blocked`。

## 3. 架构设计

右侧栏是 Workbench 的证据聚合层，只消费 Agent HTTP 和 run/session/tool/artifact/source/intent 数据，不直接触发高风险后端动作。

## 4. 功能说明：接口与数据

| 数据 | 来源 | Token | UI |
|---|---|---|---|
| Run events | `/v1/runs/{id}/events` | API | 时间线/工具卡 |
| Artifacts | `/v1/runs/{id}/artifacts` | API/control | 产物列表 |
| Sources | `/v1/runs/{id}/sources` | API/control | 来源列表 |
| Tool invocation | `/v1/tool-invocations/{id}` | API/control | 参数/结果 |
| Intents/Approvals | `/intents`、`/v1/approvals` | control | 审批卡 |

## 5. 前端设计

组件：`InspectorPanel -> EvidenceTabs -> ToolEvidenceCard -> ArtifactSourceList -> FinanceContextCard -> ApprovalPanel -> RawPayloadDetails`。

## 6. 开发规范

新增证据类型必须定义字段、来源、打开方式、错误态和 redaction 规则。

## 7. 错误说明

| 错误码 | 用户提示 | 技术原因 | 处理 |
|---|---|---|---|
| CTX-101 | 当前任务暂无证据 | no run/session | 显示空态 |
| CTX-301 | 证据加载失败 | artifact/source route error | 可重试 |
| CTX-401 | 动作需要审批 | intent/control required | 显示审批入口 |

## 10. 代码实证与成熟实现补强

### 10.1 当前代码审计

| 对象 | 代码证据 | 当前行为 | 文档结论 |
|---|---|---|---|
| 全局右侧上下文 | `desktop/src/components/AppContextPanel.tsx` | 显示连接、toolset、control/full mode、selected task context | 右侧栏要让用户知道当前任务能做什么/不能做什么 |
| Inspector | `desktop/src/components/InspectorPanel.tsx` | 按 run/artifacts/sources/tools/intents/approvals 展示详情和 run control | 右侧扩展栏是证据和审批，不是营销说明 |
| Task panels | `TaskPanels.tsx` | artifact/source 打开 Agent evidence，外部 URL 不拦截 | 来源要分 Agent evidence 和外部链接 |
| Timeline | `Timeline.tsx` | artifact.created/source.linked/market.quote_snapshot/terminal.output_artifact 等事件转可读文案 | 金融上下文来自 run events，不手写假状态 |

### 10.2 右侧栏必须展示的上下文

| 场景 | 展示内容 | 不展示 |
|---|---|---|
| 金融提问 | 股票代码、数据源状态、市场温度、风险提示、工具调用 | 不显示四工厂入口 |
| 工具调用 | tool name、参数摘要、结果摘要、error_code、side_effect | 不隐藏到 Markdown |
| 外部投递 | Gateway 平台、目标、intent/approval 状态 | 不提供一键直发 |
| 文件/终端/浏览器 | full mode、control token、命令/路径/输出 | 不在无 token 时执行 |

### 10.3 成熟技术采用

OpenAI Tools 要求工具调用证据可解释；Testing Library 要求按用户可见行为断言。AIASK 采用右侧证据栏承载工具、产物、来源和审批，不采用只在 AI 正文里描述“我已经调用工具”的黑盒方式。

### 11.3 状态和响应式

- `gated`：无 control token 时只显示只读建议；意图/审批按钮禁用。
- `degraded`：金融数据不可用时保留任务上下文，显示数据修复入口。
- 窄屏右侧栏变底部 sheet 或详情折叠，不固定占宽。

## 原有内容保留

## 功能目标

AI 对话右侧扩展栏是金融联动的核心。用户在和 AI 交流时，右侧应显示当前任务的金融上下文、数据状态、工具调用、候选股票、市场温度、审批项和产物，而不是只显示空白诊断信息。

## 代码证据

| 能力 | 代码位置 |
|---|---|
| App shell | `desktop/src/App.tsx` |
| Inspector | `desktop/src/components/InspectorPanel.tsx`、`InspectorPanels.tsx` |
| Context panel | `desktop/src/components/AppContextPanel.tsx` |
| Task panels | `desktop/src/components/TaskPanels.tsx` |
| Workbench | `desktop/src/components/WorkbenchView.tsx` |
| API client | `AiaskApi` 的 runs/events/artifacts/sources/finance/data/stock radar 方法 |

## 应该显示什么

| 场景 | 右侧显示 |
|---|---|
| 普通 AI 对话 | 模型状态、run 状态、工具调用、消息来源 |
| 文件/代码任务 | 文件产物、patch 摘要、执行结果、错误 |
| 金融提问 | 数据源状态、股票代码、市场温度、风险提示 |
| 股票雷达 | 候选、摘要、source chain、run intent |
| 量化研究 | preset、data gate、research id、报告状态 |
| 外部投递 | Gateway 平台、目标、approval/intent |
| 记忆相关 | 命中的记忆、用户画像引用、是否保存 |

## 不该显示什么

1. 不显示 Strategy Factory、Factor Factory、Incubation Factory、Factory Events 产品入口。
2. API key、token、完整环境变量值。
3. 未经审核的 raw MCP 动态工具作为一键执行按钮。
4. 实盘下单/撤单暗示。
5. 大段 raw JSON 直接铺满侧栏。

## 产品流程

1. Workbench 提交任务后，右侧自动进入当前 run 状态。
2. 当 AI 调用工具，右侧追加工具调用卡片。
3. 当任务产生产物，右侧出现 artifacts/sources。
4. 当任务需要审批，右侧突出 approval/intent。
5. 当任务关联金融数据，右侧显示 data gate、source、freshness、风险提示。

## 前端设计

右侧栏使用 Tabs：运行、工具、证据、金融、审批、记忆。每个 tab 只展示摘要，详情用抽屉/弹窗。移动端应折叠为底部面板或可切换页面。

## 验收规则

1. 发送一次对话后，右侧必须出现 run 或 response 状态。
2. 有工具调用时，能看到 tool name 和结果摘要。
3. 金融任务能看到数据源/freshness/非投资建议。
4. 审批项能在右侧确认/拒绝，但后端仍是权威。
5. 四工厂入口不得从右侧回流。

## 详细落地规范

### 问题场景与技术方案

| 问题 | 右侧表现 | 技术方案 | 代码落点 | 验收 |
|---|---|---|---|---|
| AI 回答金融问题但没有证据 | 金融 tab 显示数据源、工具、时间 | 从 run sources/artifacts 和 finance APIs 汇总 | `TaskPanels.tsx`、`InspectorPanels.tsx` | 可追溯 source |
| 工具调用太多 | 工具 tab 折叠分组 | 按 run event/tool name 聚合 | `runEvents` | 不出现 raw JSON 墙 |
| 需要审批 | 审批 tab 高亮 intent/approval | `/intents`、`/v1/approvals` | `ToolsIntentsApprovalsPage.tsx` | confirm/deny 可用且 gated |
| 关联股票上下文 | 显示 code、name、市场温度、雷达摘要 | stock radar + market temperature read-only | `AiaskApi` finance methods | 无数据时显示修复入口 |
| 用户不想用记忆 | 记忆 tab 可关闭/不保存 | user data policy | `desktop_user.py` | 关闭后不写记忆 |
| 侧栏过载 | 摘要+抽屉，不铺满 JSON | DetailDrawer/RawPayloadDetails | shared components | 移动端不遮挡输入 |

### Tab 设计

| Tab | 内容 | 不显示 |
|---|---|---|
| 运行 | run id、status、events、stop/cancel | secret、堆栈全文 |
| 工具 | tool cards、参数摘要、结果摘要 | 未审核动态工具一键执行 |
| 证据 | artifacts、sources、引用链 | 无来源结论 |
| 金融 | 数据源、温度、雷达、风险 | 实盘交易按钮 |
| 审批 | intents、approvals、blocked reason | 绕过后端的本地确认 |
| 记忆 | 命中记忆、画像引用 | 其他用户数据 |

### 代码生成/修改步骤

1. 右侧栏数据只能来自 `AiaskApi`，不要组件内直接请求第三方。
2. 新增右侧模块时同步补 mock 数据和空态。
3. 每个 tab 都要有 loading/empty/error/degraded。
4. e2e 检查发送对话后右侧出现 run/tool/evidence。
5. 负向检查四工厂入口不从右侧出现。

### 不做什么

- 不把右侧栏做成广告式功能介绍。
- 不显示 secret、token、raw env。
- 不给金融动作实盘交易暗示。
- 不用 raw JSON 替代用户可读摘要。

### 状态机补充

`collapsed -> expanded -> tab_selected -> data_loading -> data_ready/data_empty/data_error`

当 Workbench run 变化时，右侧栏进入 `context_refreshing`。审批卡进入 `awaiting_decision -> approved/denied/expired`。
