## 1. 功能设计

### 1.1 需求背景与价值

| 项 | 内容 |
|---|---|
| 问题陈述 | 金融分析可信度取决于本地数据库状态、缺失和过期情况，用户需要看清是否能分析。 |
| 解决方案 | Data 页面展示数据库、codes、missing、stale、quality gate 和 sync plan；同步写入必须受控。 |
| 业务价值 | 避免基于过期数据做错误研究。 |

### 1.2 用户故事

| 编号 | 优先级 | 用户故事 | 成功标准 |
|---|---|---|---|
| DATA-US-101 | P0 | 作为金融用户，我希望看到数据是否新鲜，以便决定是否分析。 | missing/stale/counts 可见。 |
| DATA-US-102 | P0 | 作为用户，我希望生成同步计划，以便知道会同步什么。 | sync plan 显示 commands/intent_request。 |
| DATA-US-103 | P0 | 作为 QA，我希望同步不是静默写入。 | 受控状态和 side_effect 可见。 |

### 1.3 功能分解与优先级

| 功能编号 | 功能点 | 优先级 | 当前代码依据 | 待开发事项 | 验收标准 |
|---|---|---|---|---|---|
| DATA-F201 | 数据状态 | P0 | `/v1/desktop/data/status` | 错误文案 | status/missing/stale 可见 |
| DATA-F202 | 数据质量门禁 | P0 | `agent_quant_data_gate` | 与金融页联动 | gate failed 不写 ready |
| DATA-F203 | 同步计划 | P0 | `/v1/desktop/data/sync-plan` | intent 展示 | 显示 action/params/side_effect |
| DATA-F204 | 数据库细节 | P1 | db freshness tools | 路径和后端说明 | 不泄露敏感路径 |

### 1.4 业务规则与边界

| 规则 | 说明 | 验收 |
|---|---|---|
| Sync plan 不等于执行 | 文案不能写“立即同步”除非后端确实执行并受控 | UI 文案检查 |
| 写入受控 | 同步/调度/写库必须 intent/control token | 无 token gated |
| stale 显式展示 | 过期数据不能写 ready | stale badge |

## 2. 流程设计

| 步骤 | 用户操作 | 前端行为 | Agent/API | 异常 |
|---|---|---|---|---|
| 1 | 打开 Data | 加载数据状态 | `/v1/desktop/data/status` | 失败 DATA-301 |
| 2 | 输入 codes | 刷新 freshness | status route | missing/stale |
| 3 | 生成计划 | POST sync-plan | `/v1/desktop/data/sync-plan` | 无 token gated |
| 4 | 后续审批 | 跳转意图/审批 | `/intents` | 拒绝/过期可见 |

状态机：`loading -> ready|stale|missing|error -> planning_sync -> intent_ready|failed|gated`。

## 3. 架构设计

Desktop Data 页面只调用 Agent desktop_data route；AKShare MCP/data_sync 只在后端侧执行，前端不直接读写数据库。

## 6. 开发规范

新增同步动作必须写清是否只生成计划、是否创建 intent、是否真正写库，并补 e2e 负向断言。

## 7. 错误说明

| 错误码 | 用户提示 | 技术原因 | 处理 |
|---|---|---|---|
| DATA-301 | 数据过期或缺失 | stale/missing | 显示同步计划 |
| DATA-401 | 同步需要审批 | write side effect | 创建 intent |
| DATA-501 | 数据库不可用 | db path/backend error | 显示 degraded |

## 9. 不做什么

- 不让 Desktop 直接读写 SQLite。
- 不把同步计划写成已执行。
- 不隐藏 stale/missing。

### 10.2 功能细节

| 功能 | 当前字段 | UI 表达 | 验收 |
|---|---|---|---|
| 数据状态 | `database`、`freshness`、`missing_count`、`stale_count`、`quality_gate` | 指标卡 + RawEvidence | missing/stale 不为 0 时显示 partial/failed |
| 数据闸门 | `agent_quant_data_gate` 返回 status/missing/stale | 只读工具复核区 | 工具失败不阻塞整个页面 |
| 同步计划 | `intent_request`、`data_status` | 计划 JSON + 创建审批按钮 | 无 plan 或无 token 不可创建 intent |
| 历史同步意图 | `/intents` filter `data_sync.*` | 列表显示 pending/confirmed/failed | 不直接执行同步 |

### 10.3 成熟技术采用

OpenAPI/JSON Schema 用于请求字段和响应字段定义；AKShare/本地 SQLite 数据要按 freshness、stale、missing 显示质量；OWASP 要求写入/调度动作可审计。AIASK 采用 sync plan -> ActionIntent -> approval，不采用前端按钮直接写数据库或启动同步任务。

## 功能目标

数据库页面要告诉用户：本地数据库在哪里、是否可用、数据是否新鲜、哪些代码缺数据、同步会做什么、点击同步后是否真的进入受控执行。同步按钮不能只是摆设。

## 用户流程

1. 打开 Data & Sync，自动检查数据库状态和核心数据 freshness。
2. 用户输入股票代码、日期范围、max stale days。
3. 点击检查，显示缺失、过期、可用、fallback。
4. 点击“生成同步计划”，调用 `/v1/desktop/data/sync-plan`。
5. 如果计划有写入/耗时操作，前端创建 ActionIntent 或显示确认。
6. 同步完成后刷新 readiness 和新鲜度。

## 验收规则

1. 数据库路径不硬编码，不展示敏感本地路径细节。
2. 点击同步前能看到影响范围。
3. 写入同步必须有 token/intent/confirm。
4. stale、empty、fallback、optional unavailable 都必须可见。
5. 同步后市场温度、股票雷达、量化研究能读取刷新状态。

## 详细落地规范

### 问题场景与技术方案

| 问题 | 前端表现 | 技术方案 | 代码落点 | 验收 |
|---|---|---|---|---|
| 数据库不存在 | 红灯，显示初始化/路径配置建议 | readiness 返回 missing_db | `db_freshness.py` | 不显示空白表 |
| 数据过期 | stale 列表显示 code、last_date、stale_days | freshness check | `check_db_freshness` | stale_days 可见 |
| 用户点击同步不知道会发生什么 | 先展示同步计划和影响范围 | `/v1/desktop/data/sync-plan` | `routes/desktop_data.py` | 未确认不写入 |
| 同步失败 | 显示 failed/skipped/dead_letter | data_sync envelope | `tools/data_sync.py` | 错误可追踪 |
| 缓存与数据库不一致 | 显示 cache stats 和刷新建议 | cache stats + readiness | `data_sync.py` | 不把 cache 当 live |
| 市场温度缓存缺失 | Market Temperature 显示需要同步 | sync market temperature cache | `market_temperature/*` | 热力图不画假数据 |

### 同步按钮设计

同步按钮不能直接“点了就跑”。必须分三步：

1. `预检查`：读取 data status/freshness。
2. `生成计划`：列出 codes、date range、source、预计写入表、耗时、风险。
3. `确认执行`：需要 control token 或 ActionIntent，执行后显示结果。

### 状态机

| 状态 | 说明 |
|---|---|
| `ready` | 数据库可读，数据新鲜 |
| `stale` | 部分代码过期 |
| `empty` | 表存在但无数据 |
| `missing` | 数据库/表缺失 |
| `planning` | 正在生成同步计划 |
| `awaiting_confirmation` | 等待确认/意图审批 |
| `syncing` | 正在同步 |
| `partial_success` | 部分成功 |
| `failed` | 同步失败 |

### 代码生成/修改步骤

1. 需要新同步类型时先在 AKShare MCP `tools/data_sync.py` 增加 tool 或 service。
2. Agent 侧用 Desktop data route 或 `agent_*` facade 包装，不让 Desktop 直连 MCP。
3. `AiaskApi.dataSyncPlan` 返回计划；执行类动作必须走 intent。
4. 前端 DataSyncWorkspace 增加 PlanPreview、ImpactSummary、SyncResult。
5. 测试覆盖 stale、missing、plan、confirm、partial failure。

### 不做什么

- 不让同步按钮直接绕过审批写库。
- 不隐藏失败代码列表。
- 不把空数据解释成“没有问题”。
- 不硬编码数据库路径。
