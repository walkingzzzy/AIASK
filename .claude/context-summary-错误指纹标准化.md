## 项目上下文摘要（错误指纹标准化）
生成时间：2026-03-06

### 1. 相似实现分析
- **实现1**: `apps/web/app/strategy-market/page.tsx`
  - 模式：当前失败聚合已用 `normalizeFactoryRunError()` 对原始错误做简单截断
  - 可复用：`FactoryRunFailurePanel`、`failedRuns`、`detectFailedStage()`
  - 需注意：现状会把同类错误按细节拆散，聚合不稳定

- **实现2**: `策略工厂/02-接口定义与数据模型.md`
  - 模式：当前已将 `status = failed`、`error`、`stages` 列为失败聚合可复用字段
  - 可复用：失败聚合仍只基于既有字段，不扩接口
  - 需注意：标准化应写成前端轻量规则，不伪装成服务端标准错误码体系

- **实现3**: `策略工厂/03-模块功能方案.md`
  - 模式：质量门禁模块中已把“失败原因进一步标准化”记为中期方向
  - 可复用：当前/短期/中期表达方式
  - 需注意：本轮是页面聚合标准化，不是全链路统一错误模型

### 2. 项目约定
- **命名约定**: 指纹函数继续放在 `page.tsx` 内，采用 `Factory*` / `*ErrorFingerprint` 命名
- **文件组织**: 本轮只改 `apps/web/app/strategy-market/page.tsx`
- **代码风格**: 采用轻量规则匹配，不引入第三方分类库

### 3. 可复用组件清单
- `FactoryRunFailurePanel`
- `normalizeFactoryRunError()`（将被升级或替换）
- `failedRuns`
- `FactoryMetric`

### 4. 测试策略
- **验证方式**: `diagnostics` + `git diff --check`
- **阻塞说明**: 当前 Node 环境缺少 `next`，不重复触发已知失败的 Web build
- **关注点**:
  - 相同类别错误能聚合到同一指纹
  - 未命中规则时有“未分类错误”兜底
  - 页面仍保留最近失败原始示例，避免信息丢失

### 5. 依赖和集成点
- **数据来源**: `/strategy-market/factory/runs?limit=5`
- **页面位置**: 失败原因聚合面板内部
- **后端依赖**: 无新增

### 6. 技术选型理由
- 在前端做错误指纹规则化，能最低成本提升失败聚合稳定性
- 采用“指纹标签 + 示例错误”双层展示，兼顾聚合与排查
- 不强行引入服务端错误码体系，保持与当前阶段匹配

### 7. 关键风险点
- 规则过粗会把不同错误合并，规则过细又会失去聚合意义，需要平衡
- 当前只对最近窗口做聚合，样本数有限
- 缺少前端交互自动化测试，只能依赖静态验证
