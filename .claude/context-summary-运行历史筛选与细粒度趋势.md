### 2. 项目约定
- **命名约定**: 新增状态/指标选项使用常量或字面量联合，不引入新模块
- **文件组织**: 本轮只改 `apps/web/app/strategy-market/page.tsx`
- **代码风格**: 保持轻量控制组件，优先按钮切换，不引入复杂表单状态管理

- `factoryRunsQ`

### 4. 测试策略
- **验证方式**: `diagnostics` + `git diff --check`
- **阻塞说明**: 当前 Node 环境缺少 `next`，不重复触发已知失败的 Web build
- **关注点**:
  - 空数据/筛选后无数据时的安全渲染
  - 指标切换后趋势计算是否正确
  - 历史列表、对比和趋势是否共用同一筛选结果

### 5. 依赖和集成点
- **数据来源**: `/strategy-market/factory/runs?limit=5`
- **页面位置**: 工厂运行态卡片内部
- **后端依赖**: 无新增

### 6. 技术选型理由
- 用按钮切换替代复杂筛选面板，保持实现轻量
- 趋势指标切换直接在前端计算，避免扩展接口
- 统一筛选结果作为单一数据源，降低展示口径不一致风险

### 7. 关键风险点
- 筛选后可能只剩 0~1 条记录，需要正确处理空态与禁用趋势/对比
- 指标切换若与对比表不同步会造成理解混乱，因此要统一数据口径
- 当前仍无前端交互自动化测试，只能以静态验证为主
